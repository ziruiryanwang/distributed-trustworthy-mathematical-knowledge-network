## Material draft issue corrected before use

The draft startup sequence linked operators to the TLS guide's extraction/
verification block, which itself ends with `build.py`, then displayed another
build command. An operator following both could attempt to build the same
installation twice. Require one unambiguous build path: explicitly execute only
the guide's extraction/verification portion before the handoff's build command,
or use the guide's one build and remove the duplicate. Never rely only on a
later generic warning not to build twice.

The actual PowerShell 7 path should be bound explicitly using
`$Pwsh = (Get-Command pwsh -ErrorAction Stop).Source`, then retained instead of
the TLS guide's illustrative hard-coded path. The draft correctly warned about
the issue but only displayed `Get-Command pwsh`, leaving the handoff-to-guide
assignment unnecessarily easy to get wrong. This is the same operator sequence
correction, not a new runtime mechanism.

Both concrete corrections were sent directly to `package_cost_probe` and are
now verified in the revised startup text. It stops the TLS section-1 sequence
before that guide's build command and specifies exactly one build path; it
assigns and preserves the resolved PowerShell executable. No remaining
operator-sequencing blocker was found in that revision.
