# What v4 changes

October 7, 2026. This file describes the new software boundary. Final acceptance,
actual outcomes and exact distribution pins are in the adjacent RESULTS.md and
START-HERE.md; source descriptions alone are not acceptance evidence.

## The two central advances

### 1. Selective discovery and trustworthy reuse at large network size

An agent does not download a global ledger or census of the mathematics corpus.
It asks bounded indices and provider routes for candidates, acquires a selected
finite closure, and checks the exact formal result. Existing genuine succinct
certificates cut off theorem-proof ancestry. Transparent definitions needed for
meaning/conversion remain necessary inputs; a short hash cannot remove that work.

V4 adds persistent named definition recipes to this route. Each immutable module
binds its formal type, body, policy and exact imported module identifiers.
Acquisition budgets span the whole selected dependency operation: objects,
edges, charged byte events, requests, route events and time. Already retained
objects can satisfy later requests without network acquisition.

A shared-DAG translator lowers the selected recipes to the existing checked
formal language. For an imported body v declaring type T, it preserves the typed
application `(fun x:T => x) v`. The real checker must discharge this obligation;
the advertised type, sender identity and hash are not substitutes for it.

Remote candidate search now exposes authenticated continuation pages. Each page
retains its fixed work/row/byte bounds, but a ninth match is no longer permanently
hidden behind a repeated first page. Completion means the selected provider's
local cut, not a globally complete or current view of every peer.

### 2. Reusable mathematical constructions with justified accumulation benefit

The new persistent unit is a reusable construction, not merely another name for
a separately stored complete proof or definition. A participant can acquire a
construction, refer to its exact identity in a new recipe, check the result,
publish it and let another participant acquire and use that extension.

The philosophical model is resource-sensitive mathematical structuralism:
formal structures and checked relationships constitute the mathematical content;
knowledge accumulation concerns warranted capabilities accessible within finite
resources. Logical truth need not change when a useful proof or definition is
found. Human intention is not a network acceptance condition, and the network
does not prescribe a common list of research tasks.

This model has a concrete software consequence. For the fixed ten-construction
family, the actual exact reconstruction calculation gives:

| Retention policy for the same formal endpoints | Payload bytes |
|---|---:|
| Shared recipes only | 19,963 |
| Shared recipes plus largest single reconstructed capsule | 27,609 |
| Every independent self-contained prefix capsule | 53,480 |

Thus a32KiB mathematical-payload allowance can retain the shared recipes and one
working capsule but cannot retain all independent prefixes. Every selected
endpoint was actually reconstructed. This is a finite supported capacity result,
not only an asymptotic recurrence with an unknown crossover.

The comparison is specifically against retaining/transferring independently
self-contained prefixes. It is not superiority over arbitrary compression or
an already optimized local named library. SQLite/index pages, runtime, receipts,
evidence, service, checking and proving have separate allocations. Retaining
every flattened working cache erases the storage benefit. The software does not
automatically delete caches or promise universally faster mathematical research.
Every retained canonical capsule copy counts in the payload allowance, including
copies inside native artifacts or audit directories. The actual accounting run
kept all outputs for reproducibility; it did not execute an eviction policy.

## Integration and trust boundaries

The public interfaces distinguish these stages:

`candidate -> exact custody -> deterministic lowering -> local checking -> optional certification`

Only the appropriate checking/certificate stage warrants mathematics. A producer's
local success does not become a recipient's trusted flag. Usage frequency can
inform an agent's retention or ranking choices, never validity. Search can return
several objects with the same advertised type, including invalid ones. In
particular, `publish:false` suppresses that object's advertisements; it does not
make its retained catalog entry private to queries under a shared advertised key.

The reciprocal discriminator uses Iter, repeated squaring, and a construction
composing two blocks of squarings. An independently specified law about the exact
returned construction uses an already acquired proof fragment above a genuine
certified frontier. This is substantive use of the new construction, not a count
of new files. It is familiar, preauthored mathematics, not autonomous discovery.

The existing source-free certification implementation is retained. Its CPU-only
stage runtime dependency closure was additionally audited from the exact binary,
SDK sources and retained build evidence. This supports the unchanged completion
route without another duplicate proving campaign; it does not make proving free
or turn a native check into a new certificate.

## Deployment contract

The supplied release is Windows software with bundled selected runtimes and
finite public operation/session interfaces. Direct public-IPv4 peers require
reachable addresses, compatible policy and funded service/custody. No server is
indispensable. A joining participant still needs a reachable contact; partitions,
lost last copies and unbounded hostile traffic are not solved by cryptography.

Operation limits allow a very large global corpus through many independent local
selections. They do not allow an unlimited single selected closure. Current
lowering caps include64 modules,16MiB aggregate recipe input and4MiB output.
Acquisition has its own potentially different limits. Refusal or incomplete
discovery is explicit; no stage silently converts missing information into proof.

No second physical host or Internet-wide deployment was tested. No external
publication has been performed. The project's source-license choice remains
undecided at the user's instruction. The final report distinguishes these
conditions from the implemented and tested v4 milestone.
