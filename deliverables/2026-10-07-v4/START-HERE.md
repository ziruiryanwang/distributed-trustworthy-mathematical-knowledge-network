# Mathematical Commons v4

October 7, 2026. The completed, substantially advanced v4 software milestone.
Actual release adoption is recorded in [RESULTS.md](RESULTS.md); the independent
final seal is [HANDOFF-INTEGRITY.md](HANDOFF-INTEGRITY.md). This is a fixed
supported release, not a claim that the entire global-commons ambition is solved.

## What you can do

Run an independently controlled mathematical-library node. Create a formal
definition recipe, find and acquire selected recipes from peers, check the exact
mathematics, build a new construction using those recipes, and offer it back.
The existing theorem lane supports checked law application and succinct
certified frontiers: receivers need not download the proofs behind those
frontiers. No central server, global ledger, shared research-task list or
natural-language interpretation is required.

The principal v4 addition is a persistent shared semantic library, not another
proof counter. Small contributions refer to exact earlier constructions. Their
declared types are checked rather than trusted. Bounded remote pagination also
removes the previous permanent first-eight-result discovery limit.

## The four layers, in plain language

| Layer | Question it answers | What v4 does |
|---|---|---|
| Mathematical warrant | Is this exact formal result justified? | Checks lowered definitions and proof fragments, or verifies actual compatible certificates. A hash, reputation or popular result is not proof. |
| Selective shared library | How can I obtain and reuse a small relevant part? | Content-addressed recipes, exact imports, bounded type/ID search, continuation pages, selective acquisition and retained local custody. |
| Useful accumulation | What new capability or resource improvement did this contribution enable? | Shared constructions plus checked laws; explicit endpoint/baseline/cost analysis instead of counting names. A finite payload-capacity improvement is established. |
| Independent operation | Who decides what to research, keep and serve? | Each local owner/agent, using public APIs, finite budgets and reachable peers. No central task planner is necessary. |

A typical path is:

```text
find candidate -> acquire exact recipes -> lower selected dependencies
               -> check exact mathematics -> build and contribute a new recipe
```

Optional certification supplies a separate reusable proof boundary; local
checking does not automatically create a transferable certificate. Different
nodes can retain different parts of the corpus. Needed transparent definitions
remain real inputs even when proof ancestry is succinctly certified.

## A concrete growth result

For ten fixed reusable constructions, the actual exact-size calculation is:

```text
19,963 bytes of shared recipes + 7,646 bytes for one largest capsule
    = 27,609 bytes <= 32 KiB < 53,480 bytes for all independent prefix capsules.
```

All ten endpoints were reconstructed. This proves a useful storage-capacity
region against that specified retention protocol, not faster research in every
setting. Count every retained full capsule copy, wherever it is stored; the
audit run itself kept all outputs and did not perform eviction. Runtime, indices,
checking, service, evidence and cryptographic proving also cost resources.

The corresponding acquired law is mathematically meaningful: two blocks of
repeated squaring can replace a much longer fixed-base multiplication loop in
an associative structure. Its algorithmic operation counts are theoretically
justified; actual evaluator speed and total research speed are not inferred
from checking the law. See [the detailed growth argument](../../research/cycles/v4-2026-10-07/GROWTH-OPERATING-REGION.md).

## Supported deployment and remaining research

Independent peers need reachable contacts, compatible policies, funded finite
service and retained copies. The direct public-IPv4 profile does not supply NAT
traversal or make missing data recoverable. Search is bounded and potentially
incomplete; it never certifies that a theorem does not exist. Huge global size
does not imply unlimited size for one selected dependency closure.

Tests used separate processes on one physical Windows machine. Internet-wide
reliability and arbitrary Lean/mathlib coverage are not claimed. No external
publication has been performed; the source license remains undecided as requested.
The project-wide ambition exceeds any one release: full-cost useful-research
acceleration, broader formal vocabulary and stronger large-network service
evidence remain consequential directions, not claims hidden in a version number.
