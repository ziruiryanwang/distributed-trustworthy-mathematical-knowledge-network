# CP-001G: composable evidence and practical mathematical reuse

Date: 2026-09-20. Status: integrated concept/specification checkpoint with independently reviewed repairs and an integrity manifest. This is not a software release or a claim that the ultimate project goal has been achieved.

## Purpose and entry point

Advance the actual reciprocal loop: an independent local investigator must be able to find existing mathematics, acquire and check its evidence, combine it with other developments, use it through a workable local interface, and contribute the resulting mathematics without a shared research agenda.

Start with [Operational corpus v4](../../spec/OPERATIONAL-CORPUS-V4.md), then its selected detailed contracts and the [audit disposition](../audits/CP-001G-AUDIT-DISPOSITION.md). The [mutable current-design pointer](../../CURRENT-DESIGN.md) identifies the latest integrated cut. Frozen v3/v2 contracts supply unchanged authority, transfer, native semantic, custody and migration rules.

There is no mandatory central server, global theorem ledger, natural-language/intention assessment, research scheduler or unsolved-mathematics task registry. Local agents select their own investigations. Formal acceptance and practical usefulness are separate: heuristic search/ranking is allowed, while actual claimed mathematical results require complete checked evidence.

No implementation, executable model, build, Lean replay, artifact extraction, exploit or benchmark was performed. Evidence in this checkpoint consists of specification, conditional proofs, explicit counterexamples, read-only pinned-source inspection, arithmetic and independent cross-audits.

## What the arguments establish

For a finite complete supported acyclic source graph, the source-earliest representative construction gives a finite acyclic PI1 materialization plan without recursively expanding every predecessor proof body. Its statement, instance and semantic-alias nodes have distinct obligations. The representation supports proofs appearing in types and proof-bearing data, rather than limiting the remedy to proof-only wrappers with unchanged external backgrounds.

For a fixed finite candidate graph, structural AND/OR grounding is monotone and preserves the groundability of supplied acyclic branches whose actual alternatives are present. This is a graph-planning theorem, not theorem acceptance, optimal witness selection or a guarantee that chosen evidence fits the receiver's resource/axiom policy. Changed representatives can force substantial native rechecking.

For BRIDGE1, ordinary native application establishes the actual transported value/result type under its exact checked context. It establishes a desired different predicate only with native conversion or a checked transport proof. Missing residual parameters move into an explicit extended context; they do not become silently discharged assumptions.

STRUCT2 now specifies an actual finite extractor/query protocol. Counterexamples led to explicit role lifting for Iff/Eq directions and deterministic virtual work accounting. The specification is testable; its practical recall and efficiency are not inferred from its determinism.

## Source-backed practical targets

The source investigation identified ordinary cases that need the mechanisms: `Finset.range` stores a nodup proof; `Fin.castLE_castLE` includes transitivity evidence in its statement; the List-setoid/Multiset/Finset chain carries proof dependencies into nominal interfaces. Safe classical quotient choice remains distinct from unsafe extraction.

The client audit also identifies real frontend state and exact-name dependencies in class output parameters, numerals, coercions, structures, instances and simplification. Ordinary source convenience requires a local presentation bridge, not only renamed native declarations. A correspondence recipe cannot install peer executable code or use unproved field labels as projection semantics.

These are read-source facts and specified representation/application paths. Complete runtime declaration graphs, broad supported-library coverage and end-to-end performance have not been observed.

## Remaining substantive work

Broad source-to-native reconstruction, exact qualified bootstrap/frontend inventories, difficult proof-computation behavior, affordable rechecking after large realization changes, practical structural recall and sustainable actual index/custody resource supply remain substantive questions.

Continue concept/source analysis where it can resolve concrete mechanisms.
