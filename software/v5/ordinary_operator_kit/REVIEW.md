## Binding obligations

Successful initialization is `ok: true`, operation `init`, result status
`INITIALIZED_LOCAL_OWNER`, with `result.basis.status == CHECKED` and the exact
`result.basis.local_root`. This root is explicitly selected via a report; there
is no `latest` query. A successful report is still untrusted input and never
substitutes for the actual product's protected-root validation.

Completed baseline intake has result status `BASELINE_INTAKE_COMPLETE`, an exact
manifest SHA, selected root, final local root and batch observations. A stopped
intake may retain a confirmed prefix or an unreported commit. Neither its
`last_confirmed_root` nor an `accepted` diagnostic may be promoted automatically
by this helper into a completed operation. Preserve failure reports and select
recovery separately.

The producer's intermediate `PRODUCTION.json` status is
`PREPARED_FOR_MANIFEST_WRITE_NOT_COMPLETION`. Only the final public
`produce-baseline` report has `PRODUCED_INERT_BASELINE_NOT_ACCEPTED` and completed
output/manifest paths. Even that result has mathematical acceptance false.
Publication preparation must bind that manifest to the receiver's completed
intake manifest, then select exact structured name/export/unit triples. Matching
hashes establish identity, not mathematical authority or source approval.

Find can succeed with `INCOMPLETE_SEARCH`; its exact positive row is usable as
an explicit selection, but there is no global coverage claim. Preview is
`PREVIEW_BOUND_NOT_ACCEPTED`, not acceptance. A later receive's `REUSED` result
can legitimately have mathematical acceptance false because an existing local
acceptance is reused rather than freshly checked. The kit must not invent a
positive result from these advisory reports.

## Reviewed source and fixes

The reviewer read the whole preparer and both user-facing files, then reread the
final source and final documentation additions. The public command arguments and configuration
shapes match the inspected current consumers within the documented smaller
starter subset. Init/intake deliberately have no `--output`; their actual
reports come from the bounded launcher's retained child stdout. All commands
remain inert argument arrays with a fixed `owner` or `peer` entry, not shell
programs assembled from report content. The helper does not import product
modules or read catalog/custody/index contents.

The review identified and the author corrected:

- An incorrect discovery-record schema string. The helper now requires the
  actual `DMKN_FORMAL_FEATURE_RECORD_V3`, kind and V2 locator shape.
- Missing exact export-identity checks. Producer targets and search locators
  are now bound with the public domain-separated semantic/unit/structured-name
  digest; canonical output matches the product's UTF-8 encoding.
- Incomplete root consistency checks. Completed intake batches now require
  ordered positions, CHECKED/REUSED statuses and a final root equal to the
  result root. Owner reports must match all explicit state selections.
- Fresh/existing path compatibility. Fresh leaves require existing parents;
  non-init state and reopened indexes must exist. Overlap, hardlinks, redirects
  and Windows reserved path components are refused before kit output writes.

One proposed check was correctly rejected after joint reasoning: requiring the
producer's original directory to equal the receiver's local bundle directory
would break legitimate cross-machine sharing. The selected local manifest is
bound by exact bytes/hash/semantic identity instead. Report-contained producer
paths remain unfollowed. The suite includes a positive relocated-bundle case.

No substantive blocker remains for testing this offline adapter. The preparer
does not attempt to duplicate mathematical parsing, namespace derivation,
complete manifest/unit validation, TLS key validation or source authorization.
Those remain actual product/operator obligations. A consistently fabricated
success report can still produce an inert configuration: this tool cannot
authenticate reports or turn their claimed roots into accepted mathematics.
Its report checks catch incompatible/partial handoffs, not malicious lying in
general. The product must revalidate the selected state and mathematics.
