# Next central decision: make the existing commons one usable product

2026-10-28. Independent source-only review by `release_direction`. No product
imports, tests, compilers, owner access, service, Git mutation or external activity.
This recommendation follows the selected preview work; it does not select runtime
or alter its scope. The full v5 objective remains active, local and unpublished.

## Recommendation

**After closing the bounded preview, consolidate the actual current package,
matching operator companion and preview into one self-contained local distribution
with one current use contract.** Reuse the existing flat source/build and
pack/verification machinery. Do not add another search feature, concept episode,
certificate experiment, generic package manager or mutable workspace registry now.

This is a release-interface repair, not a proposal to restart packaging research.
The native checking and reciprocal theory loop already exist. Their public entry
is still distributed across incompatible historical guides and development paths.
The concrete barrier is now visible in the actual adopted artifact, not inferred
from the number of research directories.

The single acceptance question is:

> Can a Lean investigator use only the extracted distribution and its selected
> external runtimes to locate the current commands, prepare an explicit exchange,
> read its formal candidate, develop a contribution and expose the checked result,
> without consulting this research checkout or reconstructing its history?

Do not claim measured growth acceleration or final worldwide readiness from a yes.
Do require a yes before investing in additional discovery mechanisms.

## Concrete workflow and current entrypoint

An investigator has an independently approved Lean installation/project and a
small set of replaceable contacts. They choose a concept, query known formal
symbols, inspect candidate types, receive selected evidence under an explicit
dependency policy, develop definitions/models/consequences in ordinary Lean,
check the selected contribution, and publish or hand it to an inert host. Another
investigator can take over the mathematical continuation. No global research
agenda, human-intention field or automated choice of mathematics is needed.

The adopted package is
`experiments/v5-local-checks/reply-capacity-assembly01/distribution/package`,
PROFILE `c8c8b5971e43361b7b09847b35b0e44c2645b284e59c59b90ab993136ccdb146`.
Its matching preparer is `ordinary_reply_capacity/operator/prepare_selected.py`.
The package's `run.py` supplies bounded owner, peer, query and host operations.
Those are genuine reusable operations, not merely theoretical diagrams. The
finite-map recipient and observation-growth evidence already exercises substantive
checked extension and return; repeating it would add little to this decision.

## Minimal coherent distribution contract

1. One root current guide and one bounded manifest identify the actual prebuilt,
   external runtime profile, matching operator code, preview code and build recipe.
   Root guide paths are relative to the extraction. No operational instruction
   requires an `E:` research path, an experiment directory or a missing predecessor.
2. Keep the selected 158-file package byte-for-byte intact. Put operator tools,
   preview and the authoritative current guide beside it. Explicitly identify
   the packaged historical README as historical material and direct all setup/use
   entrypoints to the root guide. This avoids a cosmetic PROFILE migration and
   preserves existing seals and reports. A later code update can replace obsolete
   embedded documentation as part of its normal release.
3. Include the complete matching operator helper closure and a unified current
   request catalog. Preserve explicit source approval, package selection, resource
   ceilings, dependency policy and report-selection disclosure. These are user
   choices; SHA computation, fresh output naming and historical lineage are not
   mathematical decisions. Do not make the user traverse predecessor directories
   to learn an action's current fields.
4. Supply the direct current source closure and build instructions as the matching
   source handoff. Reuse the selected map/recipe and existing exact-tree machinery.
   Include every actual utility dependency, but no old state, corpus or experiments.
   The source handoff's build claim must distinguish previously tested native lanes
   from any unexecuted packaging changes.
5. Provide one complete ordinary investigator route and one dedicated inert-host
   route. Expose ordinary source as the preferred route when already approved;
   preview/receive serve the distinct unaccepted-candidate route. Do not prescribe
   when an agent should investigate, force search, or automatically execute offers.
6. Separate operational results clearly: discovery information, complete formal
   display, accepted mathematics, checked continuation, publication, and a finite
   hosting lease. Their receipts remain evidence; none is renamed a stronger result.

This can use the already reviewed `ordinary_current_release` flat-selection design
and the more recent source-bundle helpers. Its old pins/counts/operator selections
are historical, so they must not be treated as current defaults. Prefer a narrow
explicit selection over a new framework. Preserve all old artifacts; no cleanup
or source-tree restructuring is part of this recommendation.

## Evidence worth collecting and stopping rule

First reconcile the extraction layout, exact dependency closure and current
command/request table from source. Check every user-facing internal link and
command path against that layout, including host and prior-report use. This
settles the main issue without a theorem experiment.

Then use a fresh bounded file-only distribution check and one relocated inert
preparation/display invocation over retained authentic input. The relevant boundary
is relocation and complete current dependency selection, not theorem truth or
network scaling. Retain existing native, recipient and host results as their own
evidence. A second native build or reciprocal mathematical episode is unwarranted
unless the actual build/checking boundary changes.

Stop when the current extraction alone supplies an internally consistent usable
route and the selected preparation/display paths work from it. Do not turn this
into an installer, GUI, service manager, automatic upgrade or account system.

## Why this has higher present payoff than the alternatives

The capability/pruning argument already explains a defensible benefit region:
checked models, countermodels and bridges can prevent wasted trials when the
prefix savings exceed discovery, adoption and service costs. The real examples
show new concepts and extensions can pass through the software. Neither result
establishes that agents will find relevant work cheaply enough, and ordinary
Git/Lake/search is entitled to the same mathematics and caches.

Another theorem about sharing cannot establish the missing prevalence of useful
exposure. Another forced-index example would not identify that prevalence either.
The latest investigator used ordinary source successfully; that is evidence
against assuming a new ranker or matcher is the next bottleneck. Global semantic
completeness is unavailable without stronger assumptions, and a new cryptographic
campaign does not remove discovery or source-usability costs.

By contrast, every actual new user must select and operate the distribution.
Fixing contradictory setup instructions has a direct, bounded target, reuses
completed implementation and avoids inventing mathematical policy. The claim is
reduced avoidable setup/interpretation work, not a measured number of seconds or
an economic dominance theorem. Packaging alone is not research growth; it is a
necessary path for people to exercise the growth capabilities already built.

A persistent workspace handle/one-command driver might later remove repetitive
hash and report plumbing. Defer it until the coherent current contract reveals
which exact repeated action warrants state or automation. An existing stateless
kit is preferable to a premature new registry. Likewise, no new general Lake
adapter is justified without an actual incompatible project.

## Remaining limits must stay visible

This next step does not complete v5. Worldwide operational assurance, independent
security assessment, sustained multi-operator availability, supported-platform
decisions, license/signing/maintenance and practical growth value remain real.
There is no authorized external participant or public release now; local packaging
cannot manufacture that evidence. The ordinary cold path still requires its
explicit bounded dependency closure; warm approved libraries and optional
certification are different tradeoffs, not a universal constant-time verifier.
Search remains budgeted and selectively indexed, with explicit incomplete coverage.

Once the current product can be used without its research history, reassess the
largest remaining deployment or observed workflow barrier. Do not automatically
select the next small patch merely because this consolidation passed.
