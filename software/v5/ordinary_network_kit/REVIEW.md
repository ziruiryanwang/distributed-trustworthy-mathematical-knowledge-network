No global completeness or search-coverage claim is created.

## Configuration preservation and finite bounds

- Direct find accepts only optional exact string `atomic-v1` or `sparse-v2`.
  Omission remains omission; no unsolicited mode switch or budget renewal occurs.
  Factored settings preserve existing search, offer and page fields/limits.
- Optional index access configuration is forwarded unchanged. Enabled values
  require 1..8 sorted unique pairs of strictly ordered 64-hex identifiers,
  strict integer quotas and at most 4096 canonical bytes. Null is intentionally
  equivalent to the product's `None`/disabled default. Create/reopen/capacity
  semantics stay product-owned; the helper does not migrate or read the index.
- Directory-find validates the exact seven public config fields, explicit
  contacts and 1..8 distinct directory seeds, 1..8 distinct normalized route
  subsets, at most 32 seed/route combinations, the actual directory limits and
  `reply_bytes >= max_bytes`. Nested search/mode is forwarded unchanged.
- Egress is separately explicit: exact schema, sorted unique 1..16 public ports
  with no test rows, or sorted unique 1..16 `127.0.0.1` test endpoints with no
  public ports. This describes the later product policy; the helper does not
  authorize or perform a network operation itself.
- Directory-serve accepts 1..2048 distinct exact routes and 1..16 distinct
  endpoint hints per route. Hints have exactly host/port/tls/server_name, use
  canonical numeric IPv4 and validated lowercase TLS names, and cannot include
  CA paths. Finite service lease, cleanup, provider and TLS settings match the
  actual product boundary. It needs no catalog/custody arguments.
- Ordinary serve retains explicit whole-custody/exclusive approval and requires
  an existing index. Its factored service validation retains the predecessor's
  field set and output form.

The query subset is intentionally unchanged: portable type symbols,
object/declaration kinds and exact declared-type keys. Normalized duplicate
specs are treated like the product's set of feature conjuncts; distinct route
