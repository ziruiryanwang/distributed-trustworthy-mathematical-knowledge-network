# Generic selected-target sealing owner

This is a new owner-controlled lifecycle over the retained small-segment producer.
It is not a peer acceptance API. A preparation, snapshot, saved report or stage
checkpoint is never a mathematical warrant. A receiver verifies the actual final
receipt independently before using or publishing its certified representation.

## One repeated workflow

Export a locally admitted mixed packet; prepare one exact native target J; execute
one bounded snapshot; fund finite missing proof stages explicitly; independently
accept the resulting A/H receipt; select the exact J member; retain/publish its
interfaces and demanded semantics; author a new native extension. That extension
can enter the same workflow with the previous A as a certified premise. There is
no global agenda, automatic certification, implicit funding or ancestry download.

## Stable installation and profile

Run within the retained owner's selected isolated Windows Python (`-I -S -B`) and
a separately bounded enclosing owner. Construction, imports, preparation, refusal,
final report and exit costs are not free and must be included in that outer scope.

`LifecycleProducer(profile)` requires exactly:

```text
schema = DMKN_AGGREGATE_LIFECYCLE_PROFILE_V1
base_profile = unchanged DMKN_V5_SMALL_AGGREGATE_PRODUCER_PROFILE_V1 object
source_pins = one {path,bytes,sha256} for every producer.source_paths() entry
snapshot_host_build = actual {result,attempt,selection,source_map,command} pins
```

The base loader validates the existing supervisor, stage-host build and A image
adoption. The new owner additionally validates the actual snapshot-host build and
the complete imported Python source closure, including package initializer imports.
All source paths must identify the actual loaded files. `profile_document()` returns
a defensive copy for caller-controlled durable saving and pinning; it writes nothing.

The profile ID is SHA-256 of the explicit lifecycle domain plus canonical lifecycle
profile bytes. Base profile bytes are not mutated. Changing the helper, host, adopted
build or installed paths changes the profile ID and prevents old-allowance continuation.
Use one stable installation across prefixes; the enclosing operation's evidence
snapshot is not a fresh executable installation. Historical cost-screen records and
failed attempts remain unchanged. Resource-refined host builds are not supported by
the old adoption grammar; they require a separately selected explicit successor.

## Prepare and snapshot

```python
prepared = owner.prepare(packet_bytes, exact_J, envelope=envelope)
report = owner.snapshot(prepared, configuration=config_pin, selection=outer_selection_pin)
```

`prepare` is pure mathematical *input selection*, with source rebinding, not checking.
The envelope is the exact `mixed_claims.packet.Envelope` type. Exact J is 184 immutable
bytes. It must name a native delta in the input, not an already-certified frontier.
The helper preserves the full backward closure and ordered I/A claim table.

The new configuration is an owner-pinned JSON document with these exact fields:

```text
schema = DMKN_AGGREGATE_LIFECYCLE_SNAPSHOT_REQUEST_V1
profile_id = the live composite owner profile ID
profile_document = pin of the complete lifecycle profile document
packet = pin of the original mixed packet bytes
target_journal = exact J as 368 lowercase hexadecimal characters
envelope = all fields of dataclasses.asdict(Envelope(...))
cycles = integer in 1..2^26
po2 = 18
diagnostic_mode = stats
limits = all keys below, each explicitly selected within its ceiling
output_directory = fresh ordinary absolute directory with an existing parent
```

| Limit | Ceiling |
|---|---:|
| worker_cpu_seconds | 180 |
| controller_cpu_seconds | 60 |
| wall_seconds | 240 |
| memory_mib | 3072 |
| active_processes | 2 |
| stdout_bytes, stderr_bytes | 1 MiB each |
| output_bytes | 208 MiB |
| output_entries | 288 |

The original configuration, profile document, packet and every adopted installation
pin must appear in the enclosing `DMKN_V5_LOCAL_CHECK_V1` selection's runtime map.
This is the actual existing local-owner selection format, not a newly invented outer
success record. A programmatic caller can be the selected harness; no product CLI is
implemented yet. `snapshot` does not fabricate or complete its own enclosing report.

Snapshot rederives and compares the entire `PreparedSeal` from the pinned originals.
It creates `wire.bin`, `header.bin` and indexed `parent-N.bin` with exact original
receipt bytes, then a pinned `staging.json` and `COMMAND.json`. These newly created
files are internally bound generated inputs, **not pre-existing runtime pins**.
The host receives receipts in the encoded claim order and performs unchanged genuine
I/A receipt verification, native relation checking and exact-A guest execution.

A clean result has status `PASS_ONE_GENERIC_EXECUTION_CAPSULE_ONLY`. Even then it is
an untrusted execution capsule, not a receipt. One attempt never starts proof stages,
retries, changes geometry or increases caps. Failure preserves its charges and files;
uncertain process closure closes the owner. `FINALIZATION-FAILED.json` overrides a
saved apparent success. Output checks are sampled censuses, not filesystem quotas.

## Adoption and ordinary production

After the enclosing operation actually finishes cleanly, collect the five pins:

```text
snapshot_evidence = {result, outer, selection, configuration, command}
```

`result` and `command` refer to the lifecycle output's `RESULT.json` and `COMMAND.json`;
`outer` is the actual enclosing completion record, not a caller assertion.

```python
request = owner.production_request(
    snapshot_evidence, allowance_id=allowance_id, budget=budget,
    checkpoints=retained_checkpoints, prior_attempts=all_same_allowance_attempts,
    output_directory=fresh_stage_output, stage_limit=finite_prefix,
    carried_external_costs=explicit_external_costs)
quote = owner.preflight(request)  # Optional fresh validation; no host/output call.
result = owner.run(request)       # Only when separately selected and funded.
owner.close()
```

`production_request` already performs the full no-runtime preflight. It validates
the new snapshot schemas, actual outer completion, source/profile/configuration,
exact generated manifest, ordered receipt bytes, saved invocation/stdout, completed
capsule and final bindings. It returns the unchanged internal small-producer request
grammar. The inherited scheduler retains all stage manifests, reservations, prior
charges and successful checkpoints. No automatic continuation or allowance migration
occurs. A new snapshot is a new session even if the mathematical target is unchanged.

The selected original packet remains an input pin during stage adoption; this is
bounded packet parsing, not rechecking certified ancestry. It is deliberately
conservative: the 20 MiB fixed-session ceiling includes original/derived input and
adoption records, not only the wire. Before layout, reserve 14 MiB for worst-case
diagnostics and remaining evidence records. Also reserve both 96 MiB capsule/segment
ceilings, 8 MiB diagnostics, logs, staged bytes and final reports within 208 MiB.
Thus some structurally valid mixed packets are refused by this production profile.
Refusal means operational incompleteness, not false mathematics. No cap silently grows.

## Assurance and economic boundary

Same A/I/F/P, exact H/J and immutable byte identity are necessary bindings, not an
independent proof of checker correctness or cryptographic soundness. Saved local
records are not tamper-proof accounting or mathematical authority. A receipt can
certify its theorem interfaces without containing every demanded transparent body;
semantic retention and publication remain separate ordinary client operations.

Price original-packet preparation, repeated native preflight, guest layout, proof,
receiving, failed searches and retained custody. This interface enables selective
renewal; it does not establish that every renewal pays for itself or that useful
knowledge grows exponentially. The full deployable v5 goal remains open.
