# Focused selected-export controls

Source plan only. Root selects execution after independent implementation and
test review. No native compilation/check, existing owner/custody mutation,
network service, publication or repeated theory episode is needed.

Use actual supported pure evidence/bundle codecs and fresh SQLite custody-format
fixtures. These contain inert claims, not fabricated accepted owner state. The
reader must never open a catalog or `.olean`; the companion's one fixed worker
runs under the existing bounded Windows Job.

1. Export one exact root through a multi-hop full-import closure; preserve bytes,
   topological order, atomic group siblings and target binding. Exclude unrelated
   custody evidence. Re-read all output through the unchanged baseline manifest
   and batch validators. Full import closure includes proof-only imports.
2. Export a structurally valid but unproved/false fixture without claiming source
   acceptance. This tests separation of custody from truth, not false admission.
3. Refuse missing locators/evidence, wrong target name/export/unit, corrupt stored
   bytes, wrong semantic identity, wrong fixed-basis binding, conflicting names,
   malformed target lists and each economically relevant finite bound. Cycle
   handling may need an explicitly labeled identity double: a true hash-bound
   cycle is not something a fixture can construct by guessing fixed points.
4. Read-only snapshot: selected database bytes unchanged, writes prohibited,
   transaction closes on success/failure, fresh-output rule and input/output
   separation hold. Journal/WAL/SHM paths refuse without recovery or mutation.
   Do not claim adversarial filesystem-race isolation from these checks.
5. Actual public companion CLI on one fresh synthetic custody, successful Job
   closure and exact baseline-compatible output, with neither Lean nor service
   subprocess. Parse static Python source first; no runtime fallback/retry.

If a retained real corpus is used, select exact manifest and byte pins in advance
and treat its copied fresh custody solely as an inert fixture. Data movement does
not renew its old mathematical acceptance, establish growth, or justify another
native replay. A synthetic fixture is sufficient for the new data-only contract;
prefer it unless the real corpus resolves a remaining group/format question.

Record failures unchanged. Tests may freeze one used source cut; any actual repair
then needs a distinct successor rather than editing its evidence. Whole-operation
Job CPU includes child work; never add nested child CPU a second time.
