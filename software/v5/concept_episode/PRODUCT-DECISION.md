## What the episode proves about concepts

A proposed a definition, developed nontrivial consequences and countermodels;
B independently chose extra structure and proved a connection to closure
operators, least fixed states and order dependence. CONTENT-AUDIT found genuine
mathematical content. This is stronger evidence than merely accepting a new
structure declaration, but the demonstrated creative A-to-B continuation belongs
to the **ordinary Lean authoring lane**. The project supplied independent inert
acceptance of A; B's return is a separate operation and its outcome is not assumed.

The defensible product requirement is an open creative loop: independently
chosen definitions and conjectures can be developed, challenged, offered, found,
checked, used and extended. The investigator may be human, symbolic or learned;
the trusted checker need not invent. A distributed system including such
investigators can develop theories without a central research scheduler.

Do not turn that into a guarantee of autonomous invention by the shipped node.
The current experiment used externally prompted investigators and supplied
handoffs, not a demonstrated self-running research service. An optional ordinary
local investigator workflow must eventually make this loop executable without
our private orchestration; it need not prescribe a common scientific agenda.

Sound definitions can be empty, redundant or uninteresting. Formal models,
countermodels and connection theorems establish particular content; usage,
compression and downstream leverage remain fallible selection signals. No
importance/novelty oracle belongs in mathematical admission. A/B provides
episode-relative conceptual choice, not literature novelty or research speedup.

## The present unacceptable bottleneck

**The demonstration's central agent supplied exactly which new work the next
investigator should read.** Repeating A/B with another supplied handoff would
not address access to unexpected useful work in a large commons.

Exact desired-type search alone is insufficient for forward theory development:
an investigator need not know the next useful statement or even its vocabulary.
But replacing it does not require a new semantic search engine. Current
`ordinary_formal_query/discovery/ordinary_export_adapter.py` already supplies
`type-symbol`, declaration-kind and structural-head features alongside exact
type keys. `OrdinaryExportAdapter.describe` extracts explicit constant/projection
references from the complete type, without reading proof history.

For a known concept symbol s and declaration d in a selected compatible finite
index, if s occurs in d's explicit type and its preview/feature extraction is
correct, then d has the `type-symbol(s)` feature. Thus a query for s can expose a
new declaration **without knowing d's name, full type or endpoint beforehand**.
Whether the actual finite search returns it also depends on coverage, caps,
ordering, routing and availability. This is an index relation, not a recall or
importance theorem.

B's actual `follows_iff_swap_le` and `mutual_follows_iff_commute` signatures use
A's `Repair`/`Follows` and B's new `OrderData`/`IsClosure`. They exemplify an
existing route from a known concept to a previously unknown formal connection.
Their names are examples for this source review, not names to reveal to a future
independent searcher or hard-code into a supposed discovery query.

After `find`, existing `preview` exposes the candidate's complete formal type
and symbol identities before proof acquisition. An investigator can select a
connection, acquire needed semantics/evidence, then use an approved ordinary
package or a supported inert route. A preview is not a warrant, applicability
proof, definition body or executable source. A correct indexed type can still
have a false advertised theorem; independent acceptance remains necessary.

This is bounded **forward exploration**, not a mandatory unresolved-task list.
Known-concept neighborhoods supply options; investigators choose their own next
questions. Proof-only dependencies are intentionally absent from this index.
Implicit relationships or bridges not expressed in indexed types can be missed;
ordinary package/source search and heuristic suggestions remain useful options.

## Why not fix the matcher first?

EXCHANGE-ROUTE establishes a sound narrow exact-record reconciliation proposal.
Its common Option/Prod obstruction is real, not dismissed. But implementing that
matcher still leaves full A above the 32-unit realization cap and does not restore
new structure/class/instance metadata. It would therefore buy another partial
importer capability without yet making this complete theory easier to develop.

Ordinary approved package handoff already preserves the rich frontend needed by
this episode. Independent endpoint checking offers a distinct assurance service;
it neither endorses producer executable code nor retroactively makes its loading
safe. Recipients unwilling to approve that package may currently lack a usable
route. Report that limitation; do not silently trade it away.

Reopen the matcher only for an actual selected no-producer-code consumer whose
needed complete interface fits the rest of the supported realization path. Do
not distort a new concept to pass that test or automatically buy metadata recovery.

## Comparator and next stopping rule

Native Lean, ordinary repositories, mirrors and existing search tools receive
full credit. They can support the same creative episode; no algorithmic advantage
follows from wrapping them. The project's potential contribution is interoperable,
bounded discovery plus optional independent acquisition and continued availability
without one indispensable provider. Those are implementation obligations, not a
new mathematical claim about invention. The existing full-cost growth/comparator
arguments still apply; no extra abstract speedup theorem is needed here.

For the next root decision, inspect whether actual admitted A/B selected targets
can populate the current ordinary peer/discovery path with their exact previews
and evidence, and whether an A-known symbol query can be specified independently
of B's target identity. Charge publication, indexing, failures and acquisition.
If an existing supported seam suffices, select only the necessary integration;
if not, identify that exact seam before a source successor. Do not implement a
new ranking service, formal ontology, bridge registry or remote model service.

Large-scale caveat: one popular symbol can have an enormous neighborhood. A
bounded prefix is neither scalable relevance nor global completeness. Specialist
corpus choice, selective conjunctions, capacity and coverage remain the existing
conditional discovery obligations; novelty may require exploring outside familiar
symbols. Success on A/B would demonstrate one real connection-access path, not
solve those obligations or justify a final-v5 label.
