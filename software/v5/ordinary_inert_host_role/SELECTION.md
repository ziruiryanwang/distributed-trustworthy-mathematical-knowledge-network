## Why this takes priority

An independent operator storing and serving inert mathematics should not need
the investigator's full Lean installation merely to pass an unrelated loader.
Current host.py calls the ordinary profile loader/NativeInstallation even though
the role never grants mathematical acceptance. This is a concrete setup burden
for decentralized participation, unlike an unmeasured few-second optimization.

The earlier ordinary_inert_mirror02 already supplies a reviewed Python-only static
mirror. Its original predecessor failed its first positive service; do not adopt
that failed service or repeat its closed prefix. Reuse the qualified successor's
loader/supervision work. The unresolved composition is current incremental sparse
hosting, latest provider/accounting behavior and a coherent supported role.
Do not invent a second storage or process-supervision framework.

Compare simply using/shipping the existing static mirror with a minimal update
that supports the current growing-custodian workflow. A new pure role must bind
exact reviewed codec/namespace/source support, not construct a fake native
installation or imply checked mathematics. Preserve prefix-support ordering,
exclusive locks, finite budgets, TLS policy and observed process/connection
cleanup. Existing host roots stay with their approved profile; no silent seal
migration. Initial scope is the supported Windows Python profile, not a generic
Linux/macOS port. Old and new peers must retain their exact wire semantics.
