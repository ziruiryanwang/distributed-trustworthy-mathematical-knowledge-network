# Independent challenge: a pure incremental custodian

2026-10-28, query_scaling. Source/file review only; no product imports, database
opens, native work, service, tests or Git. This challenges the selected decision,
not an implemented successor. Detailed dependency census belongs to DECISION.md.

## Recommendation and fair alternative

Proceed in principle with a narrow Windows/Python inert-role successor, reusing
the adopted [mirror02](../ordinary_inert_mirror02/ADOPTION.md) loader/supervisor
and the current incremental storage/transport contract. Removing a real Lean
setup prerequisite is useful for an operator contributing storage and bandwidth.
It does not establish a measured startup/CPU saving or wider platform support.
[BURDEN.md](BURDEN.md) distinguishes selected bytes from full installed size.

Shipping unchanged mirror02 already suffices for an approved static closed
bundle. It passed finite public preparation, discovery/retrieval, exclusion and
stale-snapshot refusal; its original predecessor failed service and stays failed.
Mirror02 prepares fresh stores, checks full syntactic import closure against its
supplied units/pinned basis inventory, and seals a specific immutable snapshot.
It has no incremental append. Today's contribution bundles may intentionally omit
older imports; the current host retains them without asserting checked closure.
Rebuilding complete closed generations would lose the selected incremental benefit.
Thus the existing static option is real but insufficient for this growing-host
workflow. Keep its frozen evidence; do not relabel it as the new role's evidence.

## What must be trusted, and what Lean does not supply here

Current `ordinary_incremental_host/host.py:142-145` calls full `profile.load`;
`run.py:330-350` requires and forwards Lean despite no mathematical host action.
`custodian.py:58-68` and current `peer_api.py:78-85` require an exact native
installation object. Those seams justify an explicit pure-role context, not a
fabricated `NativeInstallation`, skipped verification or weakened general API.

Pin the pure source closure, runtime selection and role policy independently.
That includes evidence/semantic/preview codecs, current baseline-bundle reader,
formal-query and export-adapter semantics, custody/index and provider support.
Do not blindly copy mirror02's entire old map: current baseline_bundle,
ordinary_acquisition and owned HTTP provider differ, even where sparse-index
modules already agree. Each transitive import must resolve inside approved pins.
Retain captured/hash-checked loading and closed package search paths; bundle data
cannot choose executable paths, module sources or a substitute codec manifest.

`ordinary_semantics.foundation_bytes()` fixes seed/inventory hashes, Lean revision
and foundation policy; `semantic_bytes()` fixes the portable interpretation.
These exact descriptors identify the selected language, not a kernel execution.
Incremental inert service needs no mathematical implementation ID, native basis
reconstruction or Lean executable. Any retained inventory-based structural check
still requires its authenticated data. Removing seed/inventory is a separate
dependency decision; saving Lean installation does not require that extra cut.

Retain current `ordinary_export_adapter.namespace_for(S)`: it commits the schemas,
feature revision, type-key profile and normalization, independently of local
implementation, root or provider. An arbitrary namespace string or old codec
with a current namespace would mislabel discovery records. New role/software
identity must coexist with the same exact evidence/preview wire semantics.
Python/OS/stdlib/SQLite/TLS remain trusted dependencies; three Python executable/
DLL pins do not constitute a hermetic runtime or hostile-local-process sandbox.

## Invariants that the dependency cut must preserve

1. **Inertness:** structurally valid false mathematics can be stored and served;
   receiving checkers retain all acceptance duties. No checked-closure claim,
   native identity or warrant follows from a host descriptor or retrieval result.
2. **Incremental prefix:** under the existing lock, commit custody before target
   previews and previews before index references. Retain support-only units;
   targets choose indexing, not disclosure. A failed append may leave a legal
   committed prefix, including newly visible targets. Do not add a whole-batch
   atomicity promise or require all imports in this append to be locally present.
3. **Permanent exclusion:** preserve `custodian.py:118-144`'s permanent lock inode,
   Windows lock semantics and marker validation across init/append/serve. Do not
   delete/recreate the lock to bypass contention or substitute the older static
   mirror's create/delete ACTIVE.lock mechanism for this current contract.
4. **Identity and freshness:** the immutable current HOST descriptor binds policy,
   source/profile identity, semantic ID and computed namespace; it is not a hash
   of all current content. Current snapshots remain separate. A pure role needs
   a fresh root/descriptor/version. No rewriting or adoption of existing host
   seals, READY files or static snapshots under a different approved source map.
5. **Resource authority:** retain explicit allowances, file/record/index limits,
   per-request and provider caps, original finite lease plus cleanup reserve,
   report bounds and whole-Job supervision. Keep accounting and closure reports;
   code simplification does not create a new allowance or renew an expired one.
6. **Transport ownership:** retain explicit whole-custody sharing/exclusivity,
   pinned certificate/key, required TLS outside loopback, endpoint checks and
   provider ownership. Hold the host lock through async drain/cancellation and
   index/custody close. Uncertain cleanup remains failure/uncertainty; a successful
   command cannot leave detached handlers/connections serving the stores.

The current peer service's stop/quiescence/cancel/gather and fallback cleanup are
part of the reusable behavior (`peer_api.py:1150-1265`), not incidental boilerplate.
Mirror02's small loopback result alone does not qualify current transport ownership,
remote TLS, scale or independent deployment. Retain their existing scoped evidence.
