# Execution approval and protected mathematical state

This operator addendum accompanies the selected bounded-transport successor.
It is not part of the earlier frozen source ZIP and does not authorize running
a project, changing permissions or deploying a service. The supported ordinary
profile is Windows x86-64 with independently approved Python 3.14.6, Lean 4.34.0,
package bytes and local state. Project execution supports **trusted projects**,
not arbitrary hostile source or native artifacts.

## Mathematical data is not executable approval

Ordinary peer discovery, preview, inspection and receive exchange bounded inert
mathematical data. A successful search, downloaded bundle, source suggestion or
provider reputation does not approve executable code. A receiver's actual local
checking result is separate from a producer's report or successful compilation.

The authoring-offer route returns unverified repository associations. It does not
retrieve, build or run the suggested project. Choosing to investigate a theorem
does not authorize those later actions. Mathematical truth likewise does not
establish that an associated program is safe.

## What local project approval means

Approve a project only if you trust its source, build/import code, plugins and
transitive compiled artifacts to run or load with the process's **actual account
permissions**. This includes dependencies reached through selected search paths,
not merely the declarations you plan to export.

`produce-baseline` requires `--approve-local-project`; the kit's corresponding
boolean starts false. That command loads an already compiled approved project;
it does not itself run Lake builds or download dependencies. Source authoring
through `contribute` and local project extraction use their own explicit local
selections. The producer flag is not a universal source-execution gate.

A project-selection SHA-256 binds the selected JSON, including paths and module
names. It does **not** pin every transitive artifact, make referenced files
immutable, authenticate a publisher or grant mathematical authority. Keep all
approved implementation, runtime and project material stable through use. A
hash obtained from an untrusted party is not independent approval of its bytes.

## The account boundary matters

Windows Job limits contain selected process/resource consumption. They are not
a filesystem or network access-control sandbox. A separate output folder is not
a separate security principal. Trusted source execution retains whatever file,
credential and network access the account possesses; environment filtering does
not establish a secret-free environment.

Hostile code with the owner's permissions can alter the package, catalog or
checked native snapshots and invalidate the premises of later mathematical
acceptance. Hashes kept in equally writable local state do not repair this.
Native snapshots may be loaded only as protected, locally produced checked
artifacts; the receiver does not support arbitrary peer `.olean` import.

If you cannot grant that trust, do not run/import the project in the commons
owner's account. Use an independently protected execution environment with
actual OS permission separation from the owner's implementation, state and
secrets, then transfer only inert outputs for independent checking. This package
does not provision or certify such isolation. Merely creating another account,
directory or container label does not establish the required separation.

## After suspected compromise

Stop relying on affected local warrants until trusted implementation and state
have been re-established independently. Preserve diagnostic evidence. Do not
restore trust merely by replaying saved success reports, copying hashes from the
affected catalog or rerunning its potentially modified checker. Recovery needs
a separately trusted implementation and clean checked state or independently
trusted recovery material; this addendum supplies no automatic recovery command.

These boundaries do not prove parser/runtime exploit absence or universal
security. They separate the supported inert-data checking workflow from trusted
local code execution, and make explicit the protected-state premise on which
the former depends.
