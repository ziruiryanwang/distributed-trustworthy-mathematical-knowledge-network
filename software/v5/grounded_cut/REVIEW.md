## Concrete reopen obstruction and selected repair

`PortableCatalog._active()` itself performs bounded work: sticky WITHDRAWN check,
one exact `meta(id=1)` identity comparison and fixed activation parsing. However,
`PortableCatalog._open()` always executes:

```sql
UPDATE operations SET state='INTERRUPTED' WHERE state='RESERVED'
```

The old operations table has only its identifier primary key, not a state index.
Opening the native catalog for every cut can therefore scan all operations even
without calling `context()`. Reusing that open path would violate the intended
history-independent close/reopen path. A long-lived handle alone does not fix
later process reopening. This is a source finding, not a timed experiment.

Root has selected the narrow conservative repair: capture a source anchor during
the one locked native derivation; on later use hold the same native owner lock and
check exact ADOPTION/meta activation/implementation/support plus sticky WITHDRAWN
through a read-only connection and primary-key lookup. Do not call catalog.open,
context, native recovery or a root/operation/schema census. Review the actual new
source before accepting this repair.

The new cut epoch deliberately remains dependent on this source support marker.
Source operational quarantine can thus over-invalidate old cut warrants; this is
conservative and is not a claim that theorems became false. Source unavailability
also refuses eligibility. Removing/replacing/renaming a marker cannot rehabilitate
withdrawn state under the protected-store/no-rollback premise. An independently
transferred support authority is possible in principle but is NOT selected.
Loss of a separately retained export proof is only custody loss, not the same
condition as source support withdrawal.

The binary Patricia representation has strict deeper child paths, canonical
masked branch prefixes and exact full keys in leaves. Insertions split at the
first differing routing bit or copy only the selected path. Same key/value is
idempotent, a changed value refuses, and a routing hash collision with a different

inserted. At most 256 branches and a leaf can be visited; no unrelated subtree or
ancestor event is enumerated.

bounds payload return using SQL length/type before Python materialization.

checked. Writes and payload bytes are charged before insertion; accounting can
conservatively overcharge a refused write but does not undercount an issued one.
All public entry points require a caller transaction. No open/commit/rollback or
automatic recovery is hidden in the map.

root eligibility, time/CPU/page-I/O limits, transaction rollback and exact summary
