# Defer shipping whole-type patterns; use the demonstrated discovery workflow

2026-10-28. growth_design_audit. Source and saved-artifact inspection only. No
product imports, owner/database access, Lean run, network, experiment or Git
operation. This note changes the recommendation, not the selected product.
Root owns selection and adoption. Existing candidate sources and controls remain
preserved.

## Decision

**NO-GO for shipping the optional whole-type-pattern profile now.** The relation
is precise and the port can be correct, but the examined actual growth workflows
do not give a natural, decision-changing positive use for this narrow relation.
The strongest relevant example instead exposes its limitation: extending a
theory changes its hypotheses, parameters and representation, not only the names
of global constants. A second full discovery namespace and its public/package/
host configuration should not be shipped merely because their implementation is
available.

Freeze the pattern helper, controls and in-progress integration drafts as
candidates. Do not discard completed work or run an invented renamed-theorem
demonstration. The earlier LAW-SHAPE-DECISION established a defensible optional
capability class; it did not establish that paying the full integration cost is
currently the highest-value way to help investigators. This workflow inspection
supplies the missing deployment decision and revises that recommendation.

**The single highest-payoff alternative using the existing APIs is scoped
discovery by a shared carrier/interface symbol, followed by bounded inspection of
the returned theorem types.** It has already exposed unfamiliar reusable laws in
the actual finite-map investigation. Use and present that complete supported path
as the default before adding another retrieval relation. No rerun is warranted
by this note. A genuinely disjoint-vocabulary discovery gap remains open; this
alternative must not be presented as a solution to all analogical search.

## The obstruction in the proposed relation

Write P(T) for the whole-type key. Ignoring digest collisions, P(T)=P(U) requires
equality of the complete retained expression trees under a bijective renaming of
nonbasis global identities. In particular it preserves:

- the number and order of outer binders and their binder flags;
- every application, constant, projection and bound-variable position;
- selected basis constants, universes, literals and repeated-symbol relations.

Erasing a global name cannot delete a hypothesis, replace a typeclass telescope
by an explicit operation contract, or unfold a relation definition. This gives
immediate negative decisions without running either the helper or a new prover.

The natural actual comparison is the old contextual-refinement criterion and
the new destructive-observation criterion. In the selected `BodyParametric.lean`
the former has implicit `K,V`, four instance parameters, `p,q`, an empty-map
witness and its equation. Its conclusion is:

```lean
ContextuallyRefines p q ↔ (mustWrite p = true → mustWrite q = true)
```

The new actual preview has twelve outer binders: two type parameters, `observe`,
`step`, `effect`, an atomic observation law, two states, two observation
equations and `p,q`. Its conclusion is:

```lean
ContextuallyRefines observe step p q ↔
  Mode.Refines (summary effect p) (summary effect q)
```

These types cannot be whole-type variants. Besides the different telescopes,
the first right-hand side is an implication between equalities; the second is
an application of a named relation. The old equivalence criterion instead ends
in equality of summaries and likewise does not repair this mismatch. Comparing
earlier failed source bodies to their corrected copies would only test an
implementation revision, not unfamiliar mathematical reuse.

The saved real `FiniteMapEffects.nonempty_iff` preview has eight outer binders;
`zero_effect_witness` has seven. Neither is a whole-type variant of the twelve-
binder reset criterion. Their role in the actual reasoning is semantic and
compositional. It is not equality of entire theorem statements.

The inspected native-query fixture is also not a natural positive pair. It asks
for `∀ a, f a = g a` over independently chosen dependent functions, expressly
without asserting truth. Its old compilation/extraction run failed an overall
check and has a separate preserved-output postcheck. It must not be repurposed
as an independently successful law-discovery episode. No suitable actual saved
positive query/preview pair was identified in this bounded review. This is a
statement about the examined evidence, not a census of all mathematics.

## One smallest real public workflow: retain the existing six-result example

The decision-changing workflow already exists; use its saved outputs rather
than spend time reconstructing it under a new feature profile.

1. A local investigator knows the carrier/interface `Std.HashMap`, but no
   finite-map theorem name or export identifier. Resolve its exact portable
   symbol by the current known-symbol path. Retain that query rather than
   reopening its context for every subsequent search.
2. On an explicitly selected finite provider corpus, submit the conjunction of
   `object-kind = ordinary-lean-export-v2`, `declaration-kind = theorem` and the
   `Std.HashMap` type symbol. This asks for unfamiliar laws over known material,
   not for an exact desired theorem statement.
3. Use the existing aggregate request, byte, page and candidate budgets. Inspect
   the returned bound type previews. In the saved run this selected the exact
   characterization and the actual execution witness above from six candidates.
4. Acquire only selected mathematics through the unchanged checked receive
   route. Develop a local consequence with ordinary authoring and publish the
   checked result. No search ranking or printed name grants mathematical trust.

The saved find used one provider and one snapshot; seven requests returned six
records. Find plus six previews used thirteen actual requests and 56,458
response-body bytes. Conservative reservations remain distinct from those
actual bytes. The result was `INCOMPLETE_SEARCH`, with no verified scan coverage,
global completeness or authenticated feature-extraction claim. This is a real
public-API example with a meaningful downstream use, not a new execution or an
estimate of network-wide search cost.

For a huge network the conditional locality is explicit. Given a chosen set of
provider corpora and a sufficiently selective shared symbol, unrelated remote
proof ancestry is not read for discovery. A hot anchor can still produce too
many candidates. Provider selection and budgets limit cost, not lost relevance.
The example establishes neither how often such selective anchors exist nor how
to route all investigators to the right specialist. Those remain substantive
growth/search questions.

## Alternatives and why none warrants immediate replacement code

| Alternative | Real advantage | Present limit and decision |
| --- | --- | --- |
| Existing scoped shared-symbol query plus previews | Works over inert published mathematics; already has a complete local public workflow; users need no unfamiliar theorem ID | Best present default. Depends on useful common symbols and selected providers; preserve incomplete outcomes |
| Whole-type variant equality | Can find independently named vocabulary when the entire retained type really is a variant; bounded DAG extraction | No natural positive pair in the relevant actual flows. Defer shipping and reindexing |
| Strip telescopes and hash only conclusions | Avoids one source of whole-type mismatch | Still misses the implication-versus-named-relation example and differing explicit argument structure. Naively dropping binders produces open fragments; the retained binding context and variable policy need definition. Do not assume a cheaper port solves the observed gap |
| Index assumptions, subterms or conclusion patterns with holes | Can expose related laws whose applicability conditions differ; permits partial queries | Requires a stated fragment relation, binder discipline, bounded extraction/postings and real selectivity. The older instantiation-discovery relation keeps rigid symbol identities, so it is not automatically cross-vocabulary analogy |
| Maintained Loogle-style project search | Richer partial-pattern search and existing implementation; useful in an investigator's approved compatible local project | Does not automatically cover arbitrary inert remote previews or resolve version/frontend reconstruction. External hits are hints followed by exact acquisition and checking, not network acceptance |
| Read a finite ordinary source/module corpus | Already generated the observed generalization and preserves explanatory context | Investigator cost grows with corpus; no universal scalability follows. Remains a legitimate local strategy rather than a mandatory network representation |

The highest-payoff next *design trigger* is an actual investigator who cannot
expose a plausible reusable law within the supported scoped-query/preview or
available ordinary-project routes. Preserve that investigator's independently
written query, candidate corpus and intended applicability question before
choosing a new matcher. A theoretical structural counterexample can rule a
candidate out immediately; no costly discovery experiment is required for that
negative result. This is not a request to manufacture another investigator or
restart a completed concept episode.

A later positive reason to reopen this exact feature would be a naturally
encountered full-type variant whose unknown nonbasis vocabulary excludes it from
a useful exact-symbol query, with a defensible candidate-bucket reduction. A
copied target statement with deliberately changed names is a capability control
only. Any claimed net benefit must cover query/extraction, fresh namespace
indexing and retention, provider work, failed search and human/agent inspection.
No such full-cost estimate follows from the present twelve pure controls.
