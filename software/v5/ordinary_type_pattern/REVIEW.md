## Relation and input boundary

The public APIs retain raw-input boundaries:
`native_pattern(native_type_raw, inventory_or_prepared, limits)` and
`preview_pattern(preview_raw, inventory_or_prepared, limits)`. The existing
native/preview readers reparse the raw bytes and establish closed, backward-edge,
fully reachable expression and level DAGs plus the exact reference census.
Caller limits can narrow the selected bounds; the pattern helper does not turn
a parsed report object into a validation token.

The inventory's size and exact fixed SHA are checked before its general JSON
parse. Prepared anchors are immutable lookup tables for a trusted same-process
caller. They are not serialized or authenticated peer credentials. Python code
already trusted in that interpreter can subvert those premises; this helper is
not a sandbox or a mathematical acceptance gate.

Each fixed-basis preview identity must appear under its exact inventory name.
A known basis ID under another name refuses. A known basis spelling carrying a
different portable ID remains nonbasis. Native queries anchor exact basis names
as an explicit frontend convention and assign distinct local identities to
other exact names. They do not invent portable IDs. Native/preview correspondence
therefore requires the stated coherent, injective correspondence of occurring
nonbasis names to portable symbols and the selected meaning for basis names.

Constants and projections use one identity map. Ordered root-first traversal
assigns slots at first occurrence; a shared subtree cannot introduce a new symbol
after its first full traversal. Skipping its later occurrence therefore preserves
the slot order of the conceptual unfolded tree. Memoized bottom-up hashes then
ignore storage numbering and repeated sharing while retaining constructor order,
repeated identities, binder annotations, de Bruijn indices, let flags, projection
fields, universe arity/positions/instances/operators and literal values. Only
the selected binder/universe labels and bijectively renamed nonbasis identities
are erased. Exact basis identities remain fixed.

Modulo hash collisions, equal keys implement this complete syntactic variant
relation. They do not establish reduction, unification, instantiation, theorem
transport, semantic equivalence, novelty or a warranted imported meaning. The
new profile is distinct from the existing exact-type profile. No old key or
index namespace is relabeled, and no acceptance rule consumes these keys.

## DAG work boundary

Validated backward edges permit one bottom-up hash per serialized expression
or level. The explicit preorder stack may pop an already visited shared node,
but each visited parent contributes only its fixed outgoing edges once. Thus
preorder work is O(V+E), not unfolded-tree size. Name, literal, JSON parsing,
input hashing and inventory costs remain paid; expected whole-input work is
O(B+V+E), subject to the stated dictionary/hash assumptions. The reported integer
`work` covers structural counts, not physical CPU or all byte processing.

The new controls observe traversal without expanding a tree. For doubling DAGs
of depth 32 and 256, each public API receives the actual raw input with prepared
anchors. A line tracer scoped to the selected `_derive` code records real stack
pops and first visits; a delegating wrapper records actual `_digest` calls while
executing the original hash function. Unique trace sites are selected from the
pinned source bytes. Expected counts are V=d+1 first visits, 2d+1 pops, V node
hashes and one final key hash. Exceeding those bounds fails immediately. The
larger fixture has 257 expression nodes but represents a tree with `2^257-1`
nodes. No such tree is allocated or serialized.

The control compares these observations with the reported counters and stores
both. This is a finite structural-access assertion, not a speed benchmark or
full-scale memory claim. Parser limits and existing validation remain active.
