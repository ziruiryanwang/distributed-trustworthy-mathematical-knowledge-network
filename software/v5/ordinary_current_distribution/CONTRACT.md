## Bounds and retention

One original caller allowance covers the whole operation. The preserved three
supervised Jobs are receiver/authoring, extractors and query; each receives only
remaining allowance after cleanup/controller reserve. An unknown child CPU
sample charges its full grant and stops the operation. Controller CPU and
inclusive Job CPU are added once, not double counted with native children.

No retry, overwrite, cleanup, download or state migration occurs. Failed output
and diagnostics are retained. An outer Job is still recommended for hard bounds
on the controller. Resource bounds are not hostile-code isolation; complete
approved Windows x86-64 Python 3.14.6 / Lean 4.34.0 runtimes and immutable
owner-controlled storage remain premises. Named runtime pins are not a hermetic
or bit-reproducible toolchain claim.
