# Reuse strict parses only inside one private operation

2026-10-26. Source-only successor. No test, installation, native operation,
package or implementation identity has been generated by this work. Existing
production and experiments remain unchanged. The concrete purpose is to remove
redundant controller work before the representative rich-library intake, not to
replace Lean checking or claim faster theorem discovery.

## Private planner and public boundary

The existing planner's body becomes:

```text
_plan_with_parsed(context, raw_units, limits, check)
    -> (Preflight, dict[exact immutable raw bytes, PE.Evidence])
```

It independently calls unchanged `PE.read_evidence` on the supplied raw units,
checks unchanged semantics, census, names, imports, reuse and topological order,
and constructs the same raw-only `Preflight`. Duplicate handling is unchanged.
The map is made from precisely those locally parsed values and keyed by their
own immutable raw byte strings; no caller supplies a parsed value or cache key.

Existing `_plan` returns only the first component. Public `preflight` remains
unchanged and exposes no parsed object, status authority or resumable grant.
Every actual `admit` independently obtains the real current parent context and
reruns the private planner on the caller's `plan.raw_units`, under fresh default
preflight limits and the actual admission budget. Forged public status/order,
missing lists and reuse IDs still cannot skip this work. A changed raw byte string
or changed parent is checked in the actual invocation, not matched to a cached
earlier success.

The private helper is installed implementation code, not a new public input
interface. Python-level hostile introspection, monkeypatching or calls into
arbitrary private methods are outside the existing no-hostile-in-process-caller
model; underscore naming alone is not a security mechanism.

## Admission ownership and native projection

After its own fresh planning, `admit` looks up the ordered units by exact raw
bytes and creates only:

- Names: the bounded output-name subtrees needed for existing report comparison.
- Unit IDs: an immutable tuple in the planned native order.
- Native unit JSON: immutable canonical bytes of those same parsed unit trees.
- The exact immutable ordered raw tuple to which those projections belong.

It then deletes both the private parsed map and its `ordered_items` alias
**before `_stage`, custody methods, catalog reservation or native supervision**.
Comprehension-local `item` and `row` variables do not escape their scopes. Output
names do not contain parent references to declarations or body DAGs. No Evidence
or proof-tree object is passed to `_execute`, a budget callback or native code.

The private `_execute` keyword is `_prepared_extension=None` for basis calls.
An extension receives the internal tuple:

```text
(exact_ordered_raw_tuple, unit_id_tuple, native_units_json_bytes)
```

Before using it, `_execute` checks tuple/bytes types, exact raw/order equality,
the unchanged 64 MiB native-input byte limit, and equality of the ID tuple to
fresh domain-separated hashes of those exact raw bytes. The subsequent grant
kind/parent/input-ID/request-hash/parent-plan/module checks remain unchanged.
Native unit JSON is exactly the serialization produced above; it is not a
publicly supplied alternative to a proof parse. The closed internal ownership
chain, not raw equality alone, establishes correspondence between that JSON and
the strictly parsed raw units.

The native event still decodes and checks the actual staged JSON and must produce
the exact names/count/artifact report under a clean live event before protected
promotion. No hash, preflight result or serialized projection grants acceptance.

`_stage` is unchanged: it still independently parses, performs the real inert
custody put and compares actual readback. Catalog reservation still independently
parses the selected extension raw bytes and creates a genuine protected grant.
All existing cleanup, abandonment and uncertain-native-event quarantine logic
after grant acquisition remains unchanged.

Serialization now precedes custody staging/reservation so that proof trees can
be released first. Exceptional allocation/encoding failure may therefore occur
earlier, before inert writes or a grant. This is not literally identical failure
timing or side effects. Such failure cannot falsely promote a root or erase old
state; normal valid projections retain the same native input bytes. Existing
budget checks remain, with no renewed allowance or new launch on failure.

## Whole-baseline metadata planning

For each baseline batch, `_plan_all` uses the same private planner's map for its
output-binding and custody-quota projections. It still performs the unchanged
`_read_batch` validation before planning. Actual later preflight/admission rereads
and independently checks the inert files, current parent and requested work.
Metadata planning never becomes a warrant.

The one internal method that receives a parsed value is existing
`_custody_increment -> OrdinaryStore._export_locators`. This is the concrete
trusted local implementation, not a peer callback. Its selected source only
iterates output rows, derives locators, canonically encodes them and returns
identity/bytes pairs. `read_locator` detaches the name through canonical
encoding/strict decoding; neither method stores or mutates the Evidence or its
document. The budget callback receives no arguments. `_custody_increment`'s
existing database/readback checks and all later real store methods are unchanged.

At each batch end, explicitly drop `parsed`, `plan`, `raws`, `raw` and temporary
bindings. Clear then delete `row` even if the ordered-new sequence was empty:
a Python loop variable can otherwise retain its last full declaration and proof
DAG after the map is gone. Retained cross-batch state contains only bounded
binding/metadata projections, not the collection of proof trees.

## Cost and memory argument

For a fresh successful batch of distinct new units, the source call counts are:

| Portable strict-parse boundary | Before | After |
|---|---:|---:|
| Whole-manifest metadata batch: file validation, planning, binding, custody projection | 4 | 2 |
| Actual file reread/validation | 1 | 1 |
| Public preflight plus actual admission, custody and catalog | 8 | 5 |
| Total per unit | 13 | 8 |

Five traversals are removed, not weakened or replaced by a general faster parser.
For the selected 44,912,843-byte closure this eliminates 224,564,215 bytes of
input to repeated portable lexical parsing, from 583,866,959 to 359,302,744.
This is a structural operation-count reduction, not a 38.5% wall/CPU speedup
claim. Hashing, serialization, filesystem, database and native costs remain.
Counts differ on duplicates, reuse, error and early-exit paths; focused tests
must identify their exact counted boundary rather than imply a universal ratio.

Both old and new planners already hold a bounded batch of parsed units:
at most 1024 units, 64 MiB raw evidence, 2097152 expression nodes, 65536 output
names and 1048576 import edges under unchanged limits. The added map owns
references, not copied raw bytes or an unbounded cache. During serialization,
native JSON temporarily overlaps that one parsed batch; Python encoding may
also allocate a transient string. This is not a claimed hard RAM bound derived
solely from raw-byte size: Python container overhead still matters.

Proof trees are dropped before staging or the native process. During native
execution only raw bytes, at most 64 MiB native-input bytes, IDs and bounded
names survive, replacing the old `_execute` list of parsed unit trees. Baseline
planning drops each batch before reading the next. No accumulated library-sized
cache or native/parsed-tree overlap is introduced. Existing outer memory caps
and finite outcomes remain necessary; this source argument does not predict
completion for every admissible maximum-sized batch.

An exception traceback may retain one bounded call's local objects until the
exception is released, as in the old parser/planner. That is not a persisted or
global cache and is not acceptance authority. We do not claim zero retention
under arbitrary callers storing exceptions indefinitely.

## Focused evidence and next gate

The independent tests should compare predecessor/successor plans and exact native
projections using genuine inert units, count changed-path parse calls, exercise
duplicates/reuse/topological/conflict/changed-input/changed-parent cases, and
show no public parsed leakage or private Evidence live at staging/native/next-
batch boundaries. Native/store/catalog doubles must be identified as such;
their outcomes establish controller behavior, not mathematical acceptance.

Source review and focused tests precede root's separate file-only installation
selection and any real native intake. The unchanged general parser/store/native
campaigns need not be repeated merely to test these two internal reuse seams.
No run, package or new trust profile follows automatically from this design.
