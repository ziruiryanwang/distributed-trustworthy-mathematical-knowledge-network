## User workflow and reason for selection

A storage-only operator receives one disclosure-approved finite baseline bundle,
prepares exact inert custody and selected formal search records, and serves them
through the existing protocol for finite leases. An investigator can discover an
unknown ExportID and selectively acquire its evidence without the original
publisher being online. Only mathematical consumers acquire mathematical warrants.

Static bundle retention remains preferred for backup or known-bundle transfer.
The added value here is the supported unknown-ID discovery/selective-retrieval
route without owner initialization, Lean installation or native checking. The
lower APIs already provide this power; the new work is safe public composition.
There is no claimed receiver-check saving, novel trust protocol or growth speedup.

## Minimal implementation boundary

Add a separate companion using unchanged selected codecs, OrdinaryStore,
DiscoveryStore/OrdinaryExportAdapter and bounded HTTP Provider. Do not patch
Provider's exact-type dispatch or any checking/admission/import rule. Use the
existing Windows Job supervisor, not a new process-control framework.

Load only a fixed, reviewed pure-source closure from the current investigator
source extraction, with explicit relative paths, hashes and bounded sizes. A
small local source manifest is executable-software selection, not peer data or
mathematical evidence. It must not permit arbitrary module/path additions or
be taken from a received bundle. Reuse existing approved launcher helpers and
supervisor sources without profile.load, owner catalogs, native artifacts or
Lean binaries. Pin the supported Python runtime independently. Source substitution
and hostile local mutation remain outside protected-software/state premises.

Two fixed public actions are sufficient:

- `prepare`: bounded baseline bundle + exact manifest hash + selected targets +
  explicit whole-bundle disclosure -> fresh inert stores and a local prepared
  descriptor. No network and no mathematical owner.
- `serve`: exact prepared descriptor + operator-selected existing endpoint/TLS
  and finite allowance -> existing read-only Provider, then verified cleanup.
  No mutation queue, remote writes, automatic discovery/replication or daemon.

Both actions run through the fixed supervised entrypoint. A private worker or
helper return alone is not successful supervised completion. Fresh diagnostics
and output paths must be disjoint from approved software/runtime/input paths.
Use explicit checks before reading/writing; never copy a live database.
The preparation worker's descriptor is data-only. Only the parent may write a
fresh local READY seal after exact worker-report/descriptor binding and clean
zero-exit whole-Job closure, with request/source identities. Serving requires
the explicitly pinned parent seal and matching descriptor, not descriptor
existence or a caller-provided boolean. Failed worker/precommit preparation cannot
promote partial output. Flush and read back a pending seal before nonoverwriting
rename to READY.json: that rename is the readiness commit point. A lost response
or interruption after it may leave a committed seal; inspect it rather than
claim rollback. This is protected local state, not a transferable attestation.

## Data relation and exact preparation

1. Use the existing baseline manifest/entry and portable evidence parsers. Check
   hashes, sizes, selected semantics, unique unit/output identities and aggregate
   censuses across batches, not only each batch. Preserve exact raw units.
2. Validate the full bundle's syntactic imports against exact supplied output
   bindings or the pinned basis inventory; reject missing, conflicting, cyclic
   or wrong-identity imports and basis-name collisions. Check target name,
   UnitID and ExportID correspond to actual supplied outputs.
3. A supplied group is indivisible bytes. Structural closure does NOT establish
   complete Lean-generated recursor inventory or correct inductive semantics;
   those remain receiver-checker obligations. Never claim checked group closure.
4. Derive only selected target previews from actual evidence, insert exact
   evidence/locators and previews into fresh existing stores, then index those
   previews. All bundle evidence, imports and supplied siblings are exposed;
   selected indexing is not a per-object disclosure ACL.
5. Close prepared stores before durable success. An interruption/late report
   failure can leave retained partial output; do not overwrite, auto-resume,
   label it ready or imply rollback. Successful preparation means structural
   readiness only, always `mathematical_acceptance:false`.

False-but-well-formed mathematics may be prepared and served. Consumers use
unchanged independent exact dependency and kernel checking. Availability,
structural validity, search coverage and mathematical truth remain separate.

## Lifecycle, resources and scope

Use ceilings no larger than selected-export: 1024 units, 64 MiB evidence,
2097152 expression nodes, 65536 output names, 262144 import edges, 64 indexed
targets. Bound previews, aggregate metadata, SQLite logical/physical capacity,
index operations, output bytes, CPU, wall time, memory and log output. Existing
individual-operation limits cannot renew the overall preparation allowance.

Prepared state is locally protected, exclusively owned, immutable-by-policy
during service. Require explicit whole-custody disclosure/exclusivity and prevent
two companion operations from sharing its stores concurrently. Open existing
stores through their ordinary APIs, with exact semantics/config/snapshot binding;
no owner acceptance flag is manufactured. Preserve lock/recovery uncertainty.

Retain Provider endpoint policy: non-loopback requires pinned configured TLS;
loopback testing does not authorize public exposure. Keep finite connection,
attempt and reply-byte budgets, one original lease deadline and cleanup reserve.
Always close provider/connections and stores, including failed readiness. Report
partial failure/uncertain cleanup honestly. New metadata is a new preparation,
not concurrent mutation or unbounded snapshot retention.
