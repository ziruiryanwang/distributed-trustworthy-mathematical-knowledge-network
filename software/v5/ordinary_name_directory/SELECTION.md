# Reusable historical name directories

2026-10-28. Root selects source implementation after the point-query source audit
and independent design discussion. No experiment or native work is yet selected.

The workflow is an investigator searching many new names from a large, stable,
already retained library. Current fresh-name projection reconstructs the complete
selected metadata each time. Existing saved specs solve repeat names, but do not
provide unqueried names. Export once, resolve many is the selected improvement.

The directory is a historical advisory projection, not a fresh owner check. It
cannot confer mathematical acceptance, current support validity, current absence,
or worldwide coverage. Receiving and contributing retain the unchanged checking
rules. New mathematical roots do not update a directory implicitly.

Use the existing full metadata-validating advisory reader once, under the ordinary
owner lifecycle and bounded launcher, then export all exact bindings after close.
Store fixed 64-byte rows consisting of a domain-separated hash of the canonical
structured name followed by its exact SymbolID. Sort strictly by name hash and
reject duplicates. Reuse the existing authenticated_index ordinal-vector hashes
and verifier; only the packed fixed-offset storage is new. Pin a final manifest
that binds count, semantic/foundation/implementation/store/root/profile identities
and vector root. Write this manifest last. Incomplete output is never a directory.

An offline lookup performs bounded binary-search probes, then authenticates its
hit or its consecutive bracketing records against that pinned vector. Untrusted
intermediate probes cannot establish absence. Correct absence additionally relies
on the approved export having established complete strict ordering. This removes
a whole-file integrity scan from each lookup while preserving the selected old
projection under collision resistance. It does not authenticate foreign claims
that a directory came from an owner. One to eight names form one conjunction;
any missing name suppresses all specs. No partial weaker query is emitted.

For N names and Q fresh-name queries from a fixed directory, exported once,
construction costs the existing context validation plus O(N log N) comparisons
and O(N) fixed-size hashing/storage. Each requested name uses O(log N) bounded
random reads and hash operations, plus its name bytes and fixed software setup.
No owner open, snapshot read, proof work or unrelated-directory scan is needed.
The investment pays when avoided repeated context work exceeds construction,
storage and lookup costs. Do not rebuild after every unrelated extension: that
reintroduces the lifetime cost. This is not a worldwide semantic-search bound.

Used sources and the current kit remain frozen. No core implementation, native
binary, owner schema, old report identity or old accepted root changes.
