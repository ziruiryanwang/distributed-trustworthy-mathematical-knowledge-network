# Next value: make an acquired preview readable before acquiring a theory

2026-10-28. Independent source-only architectural recommendation. No runtime,
product edits, owner/database access, network, or Git. This note selects nothing
on root's behalf. The two current operational fixes remain separate.

**Recommend one bounded, offline `view-preview` command in the operator companion.**
It should turn an explicitly selected existing preview report into a readable
mathematical declaration and a named exact-symbol table. Begin with previews,
not an interactive browser, body explorer, matcher, or new project adapter.
This is the smallest justified investigator-facing continuation I found; it is
not evidence that presentation is the dominant research cost.

## Observed obstruction and existing alternative

The selected `ordinary_multi_source/peer_api.py::preview` returns the validated
`preview.document` unchanged. Its header is an encoded expression DAG, and names
are structured arrays containing bytes. `inspect` similarly returns inert evidence.
The current operator's inspect preparation chooses a `type_bindings` row by
numeric `binding_index`. Thus an investigator who asks a familiar-name query can
now obtain a result but must manually decode its formal type and symbol names
before deciding which concept to inspect or whether receipt is worthwhile.
This is an actual public-interface limitation, not an inferred explanation of
the diagnostic's decision to use source.

There is already a retained, nontrivial input: dedicated-host preview01 returned
the 4,798-byte preview of `ResetEffects.contextual_iff`, SHA-256
`f3fd920019c877c33483c8b82bfa1692e300aad7307008cb70edd97d7c32a435`.
Its two observation witnesses and atomic-law premise matter mathematically.
They should be visible without reading DAG tags or relying on an agent's informal
summary. Its successful transport is already settled; fetching it again adds no
decision-changing evidence.

The exact saved input is
`experiments/v5-local-checks/dedicated-host-preview01/RESULT.json`. Reading it
confirms the problem directly: its export name begins with the decimal UTF-8
array `[82,101,115,101,116,69,102,102,101,99,116,115]`, and its type consists of
numeric DAG tags/indices including hygienic binder-name component arrays.

The strongest simple alternative is to read the ordinary Lean source in an
approved Git/Lake project, with ordinary editor search and `#check`/`#print` as
appropriate. That route actually sufficed in the creative diagnostic. Keep it
the default when suitable source is readily available. The proposed view helps
the distinct case where the user has an inert advertised result and wants to
decide whether to obtain its source or independently receive it. A hand-written
summary or source hint is useful supplementary information but need not preserve
the advertised type's exact hypotheses or symbol identities.

## Reuse check: no current drop-in formal view

I searched the exact dedicated-host source-map inputs for rendering/pretty and
restore primitives, then read the relevant helpers. `portable_preview.read_preview`
and `ordinary_evidence.name_key` already validate this inert syntax and binding
census; reuse them rather than write a competing admission/parser layer.
`OriginalExpr.lean::decode` already reconstructs a native `Lean.Expr` with exact
scope and universe structure, but does not provide a public stateless display
command. `LocalSnapshot.restoreLocal` imports previously checked protected local
artifacts and checks their correspondence; it is an owner/native environment
path, not a way to inspect an unaccepted preview without those artifacts.
Ordinary module export and approved-source `#print` are likewise existing useful
routes for already available native mathematics, not this inert-read boundary.

There is a Rust pretty-printer under `modules/native/checker/src`, but it uses
that checker's `Declar`, `TcCtx`, `ExprPtr` and export-file representation and is
absent from the current ordinary source map. Adapting/building that lane would
add more machinery than a bounded view over the already validated current DAG.
The original expression format explicitly erases metadata and does not preserve
all frontend presentation hints: ordinary source notation cannot be promised.

## Smallest decision-changing work

First write the rendering contract and a source-derived specimen for that saved
preview, checking its premises against `Proposed03.lean:245`. Do not launch a
new investigator or repeat the proof. If the resulting view is not materially
easier to inspect than the JSON, stop before packaging it.

Then implement only the offline presentation boundary, after root selection:

1. Accept one explicitly selected report and its byte hash; parse bounded inert
   input using the existing preview grammar. Do not follow report paths, open an
   owner, call a service, run Lean, import a project, or alter an original report.
2. Display the declaration kind/name, universe parameters, all binders and full
   claimed type using explicit unambiguous syntax. Preserve binder information,
   universe applications, literals, projections and exact constant references.
   Do not unfold, simplify, synthesize notation, omit hypotheses, or imply that
   the output is a compilable Lean module. Escape nonordinary names and strings
   visibly rather than silently dropping bytes.
3. Display the existing binding indices alongside readable names and their exact
   ExportIDs, plus the selected semantic/unit/export identities and input digest.
   The same index can be copied to today's inspect request. No new selection
   schema or name-to-identity equivalence rule is needed.
4. Keep output finite without recursively expanding a shared DAG exponentially.
   Use bounded explicit node references when necessary; visibly identify any
   omitted display region. Preserve raw input as the exact source of truth.
   Say plainly that this is a displayed claim and does not establish mathematical
   acceptance; parsing a saved success field cannot establish fresh network
   binding or snapshot membership either.

The critical theoretical property is referential fidelity: every displayed
constant resolves to its original exact binding, and every displayed binder use
retains its original scope. A sharing-preserving fallback must take work bounded
by the parsed input plus the explicitly bounded output, not by the tree expansion.
This is an advisory display correctness requirement, not a new trusted relation
or a demand to certify a pretty-printer. Unsupported display cases must remain
explicit raw-node references with a clear limitation, never guessed mathematics.
Resolve those two properties in the design before tests. Focused pure controls
should then target capture, same-looking distinct names/identities, sharing and
output bounds. Reuse the saved preview for the actual integration; no new native
check, grounding, peer, theorem or synthetic research episode is warranted.

Stop when an investigator can read the retained theorem's complete premises and
select its unfamiliar symbols by name from one displayed result. Extend to
definition bodies or a broader frontend only after a concrete consumer need.

## Expected payoff and what remains unproved

This reduces an unavoidable representation-conversion step for every user who
does choose inert discovery. It has small maintenance scope, no extra custody,
publication, network or proof-checking cost, and no acceptance migration. Its
economic premise is conditional: saved interpretation effort across actual uses
must exceed implementation, maintenance and display costs. No current trace
measures that saving. It is an operability investment with a plausible low-cost
payoff, not measured causal acceleration or a completed deployable release.

Existing ordinary-module export/return, project authoring and missing-proof
extraction already provide interoperability routes. With no independent user
project in hand, another generic Lake adapter would target an unobserved gap.
Keep source sharing and the current adapters available; repair a specific real
project incompatibility when one is identified. Likewise, known-symbol search
and dedicated hosting now work locally, but neither their successful controls nor
this readable view supplies selective coverage, relevant ranking, independent
availability, or an unfamiliar investigator's reason to query the system.

The concept-capability theorem still requires affordable exposure to relevant
checked mathematics before wasted effort. A readable preview lowers one possible
interpretation cost; it cannot establish the prevalence of useful bridges or
the whole-cost inequality. The diagnostic supplied no evidence to fund a new
search mechanism. Its ordinary-source success should therefore constrain further
infrastructure investment rather than trigger another forced-index study.
