## Current adapter, kit and request semantics

The selected adapter is
`ordinary_formal_query/discovery/ordinary_export_adapter.py`, SHA-256
`3ddbed2156a393b08543a5da88c89b5c5b9c2b4f65689c46fbd7623cec38db0a`,
as selected by the current source map and compatibility map. It is not the
older generic adapter or optional correlation-search implementation.

- `compile_query` accepts 1..8 specifications and returns the set of compiled
  feature atoms. Candidate matching conjoins those atoms. Consequently replacing
  the entire exact-key specs array is essential; retaining its declared-type key
  cannot broaden an exact-type search. The guide makes this explicit.
- `describe` extracts type-symbol atoms from the complete explicit type-binding
  census, including hypotheses and projection structure symbols, not proof-only
  or unfolded relationships. One/two symbols and optional theorem kind use the
  supported shape and do not require an unknown candidate's name or ID.
- The current inert kit's `query_specs` accepts type-symbol, object-kind,
  declaration-kind and declared-type-key only. The displayed portable-symbol
  shape and `declaration-kind:theorem` are correct. Direct result-head and
  binder-domain-head API support is correctly distinguished from the kit subset.
- `feature_id` hashes both namespace and feature specification. The old query's
  terminal `features` describes its exact-key query, not the proposed symbols.
  The guide correctly prohibits treating portable symbol IDs as pair-index
  atoms or using the old exact-key feature list. Current `find` recompiles the
  selected specs and returns its actual namespace/features.
- Current peer `find` accepts the existing explicit contacts/providers,
  limits/offer/page and optional mode. `directory-find` compiles nonempty routes,
  requires each route to be a subset of the new query, and combines directory
  and search request/byte allowances in one ledger. The guide correctly replaces
  old routes, retains egress/contact approval and does not promise coverage.
- `atomic-v1` is the default; optional sparse access selects an already configured
  pair when available, otherwise atomic traversal in the same V2 grant. It does
  not introduce an OR query, applicability matcher or automatic protocol retry.

## Limits and disposition

The guide preserves the important distinction between finding a shared symbol,
binding an inert preview, independently acquiring/checking evidence and actually
applying a theorem while discharging its premises. It warns about overselecting
goal symbols under specialization, missing representation bridges, popular keys,
finite prefixes, absent providers and incomplete results. No success, absence,
semantic-equivalence, novelty, speedup or scale claim follows from this recipe.

Remaining aggregate exploration cost is explicitly the investigator's policy,
not a claimed new cross-command software quota. Fresh per-command allowances do
not erase earlier costs, and the guide authorizes no automatic repeated search,
reindex, provider launch or experiment. The useful change is a documented public
composition of already supported fields and commands. The navigation correction
is complete; no additional mechanism or experiment is needed to adopt this text.
