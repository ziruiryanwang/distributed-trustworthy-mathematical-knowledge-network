# Extend mathematics and return it to the commons

Start with the same final exact-module package, approved PROFILE/runtime, owner,
custody/store ID and original persistent limits selected in
[BUILD-MODULE](BUILD-MODULE.md). A [question](QUESTIONS.md) is optional; local
agents can investigate their own concepts without searching or following a global
problem list. Ordinary Lean defines new structures and proves consequences.
Neither human intention, popularity nor a query response changes acceptance.

## Optional discovery and independent acquisition

Use the [network request forms](../../ordinary_network_kit/START-HERE.md) with
`ordinary_investigator_bundle/prepare_selected.py`, **not** that guide's historical
selector, and this same final package. Put the successful query's `SPECS.json`
array in the find configuration's `specs`. Retain independently selected `contacts`,
`providers`, `limits`, `offer`, `page` and optional `candidate_mode`; no query
supplies contact authorization. The current adapter computes namespace/features.
Explicitly authorize egress and later retrieval instead of treating directory
hints as permission. Exact-key discovery and optional sparse features remain
bounded, incomplete candidate search, not complete semantic theorem retrieval.

Preview and receive/check are separate commands after finding a candidate.
Select actual exact targets and the resulting receiver context. Do not treat a
candidate's claimed statement, matching name, returned feature, publisher
identity or source code as a proof. Offline
[selected export](../../ordinary_selected_export/README.md) and
[intake](../../ordinary_selected_export/INTAKE.md) provide an alternative when
actual inert data is available. If neither a peer nor an actual handoff exists,
continue local work; the software cannot supply useful content by itself.

## Define, prove and independently check an extension

Follow the existing [no-project authoring recipe](../../ordinary_reuse_workflow/README.md#2-author-and-check-an-extension)
with the current package/profile. You do not need a pre-existing Lean project.
Choose and approve a fresh Lean body containing your definitions and proofs.
After a received-vocabulary question or module realization, bind inputs as follows:

| Contribution input | Required actual value |
|---|---|
| `--parent-root` | Same owner's checked context, initially the module report's `source_context_root` |
| `--acquired-targets` | Explicit exact warranted `{name, export_id, unit_id}` rows, e.g. selected module `targets` |
| `--source` | Approved new Lean body, not the question wrapper or peer executable |
| `--output-names` | Structured names actually introduced by that body, not imported declarations |

An AnchorID is not a parent root. QUERY is not a proof; BINDINGS is not an acquired
target list because it lacks the required unit metadata. Explicitly choose a
checked context containing all selected targets; independent branches are not
merged by guessing the latest root. The command checks IDs/custody locators against
that exact context. New definitions and their consequences must themselves pass
the existing independent mathematical checking/admission policy.

No-project contribution reconstructs its demand-selected authoring environment;
it does **not** consume an AnchorID. Scratch theorem signatures are not accepted
axioms: new evidence is rebound to exact local identities and independently
checked before admission. Existing 32-group/4-MiB request limits remain. A query
over an import does not prove a later authoring request fits those caps or recovers
source-level notation, macros or typeclass instances. Do not silently raise limits
or change foundations to obtain a success.

If an approved ordinary project is appropriate, the existing project-return
adapter can import the locally registered module. Add `--project-authoring
<absolute-config.json>` and `--project-authoring-sha256 <exact-SHA-256>` to the
same contribution command, with a configuration of this shape:

```json
{
  "schema":"DMKN_ORDINARY_TRUSTED_PROJECT_AUTHORING_V1",
  "module_name":"NewWork.Contribution",
  "project_cwd":"C:/MyLeanProject",
  "project_search_paths":["C:/commons-work/module-01/modules"],
  "imports":[{"module":"DMKNBridge_REPLACE_WITH_ACTUAL_64_HEX_SUFFIX","meta":false}]
}
```

This is a shape, not valid ready-to-run input: use the exact `module_name` from
the successful export in `imports` and **all** its validated `import_directories`
in `project_search_paths`, plus any separately approved precompiled dependencies.
Do not substitute only the top module's directory for a longer chain. At most
16 distinct search roots/64 imports and a 64-KiB config are supported. `meta:true`
selects a meta import. Select a fresh bounded dotted ASCII output module name.
Use ordinary absolute ASCII paths and the exact supported runtime; dependencies
must already be built. The adapter neither runs Lake nor fetches dependencies,
rewrites a project, or accepts unbound project mathematics for free. Inspect
returned statements/IDs: agreement with a different project's interpretation
does not follow from sharing names. Project execution is a separate local-code
approval at account permissions, not authorization to import peer `.olean` files.
This route still independently checks the returned new evidence. The original
no-project route is often cheaper when no project environment is already needed.

## Return accepted work; keep ownership and availability explicit

Require the [common outer/owner closure checks](BUILD-MODULE.md#common-completion-checks)
and full contribution report. The inner status must be
`CHECKED_CONTRIBUTION_WITH_DURABLE_PUBLICATION_BYTES`, admission `CHECKED`, and
`local_root` equal `admission.local_root`. Failed reporting may follow a commit:
preserve failed outputs and inspect state rather than assume rollback.

Use the full result's exact `targets` in the existing
[publication command](../../ordinary_reuse_workflow/README.md#3-publish-selected-accepted-outputs-directly),
with `admission.local_root` as the publication `context_root` and the same final
package/profile. Publication indexes checked work; it does not check new
mathematics. Another owner must independently check acquired evidence under its
own supported policy. Publishing a name does not guarantee any holder remains
available or that a useful peer will discover it.

For network serving, use the [finite service planner](../../ordinary_service_plan/README.md)
with the same final package/profile. Explicitly approve disclosure of **all**
addressable custody, not just a selected target list; serving excludes concurrent
writers. Budgets/leases are finite and not renewed automatically. For a limited
offline handoff use selected export instead. Do not substitute private sidecar or
database manipulation for public operations.

For the next investigation select the returned checked context and exact useful
targets. A compatible registered module may be extended using explicit
`--module-anchor` as described in BUILD-MODULE; no-project authoring remains a
separate route. These operations support the creative receive/define/prove/return
loop. They do not guarantee worthwhile discoveries, exponential growth, complete
recall or a favorable full-cost comparison merely because more artifacts exist.

## Updates and recovery

Follow the [preserved recovery rules](../../UPDATE-AND-RECOVERY.md), with this
distribution's current package/selector. Preserve exact failed evidence, state
identity and support bindings. A module-support change can make old anchors
unusable while leaving the owner's mathematical context compatible: select a
fresh compatible realization, not an unnecessary owner reset/reintake. The
exact-module overlay retains the mathematical installation. A change to
mathematical checking/identity instead requires the recovery guide's explicit
rechecking policy; no silent migration, trust upgrade or automatic cold
reconstruction occurs. All work remains local/unpublished and the license remains
undecided.
