## Six outcome groups

1. **Policy and time division.** No-fields compatibility; all-three-fields
   requirement; 1..8 distinct approved labels; type/range refusals including
   booleans; preserved order; one reserve subtraction; pure arithmetic for
   capped/divided slots and no-positive-slot refusal.
2. **Default receive.** Real preview/evidence validation and retention through
   an explicit transport double that accepts only the old five positional
   exchange arguments. Exactly two requests to the discovery provider, no new
   source report, one READY-only admission-double call. An actual shared ledger
   retains prepaid discovery charges and narrows, never renews, its deadline.
3. **Disjoint supplier receive.** A/B explicit order excludes the discovery
   provider from acquisition. B holds selected preview/target and the first
   dependency; A holds the middle dependency. Exactly ten requests for six keys,
   three metadata preflights and one final admission double. Verify exact unit
   IDs, unchanged input config, per-source bounded counts/last reasons, and
   failed full-cap plus successful actual-byte charging on the same ledger.
4. **No invented authority or data.** Selected-unit-only makes zero ancestor
   locator/evidence requests and no admission call. Two evidence-capable holders
   that cannot supply the required preview exhaust the explicit source list;
   they do not synthesize a preview or proceed to preflight.
5. **Terminal faults and nonrenewing budget.** Real acquisition/router with
   narrow injected failures: HTTP400, preview hash, evidence identity, locator
   identity, TLS, unowned timeout, generic OS error, cancellation, local SQLite
   retention, settlement failure, exhausted aggregate grant, and owner/CA-like
   postfailure live-check refusal. No later exchange occurs. Settlement
   uncertainty retains the pending reservation rather than inventing a refund.
   Defaults still treat HTTP404 as terminal. These are controlled exceptions,
   not a security sandbox or real TLS/custody-corruption campaign.
6. **Transport classification.** Three actual finite loopback requests: legacy
   incomplete body, opt-in incomplete body, own exchange timeout. Ensure server
   tasks/listeners/writers close. Separately inject the narrow connection error
   classes and terminal TLS/unowned-timeout/OS/cancellation cases; endpoint and
   CA-setup failures occur before any dial. No external addresses are contacted.

The suite records group reports, exact request order, full ledger/client counts,
authority-double calls, actual loopback closure, immutable-input rebinding and
one final result only after all checks succeed. Failures/partial outputs remain.
No retry, repeated passing campaign or automatic continuation is selected.
