## The exact path

The selected [adapter](../ordinary_formal_query/discovery/ordinary_export_adapter.py)
uses `describe` to add one `type-symbol` feature for every exact binding in the
selected type's `type_bindings`. It also adds declaration kind and coarse heads.
`compile_query` accepts up to eight feature conjuncts. It does not unfold
definitions, examine proof bodies or infer transitive semantic connections.

The relevant source is
`research/cycles/v5-2026-10-28-growth/Proposed03.lean`:

| Published target | Visible type information | Discovery role |
|---|---|---|
| `ResetEffects.fill` | `{A : Type u} -> FiniteMapRefinement.Context (ResetEffects.Plan A) -> ResetEffects.Plan A -> ResetEffects.Plan A` | Contains both the known Context constant and the new Plan constant in its type |
| `ResetEffects.contextual_iff` | Explicit binders `p q : ResetEffects.Plan A`, ending in `ContextuallyRefines observe step p q <-> Mode.Refines (summary effect p) (summary effect q)` | Contains the newly learned Plan constant and is a theorem |

Let C be the exact previously known portable identity of the generic
`FiniteMapRefinement.Context`, and P the exact Plan identity later learned from
the returned fill preview. Subject to actual selected-export identity agreement:

1. Query `declaration-kind=definition` and `type-symbol=C`. The fill record meets
   both predicates. The query does not contain a ResetEffects name or target ID.
2. Select a returned fill candidate and obtain its ordinary type preview. The
   preview's exact name/identity bindings expose P. A name string alone is not P.
3. Query `declaration-kind=theorem` and `type-symbol=P`. The criterion record meets
   both predicates through its explicit plan binders. It is not necessary to know
   the criterion's name or complete formal type in advance.
4. Preview the selected criterion, inspect needed interfaces, then independently
   receive/check its supported closure before mathematical use.

Both queries may additionally use `object-kind=ordinary-lean-export-v2`. The
existing kit accepts these feature shapes. Learning an unaccepted symbol ID as a
search hint does not require accepting that mathematics: the second query is
metadata navigation, while later admission remains mandatory.

**Do not substitute a single `Context + theorem` query.** Context appears inside
the definition of `ResetEffects.ContextuallyRefines`, but that body is not part
of the criterion's visible type DAG. The selected adapter does not unfold it.
Publishing fill supplies the missing explicit vocabulary bridge. The older
finite-map fill may also match the first query; the previews distinguish its
different plan identity. This audit does not prescribe which candidate an agent
will choose first.

## Why separate Plan/Mode index records are unnecessary here

[Portable previews](../ordinary_lean/portable_preview.py), especially
`_from_checked_syntax` and `read_preview`, bind each visible type reference to its
exact export identity. The criterion exposes Plan, Mode, `Mode.eval`,
`Mode.Refines`, `summary` and `ContextuallyRefines` as applicable in its actual
elaborated type. Its premise types expose the atomic observation law and both
observation witnesses; the theorem does not claim they hold automatically.

The existing [custody implementation](../ordinary_multi_source/ordinary_acquisition.py)
projects locators for **every inventory output** when an evidence unit is stored
(`OrdinaryStore._export_locators`), rather than only advertised targets. The
[public inspect operation](../ordinary_multi_source/peer_api.py) uses a selected
exact name/export ID to fetch that locator and its unit, independently of whether
the dependency has a discovery-index record. Inspect returns inert bound data;
it is not mathematical acceptance. Further references can be inspected under
separate explicit bounds, or acquired as the checked target's closure.

Consequently interpretation does not require publishing Plan, Mode, summary and
every helper as additional search endpoints **provided** the selected producer
exports the necessary complete closure, intake retains it, custody has its
locators and a selected provider continues serving those bytes. Missing dependency
bytes, unavailable service, insufficient limits or an unsupported frontend can
still obstruct use. Two indexed targets do not mean two evidence units or a
constant total acquisition cost.

Adding Plan alone would not improve the Context-to-criterion bridge: Plan's own
public type does not mention Context. Adding more abstract datatype names would
increase endpoint count without establishing a new useful entry path.

One possible later distinct need is a sufficient refinement rule when both
Boolean observations are not inhabited. Then `ResetEffects.contextual_of_summary`
is the smallest relevant extra endpoint: unlike the iff criterion, it does not
require the two observation witnesses. That is a different applicability request,
not a defect in the present exact-criterion publication. No such extra endpoint
or experiment is required by this audit.

## What remains conditional until actual publication

- The producer/intake must preserve the exact existing generic Context identity;
  same printed names do not establish identity. Use actual exported bindings and
  the selected checked parent, not guessed hashes.
- Actual fill preview must bind C and P; actual criterion preview must bind the
  same P. Generated records must have the stated declaration kinds. These are
  small saved-output checks once those outputs exist, not a reason for another
  compiler run or a synthetic query result.
- Successful local publication must include both selected records. Multi-target
  publication is not atomic; a partial failure cannot be called a two-target
  exposure pass. Read its actual report.

For a correctly built finite index containing both records, the matching feature
path exists. It supplies no claim about result order, practical selectivity,
available budget, provider coverage, malicious omission, service duration or
global completeness. Sparse pair access can accelerate selective matching, but
cannot ensure that a user selects this useful connection among many matches.
The current bounded fair search can legitimately stop with incomplete results.

This is a publication-design justification for an actually checked new theory.
It is not an observed unknown-result discovery, a growth-speedup result or a new
reason to implement a matcher. Keep the planned two targets and inspect the
actual saved publication/binding evidence before making the narrower exposure
claim concrete.
