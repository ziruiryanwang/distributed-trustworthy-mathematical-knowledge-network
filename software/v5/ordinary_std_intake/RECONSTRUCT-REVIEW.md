## Why the reduced validation is legitimate here

The desired finite manifest is already independently fixed at SHA-256
`1de776b3d131c8c1be3414ed0e0cf066ebd05caebbcd1cf1b6ca80853962e59c`.
It contains the output identities from the earlier completed binding diagnostic.
For each ordered entry `(u,h,l)`, the reconstructor requires, before writing:

\[
|r|=l,\qquad H(r)=h,\qquad
H(\texttt{DMKN-ORDINARY-EVIDENCE-V2}\|\texttt{NUL}\|r)=u.
\]

Under the same SHA-256 binding/second-preimage assumptions used by existing
content identities, a different byte string cannot feasibly replace the
manifest-selected preimage. This is a **computational identity argument**, not
an unconditional mathematical proof that collisions are impossible. The raw
digest and domain-separated UnitID are not independent security assumptions;
checking both also detects schema/domain binding mistakes.

Consequently this local constructor need not reestablish every arbitrary-input
parser property merely to restore those particular committed bytes. A wrong
decoder, ordering assumption or transformation normally produces a mismatch
and refuses. Even successful exact restoration establishes only the inert
object. A prior manifest, prior successful binder or restored hash never becomes
authority that the mathematics is true. The unchanged public strict parser and
native intake remain mandatory at the subsequent acceptance boundary.

This argument depends on independently fixing the desired manifest before
construction. It would not justify accepting an arbitrary untrusted sender's
new manifest as proof of correctness. The implementation is test-only, uses
exact pinned local inputs and does not expose that general fast path.
