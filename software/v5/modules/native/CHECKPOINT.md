## Crucial unresolved boundary

`ConditionalPremise` is intentionally an **unverified mathematical premise**.
The report always says `CONDITIONAL_MODULE_EXTENSION_ONLY`,
`receipt_verification_performed=false`, and `mathematical_admission=false`.
Its caller must not treat a record digest field as if the checker authenticated
that digest. A new relation wrapper must recompute/validate the correspondence
between canonical module/group descriptor openings and these exact native rows,
bind foundation rows to F, and genuinely verify the selected module receipts.

This low-level API therefore cannot be exposed as a public acceptance command.
Its purpose is to test real kernel behavior while the new cryptographic wrapper
is developed. The guest must run the same completed relation itself and abort
on any missing witness; it may not consume a native preflight success flag.
