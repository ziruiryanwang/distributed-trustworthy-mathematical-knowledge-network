## Minimal trust and resource contract

New optional read-only route keyed by (semantic_id,export_id). One lookup returns
at most8 advisory offers/32KiB under existing aggregate network reservations.
No retry, redirect/referral chasing, native process, owner open or math acceptance.
Empty/unsupported is not global absence. Truncation is an unverified provider
statement, not an authenticated completeness proof. All returned data are inert.

An offer claims an HTTPS repository location, exact Git commit with object format,
normalized repository-relative project directory, encoded Lean module and export
name, and asserted toolchain. Full immutable commit ID, not just branch/tag. No
userinfo/query/fragment/credentials in URLs. Validate bounded strings and safe
relative paths; never pass hints to shell or automatically open/download them.
Commit identity does not pin all dependencies, prove source availability, establish
exact mathematics correspondence, or grant code-execution approval.

Use a bounded operator-selected immutable sidecar map, not a new database or remote
write API. Parse/index it once under finite startup bounds; exact-key lookup must
not scan all map rows per query. At most2MiB/2048keys/8offers per key; smaller local
caps may refuse. Provider map is only its partial catalogue; it need not hold global
mathematics. Duplicate keys/offers and malformed maps refuse. Source hints from
multiple providers remain replaceable; no globally required repository/server.

Preserve existing operations when the optional service map is absent. New client
operation is state-free; explicit local map selection and file pin for provider.
Use current JSON/name/size validators, network budget, HTTP limits and cleanup.
