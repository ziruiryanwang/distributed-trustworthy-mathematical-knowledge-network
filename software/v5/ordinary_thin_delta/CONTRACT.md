2026-10-24. Root selects this source change after the growth-value and thin-route
comparison. This is not a new native runtime, package, registration or migration.

## User workflow and payoff

A recipient already works in an approved ordinary Lean project whose selected
base interpretation is independently warranted. It acquires and checks a small
new theorem over that same base, then wants to import only the new theorem into
its existing project. It must not have to execute the producer's plugins or
replace its own base by duplicate generated definitions. Keep the recipient's
existing frontend; do not replay the producer's metadata or tactics.

The source-supported obstruction is the parked ReferenceModule's enclosing
environment header check. Stock Lean 4.34 `importModules` uses
`finalizeImport(isModule := level != .private)`. Its private view therefore has
`header.isModule = false`, even when all imported modules are modern. The current
helper requires true for both private and exported views. Source-authoring has
a related defect but is not needed for this materialization capability.

## Exactly selected change

Copy the preserved `ordinary_reference/ReferenceModule.lean` to this fresh
directory, retaining its logical module/namespace and all other behavior.
Change only `checkBaseHeaders` to require the enclosing header mode to equal
the selected `publicView` flag, with a precise failure label and explanatory
comment. Current call sites derive that flag from `level != .private` for the
separate build and reread views. Do not mutate the environment/header or alter
the imported constants.

The following remain mandatory and unchanged:

- Every imported module is modern; exact private/public module order and all
  generated headers/imports match the protected plan.
- The base is exact, locally protected and currently warranted, not approved
  merely because it compiles or a peer supplies a matching report.
- Separate private and exported imports/checks; separate frontend and kernel
  record checks; exact new inventories; no new-name collisions or ambient imports.
- Both new-proof checks and both fresh artifact rereads. The writer uses the
  exported checked view; no private-to-public map copying or header flipping.
- Existing resource limits, parser, semantic identities, declaration rules,
  complete proof input and final event/commit rules.

This file is a SOURCE OVERLAY, not a standalone program or a new installed
profile. Its eventual logical payload remains `reference/ReferenceModule.lean`.
The unchanged controller selects that exact path. Source and helper support

## Deliberate scope limits

The first capability target is theorem-only extension using the registered
public base frontier. Private-only helpers or computations unavailable through
the exported interpretation can still cause a correct refusal. There is no
automatic general Lean compatibility, cross-version mapping or branch merge.

This is materialization of already independently accepted units. It does not
perform peer discovery/admission, solve cold base onboarding, reduce all repeated
base loading, supply incremental producer export or prove useful-growth speedup.
New support registration, actual artifact imports, new proof checking, retention
and failure costs remain. Existing ordinary contribution/intake handles accepted
inputs; no `contribute-reference` repair is selected.
