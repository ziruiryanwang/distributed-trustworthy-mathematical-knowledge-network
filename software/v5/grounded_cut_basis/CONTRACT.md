## Assurance boundary

During paid native-to-cut derivation under the actual native owner lock, derive
the genuine committed zero-parent basis row/operation, not an extension filename.
Bind its root/request/operation/record digest, module, path, length/hash, 581-name
count, fixed seed/inventory and outer store/support/implementation identity in
the protected source anchor. Hash identity or a caller assertion alone is not
checked origin. Use a distinct support identity and fresh cut state.

For each actual worker event, while source and cut owner locks remain held,
authenticate the exact artifact once with bounded streaming reads and budget
callbacks. Check source eligibility before/after and retain every existing inner
check. The approved owner and OS enforce immutable artifacts/no replacement and
no whole-state rollback. No caller-supplied snapshot or arbitrary module plan.

The internal method is `SourceAnchor.basis_snapshot()` returning exactly
`{module_name, path, artifact_bytes}`. Only the protected controller/runtime path
inserts it as `basis_snapshot` in `DMKN_GROUNDED_CUT_BASIS_REQUEST_V1`. Runtime
requires the exact live SourceAnchor type and calls basis_snapshot once; caller
packets must omit that field. It returns the actual augmented request bytes for
the controller's event hash, never treating saved output as authority. The Lean worker builds
a singleton `LocalSnapshot.LocalImportPlan`: basis=root, no parent, exactly581
names, at most1GiB artifact. Preserve seed/inventory pins, source-name checks,
restored quotient/module checks, full initial census, concrete checks, signature
grounding, fresh-name/new-proof checks and final census. The distinct report is
`DMKN_GROUNDED_CUT_BASIS_CONDITIONAL_OUTPUT_V1`; include actual basis artifact
bytes separately from JSON input bytes. Runtime must bind report to request.

Restoration uses trusted native deserialization of locally checked bytes. It is
not safe parsing or independent verification of peer `.olean` files. Checked
origin, exact immutable bytes and adopted serializer/deserializer correspondence
are explicit premises: inventory normalization is not injective raw-record
equality. Fixed proof bodies remain read. No application-ancestry load is added.
Preserve clean supervision, fail-sticky withdrawal, exact frontier/freshness,
durable intent, atomic commit and indexed non-replaying resolution.
