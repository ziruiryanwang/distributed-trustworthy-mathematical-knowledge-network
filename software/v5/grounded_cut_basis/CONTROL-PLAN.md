# Fixed-basis changed-boundary controls

SOURCE ONLY, 2026-10-24. Independent review and a separate finite root selection
are required before execution. No test, import, native operation or performance
measurement has been run as part of authoring these files.

## Scope and payoff

`test_basis.py` checks only the new protected fixed-basis boundary. It does not
repeat predecessor trie, summary, census, controller recovery or general catalog
campaigns. Ordinary Lean/Lake development remains primary; this optional local
accelerator is useful only if its whole-cost discriminator later supports it.

The suite checks source provenance binding, exact snapshot authentication and
runtime request/report integration. It does not establish checked mathematical
origin for its own fixture, Lean serializer correspondence, genuine worker
acceptance, speedup, useful growth or deployability.

## Inputs and finite isolation

Run later only with the root-selected Windows Python in isolated/no-site/
no-bytecode mode (`-I -S -B`, no optimization), canonical project cwd, one exact
source snapshot and one fresh output directory below canonical `experiments/`.
The test never imports the live canonical implementation. The source snapshot
must contain these eight files at the indicated relative paths:

- `ordinary_lean/ordinary_evidence.py`
- `ordinary_lean/ordinary_semantics.py`
- `ordinary_lean/portable_evidence.py`
- `ordinary_lean/local_catalog.py`
- `ordinary_lean/portable_catalog.py`
- `ordinary_lean/ordinary_admission.py`
- `grounded_cut_basis/source_anchor.py`
- `grounded_cut_basis/cut_runtime.py`

The outer runner must pin test, source and interpreter inputs before launch and
provide its independent process/memory/output bounds. Secondary original suite
guards are 60 wall seconds and 30 process CPU seconds, never renewed by a case.
Source loading checks ordinary single-link files and nonredirected ancestors,
records hashes/lengths, and writes no bytecode. No native child, network, existing
protected store, migration, build, installation or Git action is allowed.

All SQLite databases, owner locks, pseudo `.olean` files and request/report bytes
are created afresh in the output. Selected synthetic mutations append/change a
byte, update their newly created rows, or rename a file to a retained filename;
there is no cleanup/deletion and no modification of prior evidence. The final
report and all synthetic failure evidence remain available for independent audit.

## Real implementation versus explicit authority seams

| Boundary | Real code exercised | Explicit test-only seam |
|---|---|---|
| Capture | Binding codecs; actual context, root, operation, record and artifact validators; actual Windows lock | Fixture is constructed without native admission; `_active` returns synthetic activation |
| Extra capture provenance | Actual capture and committed-operation validator | Negative tests give plausible unchanged context; three malformed rows supplied directly |
| Snapshot | Actual readonly SourceAnchor, SQLite metadata reads, lock, path/size/streaming SHA, sticky denial and budget callbacks | Fake581 names and visibly non-Lean artifact bytes; one private path mutation |
| Runtime | Actual check_packet, genuine SourceAnchor, actual file spool, parser and report binding | Fake installation/supervisor, callback-only support verifier and finite Budget type; no subprocess |

The fixture's fake basis names satisfy identifier formulas but are not the actual
Lean basis. Their artifact is plainly not a Lean object. Genuine capture of a
real native basis remains a later actual-path obligation; success-shaped fixture
records cannot substitute for it. Runtime's syntactically shaped theorem values
are deliberately not asserted to typecheck. Only an actual worker supplies that
mathematical judgment in production. Runtime authority doubles do not test
approved support installation or OS child supervision.

## Case groups

- Capture chooses the committed zero-parent basis even when an extension is
  selected; its exact record digest and descriptor bind that basis.
- Binding refuses the old V1 descriptor, wrong basis root/request/parent/module,
  non581 count, seed/inventory changes, path escape/substitution and zero/over-cap
  artifact size.
- Capture independently refuses nonnative origin, nonzero parent, nonbasis kind,
  wrong actual operation state/root/size and absent live native lock, including
  when a plausible context has already been supplied.
- Snapshot returns only the detached three-field descriptor, executes both
  metadata checks and every chunk budget callback, rehashes on each call, and
  never traverses the application history. SQL trace covers the new method only,
  not fixture preparation. Corrupt hash/size/path, missing file, source withdrawal,
  closed lock and exhausted original callback produce sticky denial. Removing
  the synthetic withdrawal marker by retaining it under another name cannot
  re-enable that anchor.
- Runtime refuses caller snapshot injection, old request schema and mismatched
  implementation before authentication/spool/worker. Success authenticates once,
  inserts only its genuine anchor's snapshot, returns the actual augmented bytes
  and binds exact saved request/report to the live call. Old report, wrong request
  ID/inventory/signatures/basis-byte count/kernel-call count, bool count and changed
  request refuse. A replacement non-SourceAnchor object refuses.

No generic catalog, theorem census or uncertain-cleanup tests are repeated.
The in-process suite is not a hostile-storage or TOCTOU safety proof: immutable
protected bytes, no whole-state rollback and trusted native loader correspondence
remain explicit architectural assumptions. A later actual mathematical event and
matched whole-cost comparison are separate root decisions, not automatic next
steps authorized by this plan.
