# Fixed-basis successor: integration and source map

2026-10-24. Source only; no build, test or mathematical event selected here.

## Complete path

1. The approved exact-source bootstrap loads the existing pinned ordinary base,
   then the distinct `DMKN_GROUNDED_CUT_BASIS_SUPPORT_V1` support. Its support-ID
   hash domain is `DMKN-GROUNDED-CUT-BASIS-SUPPORT-V1` followed by a zero byte.
2. Controller bootstrap captures the genuine committed fixed-basis descriptor
   during the paid native derivation. The unchanged catalog commits the V2
   binding's hash together with the new support ID, store and epoch in each root.
   Old state cannot satisfy these bindings. No catalog migration is implemented.
3. Controller extension holds source and cut owner locks, prepares exactly the
   selected concrete/signature frontier, and retains the full public proof in
   inert custody. Its internal request intentionally has NO basis_snapshot.
4. Runtime requires the exact SourceAnchor type and matching implementation;
   calls basis_snapshot once before native launch; adds that three-field result
   to the actual canonical request. It reserves/checks the augmented spool and
   preserves all support, budget, clean-process and final output checks.
5. The Lean driver restores only the protected singleton and checks full fixed
   inventory before the unchanged conditional proof path. Runtime binds actual
   theorem/signature output and integer counts, including basis bytes and the
   successful-path kernel-call formula, to this request.
6. Runtime returns the actual augmented request bytes alongside the live report
   and supervision observation. Controller commits their hashes only after the
   original source, frontier, freshness and atomic intent checks. Event counts
   distinguish basis_hash_bytes and basis_artifact_bytes; they do not purport to
   measure physical disk reads or all support I/O. Lost-reply resolution never
   runs the worker or hashes the basis again.

The support's new identity and new anchor schema isolate the changed semantics;
reusing the catalog schema does not reinterpret old acceptance. Unchanged catalog
records already include exact support and anchor hashes in their identity.

## Current limits

Trusted local native loading, protected owner execution, immutable files and
serializer correspondence remain assumptions. Fixed proof bodies and full
censuses still cost work. This cannot provide cold public trust from an index,
make arbitrary source safe to execute, guarantee useful invention, or establish
an economic advantage over ordinary Lean/Lake or native batching. Those claims
are deliberately not inferred from the source change.
