# Port the existing type-pattern capability to ordinary inert previews

2026-10-28. growth_design_audit; source/theory only. No runtime, owner/database
access, source modification, new corpus, external contact or Git action.

## Deduplication changes the question

This is **not a new search invention**. `software/v5/type_pattern` already
implements whole-type variant keys: first-occurrence slots for nonfoundation
symbols, shared const/projection identity, exact foundation symbols, and retained
bound-variable, universe and expression structure. The 2026-10-20
TYPE-PATTERN-THEORY proves the exact variant relation. TYPE-PATTERN-OUTCOME
(`9963383e...`) records nine passing groups and coherent old-SDK integration was
subsequently adopted. Do not repeat that theory or its 2-to-1 synthetic fixture.

The present kit instead selects the ordinary V2 preview adapter and original-Lean
expression DAG. The old helper accepts recursive module-codec trees with tagged
foundation/local/external references; its record binds module IDs and openings.
It cannot consume the current V2 preview/header/portable-ID representation.
Its bounded occurrence expansion also does not provide the current DAG cost
target. I found no later decision rejecting variant keys on mathematical grounds;
their absence here is a representation/integration gap after the ordinary-library
redesign, not evidence that the technique was disproved.

`instantiation_discovery` is different: selected conclusion paths replace outer
parameters by STAR while retaining rigid constant IDs. It helps retrieve raw
instances, but does not bridge independently named global vocabularies. Porting
both mechanisms together would enlarge this task without resolving their separate
selectivity questions.

**Recommendation: a narrow source implementation of the existing type-pattern
idea on ordinary V2 previews is defensible.** It restores a previously justified
capability to the currently usable lane, with no native build, certificate,
proof-body replay or automatic source approval. It should remain optional and
advisory. A broad analogy engine, a new theorem episode and another growth
speedup campaign are not justified by this decision.

## Exact changed algorithmic boundary

Reuse `portable_preview.read_preview` and its existing bounded type census.
For a local unaccepted query, reuse `formal_query.read_native_type`; do not create
fictional portable identities merely to prepare a structural query.

The faithful port should preserve the fixed basis. The current semantic contract
already pins a 581-name inventory (`ordinary_semantics.INVENTORY`), and
`basis_symbol_id(S,F,name)` gives its exact identities. An approved, pinned
inventory can supply this small anchor map without opening an owner or importing
Lean. For a preview, preserve an anchor only when its claimed ID exactly equals
the corresponding selected basis ID; all other distinct IDs receive slots.
Never classify a preview's symbol as foundation from spelling alone. A native
query may classify exact basis names using that same selected map as advisory
query input; this asserts no checked correspondence to its authoring environment.

Preserve universe-parameter arity/order, level syntax, constant universe instances,
de Bruijn indices, binder-info flags, let nondep flags, literal values and
projection field indices. Erase binder and universe parameter *labels*, as the
current exact type key already does. The declaration name and kind are outside
the shape; kind remains a separate selectable feature. All literals remain
literal, not wildcards. Use one slot table for constants and projection names.

There is one additional implementation obligation beyond the old theorem:
**derive first-occurrence slots without unfolding the DAG**.

1. Starting at the root, perform deterministic depth-first preorder, processing
   the node's own constant/projection reference before its ordered expression
   children. App order is function, argument; binder order is domain, body;
   let order is type, value, body; projection's child is its value. Use an
   explicit bounded stack and a visited-index set. On first occurrence of a
   nonanchor identity, allocate the next slot.
2. Process level and expression nodes in their existing backward-edge order,
   replacing each global reference by its anchor or assigned slot. Compute
   domain-separated node digests from retained scalar fields and child digests.
   Root key includes selected semantic contract, exact shape-profile version,
   universe arity and final node digest. Never serialize a recursively expanded
   normalized tree.

**Why memoization preserves the old relation.** In the unfolded ordered tree,
after the first traversal of a shared subexpression, every symbol inside it has
already been encountered. Skipping any later identical occurrence therefore
cannot change the order in which *new* identities first appear. The DAG traversal
assigns the same slots as the old ordered-tree definition. Bottom-up digests
depend on child structure, not node indices or sharing. The previous bijective
renaming theorem then applies after the explicitly retained-field projection.
Binder-label-dependent sharing differences likewise cannot introduce a new
identity absent from the earlier equivalent subtree. Digest equality additionally
uses the usual no-collision premise; mathematical acceptance never relies on it.

Let B be bounded serialized bytes, V all expression/level nodes, E their edges,
and S distinct type symbols. Expected work is O(B+V+E), including name/literal
bytes, with ordinary dictionaries; memory is O(B+V+S), including parsed input and
stack. Do not advertise a deterministic dictionary bound or ignore parsing.
An ordered-map implementation can instead state the additional logarithmic term.
No term contains theorem proof ancestry or the provider's corpus size. Existing
limits/refusals apply before these passes; no partial key may be returned.

## Minimal investigator and operator workflow

An investigator has a local law, for example a unary idempotence law over its
own carrier and operation. Another theory independently uses different carrier
and operation names with the same full declared type structure. This is a target
interface class, not a newly generated test corpus or a claim of scientific value.

The investigator supplies a pinned saved V2 preview, or an already produced
`#ordinary_type_query` AST from approved local Lean code. A small offline helper
computes one `declared-type-pattern` spec without an owner/context reconstruction.
This query contains no target name or remote ID. Reuse existing find, selected
contacts, aggregate budgets, preview/inspect and receive. After inspection, reuse
the exact acquired vocabulary or construct an ordinary checked bridge; a pattern
match never performs symbol substitution into an accepted proof.

The provider computes the same feature from each selected inert preview during
publication. It need not materialize a native project, load received executable
code or possess the theorem's proof body merely to derive the feature. Existing
index admission already rederives features from previews; client preview binding
can rederive it too. This contrasts with a locally operated Loogle provider,
which requires a compatible approved native project/environment. A remote Loogle
hint remains a useful external alternative, but the current public service is
not a provider for arbitrary independently published inert theory previews.

Wire/index changes are explicit: successor helper plus adapter feature/spec,
new feature revision/namespace, coherent package mapping and query preparation.
The existing exact-key posting/index/provider/search machinery is reusable;
native admission and mathematical evidence identities remain unchanged.
Fresh indexing is required. Old snapshots/seals/records cannot be relabeled.
If old and new indexes are served together, inherited records/postings can be
duplicated; rebuilding costs are not only one added posting per record.

One concrete source detail must be settled before implementation: current
`formal_features.MAX_FEATURES` is 128 and the existing adapter can exhaust it.
One additional required key must not silently drop an old feature. Keep the
explicit finite refusal with this new optional profile, or select a reviewed
new-profile cap of 129 and propagate it coherently; do not casually raise generic
store ceilings or call the change cost-free. Aggregate posting/byte limits still
apply. The optional pair-access table indexes only operator-configured pairs;
it need not materialize all pairs containing the new feature.

## Payoff and limits that determine selection

This port has a concrete interoperable corpus advantage over a bare instruction
to use Loogle: the current inert preview corpus becomes queryable by this one
structural relation without a native-project reconstruction. Its benefit class
is whole-type variants with unfamiliar nonfoundation symbols. This is narrower
than general pattern matching and can be brittle: a changed telescope, partial
application, implicitness, universe expression, definition unfolding or reordered
hypotheses can prevent a hit. Loogle or future richer search can be better there.

For a selected corpus, let M be the broad candidate set and k the shape bucket
within it. A query can retain a known foundation-symbol/kind conjunct and add
the shape conjunct, so k <= M; strict reduction depends on actual content.
Existing index work follows the selected posting/access path and k, not all
unrelated worldwide proofs. An enormous or spammed k remains expensive. Finite
contact/page limits report incomplete search; they do not prove relevance or
global completeness. Pattern equality supplies no semantic bridge or usefulness.

The investment is reasonable when recurring structural queries save enough
inspection/provider work to cover extraction, indexing, storage, reindexing and
failed searches. No prevalence or measured speedup is inferred. The small port
can be justified as a missing optional interface capability without pretending
that this inequality is already experimentally established. If root selects it,
only changed DAG/profile/public-API controls are needed; historical pattern
fixtures, native checks and concept-production campaigns should not be replayed.
