## Consequential change

The historical overlay pinned one local sparse PROFILE, INSTALLATION and receipt.
This successor removes those accidental artifact identities, not their assurance
obligations. The caller still supplies exact actual PROFILE and immediate sparse
receipt hashes. The installation's actual bytes must match the selected profile.

`validate_base_interface(H, profile, receipt, installation, compatibility,
source_map, *, profile_sha256)` is pure parsed-data validation. It returns
`auxiliary`, `installation_files` (27 bundled files), `documents` (six) and
`implementation_id`. The outer assembler pins and reads the two companion maps
and actual selected raw bytes before calling it. It then performs the existing
152-file full census and hash verification before copying and again afterward.
No product module, native artifact or owner state is imported or executed.

## Boundaries and proposed review controls

Owner-approved generated output is a premise. Coherent hashes do not prove
compilation correctness or native safety. External runtime pins are validated
manifest metadata; this overlay does not open those external files. It neither
changes checking semantics nor approves local source execution. The supported
platform and named runtime policy are deliberately unchanged, not generalized.

Root can test the pure predicate using coherent changed native pins and updated
support commitments, explicitly labelled synthetic metadata, never valid native
outputs. Challenge fixed auxiliary/installation sources, runtime pins, role
partitions, descriptor support groups and receipt bindings. Later actual file-only
assembly should reuse a selected real sparse build and compare all unchanged
payloads. No expensive native rebuild is needed just to change a hash. No test or
runtime has been run by this author; no success or whole-v5 claim is made here.

Public argv is unchanged from bounded transport. New README documents actual
source-build identities and the unchanged final selector; old local-only recipe
is not silently edited. Seven release integration/transport inputs fit the root's
143-payload source bundle alongside its prior 133 fixed inputs and three new
bundle payloads. The implementation note itself is research handoff, not a
runtime payload.
