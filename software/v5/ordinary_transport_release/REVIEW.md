## Why the change is justified

installation manifest and receipt. That blocks an otherwise supported build

that accidental instance restriction while preserving a finite fixed source,
role, runtime and semantic interface. It reuses the existing assembler helper
and offline selector rather than introducing another installation mechanism.

## Assembler argument

1. The outer assembler checks owner-selected actual PROFILE/receipt byte hashes,
   installation bytes bound by that PROFILE, and both fixed companion-map hashes.
2. The pure `validate_base_interface` checks compatibility of those parsed
   objects. It does not authenticate arbitrary supplied Python objects or prove
   that generated files came from correct compilation.
3. A complete 152-file input map is checked against actual bytes before copying;
   copied, source and input bytes are rechecked before the final PROFILE commit.

The validator preserves the exact 45 noncompiled auxiliary pins and 72 named
native auxiliary roles from the pinned network-kit map. The pinned bounded
source map independently supplies all 19 noncompiled installation files; exactly
eight receiver `.olean` roles may have new selected generated identities.
The nine external named-runtime literals match the existing package builder
exactly by independent source-data comparison (nine versus nine, no differences).
These runtime identities are manifest metadata here, not external-file checks
or a hermetic-toolchain warrant.

Roles, compiled directory, five support groups, semantic/platform/snapshot
descriptor and support scope remain fixed. Each support digest is recomputed
from the selected file pins under the existing domain-separated canonical-JSON
formula, and the implementation ID is recomputed from the complete descriptor.
The immediate sparse receipt must bind the selected profile/installation,
predecessor assembler/overlay, six documentation pins, twelve changed payloads,
exact counts and file-only claim. No historical generated-instance equality
remains in the new outer assembler or helper.

Path checks, full file census, per-file/aggregate limits, fresh output, exclusive
writes, hash-checked copying, no destructive cleanup and PROFILE-last ordering

The approved immutable local filesystem remains a premise: these checks are
not hostile-concurrent-writer isolation. Receipt duplicate pin annotations use
