# Native-backed context-selection discriminator

Design and source-review contract, 2026-09-21. One new bounded engineering
regression; not an execution result, autonomous mathematical authorship
experiment, growth measurement or broader launch grant.

## Chosen experiment and claim

Use a fresh cap-six node, fixed ordinary definitions X and Y, and a fixed
definition Z using X's actual receiving name. There are **fourteen CLIs, six
receiver native stages and no peer or socket operation**. A separate support
build uses one stage with two compilation children.

The conclusion sought, conditional on execution and dependency audits, is:

> A real bounded checked context can switch from a Y branch to its retained
> bootstrap context, admit and concretely reuse a separate X branch, and retain
> old artifacts, publications, replies, evidence and charges. Selection changes
> a local working head; it does not itself accept mathematics.

This does not establish semantic independence, autonomous discovery, novelty,
usefulness, scalable growth, capacity renewal, arbitrary pruning, default-cap-16
qualification or overall operability. Fixed reviewed templates suffice for this
regression; no author pause, source repair or automatic retry is authorized.

## Objects and state transitions

Let C0 be the actual fresh initialized context, with five package records.
Submit X against C0 and publish its artifact to obtain owned KX and snapshot S1.
Submit Y against unchanged C0 and publish to obtain KY and S2. P1 now has two
entries. Neither private checking nor publication imports either new definition
into the current mathematical context.

Admitting KY produces checked CY with six packages. Admitting KX against CY
would require seven and must refuse with `CONTEXT_PACKAGE_COUNT` before a
native stage is allocated. Selection returns the head to C0. Admitting the
original KX against C0 produces checked CX with six packages. Check Z against
CX. All handles come from actual responses, never manufactured expected state.

Historical KX remains usable after P1 reaches S2: existing `selected_candidate`
authenticates its immutable snapshot membership and entry, not equality with
the current provider cut. Package count is an actual package-list bound, not
a theorem count or count of unique mathematical content.

Publish and cap refusal may load the checker but allocate no native stage.

and no new mathematical description. Exact replays return stored terminal bytes.

The minimum omits optional info, inspect and publication replay calls. Adding
any requires a revised explicit allocation and expected counters.

## Fixed source templates

X, selected root BranchCompose:

```lean
universe u
def BranchCompose (A B C : Sort u) (g : B -> C) (f : A -> B) (a : A) : C :=
  g (f a)
```

Y, separately checked against the same bootstrap, selected root BranchFlip:

```lean
universe u
def BranchFlip (A B C : Sort u) (f : A -> B -> C) (b : B) (a : A) : C :=
  f a b
```

Z substitutes only the exact X name from a successful admission description:

```lean
universe u
def BranchComposeThree (A B C D : Sort u)
    (h : C -> D) (g : B -> C) (f : A -> B) (a : A) : D :=
  @__COMPOSE__.{u} A C D h (@__COMPOSE__.{u} A B C g f) a
```

This is constrained name binding, not arbitrary source synthesis. The worker
requires one returned ordinary-definition row with one universe parameter,
requires equality with X's original checked-submission description row, binds
the actual native admission response, and permits only a bounded name
matching `DTMKN.d.«[0-9a-f]+»`. Only `__COMPOSE__` is replaced. The guard excludes
source injection but does not itself authenticate the name's canonical identity.
The independent dependency audit must bind it to the actual typed definition
reference; the ordinary external-definition encoding has the form
`DTMKN.d.«840111025820<64 lowercase hex digits>»`. No imports, tactics or extra
source are introduced. Fixture bytes, including the one-universe restriction,
match the reviewed worker; this is not a general source-authoring interface.

These are review inputs, not already verified results. Unexpected rejection
ends the allocation with retained evidence; no source repair or retry follows.

## State and dependency audit obligations

Inspect actual native/canonical outputs and complete retained ledger snapshots.
Readable templates and worker assertions do not alone discharge the audit.

1. Bind exact submitted bytes/root to native source capture, candidate replay
   and inverse capture/replay. Check ordinary-definition exports, declaration
   kinds, complete canonical type/body and actual replay plans.
2. Traverse reachable type/body dependencies of X and Y. They have distinct new
   identities relative to C0; neither contains the other's new identity. Common
   foundations are allowed. Actual CX contains X but not Y's new identity, and
   actual CY contains Y but not X's new identity.
3. Bind Z's actual captured source to the fixed template and allowed name.
   Require X's exact external ref at substantive reachable application sites in
   Z's value, not merely its type or package baggage. Two application sites may
   share one constant DAG node. This is syntactic reuse, not indispensability.
4. For #9, only original-attempt/request reservation, terminal refusal and
   cleared active bookkeeping are added. No new context, stage, publication,
   entry, snapshot or head change is permitted. Checker reads remain real work.
5. For #10, only head CY → C0 and ordinary terminal request bookkeeping change.
   All earlier artifacts, contexts, publications, entries, snapshots, stage rows
   and charges remain byte-identical; P1 stays at cut two.
6. After #11/#12, old records and evidence remain unchanged while genuine new
   work is added. AX retains its C0 binding. Full database snapshots are equal
   before/after each replay #13/#14, returned bytes equal original replies, and
   the current head remains CX.

Use real-state snapshots after relevant children quiesce and with no nonempty
SQLite sidecar. Never insert synthetic database rows, reset counters, remove
old journals or mutate evidence. Immutable-file preservation checks exclude the
live control database; they do not claim the entire growing tree is unchanged.
Canonical package closure/DAG checks are necessary implementation rules; the
audit must still bind the outputs of this particular run.

## Accounting and containment

Success has ten fresh requests at 8 MiB plus six stages at 128 MiB:
`requests=10`, `stages=6`, `charged=848 MiB = 889192448 bytes`,
`active=NULL`. These are grant charges, not physical bytes, CPU or renewed
capacity. Replays add zero. Failed prefixes retain actual observed counters,
not expected successful totals; nothing is refunded.

Receiver children total eighteen: init 1, submissions X/Y/Z five each, admissions
X/Y one each. Support build separately has one stage and two compilations.

The small coordinator invokes a root-authored worker once through unchanged
`supervise.Transport`. The worker copies exactly ninety-eight pinned product
files to a fresh installation and invokes all fourteen CLIs through that copy.
No previous driver is imported. The outer Windows Job contains the worker,
management/build/node processes and nested native descendants. Count its CPU
once, never add inner Job CPU again. Coordinator/launcher CPU outside that Job
is explicitly separate; the total is not silently labelled complete.

Fixed roots are `product-local/context-native-01` for installation/state/driver
data and `software/qualification/context-native-01` for coordinator evidence.
Both must be absent initially. Retain coordinator/worker and launch snapshots.
Launch has exactly schema, pins, product, limits, retained. Pins in order are
Python, coordinator, worker, run_stage.py, supervise.py, Lean executable; the
launch is a seventh supervisor pin. Product rows have exactly
`{relative,path,bytes,sha256}` in ordinal POSIX relative-path order: four root
files API.md/manage.py/build.py/assets-lock.json, direct py/*.py and recursive
regular native/ and assets/ files. Reject reparse points and mismatched files.

Fixed request bytes are UTF-8 `{"op":"test-context-native"}` followed by one
LF byte (`0A` hexadecimal), with no other bytes. Outer limits:
450 seconds wall, 450 CPU seconds, 6144 MiB private commit, eight processes,
65536 bytes each stdout/stderr/event. Combined retained endpoint bounds:
1 GiB, 16384 files, 32768 entries. Endpoint accounting is not a hard transient
filesystem quota.

Always retain actual supervisor CPU and cleanup before interpreting success.
Census both roots only after genuine worker-tree quiescence, also on retained
failures. Uncertain cleanup forbids live-tree census. Count immutable result
and census overhead without self-referential hashes. Worker success is
`PASS_PENDING_DEPENDENCY_AUDIT`; fourteen calls, ten requests, six receiver
stages, eighteen receiver children, one support stage and two support
compilations are necessary, not substitutes for independent outcome review.

## Why this variant

The earlier five-stage X/G proposal saved one source-check stage but introduced
sender code, network fixtures, transport grants and renewed lineage audit. Peer
transfer is already separately qualified; it adds no necessary discrimination
here. The chosen six-stage all-local regression has fewer independent failure
mechanisms and requires no live author pause.

A four-stage G/H test does not establish removal of an unrelated branch because
H retains G dependencies. Dropping final source reuse saves cost but omits the
downstream-work check. Neither is equivalent to the selected bounded claim.
