## Representation and mutation boundaries

`fixture` authenticates historical G's three exact view files and H's exact
1465-byte UTF-8 source before copying. It prefixes only G's raw embedded
manifest with one ASCII space, updates framing/transport commitments, and
retains all object bytes and order. Installed inert wire helpers authenticate
the completed derivative and structurally receive/reconstruct it in a new A
fixture directory. This is explicitly not native acceptance. All derivative
pins are frozen before the first service starts.

After genuine B acquisition, the worker requires different inbound/normalized
manifest bytes and hashes, equal foundation/root/inventories and object bytes,
and exact derivative-bundle reconstruction. B's real replica view and C's real
inbound copy must also reconstruct that exact 298038-byte derivative.

`mutation_file` owns exactly two fault operations. It resolves and rejects
reparse/escaped targets before opening a write handle; the target must equal
the selected new B work path. It saves and fsyncs the original bytes, records
target/parent census and replacement commitment, overwrites only that file,
then verifies the exact one-file census delta. The first target is B's new
acquisition `incoming/manifest.json`; the second is the new replica view's
single bundle. The former becomes normalized presentation; the latter has
only its final byte XOR 1. Neither fault is repaired.

`quarantine` resolves both recorded package directories before moving either.
They must be disjoint proper descendants of B's exact acquisition request
directory, never the work/request root or any ancestor/descendant of the view.
Both fixed destinations must be absent and have that exact existing parent.
It records per-directory and request-root file censuses, moves with `Path.rename`
without deleting or overwriting, and checks each preserved byte plus the exact
renamed request census. The copies remain recoverable in quarantine. No old
allocation path is ever a mutation target, and no ledger is manually edited.

## Outcome interpretation

The worker checks the fixed negative refusals, exact replay without reservation
or preparation, post-quarantine positive B serving, fresh offline C admission,
exact H source hash/root acceptance, distinct H publication and its completed
portable view. Actual stage plans/receipts, source, artifact, publication, view,
events and state observations are retained for independent audit.

There is deliberately no new canonical proof validator. The independent outcome
audit must traverse H's actual proof from its value root and establish both
substantive G applications, authenticate full inventories/closure and verify
all native/canonical replay and source-to-view correspondence. Until that audit,
even a successful worker says `PASS_PENDING_INDEPENDENT_OUTCOME_AUDIT`.

Failure retains the actual charged prefix and all observations collected before
the failed predicate. It does not inspect mutable state after an unauthenticated
lifecycle or restart anything. The enclosing supervisor owns remaining cleanup
and actual aggregate CPU; missing evidence is unknown, not zero. This remains a
same-host regression of custody/native reuse, not independent-host availability,
novel useful growth or release qualification.

## Pre-execution independent-review correction

The first source review identified one blocking harness error before any launch:
successful `build.py` deliberately writes the `run_stage` status envelope to
stderr, whereas the first worker required empty stderr for every preparation
CLI. The corrected worker parses that single bounded build-only JSON envelope
and binds its exact `record` and `status` to the authenticated support-stage
receipt. It also binds build stdout's exact status/receipt pin to the actual
build receipt. Both checks precede either configure command; configure still
requires empty stderr. Arbitrary or additional stderr is not accepted. No
product, workload, grant, allocation or coordinator change was needed, and no
execution was performed during this source correction.
