## Release criterion

A positive speedup against solving locally is **not necessary for usable v1**.
Checked reusable artifacts and decentralized availability can justify overhead.
Require independent nontrivial discovery/reuse/contribution, prospectively
acceptable costs and a reported matched local-library comparison. Transparency
alone cannot justify arbitrary overhead: exceeding the frozen practical envelope
cannot qualify that envelope.

This refines C's gate, not the goal. Comparative improvement is required for
comparative efficiency/optimization claims, not a useful bounded capability.
One pair establishes neither population speedup, scalability, exponential growth
nor v1's deployment/reliability requirements. Heuristics remain allowed.

## Selected workload: certified chunked reduction

For arbitrary `A : Type u`, `op : A -> A -> A`, `e : A`, assume associativity
and both unit laws, **not commutativity**. Define `F xs` as the right fold of
`op` with base `e`. Prove, for every `chunks : List (List A)`:

```text
F (List.flatten chunks) = F (List.map F chunks).
```

This certifies chunk-summary computation, requiring induction and algebra rather
than mere reduction. Seeded List recursion, map/flatten/append and equality suffice;
`F` can use `List.rec` in an ordinary noncomputable definition. No new inductive,
tactic or API is needed. Fragment fit is source-supported, not executed conformance.

Prepare one independent producer's portable append/fold law, not the final theorem,
among six existing heterogeneous distractors. Freeze bytes, nonsuggestive order and
catalog. Both consumers receive identical checked vocabulary for `F` and the target;
its ID is vocabulary, not a result hint. Supply no shared-lemma name, ID, position,
proof or selection instructions.
