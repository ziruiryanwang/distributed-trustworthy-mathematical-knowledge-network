# Equal-service comparison of routing ownership choices

Date: 2026-09-20. Author: `placement_equal_service_comparison`. Status: **HELD complete source for independent review; no protocol selection**. Conceptual arithmetic and conditional arguments only. No implementation, executable model, benchmark, extraction or Lean execution has occurred. The exact SG binding remains unallocated. This comparison neither changes frozen F/G/H/O/Q nor establishes sustained useful growth.

## Result and decision boundary

Stable placement authority can eliminate remote ownership transfers caused solely by local index compaction. It can also consolidate multiple old owner groups occupying the same holders. Neither improvement is universal: retaining old owner scopes already permits zero remote mutations for a pure local layout rewrite; dispersed placements give stable groups no renewal-call saving; the candidate's coarse invalidation and repeated full scans can make its CPU/I/O cost worse than smaller scoped summaries. Adoption itself requires real old-row removal and new insertion, with overlap stock and per-holder gaps.

Consequently, **the candidate is a possible routing-amplification optimization, not yet an operability improvement established across resource dimensions**. A useful decision must compare complete finite service offers and all-prefix admission, not only theorem counts, final group counts or a successful two-member repair. This note gives the comparison equations, concrete adverse regimes and an evidence ledger for that decision. It does not select a winner by assigning invented costs to missing native or control work.

## Fix the service before counting its cost

An equal-service case is one finite owner-authorized interval and initial physical state, with the following common inputs for every alternative:

- Same provider/foundation/extractor, exact selected targets, descriptor/replay identities, native acceptance obligations and actual public posting relation. Different proofs, foundations or missing target postings are not equivalent service.
- Same retained native closures, custody pins, protection/disclosure duties, client native rechecking, query service, useful-query cohort and paid reply/acquisition opportunities. Candidate-only metadata service is a different comparison, not a cheap substitute for qualified index provision.
- Same selected `(key, cell, holder)` incidences, current signed anchors, intended copy/path duties, actual partial/uncertain placements and holder willingness. An alternative may propose relocation only as an additional charged transition; it cannot silently choose denser holders.
- Same incoming mathematical cohort and admission opportunities; same authoritative support changes, anchor withdrawals, holder churn, offered burst schedule and primitive service supplies. Protocol-specific work caused by these events is an output, not held equal by definition.
- Same explicit bounds for publication delay, permitted transition gaps, query completion, current-source-coverage degradation and incident repair. A policy that publishes fewer targets or pauses arrivals longer must report that change, not claim equal service from its smaller bill.
- Same actual resource owners and grants, finite count/byte caps, execution slots, control-body ceilings, deadline assumptions and treatment of failed calls. Unused resources at another provider are not transferable by arithmetic.

There are several noninterchangeable service observables:

| Observable | What must remain separately reported |
|---|---|
| Mathematical acceptance | Complete local native result under the exact adopted Lean-based foundation; a route response is not acceptance |
| Selected FIND relation | Every chosen target's exact current posting membership and snapshot semantics |
| Actual holder-row continuity | Whether a named row and its containing lease stay eligible at a named holder, including migration gaps |
| Current source coverage | Whether current support, owner, copy and path guards justify the source's present coverage assertion |
| Reader reachability and checked reuse | Actual reader/holder overlap, markers, provider service, discovery budget, acquisition and native application |

SG's incident theorem promises only designated-survivor row/lease continuity under its premises. Its coarse fence can simultaneously make current source coverage UNKNOWN for unrelated valid survivors. A comparison demanding continuously asserted current coverage cannot treat that theorem as satisfying the demand. Equally, O's TRANSFERRING status is not proof that every real copy is absent. For each stated service target, record both actual gaps and assertion-degraded intervals; do not substitute one for the other.

There is no global current-state oracle in this definition. Initial state, event inputs and outcomes are finite scoped observations with stated assumptions and ages. The purpose of fixing them is a falsifiable comparison, not a mandatory network workload or a shared mathematical task list.

## Exact group incidence, not a small-holder assumption

Fix a settled observation cut. Let K be the distinct owned provider keys, with `U = |K|`. Let P be the selected finite row incidence set; a row is an exact `(key, cell, holder)` tuple. Write `R = |P|`. In the simple selected depth-zero case with exactly r distinct chosen holders per key, `R = rU`. Actual deep/partial/replacement rows are a separate incidence set, never inferred to be at most rU.

For any owner assignment o, define

`P[h,o] = {x in P : holder(x)=h and owner(key(x))=o}`,

`m[h,o] = |P[h,o]|`, and `H_o = {h : m[h,o] > 0}`.

Under the applicable at-most-one-ACTIVE-group per exact holder/owner binding, the settled selected nonempty group count is exactly

`G(o) = sum_o |H_o| = sum_h |{o : m[h,o] > 0}|`.

For RETAIN, o names its old immutable owner scopes. For NORMALIZE it names the current settled owner scopes after each particular completed step. For SG it names the actual admitted A generations. UNGROUPED has R independently leased selected rows rather than G groups. None of these equalities includes empty groups, partial placements or old generations.

If each SG authority is a union of complete old key-owner classes and every resulting per-holder group fits, mapping every old owner to its A gives a surjection from occupied old groups onto occupied SG groups at each holder. Therefore

`G_SG <= G_old`.

Equality is possible. A strict saving requires at least one holder to contain rows from two old owner classes assigned to the same A. Arbitrary capacity-driven repartitioning need not be a coarsening, so the inequality is not a theorem about every deployment using SG. It also gives no byte/CPU inequality.

For one namespace with U owned keys and r selected copies, `G <= min(M,rU)` is an upper bound, where M is the number of actually usable distinct holders in that incidence. Across namespaces the valid bound is `sum_a min(M_a,R_a)`, not one global min. Exact incidence is stronger than either bound. “Many agents” says nothing about whether these selected rows share holders.

There are useful lower bounds too. If a holder h can put at most c_h of these particular rows into one group under its effective member/byte cap, then every compatible grouped placement satisfies

`G >= sum_{h with rows} ceil(R_h / c_h)`.

This is a necessary bound, not a sufficient partition/construction theorem. Canonical bytes, foundation/authority separation, aggregate holder row caps and immutable owner restrictions can force more groups or refusal. Since c_h is finite, stable authority cannot promise a fixed number of groups for arbitrarily growing retained row stock.

### Ideal occupancy is optional sensitivity, not the admission rule

Under H's explicit idealization that each distinct key independently chooses r distinct uniform holders among M, an owner with u keys has

`E[G(u)] = M * (1 - (1-r/M)^u)`.

Sum this expression over actual disjoint key-owner classes to estimate RETAIN/NORMALIZE; use the chosen A classes for SG. In the dispersed regime `ru << M`, the expectation is close to ru for every alternative, so little grouping gain is available. At high occupancy it approaches M for each owner and consolidation can help. Independence/uniformity is a model premise, not a property proved for our routing rule, and cannot replace per-holder admission, partial-state accounting or a service calendar.

## Calls, row mutations and encoded batches are different quantities

Define an owner-transfer event j by its exact actual row set X_j, with `x_j = |X_j|`. Count repeated movement of the same row in successive carries as distinct events. If every old-owned row is successfully transferred to a different group owner at the same cell/holder, the event requires exactly `2*x_j` successful row mutations in the prescribed DROP-before-PUT plan. This is a property of that selected transfer recipe, not a universal mutation lower bound over hypothetical CLOSE-all-and-repopulate alternatives. Such a different recipe needs separate authority, remaining-member treatment, peak stock and service-gap admission; it is not substituted here. Necessary OPEN/CLOSE, lookup, retries, result delivery and history work are additional. A local layout rewrite with unchanged owner assignment has `x_j=0`, regardless of which grouping policy is used.

For an operation type and exact `(holder, group, coherent state)` lane, let B be the actual number of bounded requests in its admitted sequence. Every request must satisfy both at most 64 mutations and at most 64 KiB including all headers. A candidate SG header differs from the old one; identical row counts do not imply identical B. For n mutations to one lane:

`ceil(n/64) <= B <= n`

is a valid coarse bracket **only when all singleton requests fit, the plan permits singleton progress, and no extra retries are included**. The left side is a lower bound, not an achieved packing. Sum the lower bounds separately over old DROP lanes and new PUT lanes; one cannot pack two holders or group owners into a single call. Expected roots/versions, per-key uniqueness, admission timing and one active O handoff can further restrict aggregation. This comparison uses O's specified row-at-a-time path as the conservative supplied plan; potential wider old-profile batching is a conditional alternative, not a hidden improvement to frozen O's calendar.

For a completed transfer plan, write

`Calls_transfer = B_drop + B_put + O_open + C_close + F_failure + S_settlement + D_delivery + L_lookup + M_marker`.

Terms denote actual disjoint categories of ServiceCall occurrences or other separately specified service actions under a single consistent counting convention. If a selected parent envelope already includes delivery in its per-call cost, do not add it again. The source plan must declare its convention. A single abstract mutation is not automatically a complete paid network interaction. CLOSE is required in the explicit close-empty-parent strategy; a strategy waiting for actual expiry/reclamation may omit that call but keeps its different stock, timing and service obligations.

NORMALIZE has these costs for every moved actual parent-owned row. SG has zero *compaction-caused* transfer mutations only after paid adoption and only while C, anchors, owners, paths and relevant guards remain unchanged. RETAIN and UNGROUPED likewise have zero route-owner movement for an exact local layout rewrite. New keys, actual anchor replacement, holder/path churn and capacity-driven namespace transfers remain separate events for every alternative.

In particular, a key whose eligible replacement anchor lies outside its old immutable owner scope can require a real transfer under RETAIN/NORMALIZE. SG may replace that ad within the same A, and UNGROUPED may replace its own row, when all their actual support and resource guards hold. This possible incident-work saving is separate from logical compaction and must be counted from the same supplied anchor-change event list. It is not assumed in the no-anchor-change equations.

### Renewal cost follows actual event times

Let E_g be the successful renewal occurrences actually scheduled for continuing active group g during the interval. The exact grouped renewal count is `sum_g |E_g|`; for ungrouped rows it is `sum_x |E_x|`. A settled unchanged population renewed f times has counts `fG` versus `fR`. Active-empty or partial groups renewed for real continuing obligations add their own events; expired or closed records retain stock but are not automatically renewed.

With arrivals between passes, sum the group counts **at each pass**, plus actual off-pass occurrences. Do not multiply the final population by the pass count and call it actual work. Q's first-pass/arrivals/second-pass distinction is precisely this issue. Either actual event counting or a declared conservative final-stock reservation can be used, but the latter is an admission bound rather than observed expenditure. Two renewal passes do **not** imply two complete source support scans: a coherent complete summary can be reused or paid-rebound under its exact unchanged guards. Count actual dirty intervals and scan attempts separately for each policy.

Grouping reduces repeated operation overhead; the same retained row bytes still incur real extension byte-time. Neither grouped nor ungrouped renewal renews ancestor markers, refreshes useful holder overlap, supplies a missing native proof, or creates a query-serving grant. Per-group serial contention can also make the same call total miss a deadline.

## Support scans can outweigh call savings

For each actual SG full-scan attempt j on group g, use its declared finite inputs

`(e_j, i_j, m_j, d_j, p_j, b_j)`

with exactly the meanings in the held source: traversed inventory records, total token/posting visits, actual members, complete dependency-record visits, physical index-node visits and actual bytes read including repetition. The explicit fallback budget includes

`Qscan_j <= Qdecode(b_j) + Qmap(2*m_j+1) + Qentry(e_j) + Qposting(i_j,p_j) + Qdependency(d_j) + Qcompare(m_j*e_j+32*m_j) + Qcommit_j`.

This is a supplied conservative implementation cost envelope, not measured running time. Its comparison count is a bound; a search finding an early anchor can do less work. Byte size, hash/signature costs and missing required native revalidation are not implied by record counts. Native revalidation is an additional separately admitted operation, not included for free in Qscan.

For one attempt for every group under a common authority with the same inventory size e, the entry-traversal budgets sum to `G*e`, while the linear anchor-search comparison budgets sum to

`e * sum_g m_g`.

In the settled selected-row domain `sum_g m_g = R`, so the corresponding terms are `G*e` **and** `R*e`, plus at most `32R` token comparisons and the actual map/dependency/posting/byte terms. Reducing G leaves the second term unchanged at fixed e and R. With fixed positive tokens/copies per target and one ever-growing inventory e proportional to N, this particular fallback has a quadratic **worst-case budget term**, not merely linear group-renewal work. This is not a lower bound on every correct support algorithm and is not evidence of measured quadratic CPU.

If D guarded publication changes each require another complete group sweep at the promised service level, sum the actual per-change terms. A crude stationary budget is `D*(G*e + R*e + 32R)` for these visit/comparison classes. An incident with classification and supported-result scans contributes both actual passes, with their different postsettlement/result memberships. Discarded scans and later restarts count too. The valid calculation enumerates scan attempts; D is not “one scan per theorem” by definition.

The SG coarse fence advances on selected-entry addition. Even a new target using only already-owned tokens can cause revalidation of many unchanged groups under the baseline. Several additions can precede one later scan when all intervening dirty status and publication/renewal deadlines remain lawful, but this batches visibility work and changes delay/temporary status. It is not a free reduction in D under an unchanged service offer. An incident can also force provider-wide invalidation when affected-authority completeness is unavailable.

### Do not impose SG's largest inventory on its competitors

F already permits exact guarded eligibility-summary reuse. G/H old-group support lies inside the group's exact immutable owner scope; unrelated scopes need not enter its anchor search merely because they share a provider. A legitimate scoped fallback may inspect an exact finite inventory e_s for that owner, provided it also covers all required current guards, membership and actual anchor dependencies. For such a **separately stipulated bounded algorithm**, the analogous comparison budget is

`sum_s [G_s*e_s + R_s*e_s + 32R_s]`,

plus its actual maps, dependencies, bytes and summary work. This does not assert that an efficient old implementation already exists or that all incidents stay local. Shared native dependencies can dirty many scopes; retaining scopes requires their own paid exact state. Nevertheless, assigning e_global to every old group without necessity would be a strawman.

Similarly, unchanged old summaries need not be discarded solely because another scope's selected target was added, if their complete exact guard dependencies justify reuse. This is a conditional permitted optimization, not permission to ignore missed incidents or an assertion of zero guard-check work. SG's deliberately coarse policy can invalidate a larger set than such a justified scoped scheme.

UNGROUPED has per-row current-anchor support obligations but no all-members-renewal predicate. Its actual source summary/index design must be supplied. It may use independently justified per-anchor/dependency checks; it may not claim those checks or their dependency lookup free. An invalid row need not block unrelated row renewal, although shared native incidents can affect both.

Splitting SG into several A namespaces can change both group occupancy and scan dimensions. A smaller `e_a` is lawful only if its exact named semantic inventory and owner/anchor completeness are established. Namespace names alone do not filter a provider-wide C or establish an index. Extra namespaces also add group/authority records, lanes, summaries and potentially paid transfers. No free common-C scan, lookup dictionary, resident cache or cross-group scan reuse is imported into this candidate. Such a separately specified mechanism could remove the pessimistic terms and would need its own preparation, retention, invalidation and complete-input proof.

## Two exact incidence regimes at meaningful finite size

These are arithmetic stress regimes, **not native Lean fixtures or successful supplied operating cases**. Both use 480 selected targets, 24 distinct twenty-target old owner scopes, 32 fresh distinct keys per target, r=4, U=15,360 and R=61,440 selected depth-zero rows. Each old scope owns 640 keys and 2,560 selected rows. The all-fresh 32-token assumption is an allowed resource pattern, not evidence that this native corpus exists. Adopt the same exact hypothetical targets and service assumptions across alternatives within a regime.

### Dense holder overlap

Declare an incidence in which every old scope has exactly ten rows at each of the same 256 holders. This is combinatorially consistent: label one scope's distinct keys j=0 through 639 and put key j at holders `h = 4*(j mod 64)+c`, for c=0,1,2,3. Each key has four different holders; each of the 256 holders receives ten rows, giving `640*4 = 256*10`. Repeat for the 24 disjoint key classes. This proves only the incidence counts are constructible. It does not establish that the actual key and NodeID hashes have these nearest responsive holders under F, that they are willing, or that matching native targets exist. It is not a claim that provider B has a 256-holder bound. Other network participants and holders can be arbitrarily numerous.

One SG authority that fits these rows has 256 groups with 240 rows each. A settled H/O normalization of all 480 targets has sizes 256, 128, 64 and 32; if the chosen per-target incidence is also balanced within those actual final blocks, every one of these four scopes occupies all 256 holders. That extra balance is a stated premise; old scope-level balance alone does not imply it.

| Policy at its named settled cut | Selected nonempty groups / independent row leases | Calls for two unchanged renewal passes |
|---|---:|---:|
| RETAIN 24 old scopes | 6,144 groups | 12,288 |
| NORMALIZE final 256/128/64/32 scopes, under the extra block-balance premise | 1,024 groups | 2,048 |
| UNGROUPED | 61,440 row leases | 122,880 |
| SG one authority | 256 groups | 512 |

These counts exclude adoption, normalizing work, old/empty/uncertain groups, markers, native service and support scans. SG saves 11,776 renewal calls per such two-pass interval against RETAIN and 1,536 against the named completed NORMALIZE state. NORMALIZE must pay its actual path to that state; SG must pay adoption. Comparing SG to 24 old scopes forever while omitting O's later lower group count would overstate its continuing advantage.

At a dense holder the shown provider contributes 240 selected rows, 24 old nonempty groups or one SG group; at a dispersed holder it contributes one row/group. These cardinalities do not themselves exceed F's example holder limits of 65,536 aggregate ads, 32,768 group records and 65,536 members/group **if sufficient unused aggregate capacity is actually supplied**. Other providers' rows, marker/cell records, histories and snapshots share that capacity. All byte, control, authentication, connection, lease and service limits still require a complete admission; none is supplied by these counts.

For a single SG full support sweep with e=480, its fallback allows `G*e = 122,880` inventory-record visits and up to `R*e = 29,491,200` anchor-search entry comparisons, before at most 1,966,080 token comparisons and the other scan dimensions. A stipulated old scoped linear-search fallback with e_s=20 has the same 122,880 inventory-record-visit budget and only 1,228,800 anchor-search comparisons for all 24 old scopes. Thus a 24-fold group-count reduction does **not** yield a 24-fold scan-work reduction; this chosen anchor-search budget becomes 24 times larger. Actual early hits and nonuniform record costs can change actual work, so these are transparent sufficient envelopes, not measured CPU ratios.

This dense case therefore supports a real call-saving opportunity and a simultaneous CPU/I/O counterpressure. It does not establish joint affordability merely because all shown group cardinalities fit one count cap.

### Dispersed holders

Instead declare all 61,440 selected rows to have distinct holders, with the ordinary requirement of four different holders per key satisfied. Every occupied group is a singleton under any owner partition. Then

`G_RETAIN = G_NORMALIZE = G_SG = R = 61,440`.

All grouped choices need 122,880 calls for two unchanged renewal passes, the same count as independently renewing the ungrouped rows. Changing scope organization does not reduce these calls. SG can still eliminate future compaction transfers relative to NORMALIZE, but cannot claim a renewal saving relative to RETAIN or UNGROUPED here.

With e=480, the SG full-sweep inventory budget is 29,491,200 record visits and its anchor-search budget is another 29,491,200 entry comparisons; `m_g=1` does not make the provider-wide traversal constant. Under the same separately stipulated old e_s=20 fallback, both corresponding budgets are 1,228,800. These are comparisons of the stipulated algorithms' conservative scan envelopes, not proofs of realized CPU ordering, total-maintenance ordering or native support fit. A larger upper bound can coexist with a smaller actual cost. The figures therefore expose admission pressure and block an inference of uniform maintenance savings from group counts alone; they do not independently refute actual total-cost dominance. The later fixed-dispersed RETAIN countercase in “Break-even conditions” instead supplies an exact call-axis comparison: equal renewal counts, zero RETAIN pure-layout transfer, and positive SG adoption calls under its stated service assumptions. Neither argument contradicts the zero-remote-compaction proposition.

Q's B slot has no small-holder premise. This dispersed regime is why its 480-target endpoint cannot be treated as if it automatically coalesces. Its continuing renewal pressure remains even under perfect local compaction. A real choice to seek overlapping replacement holders would introduce lookup, route-overlap, migration, capacity and service-gap costs, not revise this fixed-incidence comparison.

The source cardinalities are compatible with the **enlarged H/B count ceilings** for this selected starting state: 480<4,096 targets, 15,360<33,000 owned keys, 61,440<264,000 charged-row ceiling, and 61,440<400,000 group ceiling, with 24<64 charged old scope records and 24<32 pending inputs. Compatibility of these selected counts does not pay for transients or establish joint byte/work fit. The dispersed count exceeds the default F source's 32,768 total-group cap. SG cannot silently inherit a new binding, a namespace allocation or B's illustrative bytes-per-old-group/row merely because the comparison uses the same numeric count limits; actual SG representation and all lifecycle state need explicit admission.

## Adoption is a finite migration, not an in-place reinterpretation

Begin each adoption comparison from the **same old-mode actual state**, including every extra, partial, uncertain, expired-unreclaimed and snapshot-held allocation. SG and UNGROUPED must obtain their own exact supported codecs and paid authority. Creating an empty destination group does not transfer one old row; changing a source table label changes no remote owner.

For an explicit clean, depth-zero, failure-free adoption of R selected old-group rows to SG, with fresh destination groups and an explicit CLOSE of each emptied old group, the route-call skeleton is

`B_drop_old + B_put_SG + G_SG_open + G_old_close`.

Successful row mutations number exactly 2R for this DROP-before-PUT strategy. A group is counted in G_old_close only when all of its actual owned rows have lawfully moved or been removed and its empty state is coherent; transferring a selected subset does not permit closing unrelated residual rows. This is not the complete adoption budget: add source construction, guard/support jobs, borrower invalidation, inherited action settlement, lease events during the actual schedule, disclosure, replies, new binding state, all old/new histories and aftercare. If actual extras exist, enumerate their chosen lawful migration or retirement disposition; R alone no longer bounds the work or stock.

In the dense stress regime, the per-lane 64-count ceiling gives lower bounds of 6,144 old DROP batches and 1,024 SG PUT batches (`256*ceil(240/64)`). These are optimistic count-only bounds; actual SG encoding may require more. Under the explicit open/close strategy the resulting count-only skeleton lower bound is 13,568 calls. The singleton skeleton is 129,280 calls (`2*61,440 + 256 + 6,144`) if each single request fits. Actual execution may cost more because the omitted service/settlement categories are real. These figures are **not** a complete interval grant or a claim that an implementation can pack the lower bound.

In the dispersed regime each source and destination lane has one row. The same explicit strategy uses 245,760 skeleton calls (`4*61,440`) before other costs: one DROP, PUT, OPEN and CLOSE per row. There is no subsequent renewal-call saving against RETAIN. Amortization, if any, must come from avoided future actual NORMALIZE transfers or another separately demonstrated resource improvement. Conversion of grouped rows to UNGROUPED similarly requires old removal plus a base PUT per row; it saves SG OPEN/group metadata but adopts independently renewed leases instead.

The inequalities cannot finance themselves by future savings. Before the first effect, admit the entire chosen prefix and its aftercare from current resources. A plan may stop at real bounded release barriers and later readmit; it must carry all spent work and unfinished custody/action/owner obligations. Forecast closure, expiry or source-side deletion does not release remote physical stock.

### Migration changes the service trace

At a particular same-cell holder, old DROP must precede new PUT. The migration therefore cannot satisfy a promise that that exact selected row remains continuously served there through the transfer. If that is the required service, this adoption path is infeasible. Other copies can preserve a separately stated weaker reader/redundancy service only if their actual support, leases, paths and reader overlap remain supplied; four identities alone do not prove it.

A lawful service offer may admit explicit per-holder gaps, a sequential-transfer policy preserving a specified number of other current copies, and a finite allowed TRANSFERRING interval. Both SG adoption and O migration must be tested against that same offer and actual calendars. If DROP settles but PUT fails, preserve the missing copy and all paid histories; there is no free rollback. A lost reply retains uncertainty and may occupy the strict lane beyond a deadline.

Old and SG modes cannot coexist as two live owners of the same row. Their **physical retained generations** can coexist, and routinely do while maps, snapshots, outcomes and old row bytes await lawful reclamation. Peak stock is not the maximum of old-final and new-final stocks.

## Complete work and stock comparison

For policy v and a fixed offered interval T, use a vector of additive work resources, at least calls, source CPU, each holder's CPU/service, traffic, storage I/O and paid retention byte-time:

`W_v(T) = W_common(T) + W_adopt,v + W_arrival,v + W_renew,v + W_support,v + W_reorganize,v + W_incident,v + W_churn,v + W_history,v`.

Categories must be disjoint. For example, incident scans belong either to W_support with an incident label or to W_incident, not both. Arrival native checking may lie in W_common only when the exact same admitted cohort, retained support and native work are truly shared across policies. Actual support failures or differing admitted cohorts are observable outcomes, not a cancellation trick. W_common is included in every admission test even when algebraically subtracted to explain a difference.

At every actual owner and every prefix, separately check peak stock and deadlines. A sufficient conservative stock test from measured cut b is

`Stock_d(b) + admitted_positive_peak_d(after b through prefix) <= Cap_d`,

with forecast release credits zero. A later actual release can define a new measured base; it cannot also be subtracted from that new base. Work spent remains spent across that recut. For each real grant:

`spent + disjoint_unspent_incumbent_reserves + disjoint_unspent_optional_reserves + disjoint_unspent_aftercare_reserves <= grant`.

This is Q's residual-accounting discipline, not an extra SG budget. It applies to every resource axis, source and foreign holder. A global sum below a network total is not per-owner admission.

For groups, keep disjoint lifecycle inventories, e.g. actual ACTIVE nonempty, ACTIVE empty, closed/expired-unreclaimed and unresolved opening/other reservations whose category is not already counted. Partial/extra rows contribute to the actual nonempty groups that own them. Preserve exact generation identities so an uncertain allocation is conservatively represented once in the selected accounting scheme, not accidentally counted as both known active and a second identical reservation. Group-count bounds for selected P describe only a subset of this stock.

The relevant physical inventory includes C/R layouts, old readers and snapshots, scope/authority records, current/old membership maps, actual row generations, source summaries, reverse/borrower records, action outcomes, invocation histories, repair cursors, namespace high-water/nonreuse state, native closures, custody pins and export/protection references. An old immutable owner becoming logically unnecessary does not erase any of these actual owners. SG can avoid some future scope-group generations, but retains its own new authority and exact support state. No constant bytes-per-group estimate is selected here.

Incidents add a further feasibility condition. For each SG group repair, the conservative service bound includes old-effect settlement, two complete scans, actual cleanup and guarded renewal. The postsettlement membership must exhaustively partition into fully supported retained members and explicitly authorized removals; UNKNOWN_SUPPORT needs a separately admitted branch. Clock margins use the persisted **original effectful dispatch occurrence** and continuous monotonic basis, never the timestamp of a later replay retrieving an old result. Queue-prefix deadlines, invalidation restarts and current-source-coverage degradation must all be included. A cheap mean call rate cannot discharge these finite deadlines.

## Break-even conditions, with no invented scalar exchange rate

First require that both compared policies satisfy the **same** service offer and all their stock, deadline and per-owner resource caps. If one does not, that operating case fails for that policy; a smaller bill for missing service is not a win.

For an additive work axis d, define the complete finite-interval difference

`Delta_d(T) = W_baseline,d(T) - W_SG,d(T)`.

Positive Delta means savings on that axis. A Pareto improvement requires nonnegative Delta on every relevant work axis, at least one strict improvement, no worse promised service, and admitted peaks/deadlines. More usually there is a tradeoff. An owner may choose declared local weights or resource prices for a heuristic decision, but CPU-seconds, bytes and calls are not commensurate without that explicit choice. Even a favorable weighted sum cannot legalize an exceeded hard cap.

To expose the call axis under a clean stationary scenario, let a be the *complete extra SG adoption calls*, f the number of unchanged renewal passes per interval, `G_b-G_s` the actual group-count saving, `c_avoid` actual compaction-transfer calls avoided per interval, and `c_extra` SG-specific extra recurring calls including additional repair/renewal behavior. Suppose all these counts are stable and all other calls cancel under the fixed service. After n such intervals the call break-even condition is

`n * [f*(G_b-G_s) + c_avoid - c_extra] >= a`.

If the bracket is nonpositive and a>0, there is no finite call amortization under those assumptions. If positive, `ceil(a / bracket)` intervals is a call-only crossover, not a complete feasibility theorem. Use actual time-varying sums when arrivals, O consolidation or churn change the counts. Scan CPU/I/O can make the corresponding resource-axis crossover absent even when calls cross over quickly. The adoption skeleton numbers above are not legitimate substitutes for complete a.

Against RETAIN, c_avoid for pure local layout compaction is zero: RETAIN already needs no remote transfer for that change. Against NORMALIZE it equals only the actually avoided paid transfer occurrences; claims based on a logarithmic upper allowance are conservative opportunity estimates, not evidence that those calls would all occur. Against UNGROUPED the renewal term uses R instead of G_b, but costs and service for independent row updates/support must also be compared.

A particularly clear defeating case is fixed dispersed placements, no future owner-consolidation obligation, no anchor/holder changes, and already-supported RETAIN groups. Here group renewals are equal, RETAIN pure local compaction has zero remote cost, and SG adoption has positive cost. SG cannot establish a call advantage in this interval. Its larger coarse inventory may additionally increase support work. This does not make stable authority useless in dense, repeatedly reorganized or external-anchor-change workloads; it delineates its domain.

## Finite capacity and recurring lower bounds survive every choice

- At least R selected row records must physically exist somewhere to provide the chosen row service, with actual signed bytes, per-holder state and retained-byte-time. A common token shares one provider row across targets, but different providers' ads and actual replica copies are not the same allocation.
- With finite maximum group member/byte capacity, increasing rows eventually increases required groups, providers, holder capacity or explicit noncoverage. Renaming namespaces does not create supply. A single authority's at-most-one-ACTIVE-group per holder is a constraint, not a free extra group when full.
- Under the inherited finite-lease model, the maximum lease is 48 hours of the issuing holder's **own continuous lease clock**. If one group remains continuously ACTIVE for H elapsed hours in that same holder-clock domain, its number N of successful extending renewals satisfies the necessary bound `N >= H/48 - 1`, allowing the initial lease and finite endpoints. Thus the asymptotic lower frequency is one extension per 48 holder-hours, not per 48 source or universal wall-clock hours. Without a positive lower bound on that holder clock's progress relative to a chosen common clock, no fixed positive renewal-rate lower bound in the common clock follows; SG's holder-speed upper bound alone is insufficient. No such conversion is used here. The named twice-per-interval pass fixtures count explicitly stipulated occurrences, not a universal minimum. This necessary condition is specific to the inherited finite-lease contract, not all decentralized indexes. Markers and other duties remain additional, and grouping never makes retained byte-time zero.
- A finite RETAIN scope cap can prevent new novel-key scopes even when no pure compaction transfer is needed. One can pay consolidation, separately supply more actual scope capacity, use a different admitted role or report nonselection; none is implicit. SG still has finite C/target/token/row/authority/metadata caps. Removing one owner-scope cap does not remove those others.
- Native closure checking, proof custody and query/application work can dominate every metadata choice. Independent index slots may repeat real core storage/checking; no routing grouping scheme proves that it is cheap. Downloadable decentralized software is not free physical service.
- An infinite offered stream can exceed incumbent maintenance plus finite positive arrival/repair work even if reorganization is eliminated. Continuing useful growth requires actual future resources and useful checked reuse, not just a safe refusal rule or a growing hash count.

These are necessary engineering conditions, not a universal theorem that mathematics has fixed bytes per theorem. Demonstrated compression, shared evidence and better indexes can change constants or representations, but their actual algorithms and retained-state costs must enter the comparison.

The immediate useful next decision is whether to refine SG's support-scan mechanism or reject it for operating cases where its current repeated global fallback dominates. A new mechanism should target that particular term and preserve current guards and paid state; another favorable tiny routing trace would not settle it. Alternatively, a declared dense workload with rare dirty events might justify retaining the simple fallback, but requires full costs rather than the word “rare.” Neither path should silently replace current selected H/O/Q before the exact consumer and resource changes are reviewed.
