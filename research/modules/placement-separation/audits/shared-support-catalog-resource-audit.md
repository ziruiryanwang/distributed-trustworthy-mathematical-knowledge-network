## SSC-RES-001: smaller scoped catalogs lack an admitted current-layout domain

**Disposition: CLOSED on the 37,431-byte repaired cut; bounded applicability/resource finding.** Root raised this seam during the initial review, and both independent reviewers checked it. It is one shared root-origin issue, not duplicate independent discoveries. The following paragraphs preserve the initial finding against the 35,063-byte cut; the closure below names the actual repair.

The source admits a catalog for exact semantic inventory C and **the exact current physical FIND layout R0 implementing it**. Preparation establishes both directions: every expected selected posting exists and every realized current posting belongs to the declared relation. This properly prevents an inventory-only table from impersonating complete physical publication.

The same source says an old-scope catalog can use its own complete exact smaller inventory, then gives twenty-entry catalogs for 24 old scopes. The necessary relationship between a smaller C_s and the current provider-wide R0 is not specified. An immutable owner scope supplies eligibility membership; it is not by itself a proved projection of the current physical publication relation.

Concrete separating input: current R0 realizes selected descriptor x in owner scope S and selected descriptor y outside S. A catalog using C_S = {x} with R0 fails the source's reverse-inclusion check, because R0 also contains y. Replacing R0 by an old retained scope run R_S does not establish that this run is the current authoritative relation or that present global FIND still realizes exactly the required scoped projection. Equal bytes or a scope name does not establish that connection. A paid full physical traversal can inspect more records than the twenty logical inventory entries; excluding that work from locator arithmetic is permissible only if it remains explicitly charged elsewhere.

The flaw is **not** in the arithmetic and does **not** prove smaller scoped checking impossible. Old FULL_FEATURE can lawfully have more local support predicates than SG, and the comparison explicitly stipulates its old scoped fallback separately. The gap is that this particular candidate has not yet supplied an admitted scoped-input construction under its own stronger complete-layout equality rule.

Minimum closure condition: state unambiguously that the 371,496 figure is only conditional locator arithmetic until exact current scoped inputs and all physical projection/traversal/currentness work are separately established; do not represent smaller scoped catalogs as already justified by this recipe. Alternatively, a separately reviewed exact scoped-input contract could establish that relationship and account for its work, stock and guards. This audit does not design or select that extension. With that boundary explicit, both modes may be investigated fairly. This issue cannot justify forcing a competitor to use a needlessly global anchor-search domain, nor can the competitor receive a free current-layout projection.

## Independent arithmetic and algorithm checks

Let n be the coherent current-row count; e includes every traversed inventory record, including excluded/history/tombstones. The source requires `0 <= n <= e`. Its `L(n) = ceil(log2(max(1,n)))` and `H(n) = ceil(log2(n+1))` give conservative bounds for the named resident two-buffer merge sort and a conventional halving lower-bound search.

- At most `n*L(n)` ordering comparisons suffice for the stated merge-sort envelope. At most `2*n*L(n)` sorting-pass **slot movements**, counting reads plus writes, is consistent with copying at most n slots into the other buffer on each pass. This is not a byte count: multiply slot traffic by admitted slot width and separately charge comparison/key reads, initial emission, decoding, duplicate checking and final validation.
- At most `max(0,n-1)` adjacent key comparisons detect duplicate sorted keys. Rejecting identical current duplicates is a stricter input representation rule, not a free deduplication algorithm.
- A lower-bound search uses at most H(n) ordering comparisons; an existing candidate requires up to one further equality comparison. For n=0 there are no ordering comparisons and no existing candidate. `R*(H(n)+1)` remains a conservative, possibly loose allowance; it does not require reading a nonexistent slot.
- The maximum `2*Kmax` key bytes inspected per comparison does not pay payload reads, offsets, slot access or token/dependency bytes. The source explicitly charges those separately. It also requires resident arrays and supplied primitive bounds; it makes no logarithmic disk-I/O assertion.
- Sorting/checking the exact expected-versus-actual posting sets has its own bound. The locator-row sort is not sufficient payment for it, and the source says so explicitly.

## Storage ownership, pins and finite lifetime

The optional RAM-backed branch admits at least two `n*w` sort-slot buffers, the actual payload arena, complete input and layout pins, posting-set scratch, group maps, summaries and every simultaneous old/current/building/invalid generation. READY may eventually use one slot array; that eventual size is not the build's peak. A slot offset is not ownership of its backing bytes. Exact arena/catalog generations and checked offsets prevent recycled addresses from becoming retained evidence.

The source requires counting disjoint physical allocations once per owner/resource axis. Two catalog references to one real immutable arena therefore retain one arena's bytes plus two actual reference records; two physically copied arenas retain both allocations. Both accidental double-counting and false zero-cost aliasing are prohibited. Catalog retirement does not release independent native custody or another reader's pin. Pointer replacement, expiry and planned eviction are not physical reclamation.

At every resource prefix, Q's inherited discipline is retained: actual spent work plus mutually disjoint unspent reserves must fit the current grant; actual charged stock plus positive admitted overlap must fit each cap. There is no future-release credit. A lawful completed release can support a new measured stock origin but cannot also be deducted from that new origin, and never resets spent history.

Build and cohort metadata, lifecycle records and current/invalid/retiring generations remain finite under joint caps. A full queue cannot prevent authoritative invalidation. The bounded coarse dirty/degraded state permits refusal rather than allocating an unbounded rebuild task per incident. BUILDING has funded finite lifetime and stop/aftercare; readers that impede reclamation leave their real stock charged and can prevent successor admission. This is bounded refusal/safety, not a theorem that readers eventually release or that service survives indefinitely without funding.

## Work preservation, incidents and prefix timing

`Qprepare` pays the complete structural relation once for its named stable cohort. Each actual group scan still pays exact actual map/history inspection, signed-ad bindings, scope predicates, support dependencies, summary construction and current final guards. `D_R = sum_j d_j` retains repeated visits across all actual member occurrences and attempts; a structurally shared locator grants no cross-group native assessment cache. Missing/dirty required native assessments lead to separately admitted native work or nondecision, not invisible reconstruction in the structural lookup cost.

Group maps must include actual extra/partial placements, not desired four-copy state. A catalog does not settle old effectful calls or establish their changed maps. The incident path retains classification of the reconciled postsettlement map **and** complete authorization of the actual post-cleanup map. Cleanup of a different intended set is not a substitute. The two passes may share one catalog only if its exact guards remain valid; a relevant C/R0/V change requires a second paid build on the affected deadlines. All failed/stale attempts retain their spend and stock.

The source explicitly distinguishes work amortization from deadline amortization. A shared build is spent once but lies in every dependent job's predecessor chain. In the sufficient serial calendar, group j must accommodate the full Tprep plus its actual service-prefix sum, incumbent work and guard slack. Dividing Tprep by group count and using that quotient in every deadline would be invalid. The source's two-group counterexample checks: Tprep=4 and remaining work 2 per group give completion times 6 and 8; margin 5 for the first group fails even though aggregate work is 8.

The retained SG lease margin uses the original effectful invocation's monotonic dispatch basis. Nothing in catalog reuse refreshes it on a replay. Relevant churn can invalidate each completed build before publication, so a finite service claim requires admitted cumulative rebuild work or a sufficiently stable completion window. Pure layout compaction also invalidates this conservative recipe and its catalog-dependent summaries; its extra dirty intervals and rebuilds are explicit comparison costs, not a hidden weakening of equal service.
