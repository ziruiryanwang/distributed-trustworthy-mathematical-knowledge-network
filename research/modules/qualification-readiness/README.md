## Distinct claims and their dependencies

| Claim someone might wish to make | Evidence that would be needed | Evidence insufficient by itself | Current observed result |
|---|---|---|---|
| The declared source slice has a usable native export | Actual exact bootstrap and export/reconstruction; claimed correspondence dimensions; real checked local application for that slice | Source inspection, a generated CID, kernel rejection of malicious input, or a theorem about an unrelated realization | NOT RUN |
| The scoped network/client operations conform | Exact codecs, build/runtime/store/clock/policy inputs plus positive and fault traces for the operations actually exercised | A successful Lean replay; multiple nodes running the same unqualified implementation | NOT RUN |
| A contribution survives the declared interval and is independently reusable | Actual protected complete support, separately supplied service, current guards and later receiver acquisition/checking/application | A broker row, signed receipt, cached proof, successful publication attempt, or a past check under expired protection | NOT RUN |
| Sharing improves a declared investigation population | Nonvacuous local capability and scoped conformance, then predeclared controlled comparisons with all costs and failures accounted for | A successful hand-crafted transfer, proof citations, popularity or a larger stored corpus | NOT RUN |
| Continuing reciprocal contribution adds benefit beyond static sharing | The previous obligations plus continuing-versus-static access and repeated eligible checked re-contribution across independent investigators | More generations of dependency edges, more supplied agents/resources, or an initial shared library benefit alone | NOT RUN |

This is a dependency map, not a demand that every part of the system be universally proved or optimized. The intended claim determines the finite scope. A small honest-service pilot may make a small honest-service claim; it cannot acquire a crash-tolerance or hostile-network claim by association. Optional broker/VIEWS1 claims require their own feature-on/off coverage and cannot be imposed on direct native reuse.

- A finite preservation interval, supplied fault envelope and resource occupancy must be declared. Later reusability establishes only the observed interval/conditions, never indefinite preservation.

These obligations are already selected; this module adds the evidence handoff, not a new recovery protocol or a demand for every optional feature in the first pilot. Exact source contracts resolve any shorthand here. Their actual conformance remains unperformed.

## Result discipline

A dossier needs separate fields for completion, safety/conformance, evidence integrity, applicability and empirical decision. Collapsing them into one PASS hides important failures. Ordinary admitted work that reaches a budget/deadline without an answer is a failed completion retained in the utility denominator. It may still demonstrate correct bounded refusal. Missing or corrupted measurement evidence is an integrity problem, not an unsuccessful theorem that can be quietly dropped. An observed invalid acceptance or authority/accounting bypass invalidates the affected reliability claim even if yield is high.

An effect estimate near zero, negative, or too imprecise to support the declared benefit does not refute native soundness. Conversely, a valid theorem does not establish that retrieving it was useful. Future criteria, resource ceilings, workloads and inference scope must be fixed before confirmatory outcomes; engineering choices may be calibrated separately. There is no universal usefulness score and no human-intention assessment in acceptance.

All result rows currently read NOT RUN. Build identities, actual native artifacts, runtime evidence and measured cost/yield traces do not exist in this project's evidence. This module is therefore not yet a ready-to-execute dossier, and its audit cannot close AS-03/04/05/06/09/12 by reviewing their names.
