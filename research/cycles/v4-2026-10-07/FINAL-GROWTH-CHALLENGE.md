## Interim decision

The named-library change is consequential, provided the public reciprocal route
really works: it separates a persistent shared semantic recipe from an
independently flattened checking artifact. It need not introduce new trusted
kernel constants to do that. Exact selected inputs, typed import wrappers and
the existing final check remain separate obligations.

The mathematical/philosophical arguments in `experiments/named-library-01/GROWTH.md`
are coherent. Resource-bounded usable capability is a defensible working notion
of knowledge growth, while theorem counts, renamings and logical closure are not
adequate measures. The conditional option-capability inclusion is valid, but is
not a causal discovery theorem or a strict practical improvement. The repeated
squaring theorem and its operation counts are valid for the specified semigroup
algorithms. The new package does not thereby supply or qualify an efficient
evaluator. This is not a reason to add an evaluator to a mathematical commons;
it is a reason not to make executable speedup the principal achieved v4 claim.

The strongest new directly software-realized improvement is **finite
storage/transfer-limited accumulation of shared formal constructions**, compared
with the previous self-contained-artifact protocol. The currently written
asymptotic argument should be instantiated inside actual supported bounds.
Hypothetical positive delta, affordable proof production, future demand, or
arbitrarily large n must not substitute for that instantiation.

## One central search issue: permanent first-page blindness

Inspected `library_overlay.mjs` has `remoteFind` sending only a key; the server
calls its bridge with `limit:8`, `max_scanned:32`, `max_bytes:16384`,
`timeout_ms:250`. The public `find` command accepts no cursor. The underlying
`library_store.py` and `library_bridge.py` already implement authenticated
local-cut pagination.

Consider one reachable honest provider with more than eight valid modules
having the same structural type key, and no other provider for those modules.
Repeated type-only queries return the same initial page. A later module may
never be exposed even with an indefinitely repeated funded query. Following an
exact ModuleID does not fix this when the requester does not yet know it.
Common mathematical signatures make this an ordinary large-library case,
not merely an adversarial corner.

This is a **missing accessibility mechanism**, not the unavoidable proposition
that every finite query can be incomplete. A minimal repair is bounded remote
continuation using the already implemented authenticated cursor, with a
provider/key-bound cursor and existing metadata/request/output ceilings. Each
page must preserve its local cut, explicit completeness and refusal semantics;
there need be no single unbounded query or global recall promise. More advanced
semantic search/ranking is not required to repair this issue. Root was notified
before any new implementation was selected.

Provider discovery itself can also be incomplete through caps, partitions,
coverage or unavailable service. Those are honest deployment/query premises;
they do not justify removing continuation from a provider already found.

## Proposed finite paired representation discriminator

This is a prospective recommendation for root, not execution authorization.
Use the already exported immutable `fixtures01/RECORD.json`, source-selected
codec/compiler/lowerer and the ten positive family modules only: D0, D1 and
FAMILY_1 through FAMILY_8. Exclude the bad-signature examples and distinct D2
from the positive family accounting. No new fixture family, Lean run, native
check, proof campaign, network trial or repeated already-passing contract suite
is needed for this accounting.

For every prefix n from 0 through 8, define its endpoint set as D0, D1 and the
first n family successors. The endpoints are precisely their emitted canonical
type/body objects; both representations must be capable of reconstructing these
same objects. `record.family` starts at D1, so D0 must be included once separately.

1. Rebind every source and selected module to its exact frozen bytes. The pure
   resolver reads only the selected map, returning exact bytes. No producer's
   checked flag or arbitrary extra local module may supply a dependency.
2. Lower each of the ten roots once through the existing pure path, keeping
   each exact canonical capsule hash, byte length, semantic interface and
   lowering record. This is representation computation, **not mathematical
   acceptance**. Record any refusal unchanged; do not relabel it or select a
   larger family merely to improve a graph.
3. Compute, for each prefix:

   `N(n) = 2441 + 2034 + 1936*n` descriptor payload bytes;

   `F(n) = sum(length(exact self-contained output for each prefix root))`.

   Thus N(8)=19963 from existing actual bytes, without any new runtime. F(n)
   must be obtained from the exact outputs rather than guessed from row counts.
   Source/module metadata are not interchangeable with mathematical payload.
4. Record all graph nodes, work/substitution counters, raw selected input bytes,
   emitted bytes, current depth/module limits and maximum simultaneous working
   payload. Aggregate work across ten lowerings must not be called linear: old
   semantic nodes are revisited in successive operations. The new mechanism
   saves persistent/transferred repeated representations, not every computation.
5. An actual finite positive gap exists only at an n where `N(n)<F(n)` and
   every selected lowering fits current bounds. Pick a prospective logical
   mathematical-payload allowance S with `N(n)<=S<F(n)`. A fixed midpoint is
   sufficient; preserve all observed prefixes, not just a favorable one.
6. The named route can retain the recipe closure within S and reconstruct the
   specified endpoints; the explicit previous protocol that retains every
   independent self-contained prefix cannot retain that same endpoint set
   within S. This is a strict capacity separation **between these protocols**,
   not a lower bound against all possible compression, last-output-only
   retention, or an equally optimized local named library.

The same sums describe mathematical payload for a sequential acquisition model:
one recipient starts with neither representation, retains all selected exact
objects, and receives each next prefix once. The named route transfers each
unique module once; the prior protocol transfers the independent capsules.
Discovery, framing, failed attempts and provider service remain separately
charged. The finite byte comparison is not a measured full-route CPU speedup.

### Full resource envelope

S above is a **logical mathematical-payload budget**, a real separately enforced
store parameter, not a total-disk or total-network-cost measurement. State the
complete resource vector alongside it:

- Persistent recipe payload: S, with at most ten committed objects for n=8.
- SQLite object/offer/posting/configuration storage and page overhead: a separate
  finite page allowance, ideally with actual page/file accounting if root also
  selects one fresh store materialization. The existing minimum page allowance
  is 256 pages, not zero overhead. A physical-disk improvement needs an actual
  complete physical comparison, not just N<F.
- Provider metadata, owner configuration, receipt/law custody, installation and
  provenance/evidence: explicit separate allowances; identical shared costs may
  cancel only in an explicitly same-endowment comparison.
- Selected lowering workspace: the recorded maximum for one operation, below
  the current 64-module/16-MiB-input/4-MiB-output/graph/work/depth ceilings.
- Native checking/conversion and optional proof generation: separately funded;
  no O(n) bound follows from DAG size. For reconstruction-only storage capability
  no new acceptance is asserted by the analyzer.
- Service, discovery and acquisition: reachable retained providers or prior
  exact custody, finite owner-paid time/CPU/memory/connection allowances, and
  explicit incomplete outcomes under budget or coverage failure.

If a checker output/cache is retained for every prefix in addition to the
recipes, count it: the claimed storage saving may vanish. The comparison's
named policy retains recipes plus compact exact bindings and reconstructs
flattened caches on demand. Operator documentation must permit this policy;
the current general recommendation to retain all check outputs should not be
read as mandatory permanent retention of every full capsule. Automatic garbage
collection is not required, but an owner must know which files are reconstructible
and which exact recipe/frontier bytes must remain in custody.

## What makes the growth result substantive rather than a file-count claim

The family consists of polymorphic operations whose shared meaning is linked
to an acquired associative law. Its reusable endpoints and equivalence
relations matter; merely making ten modules does not. The public workflow must
actually acquire, use, extend, return and reacquire the exact new module, and
must check its returned meaning and the relevant acquired-law application.
The separate integrated reviewer owns those outcomes.

Conditional source reasoning can justify typing of the remaining repeated
composition family without executing an expensive new proof for every member:
composition of two functions `A -> A` again has type `A -> A`, under the same
polymorphic parameters, and typed imports preserve their declared interfaces.
That source theorem is not an observed kernel acceptance report for the inert
family. Correct lowering correspondence remains an implementation premise.

The prior release's independently flattened representations are a legitimate
software-comparison baseline. An optimized local library already providing the
same constructions is an explicit null case; the network may add cost there.
This does not erase a real protocol capacity improvement. It prevents that
improvement being advertised as superiority over independent mathematics.

## Large-network scope and remaining classifications

The selected-custody and checking design need not store or enumerate all global
objects. Routing size/load/coverage remain real; the quoted logarithmic DHT
argument is conditional on maintained healthy coverage, not a universal theorem
from an event cap. Certified theorem interfaces can remove proof ancestry;
transparent definition semantics and demanded computation remain necessary.
Finite selected-chain limits do not bound total global corpus size, but they do
bound a single compositional operation. Explicit re-expression/checkpointing
must pay its full semantic cost; it is not a free recursive extension theorem.

The new layer does not enlarge the fixed foundation's logical expressivity:
it supplies persistent shared representation and reciprocal composition above
that foundation. Full mathlib compatibility, arbitrary newly declared inductives,
and general semantic-search completeness are not silently proved by it. Nor are
they new mandatory gates invented by this review. The final supported-language
envelope must be visible and the v4 claim must be about the substantial usable
capabilities actually delivered, not an unrestricted full-Lean replacement.

Reasonable operating/model premises include collision resistance, adopted
checker/receipt soundness, compatible policies, available selected custody,
reachable contacts, finite provisioned resources and nonzero future demand for
a claimed reuse benefit. Missing cursor accessibility is instead a concrete
software limitation. Incomplete integrated return/check/package evidence is an
unclosed release gate, not a service premise. Hypothetical positive amortization
is a model conclusion with uninstantiated premises, not an achieved cost saving.
