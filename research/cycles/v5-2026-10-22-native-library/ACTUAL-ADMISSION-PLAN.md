## Default-preserving admission plan

The owner exporter permits8192 units but the receiver permits1024 per batch.
The driver plans the complete export before any expensive basis checking. Each
batch simultaneously respects:

- 1024 units and65536 newly claimed names;
- 2097152 total serialized descriptor-plus-inventory DAG nodes, conservatively
  bounding the checker's descriptor-only reference scan;
- 64MiB canonical raw-unit array and64MiB canonical evidence bytes;
- the reader's unchanged8MiB per-envelope and other default syntax limits.

A single over-limit unit is a preflight refusal, not authority to increase the
worker limits. Sequential groups are filled until a genuine bound is reached;
there is no arbitrary tiny-batch policy. Total limits are32 batches,128MiB
evidence,1048576 names and256MiB controller-authored files. The real catalog has
33 roots/operations,64MiB maximum delta,512MiB retained artifact capacity and
4096 SQLite pages. Basis reserves32MiB; each batch reserves64MiB. Failed staging
remains charged under the catalog's existing rules.

Each worker has at most180CPU/180wall seconds,1536MiB,2 processes and1MiB for
each output stream. The aggregate driver envelope is at most480 known CPU and
540wall seconds, also capped below the outer selection with30-second headroom;
preparation is included. These are a proposal for root review, **not a runtime
selection**. The outer process-tree bound must allow at least3 processes
(driver, supervised wrapper, Lean); root normally selects4. Global CPU sums
actual settled nested-Job CPU and controller CPU; the outer Job independently
constrains the whole invocation.

The worker report is individually capped at16MiB, plan at16MiB, and count at33
calls; logs are supervised at1MiB per stream per call. Thus total ancillary
output is finite even on failure. Log/disk limits are sampled and local output
is not an OS disk quota or security sandbox. Explicit artifact and file caps do
not justify a public hostile-source service.
