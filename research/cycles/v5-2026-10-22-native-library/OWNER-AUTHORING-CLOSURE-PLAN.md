# Construction, not a second semantic authority

2026-10-23. Source selection by root; implementation ownership below. The
controlling argument is [AUTHORING-AUTHORITY-REAUDIT](AUTHORING-AUTHORITY-REAUDIT.md).

## Decision and practical payoff

Use ordinary local Lean imports to construct a candidate; use the existing
independent receiver to accept it. Do not require the authoring environment to
mirror every accepted definition body. Consumer03's absent private basis name
was demanded by the old preflight, not shown necessary for the selected work.
Further owner-correspondence projection would solve a stronger and costlier
problem than receiver soundness requires. Preserve the old exact/abstract APIs
and their frozen evidence; add an explicitly construction-only path.

An acquired theorem may be represented by its exact accepted type as a checked
safe **scratch assumption**, without replaying its old proof. This is neither a
new receiver axiom nor accepted mathematical evidence. Missing definitions and
generated groups still use real checked construction. The complete new proof
must pass the unchanged receiver under exact accepted dependency identities.

## Initial bounded API and ownership

`preview_boundary_review` owns only new
`software/v5/ordinary_lean/OwnerConstruction.lean` and this checkpoint. Root owns
the command/export integration and all launches/Git. Independent source review
is owned by `admission_event_audit`.

```text
OwnerConstruction.constructPrepared(owner, OwnerRebind.Prepared, limits)
  -> Constructed {
       environment,
       interpretationLabels, targetNames,
       introducedNames, introducedSignatures,
       checkedUnits, scanNodes, encodedNodes, payloadBytes
     }
```

The first adapter indexes the existing authenticated, bounded prepared request
once. It returns that finite full name-to-ID map as **receiver interpretation
labels**, not correspondence evidence. It does not rerun the roughly49MB
preparation or perform a whole-owner/corpus census. This retained-map adapter is
not the final scalable pointwise catalog resolver.

Demand-first construction:

1. Visit only requested targets and genuinely missing construction dependencies.
2. If a name already exists safely in the owner, stop without inspecting its body.
3. If a missing accepted theorem is demanded, decode only its accepted type,
   ensure type dependencies, then kernel-check a safe temporary axiom signature.
   Record it separately and expose its namespace for local authoring.
4. For missing definitions/opaques, decode/check the full exact accepted unit.
   For missing generated groups, install the complete atomic group; refuse a
   partial existing group and never overwrite. Resolve external references first.
5. Refuse a genuinely demanded absent fixed-basis name explicitly. Do not recover
   by importing the entire private library. Refuse dependency cycles outside
   genuine generated groups.
6. Apply aggregate byte/node/name/unit bounds. Return a candidate environment
   only after the whole request succeeds; no command-state mutation on failure.

## Export and acceptance contract

The separate exporter checks only **reached** labels. A reached boundary name
must be imported from the ordinary owner environment or recorded in this
acquisition's `introducedNames`; otherwise refuse the local collision. A newly
authored target cannot silently become an accepted import merely by reusing a
name. Acquired scratch signatures export only as exact accepted IDs, never as
new axiom units. New local declarations export complete allowed units; new
generated groups remain atomic.

The current receiver controller retains exact prepared-map **and** protected
parent-ID membership checks. It independently checks every new unit under its
actual accepted context and commits actual checked output. No authoring flag,
`.olean`, matching name or local compilation result grants acceptance. Existing
receiver/compiler/profile rules are not relaxed.

Local elaboration success need not imply receiver success: incompatible local
definitions may cause final rejection. If checking succeeds, the authoritative
statement and meaning are the receiver-checked statement and exact import IDs,
not an unproved claim of local-to-receiver correspondence.
