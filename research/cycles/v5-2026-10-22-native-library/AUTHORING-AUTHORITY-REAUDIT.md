# Authoring should construct candidates, not re-establish receiver authority

2026-10-23. Independent source/theory challenge by `admission_event_audit`,
requested by root before further closure implementation. No implementation,
runtime, test, catalog operation or Git action was performed.

## Decision

**Yes: remove mandatory whole-owner semantic correspondence from the normal
best-effort authoring path.** Exact-body matching of every preexisting local
dependency is not a premise of sound final acceptance when the receiver already
checks the complete new declarations in its own independently warranted context.

It may be useful as an optional compatibility diagnostic, but it should not
force every ordinary client to reconstruct a second, closed copy of the accepted
library merely to propose a proof. Consumer03 exposes the cost of that misplaced
obligation: a hidden private basis name was demanded before any acquired method
was installed, because prior preparation followed accepted bodies rather than
only the work the local construction actually needed.

This is a simplification of authority boundaries, not permission to weaken the
receiver, import remote executable code, accept local axioms, promise every
locally compiled proof will transfer, or call an untested path operational.
Here "accept local axioms" means admitting them into the receiver's warranted
library; temporary assumptions inside construction are a separate matter below.

## The soundness argument

Let `K` be the protected receiver context, already accepted under its exact
foundation/profile. Let `A` be any authoring environment. Let `U` be inert,
bounded serialized new declaration units, including complete new theorem proofs.
Let `B` map every reached external name to the exact symbol ID resolved in the
selected `K`. The receiver decodes `U` with those bindings, checks all new units
against `K` and earlier checked units, and commits only the actual checked output.

Under the existing decoder/kernel/catalog correctness assumptions:

```text
Accepted(K) and ResolveExactly(K, B) and CheckAll(K, U) = success
    and CommitBindsActualCheckedBytes(U)
  implies Accepted(K extended by U).
```

There is no assumption `A = K`, no body-equality premise between them, and no
need to trust how `U` was discovered. The induction is over newly checked units:
each step uses only the already accepted receiver prefix and its actual new
checked declaration. The owner may be buggy, malicious, use unrelated axioms or
construct under different definitions; none supplies a receiver premise.

This statement is about formal mathematics relative to the permitted receiver
foundation, not an unqualified absolute consistency proof. It inherits the same
kernel correctness, codec, native primitive, protected-state and commit-event
assumptions as the current receiver. It does not make those assumptions stronger
or weaker merely by removing authoring preflight.

### What matching a name now means

Pointwise protected-catalog resolution chooses a **receiver interpretation** of
the serialized symbol. It does not prove that a same-named local constant has
the same meaning. For example, local `d := 0` and accepted `d := 1` can share a
name. A local `rfl` proof of `d = 0` will fail in the receiver. A local proof of
`d = d` can still pass and is valid for the accepted `d`.

If mismatched local types or definitions happen to produce a term valid under
the receiver interpretation, acceptance is still mathematically sound. What is
lost is automatic preservation of an author's intended/local meaning, which is
not the commons' mathematical validity criterion. The accepted theorem's exact
statement and import IDs must be the receiver-checked ones; interfaces should
display the resolved context, not claim correspondence that was never checked.

## Countercases and obligations that remain

| Attempt or mismatch | Required behavior |
|---|---|
| Local theorem-shaped axiom has an accepted name | It may be a construction handle; its owner record is not installed. The complete successor is checked using the actual accepted receiver theorem/definition. |
| Local axiom has no accepted counterpart | It cannot become an imported warrant by name. Reaching this axiom refuses export/admission; the current receiver rejects new axiom declarations. A separate complete checked declaration would have to replace that unsupported candidate dependency. |
| Same name, different local definition/type | Compatibility may fail, including late failure, but final checking uses only the receiver's meaning. No successful-local-build shortcut is permitted. |
| Forged symbol ID or another profile/context | Exact lookup in the selected protected context must fail. A peer's ID, local name or exporter label cannot create acceptance. |
| Incorrect generated recursor, projection or inductive inventory | Existing imports resolve to the real receiver group. New inductive groups still require complete atomic checked units and actual generated-record comparison. |
| Native evaluation or unsafe/local implementation tricks | The existing permitted-name/declaration filters and pinned receiver primitive rules remain. No `sorryAx`, forbidden evaluator, unsafe declaration, unchecked binary or fallback axiom enters acceptance. |
| Owner claims a different output than it actually exported | Canonical new evidence, exact import resolution, request binding, real worker report/artifact checks and live grant-before-commit remain mandatory. |
| Failed/unclean worker, uncertain commit or malformed input | No promotion or automatic replay. Existing bounds, supervisor cleanup and uncertain-state inspection remain. |

Full owner-body scanning is not needed to establish any of these receiver
properties. It can improve expected compatibility, but is neither necessary
nor sufficient to replace the actual final check.

## Missing accepted theorems may use temporary construction signatures

Root additionally proposed avoiding even the local rechecking of an already
accepted theorem merely to make its name usable in proof search. **This is sound
under the same final-check boundary.** The prohibition on new axioms belongs at
receiver admission, not at arbitrary candidate construction.

For an exact theorem already accepted in `K`, an explicit scratch authoring
adapter may introduce a missing axiom-shaped signature into `A` with the selected
accepted name, universe interface and type. It is an assumption **in the scratch
environment**, not a newly proved theorem there. It needs no original proof body.
The exported complete successor proof can refer to that name; the receiver uses
the real already warranted theorem instead of the scratch assumption.

Minimal disciplined interface:

1. The trusted controller resolves the exact selected accepted theorem ID and
   type/universe descriptor. A peer's self-declared theorem or owner-supplied
   digest is insufficient. Bind profile/context as well as symbol identity.
2. Introduce only a genuinely missing name; never overwrite an existing owner
   record or an accepted output identity. Use the pinned kernel to check the
   signature's well-formedness in the local environment. That is a type check of
   a declaration of assumption, **not proof checking of the theorem**.
3. Keep the scratch assumption separately classified and scoped to construction.
   Never advertise its `.olean`, environment, compilation success or local axiom
   declaration as warranted math. Any saved artifact containing these signatures
   remains authoring state, never an accepted snapshot or an unmarked replacement
   for a user's checked ordinary library.
4. At export, a reached scratch signature must stop at its exact independently
   resolved accepted ID. It must not be encoded as a new axiom unit or rebranded
   as a theorem with missing proof. A genuinely new target still requires a
   complete new proof, and may not shadow an accepted name.
5. The receiver continues rejecting every new axiom unit and independently
   checks all complete new units using its actual accepted theorem. If local
   types, definitions or primitive behavior differ, it may reject; no local
   "signature checked" or "construction complete" flag bypasses that event.

Thus the earlier rule "never insert a new axiom anywhere" was stronger than
needed. It protected an authoring invariant, not the final mathematical safety
invariant. It should not force rediscovery or replay of accepted proofs.
Preserve its previous implementation/evidence as history, not as a permanent
architectural restriction.

The useful initial scope is **accepted theorem signatures**, not invented
arbitrary claims. Keep ordinary definitions available by their actual bodies
when missing computation or type conversion requires them; existing public
definition handles may remain best-effort local interfaces. Generated inductive
groups still need their actual complete construction when genuinely missing.
There is no benefit here in fabricating recursors or changing primitive rules.
The signature's type itself may require unavailable types/definitions; such real
construction dependencies remain and must be acquired or explicitly refused.

## Practical candidate path

1. **Use the agent's ordinary trusted local Lean project.** Normal local imports
   and tactics remain authoring choices. Never execute peer source/plugins or
   load a peer `.olean` merely because it accompanied a search hit.
2. **Acquire selected missing methods, not a correspondence universe.** Install
   accepted theorem signatures as explicitly temporary assumptions when useful;
   install actually needed definitions/groups from bounded inert construction
   data through the local kernel. Reuse existing names without forcing their
   entire accepted hidden-body closure into the owner. Direct acquired
   target-interface checks are useful early diagnostics, not mathematical
   authority.
3. **Construct locally and export complete new units.** The exporter traverses
   actual new declarations. At each reached external name, a trusted controller
   resolves whether the selected accepted receiver context already supplies it.
   If yes, stop at that exact ID. If no, export its allowed complete local unit
   and recurse, or refuse if it is absent/unsupported. Never recursively inspect
   the accepted receiver definition's hidden body merely to use its ID.
4. **Independently check and commit.** Use the existing exact receiver context,
   decoder, all-new-unit kernel checks and actual event-bound commit. Preserve
   local construction success separately from receiver acceptance.

For accepted generated groups, the parent already contains the complete checked
group: only actually reached member IDs need to be carried as external imports.
Do not require the owner to reconstruct the group merely to stop at an accepted
member. Conversely, if exporting a genuinely new group, it remains indivisible;
mixed accepted/new same-name ownership must refuse or be explicitly renamed and
rechecked, never silently splice two group implementations.

The pointwise resolver can be a protected local catalog query or a separately
authenticated selected binding map. It is not an untrusted owner callback. Keep
an aggregate work/byte budget and cache exact repeated lookups. Do not replace
the old semantic census with a mandatory global-library/name census under a new
label. A small finite experiment may use the retained parent binding map, but
that convenience is not an asymptotic worldwide-search claim.

## What this does not automatically solve

An actually missing definition or missing type used by a new construction may
still require acquisition. Installing an accepted theorem signature avoids
acquiring its proof history; it does not erase dependencies of its type.
Concrete local computation can also require bodies that public modules hide.
Such a refusal should report the
actual required construction, not trigger another full private-library import
or resource-cap increase by default.

The simplified route trades a guaranteed correspondence attempt for potentially
later rejection. Its useful metric is end-to-end successful reuse per resource,
including failed construction and final-check costs. Common pinned local-library
versions, target-type preflight and cached failure diagnostics can cheaply reduce
that risk. Demanding exact equality of every body is not justified without
evidence that its avoided failures exceed its own acquisition/checking cost.

## Existing code seams: do not silently relabel them

Read for this challenge: `OwnerRebind.lean`, `OwnerUseCommand.lean`,
`owner_request.py`, `OrdinaryExport.lean`, `SuccessorExport.lean`,
`CheckedExtension.lean`, and `run_successor_admission.py`'s preparation,
per-unit import resolution and reviewed commit path.

- `owner_request.prepare` currently follows `_semantic_refs` of accepted
  non-theorem bodies and generated metadata. `rebindPrepared` then requires
  basis/group presence and exact/explicit-abstract correspondence. These are the
  construction obligations to replace, not receiver requirements to preserve.
- `SuccessorExport.selectedAbove` currently enumerates its entire supplied
  boundary, requires each name present, and documents successful correspondence
  as a caller premise. A successor must state the weaker candidate-interpretation
  contract and stop by reached accepted identity, without demanding unrelated
  owner records. Existing new-unit serialization can remain.
- `run_successor_admission.py` currently checks bundle IDs against **both** the
  prepared correspondence map and the actual parent. Direct catalog resolution
  requires an explicitly reviewed controller successor for that provenance
  seam. It is not accurate to say the whole controller is unchanged. Exact
  parent-ID checks, evidence census, the native worker/profile/kernel and the
  check-before-commit chain can and should remain unchanged.

Recommendation: implement the smallest explicit best-effort authoring successor
after agreeing these contracts, rather than perfecting a second closed-world
owner semantic mirror. Retain the prior exact helper as an optional diagnostic
or frozen predecessor. The next decisive evidence remains actual ordinary method
reuse followed by real independent successor checking, not another broad
correspondence-control campaign.
