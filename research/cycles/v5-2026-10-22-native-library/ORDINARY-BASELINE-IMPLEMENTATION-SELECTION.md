## Selected inert format and conservative source ceilings

Manifest canonical JSON: exactly `schema`, `semantic_id`, `batches`.
Schema is `DMKN_ORDINARY_BASELINE_BUNDLE_V1`. Each nonempty batch contains
exactly `{unit_id, raw_sha256, raw_bytes}` records. Derived unit filenames are
`units/<unit_id>.json`; no manifest paths or native artifacts. The manifest's
expected SHA-256 is supplied separately. Mathematical identity remains V2.

The initial trusted source ceilings (caller may only lower them) are:

| Quantity | Ceiling |
|---|---:|
| Manifest | 2 MiB, existing JSON depth/integer grammar |
| Whole units / batches | 8,192 / 64 |
| Portable evidence total / one unit | 64 MiB / existing 8 MiB |
| Encoded nodes / output names / import edges | 20,000,000 / 262,144 / 262,144 |
| New binding metadata, canonical encoded `[name, symbol]` rows | 16 MiB |
| Batch | unchanged admission 1,024 units, 64 MiB, 2,097,152 nodes,
  65,536 names, 1,048,576 edges; native serialized unit array also <=64 MiB |

These are refusal bounds, not claims that every such bundle fits memory or that
the retained large closure meets every bound. The exporter retains its existing
64-MiB writer wrapper and existing source/group/scan limits. Portable overhead
may cause a writer output to refuse. Request is <=1 MiB; project roots/modules
use the reviewed approved-project grammar; <=1,024 unique nonbasis target names.
No peer-selectable executable, inherited `LEAN_PATH`, plugins, source execution
or owner/catalog lookup is introduced in the producer.

The pure binder takes exact selected inventory bytes (hash `S.INVENTORY`),
checks the 581-name basis, validates writer schema/targets/stats and every unit,
then binds imports through the seed plus preceding emitted complete outputs.
It must call current V2 identity/evidence functions, never fake a protected
context to invoke a context-dependent binder. Targets and producer diagnostics
are inert convenience data, not additional authority fields in the manifest.
