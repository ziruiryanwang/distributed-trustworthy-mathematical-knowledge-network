## Why this step, and where it stops

A normal user must be able to find, receive, use and share mathematics without
editing an experimental driver. The previous loop established that the existing
mechanisms can cooperate, but its fixed fixture assertions are not a product
interface. The thin peer layer removes that barrier while retaining the existing
checking/custody/index implementations. It does not claim to solve relevance,
globally complete search, large local contexts or sustained net useful growth.

Do not invent another difficult theorem or certificate to validate these command
boundaries. Reuse retained valid mathematics; after the seam works, return to
existing-project integration and the strong package-sharing comparator. Source
analysis should decide whether more machinery is justified before another run.

## Public operation separation

`find` returns bounded candidates and coverage/accounting information. A match
is not mathematical acceptance. `receive` explicitly acquires and locally checks
selected missing evidence. `publish` derives inert index metadata from exact
accepted local bindings; it is not a new proof or remote publication. `serve`
exposes the selected entire custody/index for a finite lease, never remote writes
or source execution. The existing `owner contribute` remains the authoring path.

For this first CLI, `serve` must hold the existing ordinary catalog owner lock
until Provider cleanup completes. It therefore requires a selected catalog/store
as well as custody. This serializes commands using that same owner; it is not a
universal lock on unrelated programs or another catalog pointed at the same
directory. Protected storage and no uncoordinated external mutation remain
assumptions. Pure inert-only rehosting is still a lower-level API capability,
not a claim of this CLI. Sharing every addressable custody object needs explicit
owner acknowledgement. Keys and private state are never indexed by implication.

One original allowance covers each command. Composed receive loops do not mint
new budgets. Contacts are finite owner configuration, plaintext only on loopback,
remote TLS verified; trust files/config are selected and checked. Acquisition,
admission and later publication failures retain distinct facets and charges.
Acceptance cannot be silently rolled back because reporting or cleanup failed.
