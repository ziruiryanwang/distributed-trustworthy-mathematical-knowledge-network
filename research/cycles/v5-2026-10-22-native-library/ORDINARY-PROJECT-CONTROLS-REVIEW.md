## No accidental native/state/network work

Before package loading, the harness guards `subprocess.Popen`, `sqlite3.connect`
and both socket connection methods with immediate failure. It subsequently
guards the actual peer exchange and Provider start methods. Only the narrow
worker group temporarily replaces `subprocess.call` with its argument recorder;
Popen remains forbidden throughout. An unexpected real spawn cannot be mistaken
for the expected return value. Refusal helpers demand exact `ValueError` codes;
a guard's `AssertionError` fails the group instead of silently passing it.

Pre-open controls also forbid OrdinaryStore construction and admission opening.
The forwarding group replaces both with an explicitly inert object and replaces
`contribute_source` with a recorder. Its fabricated CHECKED-shaped return is
labelled `MOCK_ONLY`; final evidence claims explicitly exclude mathematical
acceptance. No real catalog operation, native check, project import or peer
request occurs in the selected code path. The small files/directories, including
ADOPTION-shaped JSON, exist only under a fresh fixture directory.

All synthetic paths are beneath the launch output; overlap with package/runtime
roots is refused. Exact generated source bytes and worker arguments are compared
to explicit expected values, not merely success flags. Captures must remain
empty after worker-input refusals. Context-manager patches restore module and
environment state on success or exception. No source/product file is edited.

## Budget and interpretation

The harness has one 50-second wall/30-second controller-CPU allowance, checked
around loading/setup and each group; it does not renew it. Root's selected
outer 60-wall/35-CPU/512-MiB/two-process envelope supplies independent whole-tree
containment. Group errors are retained as failures, not retries. A successful
report requires all five groups; native_operations and owner_opens refer to real
operations and are zero by guarded construction, not to mock calls.

These cheap controls cover the new interface plumbing only. They do not execute
the complete contribution backend, prove import resolution experimentally,
establish compatible project tactics, validate mathematical growth or qualify
deployment. Any future success must retain that narrow interpretation and pass
a saved-output/closure audit; no additional broad campaign is implied.
