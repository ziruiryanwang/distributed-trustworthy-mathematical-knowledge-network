## Entrypoint and actual API fit

`bootstrap_owner` is the peer entrypoint's small stdlib bootstrap pattern with
QUERY diagnostics and `query.py` in place of `peer.py`. It verifies the externally
selected PROFILE bytes, validates each traversed ordinary path, checks bounded
query/owner file bytes, then executes only the retained verified owner bytes.
The owner module's original-start counters are rebound to this query process's
start, so constructing its Allowance cannot reset spent bootstrap wall or CPU.
The unchanged owner bootstrap then pins profile.py before executing it.

The running entrypoint itself, Python and the OS remain trust premises, exactly
as documented. These checks are byte selection, not publisher authentication or
protection from a hostile in-process actor racing owner storage. Root scripts
are not added to the package Python search path.

The called APIs exist with the expected arguments and return fields:

- `NativeInstallation.open` is the existing immutable installation/runtime
  verifier and exposes `semantic_id` and `runtime_roots`. It loads verified
  support, but does not create/open an ordinary owner or catalog.
- `A.C.ordinary(..., directory=True, fresh=True)` requires an absent final
  directory with existing ordinary ancestors. The existing file reader bounds
  both inert inputs to 1 MiB and rejects nonordinary or multi-link input files.
- `base.separated` rejects output containment/ancestry overlap with the package
  and either runtime. Explicit input/output overlap is also refused.
- `Q.bind_native_type` accepts raw canonical type AST and exact binding rows with
  the selected semantic ID. `Q.query_spec` produces the existing feature shape.
- The loaded ordinary adapter's `namespace_for` and `compile_query` provide the
  new namespace and feature IDs. Existing `peer_api.find` uses the same adapter
  and `compile_query(adapter.namespace, config["specs"])` operation.
- `A.P.PortableCatalog._write_fresh(path, raw)` is a static ordinary-path,
  exclusive-create/write/flush/fsync helper. Calling it does not instantiate or
  open the catalog, database or mathematical owner.

`SPECS.json` is the list to place in an explicit existing find configuration's
`specs` field; it is deliberately not a whole find configuration. Contacts,
providers and network/search budgets remain separate caller choices. No search
or provider call is made by query.py.

## Inputs, budgets, outputs and failure behavior

The CLI requires explicit native-type, binding and fresh output paths plus
profile/runtime selection and finite wall/CPU/memory arguments. It validates
35–3600 wall seconds and 4–600 CPU seconds before bootstrap. Existing Allowance
then validates memory 1–8192 MiB. No worker is launched, so worker CPU remains
zero; original process CPU/wall are not renewed. Memory-mib is not a controller
RSS limit, and the existing profile/installation verification and bounded query
parsing remain cooperative. A separately selected outer supervisor is needed
for hard wall/CPU/memory/process-tree limits. This is explicitly documented,
not an omitted claimed protection.

Native AST and bindings are inert bounded bytes. The query helper reuses its
existing stricter parser/census/profile checks; the CLI does not increase them.
Both captured files are reread and compared, and the selected auxiliary profile
is reverified before directory creation or output writes. The query helper also
reparses its combined query, so combining the two individually bounded inputs
does not bypass the complete-query bound.

The success path writes only `QUERY.json`, `SPECS.json`, and `RESULT.json` in a
fresh directory. The success result binds the query, native AST, bindings and
profile hashes, namespace, feature profile and compiled feature list. Inputs
and prior outputs are not overwritten. Files are exclusive-created and fsynced;
the three-file result is not falsely represented as one atomic transaction.

Failures before directory creation produce only failure stdout. Failures after
creation retain whatever was written, report `PARTIAL_OUTPUT_RETAINED_NO_RETRY`,
and exit nonzero. The exception path cannot accidentally claim mathematical
acceptance. `A` and `output` exist whenever the guarded report-writing branch
can run. A terminal report-write failure changes stdout status to failure and
records that write error rather than retrying or deleting partial output.
Final encoding/stdout/fsync are outside the reported controller-cost sample;
actual complete process cost therefore belongs to the outer supervisor, as in
the existing entrypoint convention.
