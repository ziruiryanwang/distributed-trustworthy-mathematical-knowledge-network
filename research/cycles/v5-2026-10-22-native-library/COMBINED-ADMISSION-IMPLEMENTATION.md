whose relevant declarations are not all already accepted by the receiving
commons. We should neither reject this common workflow permanently nor trust the
author's installation. Export complete genuinely missing units, then have the
receiver check them before the contribution in the same ordinary extension.

does not create another trust mode, require whole-library authoring correspondence,
replay previously accepted proofs, or resume certificate production.

## Pure planning contract

Let K be the receiver's already accepted name-to-symbol map, P the prepared
acquired-ID map, C the unchanged consumer bundle, and S the optional supplemental
bundle. `successor_envelopes(C, P, K, target, S)` yields inert triples
`(evidence, canonical_raw_unit_bytes, lane)`; it cannot commit anything.

1. Original claimed imports must agree with both P and K. Unclaimed candidate
   names must not duplicate a claim or omit an available prepared claim. Names
   present in K receive exactly K's ID; the remaining finite set is M.
2. Without S, a nonempty M still refuses, using the original strict resolver's
   all-missing diagnostic. With S, C must be a candidate and M must be nonempty.
3. S has the exact missing-import schema, inert assurance, profile, context and
   basis. Its unique declared target set must equal M. Its imported IDs must
   agree exactly with K, but need not appear in P: supplemental library checking
   does not derive authority from the consumer's acquisition preparation.
4. S's units precede C's units. Every external reference must be bound to the
   lane's declared accepted imports or an earlier new unit. A unit's own mutually
   introduced declarations remain governed by the existing complete-unit parser
   and actual Lean checker; this helper does not pretend to validate them.
5. Every output name must be absent from K and every earlier new output. Hashes
   derived for supplemental outputs are provisional new-unit IDs, not entries
   added to K or P. Every name in M must actually be produced by S.
6. C initially sees its original accepted imports plus only the supplemental
   outputs whose names it declared in M. Extra supplemental support declarations
   are not silently exposed as undeclared consumer imports. Later C units may
   use its earlier outputs as before.
7. Every C raw unit value is unchanged. Complete reference censuses produce
   exact import envelopes under the existing V1 identity domains. The requested
   final target must be produced by C, not merely by S.
8. Each lane's actual canonical unit-byte total equals its reported byte count.
   Semantic context and identity checks do not rely on other exporter statistics
   being truthful descriptions of work; those are bounded inert accounting data.

The aggregate limits remain finite: 1,024 combined units, 65,536 combined
declared boundary entries, 65,536 new names, 2,097,152 encoded expression nodes,
64 MiB combined input bundle bytes, 64 MiB evidence and 64 MiB raw unit stream.
Supplemental lookup count is bounded by 65,536. The implementation deliberately
does not grant each lane a separate full batch allowance.

The generator can emit inert files before a later refusal such as a final byte
count mismatch. `prepare_bundle` must exhaust it successfully before any catalog
reservation or native worker invocation. Failed partial files remain retained;
their existence is not acceptance. K, P and input documents are not mutated.

## Actual acceptance remains unchanged

artifacts, copies the protected local parent without modifying it, obtains one
live grant, invokes the unchanged actual native extension worker once, and
checks its clean exit, full name/unit census and generated artifact size.
Only that live invocation reaches the existing private checked commit seam.
The controller then verifies exact final bindings and reopened catalog state.

The same proof obligation applies to the concatenated batch:

> Accepted K, exact import-ID resolution, complete new-unit checking in order,
> and the live checked-byte-bound commit imply acceptance of K extended by the
> combined new units, relative to the unchanged checker/foundation assumptions.

Neither an exporter success report nor a derived ID substitutes for any premise.
The installed Std environment used by missing-import extraction is nonhermetic
and not receiver authority. Its exported complete units must pass actual checking.
