# Independent challenge: locally checked ordinary module anchors

2026-10-23, `module_anchor_audit`. Source/theory inspection only. No Lean or
Python execution, product imports, database opens, network operations, tests,
builds or Git mutations. The canonical workspace guard passed. This note is
not source implementation clearance or evidence that an anchor implementation
already works.

## Decision

**Feasible and worthwhile in principle.** A retained, locally generated,
proof-bearing modern Lean module can be a sound boundary for later ordinary
module exports. It need not be a cryptographic certificate and must not be a
peer binary. The minimum useful first profile is one explicit locally registered
anchor root with its bounded one-parent import chain, not arbitrary branch
merging, a global module cache or a new mathematical ledger.

The practical blocker is real: `module_closure.py:28-40` caps the *total*
selected closure at 32 units; `OrdinaryModule02.lean:382-384` also enforces the
native batch bound. Current export collects above the fixed basis even when the
owner already accepted those units. Repeated ordinary project export therefore
does not inherit admission's incremental checking property. Increasing the cap
alone postpones, rather than removes, this structural cost.

## The authority that must be retained

A copied `MODULE.json`, successful-looking saved report, or artifact hash list
does **not** establish local checking. An attacker can fabricate all of those
consistently. The existing export controller does have the needed live event:
full selected-warrant collection, actual bounded worker completion, exact report
validation, both private/exported rereads and final artifact/input/profile checks
(`module_export.py:162-274`, `module_worker.py:134-169`).

Register an anchor automatically only inside a new successful export operation,
after these checks and while its original budget and owner lock remain valid.
Use an export-owned protected sidecar registry bound to the catalog/StoreID,
semantic and foundation IDs, exact runtime/checker/helper profile and policy.
It need not alter mathematical acceptance records: realizing already accepted
mathematics as a usable module is a different event from accepting new mathematics.
There must be no peer-facing or generic manifest-import registration endpoint.
For the first profile, refuse retroactive adoption of arbitrary old exports.

The protected record must bind the exact modern module names and all five file
parts, complete required parent chain, original-name-to-ExportID correspondence,
whole UnitIDs and their output groups, and the established private/public view
relation. Store actual generated bytes under the registry's ownership; an
unprotected external output path is not a durable anchor. A consumer may copy
modules for ordinary project use, but such copies do not become new authority.

The existing trusted-owner assumption matters: this protects against peers and
accidental corruption, not a malicious administrator able to rewrite both the
owner's registry and executable code. A hash proves continued byte identity
relative to a trusted record; it cannot create the record's authority.

## Conditional soundness argument

Let `P` name the exact supported checking/import policy. Let `A` be a committed
local anchor record and `B(A)` its complete protected artifact closure. Let
`Gamma(A)` be the mathematical environment and exact symbol map that its live
generation event established. The registration invariant is:

```text
Registered_P(A) implies Valid_P(Gamma(A))
  and PrivateImport_P(B(A)) realizes Gamma(A)
  and PublicImport_P(B(A)) satisfies the registered export relation.
```

This invariant is about actual previously checked artifacts, not a purported
type signature. For unchanged approved import semantics and immutable matching
artifact bytes, loading `B(A)` preserves that same realization. A new batch `D`
is decoded using only the permitted exact identities and checked as a valid
extension in both required views. Successful writing and exact fresh rereads
establish the same invariant for a new anchor whose parent is `A`. Induction on
the finite registered parent chain establishes sound reuse. The initial anchor
is the already-supported complete export checked relative to the fixed basis.

**Old proof inventories need not be re-encoded or rechecked on each reuse.**
Their correspondence was established by the registering event. Protected typed
bindings plus exact artifacts/import policy preserve that correspondence.
Metadata/header validation and artifact integrity checks remain necessary. This
is conditional on the actual importer/checker correctness, protected storage
and hash binding assumptions; it is not a formal verification of Lean itself.

## Non-negotiable composition conditions

| Boundary | Required first-profile rule |
|---|---|
| Portable identity | Exact names, UnitIDs, ExportIDs, universes, kinds and permitted policy must agree with the current selected owner context. The simplest rule is that all registered anchor bindings are an exact subset of that context, not just the requested target names. |
| Whole-unit cut | Stop closure collection only at registered complete units, retaining their complete output-name census. Never split mutual definitions, inductive/recursor groups or a unit merely because one name was found. |
| Allowed references | Decoder allow-set is the fixed basis plus exact registered unit outputs and preceding new outputs. Importing an environment does not authorize every declaration present in it. `decodeUnits:155-181` already enforces this distinction for Init. |
| Names and collisions | Refuse conflicting original-name bindings and partial group collisions. Preserve the current exact installed-singleton-theorem rule only for residual units that still provide its complete evidence; do not infer a new matching rule from name equality. |
| Private/public views | Preserve two-view checks of the new batch. Existing theorem erasure can lose definitional conversion, including `Acc.rec`-style uses; a private pass cannot waive public compatibility. Prior view relations are retained, not reconstructed from axiom-shaped public signatures. |
| Transparent semantics | Actual authenticated definition bodies and computation rules remain available through imported artifacts. A SymbolID/type-only table cannot replace semantics needed for conversion or reduction. |
| Import resolution | Supply exact explicit artifact mappings for every registered ancestor and its five parts. Limit fallback to the approved runtime; validate actual module headers against the selected finite parent plan. No inherited project or peer search path may resolve a parent name. |
| Materialization identity | Bind anchor identity and its exact import/artifact representation into the new module/cache key. The old targets-only key is insufficient: the same theorem targets may now be materialized with different parent imports. |
| Current eligibility | Recheck registered policy/runtime/owner binding, context correspondence and artifact integrity before use. Changed/corrupt/withdrawn or missing support refuses; do not silently continue with a cached success flag. |

`LocalSnapshot.lean` is **not** a drop-in modern-module implementation. Its
writer uses `isModule := false`, one `chunk.olean` and a private persistence
chain (`writeCheckedBatch:104-149`). The ordinary bridge instead emits five
modern parts and validates normal private/exported imports. Reuse the protected
event/commit pattern, not those incompatible artifact representations.

## Commit, recovery and retention

The sidecar record is committed last, atomically, after the child has closed
cleanly and every generated part and required parent remains bound. Partial
files or a pending record are ineligible. A crash before commit leaves an orphan,
not an anchor; a crash after commit leaves a valid anchor even if reporting to
the caller subsequently fails. Never reread a saved PASS file to recreate the
missing live checking event. `ordinary_admission.py:615-653` already documents
this live-event and linearization-point distinction.

An uncertain child cleanup must block further export/anchor work against the
possibly affected store until resolved, rather than minting a receipt. Do not
automatically invalidate unrelated accepted mathematics merely because an
export failed. Parent artifacts are retained while descendants depend on them;
missing files cause an availability refusal, not weaker acceptance. An initial
bounded explicit retention policy is enough; automatic garbage collection,
distributed leases and a general transaction engine are not prerequisites.

All-anchored requests may return the existing checked module without a native
worker, but must still verify registry authority, current eligibility, exact
bindings and protected artifact closure. That is a genuine local reuse path,
not permission to accept a caller-supplied binary by its manifest.

## Cost claim and smallest remaining decision

With anchor `A` and newly required units `D`, the promised removal is mandatory
*proof recollection and kernel replay* of `A`, and the 32-unit cap can apply to
`D`. Do not claim constant-time reuse: integrity hashing, import-chain metadata,
environment loading and memory may still scale with the selected anchor closure.
Cold consumers without a local anchor still need checked evidence or another
supported warrant. This change does not prove global growth, solve search recall
or make every large mathematical context fit this PC.

Proceed to a minimal source contract for the registration event, exact anchor
record and closure-cut API before implementation. No timing experiment is needed
to justify this direction. If the proposed contract can only authenticate an
anchor by recollecting/re-encoding all of its old proofs, or by trusting an
external manifest, stop and revise it before writing a larger prototype.

### Refinement made during review

The first exact record schema named a target-dependent materialization key but
did not retain the corresponding compact original target list. Reading the old
proof-containing request merely to recover that list would undermine warm reuse.
The final contract adds explicit immutable bounded `targets` and recomputes:

```text
key = H("DMKN-ORDINARY-ANCHORED-MODULE-V1\0",
        canonical({support_id, parent_anchor_id, targets}))
module_name = "DMKNBridge_" + key.
```

The exact parent AnchorID transitively commits its artifact representation and
imports. Thus changing the imported materialization cannot silently reuse the
old module name. The parent is not replaced by a same-named theorem or a local
context label. The contract also now includes the owner facade/registration
call path in the support pin set where it gates the live event; the implementer
must enumerate that set during source review rather than infer compatibility
from a whole-package or query-only hash.

### Assessed boundaries

- The sidecar is a protected local realization registry under the existing
  owner lock, not a second mathematical database or a peer-accepted ledger.
  STORE binding, exact-ID addressing, live Grant identity and commit-last
  publication preserve the local event distinction. Historical reports and
  arbitrary preexisting artifacts cannot bootstrap registration.
- Only new whole-unit metadata is stored per child. Loading the selected chain
  checks every registered binding against the current warranted context,
  rejects repeated unit ownership/name conflicts and verifies all required
  artifact parts. This is sufficient for the stated inductive realization
  argument without decoding old proof inventories.
- The pure `AnchorFrontier` is explicitly caller-authenticated input, not a
  new warrant. It validates canonical name/ID and unit/output relationships,
  whole-group uniqueness, limits and current warrants before cutting traversal.
  The unchanged planner receives basis plus anchored bindings, not the entire
  accepted context, so unanchored work cannot be mislabeled as reused.
- A nonempty delta retains existing 32-unit/4-MiB limits and real private/public
  insertion checks. Explicit full-chain artifact mapping and exact direct-import
  headers prevent accidental resolution through unrelated project files.
  Legacy one-part snapshots remain excluded. Transparent semantics and the
  theorem-erasure compatibility refusal are preserved.
- Empty delta has a separate result: the same existing AnchorID/module chain,
  a separately stated current target request, zero fetches/native calls and no
  new registration. It cannot rewrite the immutable original target list or
  fabricate an empty checked module. An all-installed-match residual may still
  refuse rather than inventing a new module.
- Staging failures leave ineligible charged orphans. Only the final record's
  no-overwrite namespace publication commits. A later error cannot revoke that
  record; explicit exact-ID lookup resolves uncertainty by checking existing
  committed state, not reconstructing authority from a saved PASS. Missing data
  fails closed. Uncertain worker cleanup blocks this sidecar, not unrelated
  accepted mathematics by default.

### Implementation obligations, not reasons for another broad experiment

Source review must check the actual private Grant/call path, canonical record
schema, dependency-specific support pins, stage-versus-commit ordering, exact
five-part import resolution and two-view child rereads. The contract's existing
profile verification must remain operative even with its narrower compatibility
key. Quotas must include orphans and copies without treating reserved storage or
failed work as free. Initial sidecar creation must fail closed on incomplete
state; it must not adopt a malformed directory on the next invocation.

These are finite implementation boundaries. They do not justify rerunning the
already successful query/discovery campaign or a 33-unit native stress test.
Focused pure cut/record controls and one genuinely incremental native use can
test the new boundary after source review. Hashing/loading the selected anchor
chain may still cost O(its bytes/metadata), and cold onboarding, large single
units and independent-host deployment remain outside this change's guarantee.
