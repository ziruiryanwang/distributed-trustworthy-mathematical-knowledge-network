## Why the construction preserves the intended boundary

The conditional argument is: authenticated selected support and one protected
eligible owner context supply exact warrants; the collector binds complete
original units and every reached import to those warrants; private installed-Init
basis comparison establishes the intended foundation correspondence; unchanged
kernel checking establishes the selected extension; a second unchanged check
establishes compatibility with exported Init; exact inventories survive writing
and rereading. These premises justify the **locally generated** module. A string
in a request, custody possession, file hash or successful source elaboration alone
does not establish any of those mathematical premises.

### Full-proof closure

The collector requires the exact pinned 581-row full basis inventory and checks
all basis SymbolIDs against the injected actual context. It validates every
selected target's ExportID/UnitID, every fetched complete evidence document,
every group member and every direct import, including imports used only by a
theorem's proof. It never replaces theorem values with assumed interfaces.

The foundation-only dictionary passed to existing `A._plan` is explicitly inert
structural planning, after actual warrants have been checked. It intentionally
prevents full-context planning from classifying all accepted units as already
reused. The existing planner revalidates bindings, rejects conflicts/cycles and
orders complete groups. No such dictionary is passed to owner adoption.

Inputs are detached before warrant/fetch callbacks; callbacks receive fresh name
structures, not live parsed unit lists. Complete immutable evidence and returned
request/inventory bytes are preserved. Counters and limits cover selected units,
bytes, names, nodes and import edges. The fetch callback must bound acquisition
before allocation and share the enclosing budget; the pure function cannot
prove that an arbitrary callback supplies genuine authority or bounded I/O.

### Native construction and modern module visibility

Private installed Init is compared directly against the full pinned basis using
`Export.compareSourceBasis`; no whole-source census is added. Allowed decoder
references are restricted to that basis and preceding selected outputs, not all
names incidentally present in Init. `CheckedExtension.checkBatch` is unchanged:
`doCheck := true`, complete real declaration values, exact generated inventories,
no fresh axioms/unsafe/partial declarations and no overwritten names.

The implementation deliberately differs from the initial seam's proposed
single private-import/modern-header construction: **two real checks** run, first
over private Init for correspondence, then over exported Init for ordinary-use
compatibility. The actual second environment is written. This is an explicit
one-time cost, not a synthetic `isModule` toggle or `import all` shortcut.
Full selected inventories are checked in both writer views. Existing exposure
repair can expose only newly checked recursors, not hidden imported basis records.
Unsupported generated visibility or unavailable conversion semantics refuse.

The pinned Lean 4.34.0 source APIs were inspected. `finalizeImport` defaults
`isModule := level != .private`; `mkModuleData` writes stage-two additions and
filters exported records through the public view. `writeModule` genuinely emits
three olean parts plus two IR parts. `ImportArtifacts.ofArrays` has exactly the
used shape `#[#[olean, server, private], #[irSig, ir]]` (`Lean/Setup.lean`).
Although the importer may opportunistically load private parts, its exported
`mainModule?` still selects exported data when `importAll = false`; the public
reread is therefore not silently a private import. Both rereads verify module
header, complete own-name census and exact inventories. Actual compilation and

The imported runtime, installed Init and checker are owner-adopted support, not

bridge addresses useful mathematics otherwise available only as commons evidence.

small module workload would establish this practical interoperability seam, not
