## Dependency-injected API

```python
collect_closure(
    admission_api=A,
    semantic_id=S, foundation_id=F, context_root=R,
    inventory_raw=exact_fixed_inventory,
    targets=[{"name": encoded_name, "export_id": export_id, "unit_id": unit_id}],
    module_name=encoded_single_DMKNBridge_name,
    warranted_symbol=warranted_symbol,
    fetch_evidence=fetch_evidence,
    check_budget=check_budget,
    limits=Limits(),
)
```

The selected already-loaded admission module supplies current E/S/PE and `_plan`;
it is never imported by a path from candidate data. This helper imports only the
standard library. `warranted_symbol(name)` must query the caller's single actual
eligible protected context, returning its exact SymbolID or None. It is not an
index claim, custody membership, caller target string or remote attestation.
The controller must hold that context stable during this operation. The helper
memoizes exact queried names and does not enumerate the full owner context.

`fetch_evidence(name, ExportID, maximum_bytes)` returns complete immutable bytes
or None. It must enforce the maximum before reading/allocating and use the same
original acquisition/deadline allowance. If following custody locators, the
controller should reuse ordinary_contribution's validated locator pattern and
the existing OrdinaryStore methods. The helper independently reparses the
actual bytes and verifies the requested name/ExportID/UnitID binding. It does
not trust a locator hash as mathematics. No implicit fetch retry exists.

`check_budget()` is invoked before/after external callbacks and throughout
bounded traversal/planning. Callback exceptions propagate without being
reclassified as mathematical invalidity. `MODULE_CLOSURE_NOT_WARRANTED` means
the selected context did not warrant a needed name;
`MODULE_CLOSURE_WARRANT_MISMATCH` means it warranted a different exact identity;
`MODULE_CLOSURE_EVIDENCE_UNAVAILABLE` means a warranted dependency's bytes were
not supplied. These are different outcomes. A generic retrieval exception is
not silently converted to absence.

## Closure and identity invariants

1. S/F must equal the selected current semantics; inventory SHA must equal the
   fixed inventory committed by F. All 581 genuine basis identities are checked
   against the actual owner warrant callback. The complete inventory, including
   theorem values and kind-7 quotient rows, is retained unchanged. No authoring
   theorem-signature projection or dynamic installed-Init boundary is used.
2. Each target binds name, UnitID and ExportID using the current semantic formula.
   Basis-only targets refuse: approved normal Init import is cheaper and needs
   no bridge. Target JSON is copied before invoking external callbacks.
3. Each reached nonbasis unit is fetched at most once. Its exact canonical
   portable bytes bind its full raw unit and ordered direct imports. Its target
   and every generated group output must match the selected owner's exact
   warrants. Overlapping groups, basis-name collisions and changed target units
   refuse; a missing group member is not supplied by name alone.
4. Every direct import is traversed, including names occurring only inside proof
   values. Only the verified fixed basis stops traversal. Complete theorem
   values remain present; no signature-only unit, new axiom, proof deletion or
   name rewriting is generated by this helper.
5. Reuse admission's existing pure `_plan` with an explicitly inert dictionary
   containing **only fixed-basis bindings**. This is not the actual owner
   context, an adoption object or a checking receipt. It is never returned as
   one. `_plan` supplies exact import/group/conflict/cycle checks and deterministic
   topological ordering. Reused IDs must be empty and every fetched unit must
   appear in its rechecking order. Calling normal preflight on the full owner
   context would incorrectly elide all rebuilding work as already reused.

Under the actual-context callback premise and collision resistance, the returned
ordered full evidence therefore describes precisely the warranted selected
closure above F. The stronger conclusion that a new ordinary module realizes
that closure additionally requires the native builder's unchanged checking,
private inventory correspondence and public-import compatibility. The labels
alone never establish those premises.

## Exact native request agreement

```text

```

The request is canonical JSON. `module_name` is one encoded ASCII string,
`DMKNBridge_` followed by 64 lowercase hexadecimal characters; it is not a path.
`targets` contains selected encoded names in original caller order. `unit_ids`
and `units` have matching deterministic dependency-first order. `units` contains
the current codec's raw unit arrays, not portable evidence envelopes. The
controller keeps the exact `ordered_evidence` alongside the request; native
labels/IDs are echoes, not native cryptographic validation. The full fixed
inventory is a separate byte-exact input. Root must bind the request and evidence
bytes to the actual selected builder invocation and retain its results.

The frozen result also includes target/basis bindings and counts. Mutable parsed
documents are not returned. A module-name hash is caller selection, not a cache
validity proof: root's cache key must additionally bind the writer/runtime/export
policy and actual unit identities, with operation context retained as provenance.
The mathematical cache key must **not include the mutable full context_root**:
unrelated accepted growth must not force a rebuild of an unchanged selected
closure. The actual context is the source of build-time warrants/provenance,
not the identity of that reusable mathematical closure. Root owns module-name
and cache-key derivation; this collector accepts neither an unverified cache hit
nor a cache claim in place of actual selected evidence.

## Resource and reuse boundary

Default and hard ceilings: 32 targets, 32 units, 4 MiB per unit, 4 MiB total
evidence, 4 MiB native request, 131072 unit nodes, 4096 selected output names,
32768 import edges. The fixed 581-name boundary is additional fixed work, not
charged as 581 selected declarations. Native-request overhead can cause refusal
even if total evidence fits; it does not enlarge the cap. A future local operator
must explicitly select any wider supported envelope rather than retry here.

For a successful closure, fetched bytes and warrants depend on the fixed basis
plus reached units/names, not unrelated corpus size. Existing `_plan` reparses
the bounded selected units once and uses a heap for deterministic ordering.
The collector does not reproduce that algorithm. The caller's existing
`catalog.context` validation can still walk local metadata lineage, and the
selected proof closure itself may be large. This helper removes neither cost
and does not provide succinct cold verification.
Future separately checked reusable module boundaries could stop repeated prefix
rebuilding, but that mechanism is not implemented by this Init-only bridge.

The point of the bridge is paying an explicit selected rebuild once to obtain
normal reusable local Lean modules, not replacing approved packages that already
contain the result. Public source integration, normal import use and practical
cost benefit remain unexecuted obligations.
