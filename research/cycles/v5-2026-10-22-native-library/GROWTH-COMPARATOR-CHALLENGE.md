# Growth challenge: what changes the outcome, not merely the delivery route

2026-10-24. `cold_intake_strategy`, under root's explicit independent assignment.
Source/theory only: no experiment, source import, owner opening, native build,
network operation or Git mutation. This note does not predeclare the selected
eight-call ordinary-reference workflow successful. Its source review and actual
outcome have separate owners. The full usable-v5 objective remains unchanged.

## Decision in plain language

The commons can be valuable as **a practical way to make independently produced
mathematics discoverable and safely reusable**. It does not need a proprietary
mechanism that outperforms every possible implementation of ordinary sharing.
Git, ordinary Lean libraries, a shared formal index, and this software's inert
evidence/checking route are competing or cooperating implementation choices.
The best existing combination belongs in the product when it wins.

However, a successful exchange of four small theorems is not evidence of faster
research. Nor does a theorem about a supercritical reproduction matrix establish
that our particular software creates such a matrix under equal resources.
The highest-payoff next growth decision is to isolate **one genuine friction**
that prevents already-funded work from becoming another agent's usable input,
and justify removing that friction against the strongest simple route. Do not
invent a difficult theorem merely to rescue the preferred transport.

This is not a proposal for another protocol or test campaign. It challenges
the comparator and causal interpretation of the mechanisms proposed in
[PRACTICAL-NEXT-DECISION.md](PRACTICAL-NEXT-DECISION.md).

## Four claims that must not be substituted for one another

Let a finite evaluation history specify exact formal endpoint statements,
foundation/checking policy, initial libraries and caches, an aggregate resource
budget, participant opportunities, and a finite retention horizon. The endpoint
set is an evaluator's instrument; it is not a network-wide task list or an
input about human intention to mathematical acceptance.

1. **Valid accumulation:** additional warranted declarations become available.
   A known theorem with another proof can satisfy this, without novelty or speed.
2. **Access expansion:** an agent can now obtain/use a result it could not access
   through the earlier route. Copies at several agents increase distributed
   access, not the number of distinct global mathematical results.
3. **Capability or productivity improvement:** the same aggregate resources
   yield more predeclared independently checked endpoints, or lower full cost
   for the same endpoints. This requires a causal counterfactual.
4. **Implementation advantage:** this commons implementation improves on an
   equally capable ordinary sharing implementation. This is stronger than (3)
   relative to genuinely isolated agents and is not required of every component.

The existing checked-reference workflow targets (1) and a prerequisite for (2).
Its default-simp/notation and generated-delta boundaries matter for real use.
It is neither a speed comparison nor evidence for (3) or (4).

Fixed-foundation mathematics has the old logical-omniscience distinction:
adding a proved lemma need not enlarge ideal deductive closure, while it can
change finite agents' access and capabilities. The resource-bounded account in
[PHILOSOPHY-OF-GROWTH.md](../v4-2026-10-02/PHILOSOPHY-OF-GROWTH.md) remains apt.
No additional metaphysical commitment is needed to justify the software.

## Comparator simulation lemma: why ordinary sharing is not the enemy

Fix a commons policy C and a comparison policy class G. Suppose G can:

- receive the same immutable artifacts and public discovery metadata at the same
  times, without privileged hidden result IDs;
- run the same mathematical checker, local reasoning and caching algorithms;
- simulate C's send/receive/state operations at no greater charged cost and
  under the same resource/assurance constraints.

**Lemma.** Some policy in G has exactly C's checked output trace and no greater
cost. Thus C cannot strictly dominate the best policy in G for this history.

**Proof.** Start with equal mathematical and local policy state. Induct over C's
observable events. The simulator takes the corresponding local computation or
delivery event, preserving accepted outputs and state, and charges at most its
matched cost. Induction gives the same final outputs and the summed cost bound.
The same construction couples randomized policies using the same random bits.

This is a conditional simulation argument, not a claim that today's unmodified
Git command implements formal discovery or independent checking. It forces the
author of an advantage claim to name the missing premise: discovery latency,
selective proof transfer, safe data-only admission, availability, compatibility,
or integration labor. Each may be real; none follows from the word decentralized.

In particular, a deliberately batched "static library" is not the strongest
Git baseline if ordinary branches, pinned commits, mirrors or immediate pulls
could serve the same need. A real release policy or review delay may be modeled,
but must be a genuine workflow constraint, not imposed solely on the control.
If the ordinary route incorporates the useful new index/check adapter, that is
successful technology transfer, not a failure of the mathematical commons.

## Equal research budgets and the causal intervention

Compare whole histories, not a recipient's cheap tail to another participant's
entire discovery. Both arms get the same initial Lean library, proof tools,
cache capacity and available optimizations. Charge all producers, recipients,
index/custody/service operators and failed work against the same aggregate
budget. A theorem already installed in both arms is not a network discovery.

A clean early intervention holds funded producer activity fixed and changes
only the sharing/reuse route. This can establish transmission/integration
effects. It does **not** measure the long-term feedback by which exposure changes
what agents choose to research. A later adaptive-history claim needs both arms'
changed research allocation and all costs, including failed explorations.

This leads to a useful distinction about sunk work. If a producer would have
made the same discovery in both histories, its identical production cost cancels
in their difference, although it remains in both totals. If the commons induces
that discovery speculatively, its cost is incremental and cannot be declared
free because a later recipient sees only a short proof application.

Use rates need the same care. Repeated warm uses by one agent are not repeated
cold proof searches. A cache-aware comparator can generalize once and reuse its
own method. Merely mentioning the remote theorem in a proof demonstrates a
dependency, not that the theorem was necessary or cheaper than available tactics.

## A useful sufficient theorem that does not assume hard proof search

We can establish **composable capability delivery** without inventing a lower
bound for all possible mathematical reasoning algorithms.

Fix a finite, predeclared family Q of distinct formal endpoints. For each q in Q
specify a concrete supported proof-construction procedure that requires a finite
set S(q) of exact reusable methods. Assume, for each required method:

1. It was actually produced under the charged history and the required checking
   policy, or has an explicit production cost/bound in that history.
2. Discovery and acquisition return its exact warranted interface within their
   stated charged resource bounds; required transparent semantics are included.
3. A supported composition argument gives a checked q from those interfaces,
   with a finite bound on local proof construction, conversion and checking.
4. The *aggregate* bound includes shared investments once, all per-owner checking,
   failures and service, fits the budget, and meets memory/deadline constraints.

Then that history supports every q in Q within the stated aggregate budget.
Proof: induct through each finite acyclic dependency/construction plan; premises
are warranted before use, the specified local inference preserves validity,
and the bounded event accounting fits the aggregate allowance. Shared resources
can be charged once only when an actual retained reusable object serves both
uses; otherwise separate receiver costs remain.

This is stronger than counting stored artifacts: it gives a constructive map
to external endpoints with charged acquisition and application. It supplies an
absolute capability guarantee, not an advantage over a baseline that may also
solve Q. It is applicable to parametric methods, algorithm correctness lemmas,
transport principles and interface bundles, not just long proof witnesses.

For a strict comparative success claim, supply a separate baseline upper bound
on achievable endpoints. For example, under a specified stochastic workload and
specified baseline policy, if each q has baseline completion probability at most
epsilon(q), while the constructed route has at most delta(q) total delivery/
construction failure probability, then its expected number of completed distinct
endpoints exceeds the baseline by at least

    sum_{q in Q} [1 - delta(q) - epsilon(q)],

provided the aggregate budget premise holds in both histories. No independence
between endpoint failures is needed: linearity of expectation suffices. If stage
failure bounds are conditional on earlier successful stages, a union bound gives
delta(q) at most their sum. A positive sum proves a specified-policy difference.

The difficult new premise is epsilon(q), not the displayed subtraction. It can
come from a justified bounded algorithm model, retained deterministic trace,
or suitably independent evidence; "the local library lacks this lemma" is not
such a bound. An alternative proof or tactic may defeat it. Do not present this
as a lower bound against arbitrary mathematical ingenuity or all Lean users.
Where no defensible epsilon exists, retain the absolute capability theorem and
state that comparative productivity remains open. That is honest scientific
scope, not permission to label the full v5 goal complete.

## Complementarity: correct model, misleading cheap proxies

The supplied catalytic-hypergraph text correctly notes that methods can be
complementary. This has a concrete decision consequence that simple citation or
compression counts miss. Let F(A) measure completed endpoint value when methods
A are available. One endpoint may require both a representation lemma a and a
transport lemma b. Then

    F(empty) = F({a}) = F({b}) = 0,    F({a,b}) = 1.

The marginal value of b increases when a is present. This violates the
diminishing-returns inequality required for submodular greedy guarantees.
Consequently, a rule that rejects every individually unused lemma can discard
valuable coherent bundles. Conversely, assuming every bundle is catalytic can
justify unlimited useless storage. Evaluate a bounded bundle through actual
downstream applicability and costs; do not assign an intrinsic value bonus.

This supports the proposed reusable-method-plus-interface endpoint, but it does
not establish its novelty or superiority over a normal package containing the
same bundle. Newly transmitted executable tactic/instance metadata also cannot
be assumed to travel through inert mathematical evidence. That implementation
boundary must stay in the capability premises.

## Why the supplied exponential-growth models do not yet select architecture

The reproduction result is mathematically valid under its conditional inequality
E[Z_(n+1) | history] >= R Z_n and rho(R) > 1. The problem is causal calibration,
not the Perron-Frobenius algebra. Three missing links are central here:

- **Budget closure.** If every seed funds b positive work units, generation n
  spends work proportional to Z_n. Exponential generations then require growing
  aggregate work unless costs fall correspondingly. At fixed aggregate work W
  and positive minimum work c per materialized contribution, there are at most
  W/c such contributions. Removing this bound by renaming "generations" does
  not accelerate mathematical production per hour.
- **Feedback attribution.** More downstream citations may reflect topical
  popularity, easier tasks, duplicated derivations or more compute. A fitted R
  from successful runs does not establish the counterfactual without sharing,
  and failed episodes must remain in its denominator/resource history.
- **Nonduplicative value.** Splitting one parametric theorem into many wrappers
  can inflate artifact descendants without adding capability. Multi-parent
  outputs cannot earn full independent credit once per parent. A fixed endpoint
  distribution has bounded remaining loss, so permanent positive marginal
  value per new contribution eventually fails on that distribution.

Likewise, bn modules supporting b^n compositions is a coverage statement, not
an inferential lower bound. A common generic interpreter or composition theorem
may already construct the same family cheaply; aliases and vacuous parameter
changes need not be distinct useful problems. The hard hypotheses are genuine
endpoint distinctness, compatible semantics, cheap construction/checking and
improvement against the allowed baseline. No planet-scale experiment is needed
to recognize these logical limits.

Do not build a growth-matrix estimator or tune network topology from guessed
spectral coefficients now. The first supplied text's resource-bounded capability
curve is the more robust primary interpretation; its N-times-average formula
must be applied to cache-aware histories rather than multiplied cold-task loss.
The existing rent-or-buy and finite service-region results already address
conditional investment economics. Re-deriving them would not supply the missing
mathematical/workflow premise.

## Concrete falsifiers and strongest present claims

| Tempting inference | Counterexample or missing premise | Defensible claim instead |
|---|---|---|
| A theorem appeared in B's proof, so sharing accelerated B | The same result is solved by `simp`, induction or an existing generic theorem | Actual warranted reuse; no speed claim |
| A uses one source call and B reuses, so B saved discovery | Source calls hide reasoning cost; the baseline may construct the same proof directly | A specific elaboration/preparation path was omitted |
| Proofs are cached, so growth is scalable | Fresh local context hashing/name reconstruction can grow with the selected branch | No mandatory new checking of already warranted units; other local costs remain |
| Every new peer adds productive capacity | Both comparisons already have the same aggregate compute, or hot-key service saturates | Distribution/access changes, conditional on service capacity |
| Full-library Git transfer is expensive, so selective evidence wins | Sparse/subpackage sharing or an existing warm compatible library may avoid those bytes | Selective transfer under exact matched access/cache assumptions |
| A new abstraction supports infinitely many inputs, so its value is enormous | A cheaper baseline algorithm already covers them; demand may concentrate elsewhere | A compact, checked parametric interface and a stated application-cost bound |

The ordinary-reference architecture has a coherent practical thesis: preserve
ordinary local Lean development, make an exact mathematical delta reusable as
inert data, and avoid repeating old checking once local warrants exist. It is
not yet a proof that a user should migrate an entire library or that broad
research accelerates. Current context/identity/metadata limitations can make
ordinary pinned packages the better route. That outcome should guide design,
not be hidden in benchmark exclusions.

## Minimal evidence, only where it changes a decision

Finish the already selected local-reference workflow. Reuse its results to
settle notation/extension and new-proof authority premises; do not rerun it as
a growth experiment. The proposed two-owner unfamiliar-method endpoint would
settle a different compositional interoperability premise, not by itself speed.

Before any comparative experiment, root should name one workflow constraint
that differs after permitting the ordinary baseline its best simple tactics,
caches, source/package sharing and the same public index. If no difference
survives source reasoning, stop that comparison. Examples that could survive
are owner-unapproved executable source versus inert checked evidence, costly
manual compatibility work, or delayed useful discovery; none is established
merely by selecting a small controlled fixture.

If the difference is representational/API compatibility, one existing artifact
and one independent consumer may suffice. If it is a constant in a justified
cost model, only that changed boundary needs measurement. If it is an actual
research-success probability, an invented local timing test cannot settle it:
use an honest policy-specific claim and later real independent usage rather
than a new expensive certificate or giant-network simulation.

Recommended decision now: retain the ordinary-library/inert-delta route as the
candidate that removes a real adoption obstruction, and treat useful research
amplification as a falsifiable hypothesis about delivery plus application.
Do not expand architecture until a concrete friction survives the comparator
challenge. The current software can eventually be valuable without proving
inevitable or exponential novel research; it still must deliver reliable,
usable reciprocal workflows and honest capacity/assurance boundaries.

## Follow-up: cheap application recipes as portable advice

Root subsequently asks for a focused theoretical challenge to recipe sharing,
not another library protocol. This section is source/theory only. It relies on
neither a completed reference workflow nor newly retrieved literature.

### What changes, and what does not

A theorem says which conclusion follows from which premises. A recipe can add
how a particular local problem is reduced to an application of that theorem:
parameter choices, a checked adapter/transport lemma, and remaining obligations.
It can reduce a reasoner's *selection and instantiation search*. It does not
make the theorem true, remove unproved side conditions, or grant an import warrant.

The useful hypothesis is narrower than "more lemmas help":

> A short, transferable record of a successful application pattern can make
> existing mathematical knowledge easier to apply in structurally related,
> independently selected situations.

This is ordinary procedural advice, not a required global research policy.
It is compatible with mathematical validity being independent of human
intention and with every local agent choosing its own work.

### A minimal soundness argument

Treat a recipe as untrusted finite data, for example an exact theorem identity,
suggested argument expressions, references to explicit checked adapters, and
application-order hints. Its annotations are not accepted proof facts.
The consuming agent resolves identities to its actual warranted environment,
forms the proposed term using trusted local tools, discovers the real remaining
goals, and checks the complete resulting proof under the ordinary policy.

For the simplest case, if

    Gamma |- t : (x : A) -> B(x)    and    Gamma |- a : A,

the calculus's application rule yields

    Gamma |- t a : B(a).

Iterate for a dependent telescope. At each stage later argument types depend
on earlier actual arguments; universe instantiation and conversion are checked,
not inferred from matching printed names. Adapter premises require their own
checked terms. If a recipe instead transports between environments, it needs
an actual type-preserving interpretation/checked transport construction; a
symbol-renaming table is not sufficient for arbitrary definitions.

**Advice-erasure property.** If the only acceptance path is checking the complete
constructed term in the actual warranted environment, removing all recipe text
after construction leaves the same mathematical acceptance judgment. Therefore
a dishonest recipe can cause a bounded failure or wasted effort but cannot,
by itself, justify a false theorem. This claim is conditional on the underlying
checker/profile/import soundness and the stated parser/execution boundary.

It does not hold if a recipe's alleged solved obligations are inserted as
axioms, if a claimed matching theorem type replaces the real imported type,
or if a report that some remote tactic succeeded is treated as acceptance.
It also does not establish computer security: arbitrary downloaded Lean source,
tactics, macros and initializers are executable content. A source snippet must
remain inert advice until an owner explicitly chooses an approved execution
route. A bounded declarative term/application language is a different boundary
from a promise that arbitrary tactic code will be harmless.

The current inert mathematics exchange does not transmit arbitrary newly created
simp/instance/tactic registrations. A recipe that relies on them must name the
missing local prerequisite or use explicit checked applications instead. Local
typeclass synthesis is allowed as an independently charged heuristic; success
and the synthesized terms must still be checked. Unsolved metavariables and
universe constraints are remaining work, not holes the recipe may certify away.

### Cost and search claims that can actually be justified

For a specified local strategy that ordinarily tries applications in order,
suppose the successful one is at position j and failed attempts cost c_1,...,
c_(j-1). A correct recipe reaching the same complete proof can avoid those
specific trials. Its maximum gross trace saving is their sum, plus any actually
eliminated instantiation/adaptation work; subtract recipe production, search,
transfer, validation and failed-suggestion costs. If the ordinary strategy would
already try that application first, this alleged advantage disappears.

This trace statement can be proved from a fixed finite algorithm/history; no
new timing experiment or conjectural general proof-search lower bound is needed.
It is not a guarantee against a better heuristic or a baseline that already
cached the same pattern. A different endpoint or substitution does not itself
establish a cold trial sequence. The producer's successful trace is also not
a generalization theorem: replay under new hypotheses may fail.

Recipe term size can be bounded syntactically using a retained DAG and explicit
substitution/sharing limits. Do not infer linear Lean checking time from that
size: dependent conversion, transparent computation and solving side conditions
can dominate. Finite resource caps give termination/refusal bounds, not successful
completion bounds. An adapter that solves the difficult part may itself be the
valuable contributed theorem; its production and acquisition are not free.

A small recipe catalogue might be more useful than a vast undifferentiated
theorem list because its entries expose application structure. But it does not
eliminate indexing. A consumer still has to find the right pattern from its
own goal and local premises without the answer's hidden name. Joint premise
compatibility, vocabulary mismatch and broad structural keys remain relevant.
Use existing search/preview channels where possible; no claim follows that a
recipe key has logarithmic semantic lookup cost at global scale.

### The Git and causality challenge still applies

Git can store exactly the same theorem, inert recipe data and checked adapter
artifacts; ordinary tools can use the same local interpreter/API. Thus the
recipe idea can improve the commons without proving any unique transport or
blockchain advantage. If it works, make it an interoperable library interface,
not a reason to exclude ordinary pinned repositories from the network.

To isolate advice value, compare theorem-plus-interface access with the same
access plus recipe advice. Both arms get identical initial mathematical facts,
returned theorem evidence, local tools, cache rules and total research budget.
The recipe treatment's extra information is precisely the intervention; charge
its authoring/generalization and delivery. Do not secretly give the baseline
only statement strings while giving treatment ready imports and better tactics.
Any later evaluation should use independently selected downstream endpoints,
not exact replays that a baseline proof cache would already solve.

### Falsifiers that should stop investment early

- The ordinary local tactic/explicit application already finds the proof cheaply.
- The pattern cannot be described or discovered without naming its hidden answer.
- Remaining obligations account for essentially all work; advice removes little.
- Generalization fails on changed parameters, universes, hypotheses or notation.
- Advice only works by executing unapproved remote extensions or bypassing checks.
- Nearly every recipe requires bespoke manual transport into the receiver's
  vocabulary, erasing the advertised integration benefit.
- Recipe metadata, bad suggestions or selected-context costs exceed the avoided
  application-search effort; exact replay savings are already warm-cache savings.
- A standard Lean/package interface delivers the same capability more simply.

No new recipe runtime is selected here. First ask whether one retained useful
proof application can be described as a small explicit pattern using current
trusted local APIs, with meaningful instantiation choices and modest side
conditions. If not, do not build infrastructure to hide that deficit. If yes,
the narrow changed uncertainty is transfer/generalization of that advice, not
another proof-production campaign or a full global index redesign.
