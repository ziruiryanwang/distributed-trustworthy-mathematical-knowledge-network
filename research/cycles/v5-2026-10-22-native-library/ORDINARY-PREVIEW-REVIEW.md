## What the source establishes

### Bounded original type syntax

`ordinary_preview.py:78` first uses the existing evidence grammar for kind,
original names, ordered universe parameters, backward DAG edges, uint ranges,
closed-root scope and name/literal/depth bounds. It then marks reachable
expression and universe indices without expanding sharing.

The reachability cases agree with `OriginalExpr.lean:244`: sort to universe;
constant to its universe instances; application to both children; lambda/forall
to domain and body; let to type, value and body; projection to its argument;
bound variables and native Nat/String literals are leaves. Universe successor,
max and imax edges are likewise covered. The inherited reference census includes
constant names and projection-structure names, not binders or universe parameter
names. Requiring every serialized node to be reachable makes that all-node
census equal the type-root census.

The default total raw preview limit is 1 MiB. The combined node limit is 65,536,
with at most 8,192 universe nodes and 4,096 distinct type bindings. These bounds
are checked before the second reachability pass; a peer cannot grant itself
larger limits. Validation/traversal costs depend on this selected preview, not
on the global mathematical corpus or an expanded expression tree. The parser
does perform a finite grammar pass and a reachability pass, not literally one
total visit per node across all validation stages.

### Exact header and binding extraction

`OriginalDecl.lean:123` produces inventory rows
`[name, kind, parameters, typeDAG, details]`. The preview builder at line 170
selects exactly one claimed row and emits only `[kind, parameters, typeDAG]`
plus identities. It never emits `details`, the descriptor body, another
inventory row, unrelated imports or owner paths.

For each reachable type reference `n`, the builder uses:

```text
if n is in the unit's exact claimed export census:
    ExportID(profile, UnitID, n)
else:
    the evidence's exact direct import binding for n
```

This handles inductive/generated members without recursive self-hashing.
`read_preview` requires binding names to equal the sorted distinct reference
census exactly, refusing missing, extra, duplicate or reordered bindings.
It does not mistake those still-advertised symbol IDs for warranted meanings.

### Raw identity, not mutable parsed claims

`_read_exact_evidence` at line 158 ignores caller-supplied `Evidence.document`,
`.unit_id` and `.census`. It extracts only exact `bytes`, checks the separate
8 MiB evidence limit and reparses through `read_evidence`. For resolution, the
domain-separated raw UnitID is checked before parsing. `resolve` then checks
profile equality and reconstructs the complete preview, requiring exact byte
equality with the original advertisement.

Consequently, subject to collision resistance and these source predicates,
successful resolution means:

```text
the bounded acquired canonical evidence has the advertised UnitID;
the selected claimed inventory header and derived type bindings reproduce
the exact advertised preview bytes.
```

It does **not** mean the claimed inventory is generated by valid Lean
declarations. That still requires warranted import matching, actual native
checking and actual-output comparison. Mutable `Preview.document` likewise
does not create an authority token: public `describe` and `resolve` take and
reparse raw bytes rather than accepting an existing parsed Preview.

### No accidental trust promotion

`describe` explicitly returns
`ADVERTISED_TYPE_PREVIEW_NOT_EVIDENCE_BOUND`. `resolve` explicitly returns
`EXACT_EVIDENCE_HEADER_BOUND_NOT_MATHEMATICAL_ACCEPTANCE`. Both return
`mathematical_acceptance: false` with a further required gate. The wire schema
has exactly six fields, so a peer cannot add a `verified`/accepted flag.

Neither function claims an index commitment, corpus completeness, actual proof
checking, protected catalog insertion or existence in an accepted library.
No file/network/import execution is exposed by the preview. The separate later
index adapter must establish record/preview hash and feature consistency.

## Important limits, not blockers for this seam

- Canonical JSON and reachability do not establish the full canonical Lean DAG
  projection: duplicate nodes or noncanonical postorder can remain advertised.
  `OriginalExpr.decode` independently re-encodes and rejects such representations
  at actual admission. The preview correctly grants no authority before that.
- A mathematical type can itself contain let/lambda terms, literals and proof
  terms in dependent arguments. Keeping the exact type necessarily retains
  those. “Proof-free preview” means excluding the declaration's separate
  proof/value body, not asserting that no expression in a type can be a proof.
- `preview_from_evidence` and `resolve` scan the bounded whole evidence envelope,
  including inert body syntax, before selecting its header. They are not
  proof-body-free *production/verification cost*. Search-time `describe` reads
  only preview bytes. Do not invoke full evidence resolution for every search
  candidate and claim the cheap-preview design is preserved.
- Errors may be `EvidenceError` from the reused grammar or `PreviewError` from
  this seam. The caller must treat both as charged bounded candidate failures.
  Neither is a mathematical invalidity verdict or justification for retrying
  under fresh allowances.
- Byte limits here apply to already-received bytes. Transport, repeated
  candidates and kernel calls still need the parent operation's aggregate
  acquisition/resource/deadline grants. The module does not implement them.
- The discovery-seam document's proposed `resolve(record, preview)` describes
  index binding; this module's `resolve(preview, evidence)` is a distinct next
  boundary. Integration must keep these two assurances explicit rather than
  treating the same verb as interchangeable authority.

## Minimum decision-changing checks before integration

Do not repeat unchanged kernel/index campaigns. One root-selected small check
can cover: a genuine ordinary exported header; an own-unit inductive-member
reference; shared binder/projection/literal DAG syntax; orphan/open-root and
limit refusals; exact header/binding/unit/profile mismatch; mutation of cached
Evidence fields while retaining raw bytes; and explicit false acceptance.

After those checks, the high-payoff next work remains connecting the existing
index to real ordinary admission and source reuse. This preview alone supplies
no discovery/growth result and should not become another isolated campaign.
