## Decision and marginal payoff

Once the selected incremental-module boundary is operational, the next relevant
adapter on this assignment is **explicit extraction of missing complete
declarations from a caller-approved compiled project**, followed by the existing
portable completion and independent admission. Root separately owns the
context-bound query adapter; this note neither duplicates nor reprioritizes it.

The practical workflow is ordinary: a contributor uses a normal Lean library,
authors a new result, and finds that the receiving commons lacks one of that
result's imported lemmas. They should not have to reauthor the result, replace
their editor/tactics, copy a complete library, or purchase succinct certificates.
The retained candidate plus a narrow approved module selection should suffice
when the genuinely missing closure fits the selected resource envelope.

The existing `ORDINARY-LIBRARY-INGEST-DECISION.md` establishes the extraction
mechanism and trust distinction. Its statement that the portable binder lacks
supplement planning is historical: `ordinary_library_package/library_completion.py`
now contains `complete_candidate`; the currently inspected

not a missing proof calculus or new acceptance algorithm.

## Minimum contract

Inputs are (i) the same protected receiver parent and retained request/candidate
hashes already used by installed-Std extraction, (ii) a local owner-approved
finite ordered set of compiled artifact search roots and module names under the
supported exact Lean toolchain, (iii) fresh output, and (iv) the original remaining
allowance. The operation computes the missing target set from the retained
candidate; callers do not substitute a different mathematical target list.

Use a small extraction-specific selection rather than importing authoring's
entire execution configuration. The selection needs at most the existing
16 search roots and 16 source modules, with explicit module/path grammars,
duplicate rejection and runtime precedence. It does not need a project source
body, generated module name, meta-import flags, working-directory scripts,
plugin list, package solver, or a Lake invocation. If an implementation accepts
the existing `TrustedProjectAuthoring` document for convenience, it must derive
and validate this narrower selection explicitly and refuse meta imports; the
authoring object itself does not establish extraction approval.

Approval must be supplied by the local operator, not inferred from an inert
candidate, peer offer or peer-supplied config. Locally approved artifacts may be
loaded but are not hermetically pinned transitive library contents merely because
the toolchain/exporter executable is pinned. Report exactly that distinction.
Existing ordinary-path checks, fixed runtime-before-project precedence, selected
same-version runtime, disabled plugins/extensions and resource supervision remain.
Do not auto-fetch, auto-build, run package initialization, or deserialize a peer
binary. The in-progress Windows long-path decision also applies to these actual
filesystem calls; no separate path workaround should be invented here.

The native request successor should add only the approved search-root selection
and prospective remaining content limits to the existing checked request labels.
Validate them before import. Use one private `importModules` environment with
the shared complete-proof exporter, then exit before admission. Reuse the
existing protected point-lookup protocol unchanged. Targets may be imported
declarations in this extraction-specific operation; the new-contribution
exporter's `CURRENT_MODULE_TARGET_REQUIRED` rule is unrelated and stays intact.

## Exact acceptance claim

Let `K` be the protected receiving context, `C` the unchanged retained candidate,
`M` its actually unresolved imported names, and `U` the newly extracted
supplementary units. The completed plan must satisfy:

1. Supplement target names are exactly `M`; original candidate bytes, targets,
   claimed IDs and parent selection remain unchanged.
2. Every cut import is an exact symbol ID returned by a protected lookup in
   `K`. A familiar source name alone is not a warrant or a semantic-equivalence
   certificate.
3. Every remaining dependency is either an earlier complete unit in `U`, an
   earlier complete consumer unit where permitted by existing ordering, or a
   warranted boundary import. Supplemental units cannot depend forward on the
   consumer. No new output collides with `K`, another supplemental output or a
   consumer output. Inductive groups remain whole.
4. Supplemental outputs remain provisional until the existing receiver checks
   the ordered `U ++ C` batch. Do not insert them into the protected parent to
   satisfy the binder. READY/extraction success is not mathematical acceptance.
5. The existing final receiver policy checks complete safe declarations, exact
   generated-record agreement, permitted foundation/axioms and all aggregate
   limits. The adapter adds no new axiom or trust mode.

The consequence of successful final admission is the receiver judgment
`Gamma_K |- rho(p) : rho(T)` for the exported term and statement under the exact
accepted name interpretation `rho`, conditional on the existing checker
assumptions. It is not an isomorphism between the entire local project and `K`,
nor evidence that all same-named local and received declarations mean the same
thing. Return the exact admitted statement/bindings and preserve the original
candidate; human-intention comparison is not part of this protocol.

Modern Lean public imports may expose an axiom-shaped theorem interface without
the proof value. The extractor must request the compatible private artifact
environment and find a complete safe nonaxiom record. Missing private parts,
an axiom record, unsafe/partial code or unsupported declarations cause refusal.
Neither a public signature, a compiled binary, nor a scratch theorem assumption
recovers the missing proof. Do not relax the receiver to make a project pass.

## Cost contract: prevent predictably wasted extraction

The current public completion envelope is 32 combined units, 4 MiB combined
input, 131072 combined nodes and 4096 selected names/bindings. The native
installed-Std exporter currently permits up to 1024 units, 2097152 scan nodes
and a 64 MiB serialized bundle, so it can complete work that the public controller
will inevitably reject. Generalizing the importer should not preserve this
avoidable mismatch or silently raise all public limits.

From the already validated retained candidate compute at least:

```text
remaining_units = public_unit_limit - consumer_unit_count
remaining_bytes = public_input_limit - exact_candidate_byte_count
remaining_nodes = public_node_limit - validated_consumer_node_count
```

Refuse before native import if any required remaining capacity is exhausted.
Pass these bounds prospectively to the extractor. Bound unit count and traversed
nodes during export, unit JSON size during encoding, and the full supplement
envelope before writing it. JSON/statistics/binding overhead is part of the
supplement byte limit; summed unit bytes alone are not sufficient. A conservative
early cutoff is acceptable if reported as a resource refusal. The final existing
combined planner remains authoritative and checks the exact aggregate quantities.
Do not equate native traversal counters with portable node counts without an
explicit correspondence; distinct conservative caps can coexist.

For missing closure `U` and reached protected boundary lookups `B`, selective
traversal/checking avoids replaying proofs behind the known boundary. However,
private module import can deserialize the selected modules' transitive artifact
environment, and missing inductive-group recovery can require a bounded census.
Thus total source-side cost is not proved `O(|U|)` and is not independent of the
selected library. Use narrow module selections and one extractor environment;
do not start a large cold-library campaign just to demonstrate the adapter.

Native work, failed lookups/extraction, retained bytes and subsequent admission
must remain charged. Distinct explicit CLI calls are distinct charged operations,
not a reason to repeat authoring or hide failed work. Incremental local anchors
help warm ordinary exports after acceptance; they do not make a new large missing
closure free. The historical ReadFootprint closure was 2852 units and about
49.5 MB, outside this public envelope. Its legacy recovery is not generic public
support and should not be rerun as the next test.

## Do not confuse ingestion with full project compatibility

Successful extraction/admission does not by itself guarantee that the admitted
result can be installed under every existing ordinary library environment.
The current module bridge permits exact installed singleton-theorem matching;
existing definition/group collisions are separately refused. General-project
extraction does not resolve those collisions, incompatible foundations, absent
private proof data, large cold onboarding, arbitrary tactics or version mismatch.
These boundaries should be explicit diagnostics, not implicit retries or renamed
declarations with changed semantics.

The useful default remains conventional pinned-package sharing when collaborators
need most of the same library and approve its code. The commons should complement
that workflow with selective discovery, inert exchange, independently checked
extensions and custody. No claim is made that our extraction route is always
cheaper than ordinary library imports with comparable caches and assurance.
