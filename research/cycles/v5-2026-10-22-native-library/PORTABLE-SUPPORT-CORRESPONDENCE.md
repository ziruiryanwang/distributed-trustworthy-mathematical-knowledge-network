2026-10-23. Root source argument for the selected ordinary-library transition.
This is not a migration result, portable certificate or authority conveyed by
downloading this document. No new native runtime is selected here.

## Scope and purpose

We need a contribution to have the same mathematical identity at different
nodes without including one machine's paths, checker binaries or local store
in that identity. We do not need to rerun accepted proof checking merely to
replace those metadata identifiers. The one-time owner-local transition is
justified only when it preserves the actual interpreted declarations.

The eligible V1 profile is exactly:

```text
fd23ae289706e5a3277a3c4304de83d65498755dd014b234810e79539f5c8219
```

The implementation must derive it from the canonical retained profile bytes
and compare the root-selected manifest; a prose transcription is not an input.
The check lineage begins with the original basis and three ordinary checked
batches, and may include the independently audited seven-unit successor.
Original records, complete evidence, failed history and snapshot bytes remain
retained. An arbitrary peer's database cannot become eligible by supplying
matching-looking marker fields or a PASS file.

## Identifier-translation argument

Suppose an eligible checked prefix K has old name bindings B and portable
bindings B'. Maintain the invariant that B(n) and B'(n) name the same actual
declaration in K, despite unequal identifier hashes.

Base: reconstruct the exact fixed inventory from its authenticated bytes,
match every old basis name/ID, and derive portable basis IDs from S, F and
the unchanged original name. This renames metadata for an already checked
basis; a count of 581 names alone cannot establish the invariant.

Step: recover the exact retained V1 unit and its ordered complete direct
imports. Verify old imports against B and original unit/output identities
against the accepted root record. Replace only the envelope identity/schema
fields and import IDs with their previously paired B' IDs. Preserve the raw
declaration unit bytes and every name. The Lean decoder consumes those raw
units and original names, not envelope identity hashes. Therefore, by the
prefix invariant and unchanged interpretation, the actual judgment and output
declarations are unchanged. Extend the pair map by the corresponding outputs.

The proof depends on the source's actual accepted lineage and the same checker
interpretation. A syntactically successful translation of unknown or false
claims proves neither premise. The pure translator intentionally carries no
acceptance authority.

## Native snapshots and activation

Local root handles can change, but copied snapshot bytes and their embedded
module names and parent-module names cannot. The portable catalog must store
these names explicitly rather than derive old modules from new root handles.
When extending an imported context, the existing native worker receives the
exact actual module/import plan. It checks only the new raw units and writes
a new delta with the new grant's module name and the original parent module.

Only the owner-local importer can activate the fully validated selected chain
in a fresh destination. Before activation it is unavailable to normal use.
Original checking support and translation support are recorded separately;
an imported record must not pretend it was newly checked. Local state integrity,
no unauthorized rollback and applicable support-withdrawal assumptions remain.

## Required next discriminator

The correspondence establishes the reason to avoid replay, not that the new
Python implementation is correct. Focus controls on exact import/byte/name
preservation, ineligible source/refused activation, original module preservation
and live-grant discipline. One small actual extension above an imported parent
will test the changed catalog-to-native handoff. Do not rebuild or recheck the
old accepted proof corpus as a substitute for these narrower obligations.
