## Completion: independently derived obligations

The unchanged `portable_candidate.bind_candidate` is the reference boundary.
The proposed first-bind/combined-bind strategy is sound in principle only if
the first call uses the real protected parent and validates the original graph
before obtaining its missing set. A second bind must still use that real parent;
supplemental exports are earlier new declarations, not accepted parent facts.

Required negative distinctions for actual source review:

- A supplement when nothing is missing; duplicate, extra or omitted missing
  targets; a requested supplemental target absent from its inventory.
- Wrong S/F/root or old V1 identity domains disguised by new envelope metadata.
- A forged supplemental boundary ID, original prepared/claimed ID overwritten
  by a supplemental claim, or any parent/output or cross-lane output collision.
- A supplemental unit depending on a later consumer unit; consumer dependence
  on a supplemental helper that the original candidate did not declare missing.
- Malformed original forward/cyclic dependency graph returning NEEDS before it
  is validated; the unchanged binder already rejects this and must run first.
- Aggregate raw input, unit, node, output-name, boundary-row or evidence-byte
  limits exceeded even though both lanes separately fit their own caps.
- A global budget/cancellation or protected-lookup error converted to READY.
- Partial evidence escaping before complete planning; no protected state is
  mutated and the returned plan still states no mathematical acceptance.

Original consumer units must retain identical canonical unit bytes, targets
and prepared claims. Hashes bind input identity, not proof authority. New V2
UnitIDs/ExportIDs come from the existing portable codec/semantics, not legacy
profile-dependent identifiers. Point lookups need one bounded shared cache.
No change to the native checking relation is in this review's scope.
