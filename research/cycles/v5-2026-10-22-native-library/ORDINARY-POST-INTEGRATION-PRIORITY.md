# After query integration: make ordinary reuse genuinely incremental

2026-10-23. Source/theory recommendation by `query_native_boundary`; not a new
implementation or runtime selection. Root owns selection. No compilation,
owner operation, network, product edit or Git mutation was performed for this note.
Public integration is now raw PASS; its independent outcome review remains open.

## One priority and the actual workflow

**Next resolve and, if cleared, implement one exact locally checked module anchor
for incremental ordinary-project export.** A person imports a commons result,
proves something in their normal Lean project, returns that contribution, then
imports the next result. Their previously checked mathematics should remain a
usable module boundary, rather than repeatedly becoming a new full-proof export.
This structural blocker is more consequential than another ranking profile or
another demonstration once the selected query/find/import/use integration closes.

The user has no existing local project to supply. This is a source-established
operability problem, not evidence of real-user demand, broad library support or
positive growth. Preserve that distinction; do not manufacture demand with a
hand-picked short theorem. Ordinary Lean package sharing remains a legitimate
implementation alternative, not a competitor to handicap.

## The blocker is already established; no stress experiment is needed

In `software/v5/ordinary_module_bridge/module_closure.py`, `schedule` stops only
at the fixed basis, traverses **all** imports including proof-only ancestors, and
uses `foundation_only_plan_input` deliberately. Existing owner acceptance is not
an export cutoff. `Limits` permits at most 32 units, 4 MiB total evidence/request,
131072 nodes, 4096 names and 32768 edges. The bound applies to total selected
nonbasis closure, not just newly learned units.

`ordinary_module_matching/module_export.py` calls this collector and describes
prior generated module reuse as unimplemented. `OrdinaryModule02.lean` imports
only Init, decodes only basis-plus-selected names, independently caps units at
32, and checks additions privately and publicly. Exact installed-theorem matches
still arrive in the complete selected closure. They do not change its cutoff.

Consequently a warranted target with more than 32 distinct reached nonbasis
units is refused before ordinary export, even if its new delta is one unit.
That is a direct code consequence, not a claim that the current fixture reaches
the bound. Raising caps moves the wall and retains repeated work. The owner
already has delta snapshots and warm checked reuse; the ordinary bridge loses
that useful boundary. Fix this seam rather than redesigning the whole network.

## Minimum contract: one local anchor, not generic binary trust

1. **Authority.** An anchor is a previously generated, successfully checked and
   reread local module, registered by the trusted local controller. Retain the
   actual successful event, exact request/report correspondence, policy/runtime/
   helper identities, source-context warrant and all artifact commitments. A
   copied `MODULE.json`, arbitrary hash list or peer `.olean` is not such an
   event. Reuse owner receipt/lifecycle concepts, not snapshot bytes: LocalSnapshot
   writes legacy `isModule := false`; this bridge requires modern five-part imports.
   The current export manifest alone is not a new trusted registry.
2. **Exact meanings.** Bind original Lean names to the actual portable UnitID
   and ExportID, ordered universes, declaration/group kind and interface meaning.
   Preserve the full original evidence identity even when public theorems are
   axiom-shaped handles. Require each anchor binding used by the cut to remain
   eligible with exactly that identity in the selected owner context. A spelling,
   source filename, module origin or equal-looking type is insufficient.
3. **Whole-unit frontier.** For target set X and anchor map A, collect D(X,A)
   until the fixed basis or an exact anchored unit is reached. A unit/group may
   be cut only when all its outputs and identity are realized by A; no partial
   mutual group. Every uncut dependency is included and topologically ordered.
   All edges of the new closure terminate in basis, anchor or earlier new units.
   No ambient installed declaration becomes a decoder input just by existing.
4. **Real imports.** Pin one anchor's entire local artifact/import chain, not
   merely its top `.olean`; retain its five artifact parts and approved runtime
   dependencies. Child imports and its module/cache identity include the exact
   anchor selection. Use explicit artifact maps and the existing no-plugin/no-
   extension import controls, not inherited search paths. No arbitrary branch
   merge, peer binary, downloaded source execution or unrelated project import.
5. **Private and public compatibility.** Check the new delta against the actual
   private imported environment and separately against its ordinary public view.
   Reject changed names, universes, meanings, unsafe records and overlapping
   additions. Preserve transparent bodies, reducibility and recursor computation;
   theorem proof irrelevance does not replace these rules. Public theorem
   handles require the anchor's prior private proof warrant, and the actual
   public delta check remains mandatory. Bind actual resolved records, not
   `getModuleIdxFor?` alone; Lean may resolve duplicate theorem records.
6. **Persistent use and failure.** Write only new declarations and the exact
   anchor import; fresh private/public rereads precede registration. The consumer
   must keep the anchor chain available on its ordinary Lean import path. Do not
   flatten it away during packaging or claim the child is standalone. Missing,
   altered, withdrawn or policy-incompatible support makes the anchor ineligible;
   retain failed work uncommitted. Revalidation/rebuild needs a separate explicit
   route and budget, never silent peer-binary acceptance or automatic retry.

Source files used by a later ordinary project are not themselves authority.
Its returned evidence still needs exact extraction/binding/admission. The anchor
cuts only already warranted dependencies; new source dependencies outside it
remain missing work. Original source need not be reread merely to use a protected
checked module, but retain source/evidence needed for recovery or cold transfer.
Local receipt/storage integrity is the existing trusted-owner premise, not a
cryptographic certificate protecting against an owner who forges their own state.

## Conditional soundness and the exact efficiency claim

Let F be the pinned foundation. A registered anchor has an established
interpretation of its selected private records in F and a warranted public-view
relation. Exact immutable imports and non-overwriting additions must preserve
that interpretation. If all new references are in F, A or earlier delta units,
the unchanged checked insertion establishes the private extension inductively.
The independent public check establishes that this particular extension works
through the actual ordinary interfaces. Fresh rereads bind that result to the
saved child. Therefore repeated eligible extensions preserve warrant under F.
This is a conditional argument and contract, not a proved kernel refinement or
permission to skip any unresolved importer/public-view correspondence obligation.

The same **32-unit/4 MiB delta limits** can then bound D(X,A), rather than all
historical units. The anchored units incur no new portable-proof acquisition,
decoding or kernel insertion. This requires a retained checked identity map,
not reconstruction of all old proof inventories on each export. Cold receivers
without this anchor still owe their missing warrant. A large first export or
single oversized unit is not solved by this one-anchor step.

Context/catalog and allowed-name reconstruction may still cost O(K), where K
is the selected local context; fresh integrity reads/imports can depend on all
retained artifact bytes. Anchor chaining does not guarantee bounded RAM, constant
warm time, global search completeness or a physical full-cost saving. Price
registration, retention, integrity, imports and failure recovery too. Bounded
project contexts/batches remain preferable to a single global local environment.

## Decision gate and explicit no-experiment stopping rule

Before implementation, establish by source review that the retained event/map,
frontier cut, exact private/public imports and invalidation rules above compose
without accepting unknown binaries or re-encoding old proof inventories. If they
do not, **stop this route and redesign; do not raise bounds, run a synthetic
33-unit failure, restart certificates, or add a timing campaign**. If they do,
root may select one successor and a small changed-boundary positive/refusal
integration; the existing query and native tests must not be repeated wholesale.

Defer automatic query bindings, cheaper query-only profile loading, broader
applicability search and resident workers until this decision closes. They are
real issues, but manual bindings or exact-key brittleness do not justify a new
LLM service or another toy growth trial. Reassess priorities if ordinary package
reuse already supplies this workflow more simply. Positive net growth remains
subject to the existing full-history, equal-cache comparator, not theorem count.
