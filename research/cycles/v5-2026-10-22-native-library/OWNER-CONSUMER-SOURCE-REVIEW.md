## Owner-use transaction

The command reads the actual command `getEnv`; there is no second module import
or reconstructed unrelated owner environment. All header/file parsing, rebinding,
complete-read validation, local extension construction and diagnostic IO occur
before the sole final `modifyEnv`. A failed `run` returns no candidate to install.
The pre-install diagnostic says ready for authoring, not mathematically accepted.

The header requires its seven named fields, exact schema and equality to all
three controller-selected IDs. Fixed numbered filenames are constructed locally;
no JSON-provided path is opened. Raw file caps precede parsing. Lexical preflight
limits bracket depth, uint64 digit sequences and strings before JSON parsing;
the parser handles the remaining grammar. A single 64 MiB raw budget covers
header and groups, with 1 MiB and 8 MiB per-file ceilings, and sequential callback
indices prohibit duplicate/out-of-order group acquisition. Existing rebinding
limits separately cover rows, encoded nodes, scans and new checking.

The command does not itself authenticate accepted IDs, reject duplicate JSON
keys, establish canonical bytes, prevent local file replacement or authorize
filesystem aliases. Those are explicit immutable-controller preconditions. It
is not a public hostile-source endpoint or an OS sandbox. Pre/post byte checks
are useful evidence but are not a defense against arbitrary local mutation and
restoration during execution.

`BoundContext` uses a private plain `EnvExtension`, not a persistent extension.
The pinned Lean implementation's `.local` mode stores current-branch state
without waiting on other branches; its persistent-extension documentation does
not make this plain extension persistent. The public getter checks the original
main module, and a second use is explicitly refused. This is source-local
correspondence plumbing, not an unforgeable warrant against hostile owner code.

## Export composition argument

Let K be the independently warranted receiver context, B the completed exact
owner correspondence, and U the new exported units. The required premise is:
each B entry denotes the same accepted meaning in K and the owner, with theorem
interfaces treated as interfaces and non-theorem computation semantics retained.

Under that premise, the changed scheduler has the intended cut:

1. Selected boundary names stop before `makeUnit`; their theorem proof bodies
   are not expanded or serialized. Boundary references retain exact symbol IDs.
2. Nonboundary references are converted to existing atomic group-owner keys.
   Every new unit retains the original declaration and complete emitted inventory.
   New axioms, quotient primitives and unsafe/unsupported declarations cannot
   acquire acceptance through this path. An axiom-shaped public handle outside
   B gets an explicit missing-warrant/full-declaration refusal.
3. An emitted unit cannot overlap B. A referenced generated member absent from
   B whose owner is in B refuses rather than treating a partial group as complete.
4. New units are dependency-ordered; missing or cyclic closure refuses. The
   source retains the prior exact codec and independent checking interface.
5. The command requires the same source-local B, a nonimported theorem target
   outside B and nonempty new closure. Its output is inert and never changes the
   receiver context. Imported-source identity checks are read from the pinned
   Lean `isImportedConst` implementation, not inferred from naming conventions.

Thus a receiver that resolves each imported ID in K and independently checks U
can extend K without replaying B's theorem bodies. Export alone establishes
neither the premise nor successful checking. A fabricated helper argument can
produce only claims; it cannot promote accepted catalog state.

The shared old `selected` entry still runs exact fixed-basis correspondence
before the scheduler. The new internal boundaryReferences field is not added to
the historical OwnerExportCommand bundle schema. Existing saved source/binary
snapshots are unchanged; no frozen receiver profile migration follows.

## Import census and cost boundaries

`boundary_imports` is a lookup map, not an envelope import list. `makeUnit.refs`
also contains literal-stage support; scheduling edges use group owners whereas
evidence imports must preserve referenced member names. Integration must derive
each exact envelope import census with `ordinary_evidence.inspect_unit`, resolve
it against the authenticated map or previous new units, then parse and check the
result. Incidental stage-only names must not become extra evidence imports.

Ordinary new definitions/theorems use point lookups and selected traversal, not
a full owner census or ancestral proof replay. A genuinely new inductive group
still triggers one bounded complete local grouping census; this fallback is
reported and is not globally size-independent. The supplied boundary is scanned
linearly up to 65536 names. BootstrapSupport's internal scans/encoding remain
subject to the selected outer CPU/wall/memory supervision; declared limits are
not a guarantee of a hostile-input sandbox or constant memory per unit.
