## Why this direction

The next useful increment must connect actual mathematics to ordinary network
operation, not add a local-only vault or configure a fictitious A authority.
Source review found that the existing mixed packet parser and verifier already
support exact I receipts without any A owner. Only the network profile requires
an A image. An explicit, permanent I-only network profile is therefore a small
real capability, not a new checker or conversion of proof representations.

The narrow correctness argument is restriction: the new profile allows only
tag-0 terminal claims. `parse_packet(..., aggregate_image=None)` rejects tag-1
claims before receipt/native verification. The exact existing ReceiptVerifier
checks I statements, and MixedDeltaVerifier checks every unsealed native delta
under unchanged I/F/P and all closure/resource limits. Custody and discovery
remain untrusted; no profile, packet, offer or saved report creates authority.

This gives a useful deployed mode with bounded unsealed dependency work. It
does **not** solve indefinite frontier advancement: genuine affordable A
certification remains a central open v5 obligation. Keep that distinction in
APIs and evaluation. No new A image/proof is needed for this increment.
