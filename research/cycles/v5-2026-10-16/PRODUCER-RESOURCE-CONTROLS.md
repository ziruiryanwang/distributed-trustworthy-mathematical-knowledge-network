| Control | Assertion |
|---|---|
| Explicit V2 schema | Required resource field; missing field, V1 with/without field, and extra field refuse; no automatic conversion/default. |
| Exact field type/range | Built-in integers 1, 4,096 and 8,192 pass; booleans, zero, negative, 8,193, floats, strings and null refuse. |
| Actual supervisor capability | Profile cannot exceed the supplied supervisor ceiling; malformed non-integer ceiling refuses; lower exact capability is honored. |
| Per-kind request bound | All five stage kinds accept explicit 5,120 within that profile, reject 5,121 and invalid types; retained process/log caps and `P.COMMON` remain unchanged. |
| Whole-profile identity | Different ceilings change the full canonical profile identity; in-place field mutation fails the unchanged profile integrity check. |
| Captured forwarding | One synthetic dispatch records exactly selected 6,144 MiB, not profile maximum 8,192, and matching durable reservation; returns a clean nonzero result immediately. No host or artifact is produced. |
| Incompatible history | An explicitly synthetic prior-record fixture is accepted by the same-profile/budget request validator but rejected after profile or request-budget change. No output attempt directory is created in this control. |

The test invokes the actual V2 constructor. Its inherited installation loader
and build/image adoption are mocked, but field/schema/source-pin/profile checks
remain real. Snapshot adoption is bypassed only to reach resource request
validation. The fake supervisor contains the chosen ceiling and file helpers;
all invocations are forbidden except the one explicitly enabled capture. That
capture does **not** allocate 6 GiB: it only inspects the value passed by actual
controller code and returns a synthetic failed-command observation.

The saved history record is clearly labeled
`SYNTHETIC_LINEAGE_FIXTURE_NOT_AN_EXECUTED_ATTEMPT`; fields unused by the request
validator are null. This isolates its profile/budget comparison without another
old workflow run. It is not an operational PASS, proof, receipt, spend ledger or
real constructor-adoption record. Positive and negative request validation use
the same fixture, so unrelated parsing failure cannot masquerade as the expected
