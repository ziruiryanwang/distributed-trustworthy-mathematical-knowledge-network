## Decision: finish indexed exchange, then qualify bounded referrals

The chosen indexed-peer scope is proper **as an integration gate**: it gives
operation-local exact-key lookup and four-file certified custody over known
contacts. It does not solve finding an unknown holder in a huge population.
Its configured-endpoint rule also deliberately refuses the referrals needed
for such discovery. Merely increasing its contact cap would leave this central
gap unresolved.

The smallest routing successor is an **iterative, budgeted, key-rendezvous
client and referral RPC**, reusing the same indexed-find/acquire/verify interfaces.
No theorem ledger, global peer list, second acceptance engine or central
membership issuer is required. Do not start this successor before the selected
indexed-peer interface and its actual certified loop are qualified. Implement
this boundary only if the priority discriminator below selects routing;
dynamic partition trees, global rankings and universal
semantic search are not prerequisites for this bounded successor.

### Priority discriminator: a local query may be the earlier missing seam

A lookup for one already-known interface ID among100,000 unrelated rows proves
metadata locality, not finding a useful unknown lemma. Common Eq occurrence
keys can repeatedly return128 irrelevant rows; starting a fresh query need not
improve that. A name-erased full-type fingerprint requires knowing the exact
formal shape and ordering, which can be precisely what the agent is missing.
Sending either deficient query through a large overlay does not repair it.

Therefore **do not preselect both a routing implementation and a richer query
engine**. After current indexed qualification, the first cheap decision is a
bounded metadata-only selectivity screen on a known reachable index. Use the
actual A/B capsule types as positives and predeclared well-formed inert type
descriptors as distractors; no new proof or mathematical claim is needed.
Hold candidate ordering, query/row budgets and desired partially specified
mathematical signatures fixed. An evaluator may know positive IDs to score
the test; the consumer/query builder receives no IDs, declaration names, exact
full-type hashes or oracle-selected selective keys. This screen does not prove
growth or universal retrieval quality.

If current queries cannot express the partial signatures, or exhaust their
128 scanned-row budget before a usable positive, choose **one bounded local
structural-type/conjunction seam first**: derive finitely many depth-bounded
telescope/premise/conclusion/application-shape keys from canonical types;
retain referenced meanings, perform no unbounded reduction, choose one indexed
driving stream and test remaining keys only within the shared scanned-row cap.
Cap extracted keys and pattern depth. This is syntactic candidate selection,
not theorem equivalence or acceptance. Do not hand-code A/B-specific features.
Its adoption gate is improved positive retrieval within the same work budget,
with unchanged unrelated-data locality and no increased proof authority.

If the existing query is selective enough on a reachable index but the holder
is unreachable from bounded known contacts, select the routing contract below.
If both fail, fix the cheap local query boundary first, retaining this routing
contract as unselected design. Current evidence supports the necessity of both
boundaries eventually, not a claim that overlay implementation is already the
most productive next code change. The sole current code selection remains
indexed-peer01; this paragraph authorizes no new implementation or runtime.

The proposed numerical caps are prospective engineering test parameters, not
performance evidence or a new unrestricted launch authorization. The iterative
choice is material: an untrusted remote server cannot multiply this caller's
fanout by inventing a fresh forwarded budget. A malicious server can still
waste its own resources; that is not a controllable global resource guarantee.
Server-side request size, parsing, row-scan and time limits remain mandatory.

### Do not hide the hot-key problem

Exact bundle/interface keys normally have few rows. A fixed-support constant
key such as equality may occur in almost every theorem. Faster routing of that
key does not make its posting stream selective or useful.

For the minimal successor, make partitioning explicit and static in the typed
namespace: exact bundle/interface keys use partition0; feature/statement keys
may use an owner-adopted8-bit prefix of bundle ID. An offer goes to its one
partition for each selected key, not all256. A broad query selects at most two
partitions and reports which of256 it covered; it must not silently broadcast
to the rest. A subsequent explicit query can spend another declared budget,
but a library wrapper cannot secretly loop until all partitions/peers are read.
An unsplit exact-key list that becomes hot is capped and reports saturation.

This is intentionally a **bounded partial-discovery** contract, not a claim
that two sampled partitions give adequate recall. Fixed partitioning can still
overload a popular bucket at extreme scale. Finite storage/quota refusal and
incomplete coverage are honest failures of availability/recall, not invalid
mathematics. A future adaptive split directory is justified only when measured
hot-key saturation makes this the next actual obstacle; it must then have
bounded tree-page reads and migration costs, not a global partition manifest.

Do not make a huge-network useful-search claim from rare exact-key tests alone.
The current single-key interface lacks a general mathematical pattern matcher;
most useful queries may require better structural features or bounded local
ranking. Query selectivity, routing reachability and receipt validity are
three separate success conditions. This successor tests the second one.

## Churn, adversaries and metadata are not free

Advertisements are inert leased rows keyed by namespace/key/partition/bundle/
holder. The same holder refresh is an idempotent update, not another theorem.
Keep at most a fixed number of holder alternatives per bundle and exact local
row/byte quotas. A node authenticates the announcing transport endpoint and
binds its advertised holder reference to that identity; this does not prove
custody, honest tags or future service. Acquire still checks exact bytes and
the independent receipt policy. A poisoned posting can waste bounded work but
cannot authorize a mathematical result.

Each lease has a bounded local retention interval. Expiry, failed refresh,
route replacement, repair and re-advertisement use a due-time index and an
explicit maintenance allowance: at most `m` rows/`u` peers/`b` bytes per round.
No hidden scan of all contacts or all retained objects at startup, query or
timer tick. Ongoing work across many rounds is charged; eventual completion
requires supply capacity to exceed the sustained due workload. After churn,
holders re-advertise to bounded new replica candidates. Exact-byte custody can
outlive the original producer, but neither leases nor certificates create a
holder or permanent storage entitlement.

No single globally agreed membership/split epoch is assumed. Replicas can have
different local cuts; a requester unions exact descriptors and deduplicates
without calling that union complete. Missing replicas, stale cuts, partitions,
budget exhaustion and unavailable holders remain distinct outcomes. A route
can be repaired locally while independent mathematical contributions continue.

Conditional liveness requires all of the following: sufficiently stable and
connected routing tables, a reachable entry into the supported overlay, at
least one reachable honest selected index replica with a current relevant
advertisement, an available exact-byte holder, and enough request/maintenance
budget. Balanced well-maintained honest XOR routing motivates expected
logarithmic hops; the product has not proved that bound. An arbitrary Byzantine
majority near the target can eclipse a key. Certificate-derived IDs can be
ground or multiplied, so per-ID quotas and hashed IDs do **not** imply a bound
on adversarial density. A finite owner-selected laboratory population tests
mechanics, not permissionless admission or Sybil-resistant discovery. Any
later admission/independence premise must be stated without installing an
indispensable central issuer by accident.

For `M` advertisements, at most `K` advertised keys each, replication `r`,
descriptor size `d` and average lease lifetime `T`, aggregate index payload is
on the order of `r*K*M*d`, and refresh traffic is on the order of that quantity
per `T`, before routing/repair overhead. These are network-wide costs, not
per-query scans. Selected nodes may decline roles or excess custody. Skew
invalidates a blanket balanced `M/P` per-node claim.

For one query, let `h` be attempted RPCs, `s` examined postings, `z` returned
descriptor bytes and `n_j` the local index size at queried node `j`. Charge
bounded parsing/network work and actual indexed page visits, including possible
per-row primary-key lookup factors; do not assert `O(log n_j+s)` without the
covering-plan evidence. There is no required linear peer-count, unrelated
corpus-size or ancestral-proof term. This does **not** claim constant disk IO:
B-tree height/cache behavior and selected record sizes remain real costs.
Custody acquisition additionally charges the selected four payloads and real
verification. Query/router startup reads no mathematical bodies.

## Decisive successor tests, without another proof campaign

Reuse genuine qualified bundles for integration; inert noise is explicitly
not mathematical growth. Use a small multi-process loopback topology with
local bucket tables, not a controller-injected global peer roster.

1. An entry node does not know the holder or destination shard directly.
   An exact typed key reaches it through at least two referrals; another
   node acquires and independently verifies the existing certified bundle.
2. Grow unrelated synthetic routing/metadata populations, then make unrelated
   blobs and an unselected shard inaccessible. Startup and selected lookup
   must perform no such blob reads, whole-table scan or all-peer enumeration.
   Inspect SQL plans plus actual page/record/network counters; unchanged wall
   time alone is not an access-boundary proof.
3. Fill a common equality-key stream beyond row/storage limits. The route and
   scanned-posting/byte budgets must hold even when fewer than four candidates
   survive filtering. Return explicit partition/cut coverage and saturation,
   not a global empty or complete claim. Do not measure only rare keys.
4. Drop one contacted replica/holder and expire an ad. A bounded alternative
   can succeed if present; otherwise return unavailable/incomplete. Count all
   repair/refresh RPCs separately, including failures. No all-peer rescue.
5. Adversarial referrals exercise cycles, duplicate IDs, self-referrals,
   closest-node lies, wrong certificate pins, forbidden endpoints, giant or
   poisoned postings and timeouts. Verify exact total limits and zero accepted
   mathematical state from metadata alone. A selected bad-density/eclipsed
   topology must terminate honestly, not be expected to discover the target.

Passing qualifies this local protocol/access boundary only. It does not
simulate a deployed huge network, establish recall under arbitrary churn or
prove logarithmic routing empirically from a handful of nodes.

### Producer throughput and honest break-even

Report three distinct views, never mix them:

- **Incremental current installation:** existing backend builds and actually
  retained seed production are sunk; all new offer/search/custody/verification,
  authoring, child certification, maintenance and return checking are charged.
- **New deployment/library investment:** include attributable backend setup
  and seed certification once. Charge shared setup to both certified arms
  consistently; comparison against native-only software cannot simply cancel
  a certificate backend the native arm never needs. Missing historical costs
  remain unknown rather than zero.
- **Reuse amortization:** vary the number of genuinely distinct cold or warm
  consumers analytically using measured cost components. Do not manufacture
  thousands of duplicate theorem runs, count cached receiver checks as fresh
  discoveries or charge native ancestry replay to already warm native nodes.

For a fixed object, write `P_C,P_N` for certificate/native producer costs,
`B_C,B_N` for allocated one-time backend costs, `D_C,D_N` for measured total
maintenance/publishing differences over the observation horizon, and `v_C,v_N`
for comparable per-consumer search/transfer/check/use costs. A constant-cost
break-even prediction requires

```text
R * (v_N - v_C) > (P_C - P_N) + (B_C - B_N) + (D_C - D_N).
```

If `v_N <= v_C` and the right side is nonnegative, no positive reuse count
breaks even in that model. If maintenance or cache regimes vary with `R`, use
the actual sum instead of this linear shortcut. Compare both cold and warm
native checks, and account for interface bytes, definitions actually needed,
network transfer and honest native caching. The matched certified-arm trial
isolates seeded reuse; the separate native-only cost view asks whether the
certificate machinery pays for its additional large-network assurance at all.

Root's current provisional producer estimate is roughly850 CPU seconds per
segment plus200 for associated lift/join, with66 segments for the base pair:
roughly69,000 CPU seconds, **not an adopted full-run measurement**. A few
millisecond receipt checks cannot erase that investment or the independently
charged new-child certificates. Measure actual new `N`, total proof CPU,
public-controller costs and output sizes, including failed stages. Under fixed
available CPU rate `W` and average actual certificate cost `p`, sustained
certified-contribution rate cannot exceed `W/p` without another resource or
algorithmic improvement. Counting two outputs in a batch is not automatically
two useful outcomes.

The result may be negative: simple native local proofs may win overwhelmingly,
even if certified reuse avoids ancestral download. Prioritize producer
throughput next if the completed matched comparison misses its saving bar,
certificate production dominates measured total cost, and the measured cold
receiver saving implies a break-even count beyond the declared plausible reuse
horizon—or no break-even at all. That finding warrants a minimal producer
optimization experiment (measure changed work/CPU without changing acceptance),
not another layer of ranking, attribution or routing decoration. No finite
positive pilot establishes sustained or exponential useful growth.
