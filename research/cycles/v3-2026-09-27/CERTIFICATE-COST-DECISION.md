## Decision in brief

Use the already required certificate campaign to report **history-independent
certified reliance and its actual cost**, not to manufacture a new growth trial.
Keep three statements separate:

1. Source16 already has a scoped reader improvement: 27.184466% less pooled
   reader CPU on the two fixed source14 comparison fixtures, with output parity.
2. If the selected real certificates, cold checks and next-generation composition
   pass, they support a finite **certified reuse mechanism** that does not supply
   parent proof histories to each new consumer/prover. Measure its expense even
   if it is slower than native checking on these small examples.
3. Faster **useful mathematical accumulation** is not yet established. The held
   J/K comparison has no consumer results, and the Fin/L/M/N/P certificate
   campaign is not that comparison. P's Church conjunction is a two-parent
   correctness discriminator, not evidence of mathematical utility or discovery.

Do not rerun old reader/agent campaigns, delay central certificate execution for
a new benchmark, or silently turn the conditional amortization calculation below
into measured positive benefit. If no matched native intake/import cost exists,
the honest numerical break-even answer is **undetermined**, with its missing
inputs explicit. That is a useful engineering decision, not a benchmark failure.

## Define the unit of work before comparing costs

For a fixed exact theorem q and assurance policy, distinguish:

- **Certificate check:** full successful receipt verification plus exact public
  journal binding. The current cold host command measures this boundary only.
- **Cold usable intake:** discovery/acquisition as selected, certificate/native
  authentication, actual interface decoding, required type/definition hydration,
  compatible Lean import and accepted-interface registration.
- **Warm local use:** exact registry/cache lookup, required local materialization
  and the new proof's own checking. Neither method should revalidate unchanged
  already-accepted evidence merely to make the comparison favorable.
- **New certified contribution:** own mathematical delta preparation/checking,
  immediate-parent certificate consumption, actual proving/compression/resolution,
  final successful full verification, serialization and selected publication.

A148-byte journal is neither a148-byte certificate nor a148-byte reusable
mathematical library entry. It binds hashes; it does not contain the exact type.
The current cold receipt command does not materialize a Lean declaration.
Until that importer is executed, report `certificate-check cost`, not full
`cold usable intake cost`. Certificate validity cannot hide missing type data.

The native baseline must meet the same exact supported mathematical endpoint
and declared trust semantics. A stock-Lean proof check, a conditional Nanoda
check, and the actual hash/policy/parent-authenticating guest relation are not
automatically equal comparison endpoints. Do not inflate a native proof chain:
allow direct proofs, existing library results, native proof simplification and
local caching when available. N's old M axiom is not free external evidence.

For general later profiles, the unavoidable data term is selected interface

inductive/recursor rules and reference bindings when needed; a body hash alone
cannot execute a reduction. Missing D means unavailable/refused use, not

The strong cheap alternative is a local exact accepted-result cache bound to
foundation, checker/relation/image, assurance profile and immutable interface
identity. A warm node may reuse a locally established native judgment without
redoing its old proof. Such a cache does not transfer trust to a new independent
node, and invalidation/revalidation after profile changes remains necessary.
Certificates target that cold cross-trust-domain boundary; they do not need to
beat a memory lookup on every warm theorem citation. Popularity can guide local
certification/retention policy but never replace proof acceptance.

## Exact break-even calculation to fill from actual evidence

Choose one cost unit, for example inclusive product CPU seconds, and a fixed
theorem/workload. Let Pn/Pc be native/certified one-time production cost on the
same declared scope. Include any incremental profile setup in Pc−Pn if the
scenario is fresh deployment; state its amortization if already installed.
Let An/Ac be **full** first usable intake cost at a new trust domain, and Wn/Wc
the subsequent local warm-use costs. For domains i with mi≥1 uses:

```text
native:     Pn + Σ_i [An_i + (mi−1) Wn_i]
certified:  Pc + Σ_i [Ac_i + (mi−1) Wc_i]
```

If matched domains have stationary An/Ac and equal warm-use costs, write
ΔP=Pc−Pn and ΔA=An−Ac. For Q independent cold intakes, certified saves that
cost unit exactly when `Q*ΔA > ΔP`. If ΔA>0, the first strictly beneficial
positive integer is:

```text
Q_min = max(1, floor(ΔP / ΔA) + 1).
```

If ΔA≤0 and ΔP≥0, no positive break-even is established. If costs vary or warm
costs differ, use the explicit sum; do not force this simplified quotient.
Q counts cold trust-domain intakes, **not** every proof-reference occurrence,
API request, local cache hit or claimed global user. A second cost dimension
(for example bytes) needs its own calculation and may have the opposite sign.

For conservative measured intervals ΔP∈[pL,pU], ΔA∈[aL,aU], a sufficient
worst-case threshold is `Q*aL > pU` only when aL>0. These small single samples
do not justify inventing confidence bounds or stationarity. Any numerical
threshold derived from them must be labeled an illustrative projection for
that input/cost scope, not a forecast of adoption, throughput or useful growth.

At this checkpoint the new Pc, Ac and matched full An are not available.
The prior source13 Count cost cannot fill An for Fin/N/P; the tiny native
Nanoda measurements cannot fill full usable intake; EQ-DAG1 verification
cannot fill the new Ac. Therefore **no numeric break-even count is currently
defensible**. Once actual receipts exist, their costs populate certificate
subcomponents, not the missing import/control costs by inference.

## Release claims and the next decision

The minimum substantive, honest tentative-v3 statement is:

> A measured native-reader optimization preserves exact outputs on its fixed
> workload. Separately, the new experimental certificate path [if all relevant
> gates actually pass] certifies these exact supported mathematical deltas using
> immediate parents, with reported producer/cold-verifier costs and no mandatory
> parent-proof input. Net whole-loop speed and faster useful accumulation remain
> unestablished; certificates carry additional checker/cryptographic assumptions.

To upgrade `certificate-check` to `usable certified commons`, the immediate
missing core step is a real receipt-bound capsule/import/new-contribution path,
not more synthetic generations or networking polish. To upgrade to measured
useful-growth advantage, the existing J/K-style matched finite endpoints need
real ordinary publications and accounted controls; no coefficient of the two
TXT models supplies those observations. The core can remain task-independent:
an evaluator's workload is not a network goal list or human-intention predicate.

No new benchmark is commissioned by this note. Use the required certificate
outputs to decide whether to integrate a scalable experimental path, retain
native mode for small/warm workloads, or stop on a central cost/compatibility
failure. A costly but correctly history-independent path can validate an
architectural mechanism without being an efficient release yet. Preserve that
distinction rather than claiming either universal victory or impossibility.
