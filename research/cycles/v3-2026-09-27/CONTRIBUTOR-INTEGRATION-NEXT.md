### Minimum public interface

Retain the current user inputs: independently adopted profile and hash,
ordinary source file, root name, zero to eight immediate-parent bundles,
fresh operation directory. Add **explicit bounded continuation**, for example:

```text
prepare --profile P --profile-sha256 H --run R
        --source S --root-name N [--parent B ...]
advance --profile P --profile-sha256 H --run R --max-new-stages K
```

These are proposed API names, not currently callable commands. `prepare`
verifies parents, compiles the source once, clean-rechecks/exports, binds all
exact bytes and captures one real execution snapshot. It reports actual N/A
and estimated next-stage requirements without promising a certificate.
`advance` processes at most K **not-yet-completed** stages under the same
fixed operation budget/deadline. It is allowed to end with an honestly labeled
retained prefix. Explicit owner renewal, if later supported, must retain all
previous costs and is a separate policy action; it is not implicit in resume.

State must bind installation/profile/image/foundation, exact source/root,
ordered parent receipt/journal/capsule pins, child packet/interface/journal,
snapshot/session key, N/A, completed stage pins and cumulative charges. Reopen
only operation-local paths; refuse drift/unknown state. Never infer stage
success from a filename. Driver07 verifies the cryptographic objects it
consumes. A local manifest records safe continuation; it is not network
authority or a replacement for final verification.

Minimum resume support is between completely closed, pinned stages. Preserve
failed attempts and never overwrite their output names. A partial stage or
ambiguous close must be reported; automatic repair/retry and crash-exactly-once
accounting are not already provided by the research adapter. Any handling of
such a case requires a deliberately selected conservative resume rule, not
pretending the stage consumed no resources.

When all stages finish, require exact full final receipt/image/journal,
all assumptions resolved, fresh cold verification, immutable-input rebind and
clean workers before four-file commit. Preserve the existing experimental
non-native success label. The already qualified receiver then checks those
four files independently. A native-only or checkpoint-only exit must not
create a success bundle.

### Do not multiply the whole-installation scan by 95 stages

Old source02 `invoke` calls full `Installed.rebind()` both before and after
each command. Naively placing a 95-stage sequence inside it entails at least
190 scans of 2.345 GB, about **445.6 GB of logical hashing**, independent of
mathematical ancestry. That is a source-derived cost warning, not measured
physical I/O or a reason to discard integrity checks.

The narrow candidate should define role-scoped phase asset sets: native work
needs the Lean closure, while proof stages use crypto/controller assets and
their own immutable inputs. Full installation adoption at invocation/resume
and completion, with exact active-role rebind per stage, can avoid reading
inactive Lean assets at every cryptographic step under the already explicit
cooperative immutable-owner filesystem assumption. This is a proposed reviewed
policy delta, **not** permission to skip checks silently. Test active-asset and
snapshot mutation refusal, and charge initial/final static hashing. If root
does not select this delta, retain whole-map checks and disclose their costs;
do not report inner proof timing as total contribution efficiency.

1. **Wait for actual child evidence.** Inspect full01's final result if it

   One installed ordinary-source elaboration/recheck is a necessary new

4. **Reuse completed work honestly.** If installed preparation produces the

   relabeled fresh installed proof production. If a genuine unproved prefix
   remains and is exactly transferable under the public resume rules, finish
   only its missing stages. Do not rerun completed segment proofs for a demo.
5. **One actual installed contribution endpoint.** If the old child is fully
   complete before installation, choose one new bounded ordinary child of an
   already certified parent and run the installed public pipeline once; do not
   reprove L or rerun the same completed child merely to manufacture an
   end-to-end label. Root must select its scope/budget. Export the real bundle
   and check it with the unchanged installed receiver.
6. **Changed-boundary controls only.** Wrong profile/parent, changed source or
   packet after prepare, wrong snapshot/key/checkpoint, unresolved final claim,
   exhausted allowance and nonclean worker must refuse without a success
   bundle. Preserve ordinary graceful-stop/resume accounting. Separate hostile
   OS isolation, broad Lean support and independent-host claims remain unmade.

Stop condition for this successor is a portable ordinary-source contributor
whose exact produced bundle passes the existing receiver, with real recursive
parent discharge, no mandatory ancestry inputs and complete measured costs.
It is not an assertion of production Nanoda/Lean equivalence, asymptotic
cryptographic assurance, faster useful growth or global release completeness.
