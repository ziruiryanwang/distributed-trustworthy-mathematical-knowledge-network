## Decision

The retained project contains substantive reusable material for a **principled
engineering paper about cumulative formal agents**, but not an established
empirical result that the commons accelerates useful mathematical growth.
The best currently evidenced technical problem is the gap between *a checked
result*, *an executable authoring environment*, and *affordable continued use*.
The strongest concrete candidate mechanism is **root-bound, locally warranted
interface cuts**: prior checked theorem interfaces can discharge scratch
assumptions while demanded computational semantics remain concrete. Independent
native checking, exact identity, persistence and explicit uncertainty are the
surrounding protocol, not a claim that a remote success flag carries authority.

For PAgE, an evidence-contract/protocol paper can use the concept episode as its
motivating agent case and exact failures as counterexamples to tempting designs.
A warm-reuse paper can go deeper on locality but still needs a justified novelty
delta and a fair cost discriminator. The literature reviewer owns novelty; this
audit does not certify it. No acceptance probability can be estimated reliably
from the retained material, and no high-probability acceptance claim is justified.

Do not make either of these the primary paper claim now:

- “The system creates new-to-literature mathematics or speeds creative growth.”
- “The system achieves practical cold ancestry-free verification at global scale.”

These are not missing adjectives; the necessary evidence is absent.

## Strong baseline gap

The project already states the correct comparator-simulation lemma in
`v5-2026-10-22-native-library/GROWTH-COMPARATOR-CHALLENGE.md`. If an ordinary
workflow receives the same artifacts at the same times, can run the same tools,
and simulates the proposed operations at no greater cost, it can reproduce the
same output trace. The paper must name which premise fails in the selected
realistic workflow rather than implying inherent creative power from networking.

At minimum give the baseline:

1. Ordinary approved Lean/Git/Lake projects, pinned dependencies and mirrors.
2. The same producer discoveries and release times, not a fake static library.
3. The same underlying reasoning tools, model, prompt/information allowance,
   caches and compatible local mathematical foundation.
4. Real search/navigation facilities; do not compare indexed access with no
   possibility of looking for a lemma.
5. Native batching when results coexist, and incremental/native library reuse.
6. Equal security/trust obligations. “No foreign executable loading” is a real
   policy constraint, but not an artificial tax imposed only on the baseline.

The existing episode proves no advantage over this baseline. Original-project
buildability is positive evidence *for* the baseline. One receiver's cheap use
cannot be compared with a baseline's entire original discovery cost; shared
production, maintenance, missed searches and failed adoption must be allocated.

For cuts, compare against both isolated native sequential admission and ordinary
batching. If a maintained resident Lean worker can satisfy the intended trust and
failure policy more simply, it is an architectural alternative, not a forbidden
optimization. Its long-lived state/failure assumptions differ and must be stated.

## Minimal decision-changing work before committing to paper writing

### For a protocol/locality paper

First do source/theory work, not more experiments:

- Give an explicit operational model whose states distinguish advisory bytes,
  checked local warrants, approved authoring realizations and available custody.
  Prove a concrete safety statement for consuming warrants and returning claims;
  identify exact trusted implementation premises. A hash or exit-zero event is
  never the induction premise by itself.
- State the one-way cut realization theorem precisely for the supported Lean
  fragment and the selected implementation. Explain why loss of theorem-body
  reduction may cause refusal without invalidating positive results. The old
  proof-erasure counterexample is paper/source evidence at an old Lean pin, not
  an executed current-4.34 result; do not present it as one.
- Extract operation counts from actual source: existing ordinary fresh contexts
  have linear lineage/name walks and hence quadratic cumulative metadata visits
  for bounded-size one-declaration histories. The cut claim removes mandatory
  prior theorem-proof traversal, not demanded semantic conversion or fixed-base
  costs. Fixed limits alone are not an efficiency theorem.
- Complete a related-work delta against actual theorem stores, LCF trust,
  independent Lean checking, proof-carrying code and agent memory/tool contracts.
  Stop or redirect if the selected contribution is only established practice.

Only if a practical-efficiency claim remains essential, the **already written**
`grounded_cut_basis/PAYOFF-PLAN.md` is the smallest available discriminator:
one shared genuine setup, old/restored cuts, ordinary sequential and batched
comparators, nine mathematical workers, no intrusive profiler, one original
budget. Its comparison driver is source-only and must pass review before a
fresh root selection. Do not rerun concept formation or build a broad benchmark
to answer this narrow question. A negative result should narrow/redirect the
paper, not trigger parameter fishing. One run can reject an obvious bad route;
it cannot justify confidence intervals or an asymptotic crossover.

### If the paper instead centers empirical useful growth

No small retelling of the existing case closes the gap. The minimum credible
design needs a new prospective evaluation with multiple independent downstream
opportunities, equal budgets, blinded access to output identities, an optimized
ordinary sharing baseline, all failed episodes retained, and endpoint/content
evaluation independent of the producing agent. Sample size must follow a
predeclared effect/uncertainty goal, not the available number of successes.

Separate two interventions: (a) availability of useful external mathematics;
(b) the proposed discovery/adoption infrastructure versus ordinary sharing of
the *same* mathematics. A positive (a) result does not show superiority in (b).
Exact formal endpoints or assessed theory contributions can measure capability;
raw theorem IDs, number of definitions and citations cannot be the sole outcome.
Do not call model self-evaluation an external novelty judgment.

This is substantially more expensive and less presently justified than the
protocol/locality route. Recommend against committing to a growth-speedup
headline unless a real, discriminating workflow is identified in advance.

- New definitions/groups are not admitted by this accelerator. Ordinary native

## Growth-first experiment: distinguish discovery, sharing and topology

The user priority requires evidence that agents discover useful **new-to-their-
initial-corpus theorems**, not merely retrieve an old endpoint or check faster.
“New” here must be scoped explicitly; literature novelty is not automatically
available from any local experiment. Research tasks are local evaluator inputs,
not a global agenda added to the network's mathematical acceptance rules.

### Causal questions and arms

Freeze producer outputs before running consumers; producers must not see the
consumer briefs, target endpoints, treatment assignment or later failures.
Give every arm the same initial library, model/tools, compute grants, authored
project policy and common seed vocabulary. Producer work and network service
are paid once in the actual experiment and explicitly allocated in reported
whole-history alternatives. Do not price an already-produced remote idea at
zero while charging the control to invent it.

| Arm | Available outside mathematics | Purpose |
|---|---|---|
| L: optimized local investigation | Initial library, normal Lean tactics/search/caches; no new producer corpus | Measures the effect of access to independently produced mathematics, not decentralization. |
| C: centralized shared knowledge | Same newly produced complete corpus as D, one searchable server/index, identical result and source delivery interfaces | Essential control for centralized shared memory; matches information and search semantics. |
| D: decentralized providers | Same corpus/availability times partitioned among several independently configurable providers, exact same client primitives and aggregate budget | Measures the cost/capability of decentralized access, conditional on supplied contacts; no automatic creative advantage is presumed. |

An ordinary Git/Lake/search comparator G is also needed before claiming an
implementation advantage. It may be a separately measured instrumented route
for the same C/D returned source, or an additional agent arm if its interface
meaningfully changes investigation. It must not be handicapped with delayed
commits, no search, mandatory rebuilding, or inferior library/tactics. Current
Lean 4.35 validation belongs in this comparison where compatible, but adopting
or porting it is a separately selected engineering task, not free infrastructure.

Possible supportable conclusions differ:

- D better than L: external sharing helped under these conditions. Not evidence
  that decentralization caused the gain.
- D comparable with C, with demonstrated operation after one selected provider
  disappears: useful sharing survives a decentralized placement/failure model.
  “Comparable” needs a prospectively chosen margin and uncertainty analysis.
- D worse than C on latency but retains unique reachable knowledge after C's
  sole provider fails: an availability/cost tradeoff, not universal acceleration.
- D no better than G: the system can still integrate useful services, but do not
  claim unique algorithmic discovery power or implementation speedup.

Do not manufacture failure solely in C while granting D uncharged replication.
If studying redundancy, give both designs equal storage/replica budget and state
the correlated-failure model. A centralized index can be replicated too.

### Minimum fresh mathematical episode design

Use several small domains sharing only an initial formal nucleus. Producers
independently select and prove reusable laws, definitions or countermodels from
that nucleus, without seeing eventual consumer questions. Freeze **all** outputs
and costs, including empty/failed producers, before consumer assignment. Do not
curate only the producer lemmas which later make D succeed.

Consumers receive research briefs broad enough to choose a conjecture or useful
generalization themselves, but bounded enough for external adjudication. They
must return a checked substantive theorem not already supplied verbatim in their
initial corpus, with a dependency/use explanation and failed attempts. A simple
restatement/renaming/instantiation is not counted as a new research endpoint;
checked bridges, strengthened claims, new conditions, countermodels and theory
connections can qualify under a frozen rubric. Exact semantic novelty in full
Lean is undecidable, so the nontriviality rubric needs blinded content review,
not only hash inequality. Do not conflate a failure to prove with a refutation.

For the first **feasibility discriminator**, use a small fixed batch of matched
briefs across L/C/D and preserve every outcome. Three or four matched briefs can
expose no retrieval, no use or pervasive integration failure cheaply; they are
not automatically enough for an acceptance-ready efficacy estimate. If the
discriminator gives no plausible effect or the scaffold dominates, redirect
before funding a larger campaign. A subsequent sample size must be selected
against meaningful effect/uncertainty goals using separate pilot information,
not increased until a p-value passes. Existing A/B must not become that pilot
retroactively or be replayed with its known successful endpoint as a new trial.

Primary outcome: cost/time to the first independently judged substantive,
kernel-checked new-to-initial-corpus contribution within the original budget;
failures are right-censored/non-successes, not discarded. Secondary outcomes:
checked contributions at fixed budget, actual external theorem/definition use,
failed conjectures, query/preview/inspection cost, source-adoption work, native
checking cost, and returned contribution's subsequent usability. Report paired
effects and uncertainty, not only totals or best examples. The exact dependency
trace demonstrates reuse; it alone does not establish that reuse was necessary.

### Anti-leakage requirements

- Fresh consumer contexts must not inherit this project's A/B case, root's
  expected theorem, producer reasoning, treatment results or model summaries.
  `fork_turns="none"` helps conversational isolation but is not filesystem/tool
  isolation; all current subagents otherwise share the same workspace.
- Give each consumer only approved initial files and a bounded tool broker.
  Enforce/read-log corpus access rather than trusting an instruction not to
  inspect hidden producer files. No unrestricted repository `rg` or shell path
  may reveal treatment answers in a nominally isolated arm.
- Root may route exact actual public outputs and provide mechanical compiler
  feedback, identically in every arm. Root must not propose the next theorem,
  choose the useful result, repair mathematical arguments or selectively renew
  a failing arm. If intervention occurs, record it as contamination or restart
  a prospectively defined fresh unit—not a hidden successful correction.
- Randomize treatment order/assignment and provider-order where it can affect
  results; use independent consumer contexts. Agent instances sharing a model
  are not statistical independence by themselves. Record provider/model version
  and nondeterminism, and avoid claiming reproducibility from temperature alone.
- Keep outcome reviewers blind to arm and search trace during content judgment;
  audit trace/use separately afterward. Internal AI review can be disclosed
  screening, but independent human mathematical assessment would materially
  strengthen a paper claiming meaningful concept/theorem discovery.

question. Conversely, forcing every creative edit through the narrower inert
materializer would distort the available rich Lean baseline.

The direct peer source places precise limits on topology claims:

- `_contacts:102` accepts 1–64 explicitly supplied labeled contacts. `find`
  selects 1–64 of them, loops sequentially over providers and their partitions,
  and does not implement peer bootstrap, referrals or DHT routing.
- Public find caps returned candidates at 256, requests at 512 and replies at
  32 MiB, within the lower selected SearchSession budget. Core SearchSession has
  broader ceilings, but those are not the public client profile. Candidate pages
  have at most eight matches; a limit is a bound on work, not a relevance claim.
- Recognized settled provider failures skip that provider without retry or grant
  renewal. One slow request may consume the remaining original deadline: source
  explicitly does not promise fairness. This can materially affect the D arm.
- `receive` resolves missing evidence from its one selected provider. It does
  not automatically locate different dependency holders or fall back to other
  providers. Whole-closure custody or explicitly staged alternate acquisition is
  needed; do not pretend independent small shards already compose transparently.
- The existing episode was one loopback service, no TLS. Several local services
  would demonstrate implemented multi-provider execution on one host, not
  independently hosted reliability or planetary scale. The supported protocol is
  direct-contact federation, not a permissionless globally routed network.

### Required logs and PC-feasible scheduling

Retain exact initial corpus/source hashes, producer briefs, all declared outputs,
compiler diagnostics and source revisions; assignment/randomization seed; exact
consumer system/task prompts; model/version/settings and all visible messages;
every tool request/result; query specs and actual records selected; per-operation
public reports; original aggregate grants and monotonic budget accounting;
native Job CPU/peak memory, network bytes/requests, service cost and all failures;
final formal sources, checked target types/dependencies and blinded scores.
Never require or fabricate private chain-of-thought. Visible decisions, tool
actions and final proof artifacts suffice for the audit.

The existing runner logs CPU/wall/memory and command output, not LLM tokens,
token prices, hidden reasoning or end-to-end research time. The experiment must
obtain actual model usage from an authorized execution interface or report it
as unavailable and bound calls/output tokens instead. Do not label “equal token
budget” merely because two prompts requested equal effort. New API provisioning
or paid compute requires separate deliberate selection; no such action here.

Retained small Lean compilation/admission peaks are about 0.5–0.7 GiB, and the
prior concept corpus is under 1 MiB of evidence. This supports a bounded local
prototype, not an inference about free RAM today or future large libraries.
Keep several lightweight provider processes running within one aggregate cap;
serialize memory-heavy Lean checking. Producer/source reasoning and read-only
audits can proceed independently, but do not run competing timed native arms
simultaneously and call their wall time a controlled latency comparison.
Avoid redundant runtime copies, repeated basis builds and new certificate work.
The PC is sufficient in principle for this small causal discriminator without
claiming it can emulate independent failure domains or global traffic. The
larger uncertainty is experimental validity and relevance, not raw machine size.

**Recommended next decision:** root select the mathematical opportunity and
pre-register the L/C/D causal model, information firewall, source-delivery
baseline and stopping rule before authoring a harness or creating new producer
mathematics. This is a concrete gate, not another generic growth essay. If no
affordable nontrivial opportunity survives the fair C/G controls, redirect the
paper claim rather than manufacture an advantage for decentralization.

## Latest direction: automated abstraction with hidden downstream transfer

### A stronger and cheaper causal question

Do not compare an agent with a useful library against a deliberately forgetful
agent. Instead ask:

> With the same initial mathematics and aggregate research resources, does
> explicitly inventing and proving reusable abstractions from completed local
> investigations improve subsequent, hidden theorem work over an ordinary
> cache-aware Lean investigator?

Both routes produce mathematics. The intervention is the research policy that
converts initial discoveries, repeated proof obligations and counterexamples
into reusable definitions/lemmas/bridges. No new network topology is necessary
to test this. Common existing storage/index/checking can carry the outputs in
both arms. The product value is independently reusable warranted work, while
the paper's causal claim concerns the selected discovery policy.

The obvious related-work risk is that lemma-learning, skill libraries,
conjecturing, proof reuse and counterexample-guided invention already exist.
The literature agent must locate the precise surviving difference before the
experiment is sold as novel. A well-controlled null result is informative but
does not, by itself, guarantee a strong workshop contribution.

### Concrete mathematical family that fits the retained local stack

Use the already checked A/B repair/closure theory as a **common seed in every
arm**, not as a treatment invention and not as a new experiment result.
The unproved continuation suggested in B-RESEARCH is finite/rank-bounded
repeated schedules rather than one-pass Safe schedules. This is a realistic
new investigation direction with an existing meaningful vocabulary and no
need for mathlib-scale installation, certificates or a replacement prover.

A precise evaluator-side reference family is:

- A partially ordered state type X; a finite list of monotone inflationary
  updates `f_i : X -> X` (individual idempotence may or may not be needed).
- A rank `rho : X -> Nat`, bounded by B on reachable states, increasing strictly
  on every strict state increase. Do not assume an arbitrary finite type has
  a useful rank without constructing it.
- A complete pass F applies every selected update at least once.
- Iterate F from initial x. A positive generic theory can establish stabilization
  within a rank-derived bound and that the stable state is the least common fixed
  point above x; different complete pass orders then have the same stable result.

The principle is modelable in advance: monotonicity bounds each iterate by any
common fixed upper bound; inflationarity produces an ascending chain; strict
rank increase bounds changes; if a whole inflationary pass returns its input,
antisymmetry forces each intermediate update to preserve that state. For a
global rank in `0..B`, the candidate bound `F^(B+1)(x)=F^B(x)` is consistent with
this argument, but actual formal statements must be checked, including B=0,
duplicates, empty schedules, reachability restrictions and equality decisions.
This is an evaluator feasibility argument, **not** a theorem supplied secretly
to the treatment agent or a completed Lean proof.

Useful potential downstream domains are finite Boolean fact propagation,
finite relation/reachability closure, Horn-rule saturation and worklist
order-independence. The held-out consumers should face changed representations
and residual obligations, not only substitute a new numeral into a generic lemma.
Countermodels can expose missing inflationarity, monotonicity, rank bounds or
schedule coverage. Native `decide` on a tiny concrete state does not substitute
for a parametric theorem about the algorithm family.

This family is mathematically familiar; the paper would study *automated
formation and transfer of useful formal abstractions*, not claim new fixed-point
mathematics. If ordinary Lean tactics or the baseline solve every selected task
almost immediately, this family is not discriminating and must be abandoned
before the main study. Do not make the baseline forget standard fixed-point
lemmas when they are in its approved initial library. An alternative library
already proving the generic result is a legitimate strong comparator.

### Matched research arms

1. Freeze initial library, visible training investigations and hidden consumer
   briefs/endpoints before producer work. The evaluator owns hidden files in an
   access-isolated location. Neither producer nor baseline sees hidden tasks.
2. Give both arms the same visible investigations and the same total budget.
   Both retain every successfully proved theorem, failed proof log and source
   project in an ordinary searchable Lean library. Both may naturally invent
   local lemmas; banning that would handicap the baseline.
3. Treatment reserves a predeclared fraction of its budget for candidate
   abstraction/conjecture generation, proof or countermodel search, and checked
   reusable publication. It may introduce definitions and parametric bridges.
4. Baseline spends that same amount on its ordinary best next investigation,
   proof completion and library organization, without the new compulsory
   abstraction policy. It has equal tools and context capacity. Preserve all
   its extra successful results; do not discard them to equalize theorem count.
5. Fresh matched consumers get their arm's resulting library through identical
   search/adoption tools and the same hidden brief and budget. The ordinary
   baseline is allowed to generalize during the hidden task too.
6. Both arms cache downstream results and may reuse earlier consumer work when
   the evaluated history permits it. If tasks are independent fresh consumers,
   say so and additionally report the warm shared-history alternative; do not
   pretend every repeated use is a fresh cold proof search.

An optional oracle access condition can measure the ceiling from giving an
actually generated useful lemma directly, but it is not the deployable system
and its results must not replace search-mediated consumer performance. A
size-matched irrelevant-library control can diagnose context overhead, but
cannot replace the ordinary cache-aware baseline above.

The main prospective metric can be completed distinct hidden checked endpoints
under equal full-history budget, or charged cost to complete the same endpoints.
Hold novelty/content judgment separate: new-to-library conjecture generation
is a different outcome from proving an evaluator-supplied target. A paper that
only measures the latter must call it theorem proving/transfer, not unrestricted
autonomous theorem discovery. Include a bounded open conjecture-generation stage
and blinded substantive-content evaluation if making the broader claim.

### Full-cost theoretical link

For q downstream consumers, let I be the incremental cost of abstraction
production/validation above the control's useful alternative work; let d_j be
control downstream cost and r_j treatment discovery/adoption/proof cost. Charge
shared storage/service and failures as H. The finite-history benefit condition is

    sum_j (d_j - r_j) > I + H.

This is an accounting identity/condition, not the contribution by itself. The
study must supply the unknown magnitudes and show that costs were not shifted
off-ledger. A reusable family can make the region nonempty, but mere parametric
syntax does not prove the control could not discover the same theorem cheaply.
The existing prefix theorem explains why positive eventual savings do not imply
better results at every short budget; report the investment and downstream
curves rather than cherry-picking the first favorable q.

The practical theoretical target is a transparent causal decomposition:

    generated mathematical abstraction
      -> exact applicable interface exposed to a new investigator
      -> discharged new residual obligations
      -> checked contribution within the charged budget.

Each edge has implementation/log evidence. The last comparison is experimental,
not inferred from dependency edges or citation counts. If exposure fails, first
separate search failure from an unhelpful abstraction; if checking/authoring
dominates, revise that integration rather than claiming the mathematical idea
was useless. The aim is to choose a better research process, not rescue one
preselected architecture.

### What to do next, without starting the study here

Select a small standard source project and common seed, then have an evaluator
specify hidden rank/worklist transfer tasks while a separate producer-facing
designer specifies visible investigations. Audit overlap, likely trivial tactic
solutions, ordinary-library alternatives and source-delivery feasibility before
launch. Build the smallest access-isolated, aggregate-budget agent harness using
existing public commands only after those facts survive review. No new consensus,
peer routing, certificate, model training or formal-importance oracle is needed.

Current desktop agents can draft and audit these plans, but unrestricted shared
filesystem access is not a scientific hidden-test boundary. The evaluation must
either enforce a restricted tool/file interface or disclose that it relies on
behavioral compliance and weaker blinding. Do not start many nominally independent
trials with inherited full project history and later describe them as blind.

This direction has higher expected marginal value than finishing cut-performance
optimization for the paper. Its remaining decisive uncertainty is whether the
generated abstractions improve hidden mathematical work against the ordinary
adaptive baseline—not whether another theorem can be stored or exported.
