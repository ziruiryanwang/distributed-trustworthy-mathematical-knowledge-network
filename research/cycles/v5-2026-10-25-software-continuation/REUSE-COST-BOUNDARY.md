## What each operation actually pays

Distinguish worldwide corpus size N, selected local context K, selected source
interfaces/semantic preparation S, missing evidence closure D, chosen module
anchor chain A, and local catalog operation history H. These are not interchangeable.

**Acquire.** Exact custody access uses primary-key object/export lookup and reads
the selected bounded BLOB; quota status reads one metadata row. It does not scan
all unrelated proof objects. Remote receive obtains the selected preview and
whole evidence unit. Under `selected-unit-only`, missing prerequisites produce
`NEED_GROUNDED_PREMISES` before ancestor locator/evidence calls or admit. This is
controlled nonacceptance, not cheap cold acceptance. Explicit `bounded-closure`
can traverse D, with repeated preflight over the accumulated selected batch.
Provider/search costs and database/page behavior remain real; no constant-time
or global-completeness guarantee is inferred from exact lookup.

**Admit, already-grounded parent.** Preflight decodes the selected evidence and
checks exact bindings against K. Exact already-present whole units are reused;
`admit` still revalidates and stages/reads back those units, then returns REUSED
without a new native worker if there are no new units. For new units, it restores
the selected protected parent and checks the new batch. Old accepted proof
derivations are not kernel-replayed, but context metadata and local artifacts
remain required. Snapshot chunks contain only new declarations plus one parent
import, not cumulative full-environment copies.

**Hot versus cold.** Within one owner process, verified snapshot artifacts have
an integrity cache. A fresh owner process starts with an empty artifact cache;
selected lineage/bindings are rebuilt and selected artifacts hashed. A fresh
native extension also loads the selected local import chain and rebuilds allowed
names. Thus retained acceptance is warm in *warrant*, not necessarily resident
memory or zero-I/O execution. Existing reports already establish these costs;
this audit does not infer eager copying of every ancestral proof by Lean.

**Author.** The ordinary contribution route first constructs K's protected
lookup, then prepares selected semantic interfaces S. Singleton theorem packets
carry the theorem signature, not its proof-only ancestry. However, the current
local preparation callback still reads/validates that theorem's complete retained
evidence unit before projecting the signature; this was already documented by
owner_request. Definitions and generated groups require their supported semantic
closure, and absent non-theorem materialization may require complete imports.
This is bounded selected syntactic preparation, not a demand-minimal evaluator
that fetches exactly the definition reductions later used. Approved ordinary
projects remain the richer authoring route; scratch assumptions do not grant
mathematical acceptance to the returned contribution.

**Export/use.** Cold generated-module export collects/checks the selected complete
proof closure above Init. With an explicit registered local module anchor, it
validates that frontier against current warranted bindings and collects only the
unanchored delta; anchored old proof inventories are not fetched or decoded.
All-anchored targets reuse the module without a new native call. Anchor metadata,
artifact integrity and importing the selected A still cost resources. This is
local event reuse, not permission to trust another peer's executable module.

None of these paths requires processing the world's N results. Their local
envelopes can nevertheless refuse useful work if K, S, D or A is too large.
Transparent semantics, whole generated groups and independently checking a cold
missing warrant cannot be removed merely by adding an index or a signature hash.

## The existing small-context workaround remains operational

`owner.py` forwards `--parent-root` to baseline intake. Intake explicitly accepts
any eligible protected root, validates the known retained dependency bundle,
and independently admits bounded batches above that root. It does not force the
most recently created branch, trust another branch's success flag, or import
unrelated later roots. The final peer receive path likewise uses the explicit
parent and contains the selected-unit-only branch adopted after the earlier
lifetime audit. No current source contradiction was found.

Re-admission into a smaller context pays actual selected proof costs. This is
not a universal minimal-closure collector, free branch merging or a proof that
every research history decomposes into small useful contexts. Existing native
limits, source/frontend compatibility, custody and retention costs still apply.

One bookkeeping caveat should remain visible: a small K in one large catalog is
not independence from *every* kind of unrelated local history. Catalog open marks
RESERVED operations INTERRUPTED (`portable_catalog.py:238`), and reservation
aggregates counts/reserved bytes across its operations (`:557-559`); baseline
capacity planning repeats those aggregates (`baseline_intake.py:141`). They do
not decode unrelated mathematical proofs, but can touch H operation records.
The catalog has explicit finite caps; existing separately initialized bounded
catalogs can also bound H, with setup/re-admission charged. The lifetime decision
already leaves such bookkeeping in W_jt, outside its restoration-only bound.
This is a limitation of an overstrong total-cost locality claim, not a newly
demonstrated reason to change the selected workflow or implement quota counters.
