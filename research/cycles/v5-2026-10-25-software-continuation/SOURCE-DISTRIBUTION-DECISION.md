The adopted fair-search package has a clean source recipe, but its inputs are
spread across historical-named source directories in the large research
workspace. An independent operator should not need that workspace, experiment
outputs, or an old native installation merely to obtain the current source.

The smallest useful deliverable is an explicitly selected source tree/archive
containing the **unchanged exact 100 existing files** below, plus a short root
build/use guide, exact manifest, and a small file-only verification/materializing
entry. Preserve the relative `software/...` layout. Reuse the existing builders,
overlay and selected-package kit; do not flatten imports, edit frozen constants,
rewrite the build system, add an installer, or repeat native qualification.

This is a distribution/operability improvement, not a new search/growth mechanism.
It does not supersede the independent paper investigation, establish useful
mathematical growth, or meet all final-v5/public-release gates.

## Dependency reasoning

The bounded builder's 84-input map contains all **47** base-builder inputs.
The map provides **64** direct output copies and **29** compile-lane source rows:
eight receiver, thirteen authoring, seven extractor, and one query row. Repeated
source files across lanes are intentional; transforms and distinct compilation
environments must not be conflated.

The top-level bounded builder stages only its map, builder and named inputs;
bootstraps the pinned base builder; runs the preserved base, extractor and query
lanes; and assembles the declared output map. Base-builder dynamic imports come
from its explicitly staged input tree. The ordinary installation helper resolves
its adjacent staged Python modules. The fair assembler reads the explicitly
selected base package/receipt and its six files beneath explicit `--source-root`;
it imports no product code. The kit wrapper resolves its pinned helper/map
relative to itself. Consequently none of these entry paths needs this research
workspace's absolute location.

A finite text search over the selected 100 paths found no `E:\`, `D:\`,
`experiments/`, `product-local/`, or `parents[` match. This is supporting evidence,
not a proof of absence of every hidden environmental assumption. Builder source
inspection, explicit source staging and source-map inclusion give the stronger
dependency argument. Existing `C:\...` paths in documentation/examples are
placeholders to replace, not required machine paths.

No separate historical `ordinary_research_distribution/build.py` or earlier
installation is required: the bounded builder is already a self-contained
successor, despite its description naming its historical predecessor.

The actual adopted fair package remains the separately qualified 148-file output
at `experiments/v5-local-checks/fair-investigator-assembly01/assembled/package`,

   Preserve its separate terminal receipt and use its exact new PROFILE.
5. Select the resulting complete package/runtime separately, then use

## Risks and economical validation

1. **Documentation links and historical labels.** Some frozen source README
   links target files which exist only after assembly; selected-kit evidence
   references point into the retained research workspace. A new root guide must
   clearly distinguish source-location and built-package documentation, and
   identify historical evidence references as external to this compact artifact.
   Do not silently rewrite frozen docs. A small separately selected evidence
   supplement is optional, not a compilation dependency.
2. **False self-containment.** The compact source still needs complete runtimes.
   Shipping only the 23 pinned runtime files would be incorrect.
3. **False release authentication.** The archive/manifest identifies exact local
   bytes; public signing, license, security review and operational qualification
   remain separate, unresolved decisions. Keep it local until authorized.
4. **Regression through consolidation.** Do not reimplement builders or remove
   apparently redundant predecessor inputs: the base stage really consumes them.
   No basename flattening, newline normalization or edited historical constants.
5. **Wasted verification.** Use file-map/closed-dependency checks and a relocated
   file-only integrity check if root selects materialization. Native correctness
   and existing product integration evidence should not be rerun merely because
   unchanged source bytes were copied. A later independently hosted pilot or
   changed runtime can justify a new build under its own explicit selection.

Recommendation to root: select the compact allowlist artifact now if no larger
concrete software blocker has been found in parallel. Implement one bounded
file-only packaging/verification seam and the outer guide. This closes an actual
fresh-user distribution dependency at a few MiB, with no mathematical-policy
change and no expensive experiment. Do not automatically expand this into a
new installer, updater, dependency manager or release-signing infrastructure.
