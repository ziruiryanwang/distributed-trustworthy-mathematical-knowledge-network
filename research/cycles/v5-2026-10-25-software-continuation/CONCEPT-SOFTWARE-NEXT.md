## Decision

The paper checkpoint has **not established a growth advantage or a need for a
new research-policy subsystem**. Its current recommendation is to study ordinary
Lean investigators with durable source libraries, separating statement invention,
transferred capability and full-cost improvement. Ordinary cached libraries are
the strong comparator. Do not infer that the commons needs a conjecture scheduler,
semantic novelty score, new module format, certificate mechanism or agent platform.

One already justified usability requirement is narrower: after discovering a
definition or theorem, a new investigator should be able to locate an ordinary
project in which to develop consequences. The product already has the relevant
advisory lookup and provider role. The new operator kit supports querying those
hints but intentionally does not cover the optional provider configuration.
This is a **documented-subset handoff gap, not an architectural blocker**.

Recommend at most **one worked documentation addendum**, not another helper,
package revision or mathematical experiment. If the existing API instructions
already suffice for the intended operator, no change is necessary.

## Candidate: connect the two existing public instructions

### Actual operator/investigator workflow

1. A producer develops and compiles an approved ordinary project, produces its
   inert export bundle, independently admits the intended work and publishes
   selected exact targets through the existing commands.
2. If the producer has an existing repository/revision they are authorized to
   disclose, they explicitly select an advisory map linking the exported target
   to that repository, commit, project subdirectory and logical module.
3. They use ordinary public `serve` with that map. A new investigator's existing
   `find` -> `preview` -> `authoring-offers` path can obtain the hint.
4. The investigator separately decides whether/how to obtain and approve the
   project, checks the relevant exact export correspondence, develops their own
   definitions/consequences, then uses the existing return path. No automatic
   cloning, installation or execution follows a theorem lookup.

The addendum should join these existing instructions into one exact worked
example. It should neither silently patch the kit's generated `RECEIPT.json` nor
modify a prepared config while retaining its old hash. Instead it should show a
**separately selected fresh public serve config** and its new hash. Reuse the
existing launcher and explicit profile/state/runtime/output/allowance conventions.
Leave the original prepared directory and frozen helper bytes unchanged.

### Exact public data mapping

The full successful `produce-baseline` command report contains
`result.status = PRODUCED_INERT_BASELINE_NOT_ACCEPTED`, `result.semantic_id`, and
`result.targets[i] = {name, export_id, unit_id}`. These are the terminal report's
fields, not `PRODUCTION.json`, which is an intermediate observation. Their actual
construction is in `ordinary_producer_package/baseline_production.py:291-323`;
the kit's existing reader checks the name/unit/export binding at
`ordinary_operator_kit/prepare.py:321-339`.

The advisory map has the existing shape:

```text
schema = DMKN_AUTHORING_OFFER_MAP_V1
entries[j].semantic_id = selected producer result.semantic_id
entries[j].export_id = selected producer result.targets[i].export_id
entries[j].offers[k].export_name = selected producer result.targets[i].name
entries[j].offers[k].module = explicitly selected actual structured logical module
entries[j].offers[k].repository = explicitly selected credential-free HTTPS URI
entries[j].offers[k].object_format = sha1 or sha256
entries[j].offers[k].commit = explicit full revision, not a branch/tag
entries[j].offers[k].project_dir = normalized repository-relative project directory
entries[j].offers[k].toolchain = explicitly asserted compatible toolchain token
```

The producer report does **not** establish the final five project-location/revision
claims, prove that a given source checkout produced its compiled inputs, or supply
a unique module for every target. Do not guess a module from a declaration prefix.
The operator must obtain the mapping from the actual approved project and build
selection. `project_dir` is relative to the repository; local build-search paths
are not values to copy into that field. Offers are claims, not certificates.

Limits are already fixed: a map at most 2 MiB/2,048 keys, at most eight offers
per key, no duplicate keys/offers; full structured names and exact field sets;
bounded source URI/relative-directory/revision syntax. Use the existing canonical
UTF-8 JSON encoding (`sort_keys=True`, `ensure_ascii=False`, compact separators,
`allow_nan=False`), not PowerShell's default JSON formatting or BOM/newline output.
Do not copy the existing `SYNTHETIC-MAP.json`'s `example.invalid` URI or dummy commit
as a real source offer. Canonical serialization is necessary for this map, not an
assertion that every operational JSON input uses identical canonical-byte rules.

The public serve config adds exactly:

```text
authoring_offers = {path: explicitly selected absolute map path,
                   sha256: SHA-256 of its exact bytes}
```

All existing custody disclosure/exclusive-owner/service lease/limits still apply.
The operator must separately approve revealing repository names and revisions;
ordinary custody disclosure does not imply approval to reveal private project
locations. A previously private repository is not to be published merely to fill
this example. The lookup may legitimately return no source offer.

### Simpler existing alternative

Read `ordinary_authoring_offers/API.md` + `CODEC.md`, create the exact map/config
manually, and use the existing public entry. This already implements the workflow;
there is no missing mathematical or peer operation. A one-page worked addendum
only reduces the need to combine separate schema documents. It has a lower
maintenance/safety cost than another version of the pure preparer or a broker.

### Expected payoff and stop condition

Expected benefit is a reduced operator handoff error rate and making source hints
usable in the practical concept-development loop. No source guarantee, discovery
quality improvement, autonomous concept invention or measured growth improvement
follows. If relevant approved projects are not available, this addendum cannot
create them and a downloader would not repair the missing supply.

Stop after source-reviewing the exact worked data mapping and launcher argument
shapes against the existing public API, with explicit disclosure and evidence
limits. Do not launch another concept episode, native build, certificate campaign,
network deployment or complete package test merely for this addendum. Do not add a
new helper unless a real operator subsequently demonstrates a failure that the
existing public interface and worked example cannot reasonably resolve.

## Why no second candidate is selected

The paper's metered/isolation-aware agent harness and experimental policy contrast
are real study prerequisites, but that work belongs to the other chat and is not
an established product requirement. Novelty ranking, abstraction investment,
semantic equivalence and automatic consolidation remain hypotheses rather than
validated reasons to change this architecture. Treating them as required software
now would repeat the sunk-cost architecture error the user asked us to avoid.
