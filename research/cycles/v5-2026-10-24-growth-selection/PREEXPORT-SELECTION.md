## Decision-changing evidence

Does an existing tool return an adequate advisory candidate and source/package
locator from a locally meaningful formal query without requiring our evidence
export? Can it be used through replaceable finite-corpus providers without one
indispensable server? What additional local glue is actually absent, as opposed
to a better search engine we merely wish existed? Resolve these from source where
possible. A finite API/parser integration check can later verify a chosen adapter;
it cannot establish broad mathematical uptake, relevance or global completeness.

The output must change the next software action, not repeat the existing demand-
materialization or growth inequalities. Prefer a maintained tool when it fits;
explicitly reject a new abstraction when ordinary use already supplies its value.

## Closed decision: reuse upstream; defer new transport

Root read both complete PREEXPORT-TOOLS and PREEXPORT-CODE-GAP notes. The source
investigation is complete. Loogle provides ordinary formal search and maintained
clients already support configurable providers. A bounded plural client has a
coherent narrow contract, but its marginal value is conditional on useful corpora
and a consumer who needs that multi-provider boundary. Neither is established by
this inspection. Implementing transport now would not resolve the growth question.

Therefore **no new discovery client, matcher, registry or runtime is selected**.
Use existing upstream tooling where approved. Preserve the response-shape and
resource findings for a later concrete integration; do not repeat the public GET.
Current exact evidence search remains available with its existing semantics.
Source names or unmaterialized hints must not be placed into its proof-derived
identity namespace. Advisory discovery never supplies mathematical acceptance.

This closes the task at hand without an implementation campaign. It is a payoff
decision, not a claim that bounded multi-provider discovery has no future value.
Reopen only for a named workflow with useful independently served content and an
actual missing client boundary, or a deployment requirement that makes it necessary.
The user's growth-first steering now takes priority over further adapter work.
