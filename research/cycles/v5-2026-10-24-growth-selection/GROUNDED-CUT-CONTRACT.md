# Grounded interface cuts: bounded local acceptance and recursive reuse

2026-10-24. Root design selection after reading both appended source reviews in
LIFETIME-VIEW-FEASIBILITY. Full v5 remains active. This selects a finite contract
and existing-theory dependency trace, NOT implementation, migration, native work
or cryptographic production. The ordinary bounded-operation package is a separate
completed-source integration; no used checker or evidence is modified here.

## Decision and actual workflow

An investigator who has already checked useful mathematics should be able to
continue it without restoring every earlier proof. Current native admission
rechecks only new proofs but rebuilds the selected parent chain. Repeated small
extensions can therefore revisit quadratic total history. Existing batching and
small specialty roots remain preferred when they already solve the workload.

Investigate a distinct local rule: check new proofs in a small environment whose
old theorem assumptions are discharged by exact, earlier local checking warrants.
The new rule accepts fewer computational uses than full native imports; that is
allowed. It must not accept an unwarranted assumption or claim compatibility it
does not have. This is not a solution to first-use cold trust or automatic novelty.

The first candidate accepts EXACTLY ONE NEW THEOREM PER EVENT over an existing
compatible theory, referring only to earlier committed warrants.
Ordinary approved projects still introduce definitions, structures and inductive
theories through the current full route. Cheap continuation can later justify
support for new singleton definitions, but it is not needed to decide this seam.
This restriction is on the proposed accelerator, not the commons' mathematics.

## Logical rule and unresolved assurance obligation

Let K be a genuinely warranted local context under fixed foundation F and an
eligible support epoch e. Build H from F and a finite selected semantic closure.
Each nonfoundation axiom in H must be c:P where c is an exact earlier theorem in
K, with the same name, portable identity, universe parameters and full type.
No arbitrary local project environment is a permitted starting H.

For every concrete non-theorem record retained in H, keep its exact type, body,
universe data, reducibility and generated group/recursor rules. Reconstruct/check
whole groups, never isolated constructor or recursor signatures. Close all type
and value references, including implicit primitive/literal requirements. This
closure may stop at warranted theorem types, not at arbitrary definitions.

Require a realization J from H to K: foundation and concrete computational rules
have their existing meanings; each scratch theorem assumption denotes its exact
earlier proof. J must preserve the actual typing/conversion rules used by the
selected Lean profile. If the kernel checks H |- t:Q with Q:Prop, then this
realization gives K |- J(t):J(Q). That conditional implication is the acceptance
argument. Generic substitution is not a completed proof of the implementation's
inventory extraction, primitive coverage or correspondence to the Lean kernel.

Only successful small-environment checks count. A proof that needs an omitted
theorem body may fail; report an unsupported/unsuccessful cut check, not falsity.
Never fall back to larger acquisition or restoration within the same allocation.
No preservation of every original native success or constant checking cost is
promised. The old proof-erasure counterexample does not refute this one-way rule.

## Local state and authority

The necessary new local state consists of immutable, typed summaries and a
root-bound persistent name map; it is not a global ledger or peer trust service.

- A theorem summary binds name, kind, universe parameters, full type, exact
  symbol/export/unit identities and the earlier accepted event/support binding.
- A concrete-group summary binds all exact descriptors and generated inventories,
  group membership and required identities. The group cannot be silently split.
- A logical root binds the foundation, store, support epoch and immutable name-map
  root. Lookup must establish both positive membership and absence of new names.
- An accepted cut event binds its old root, selected summary frontier, checked new
  theorem units, clean worker event, result summaries and new map root.

Summaries are local memory of genuine checking events, not claims that short types
hash to old full UnitIDs. First derive and authenticate them during a real accepted
event, or perform one explicitly paid migration of an eligible native root. The
current profile's whole-parent verification may be needed once for that migration.
Never manufacture authority from a downloaded summary, saved PASS or matching name.

A persistent authenticated trie is one implementable map candidate. Charge the
initial construction, copied update paths, retained nodes and integrity reads.
Hashing a name does not excuse collisions: retain and compare the exact encoded
key, refusing inconsistent identities. A full name-map copy at every extension
does not meet this design. The concrete data structure is not selected yet.

Protected storage/OS and approved checker/controller integrity remain assumptions.
Checksums can detect changed data relative to a protected root; they cannot defend
against an attacker rewriting that authority itself. Original proof custody and
authoring-source retention remain separate availability responsibilities.

## Acceptance and crash boundaries

1. Under the existing serialized owner discipline, select eligible root K and one
   original finite resource grant. Bind the support epoch and all request bytes.
2. Resolve only the demanded exact summaries, checking root membership and new-name
   absence. Form the complete scratch closure and exhaustive assumption census.
3. Launch one fixed pinned worker with the exact foundation/closure/request. No
   source, plugin, peer binary or arbitrary caller environment is loaded.
4. Reconstruct H and check exactly one complete new theorem type/proof using the
   real kernel. Require a theorem declaration, Prop-valued type, exact claimed
   inventory and a name absent from the complete old map. Scratch assumptions must
   correspond bijectively to selected, eligible earlier theorem handles.
   Unexpected constants/axioms fail closed; no pending intra-batch references.
5. Obtain the existing clean process-tree completion event, exact report and
   immutable output bindings. Recheck request/root/support eligibility before
   promotion. Worker output alone is not permission to choose a different root.
6. Atomically commit event, exact result summaries and persistent-map root. Only
   that transaction creates eligible local warrants; partial staging does not.
7. Future cut calls use those committed summaries rather than importing a scratch
   olean or replaying a native one-parent chain. New references must point to
   earlier committed events; cycles and mutually pending warrants are forbidden.

Uncertain/interrupted execution preserves diagnostics and staged bytes but creates
no eligible event without the protected transaction. After an uncertain commit
reply, recovery inspects the actual committed event, not a remote/client success
flag. No silent replay, allowance renewal, source-state migration or lock removal.

Start with one conservatively selected support epoch: withdrawing any required
checking support invalidates the whole affected epoch, including descendants.
This may over-invalidate but avoids recursively revisiting proof histories on
every use. An epoch rename cannot rehabilitate withdrawn warrants. Upgrades or
cross-epoch imports need explicit revalidation; selective revocation is deferred.

## Return, coexistence and mathematical identity

Keep complete NEW theorem proof units and exact import bindings for ordinary
inert publication. No scratch axiom is published as a newly accepted axiom, and
no scratch olean is labeled a checked native snapshot. Other receivers ground
their own premises; they do not trust our cut-event report or implementation ID.

Existing native catalogs cannot restore a new cut origin unchanged. The design
must use an explicit distinct origin/backend with compatible public operations,
not a Boolean bypass inside _commit_checked. Do not promise direct native-project
materialization from these summaries. The already approved ordinary project
remains an authoring route; native replay remains a separately selected option.

Select a distinct local `grounded-cut` warrant contract and backend. Its assurance
is the positive interpretation rule above, not a silent reinterpretation of the
old `kernel-checked-extension-of-warranted-parent` origin. It requires a distinct
implementation/support identity and an explicit correspondence to the selected
Lean foundation. Ordinary V2 exported proof bytes remain publishable as inert
claims only; neither old native-origin/profile conformance nor direct native
snapshot compatibility is asserted. First persistence uses one native-bootstrap
source lineage and one conservative support epoch; cross-epoch migration is
deferred. These choices close the independent review's two contract conditions,
not its remaining implementation and full-cost gates.

## Cost target and falsifiers

For a finite sequence, target

    initial_summary_cost + sum_i(index_i + semantic_closure_i
      + new_proof_check_i + commit_i + failed_attempts_i),

plus retained storage, public evidence/authoring distribution and service costs.
There should be no mandatory read proportional to omitted old theorem proof
ancestry or unrelated root history. Large selected types, concrete definitions,
groups and proof terms inside their bodies still cost their actual sizes.

This is a nonempty conditional benefit region, not a measured research speedup:
the avoided restoration/re-admission must exceed setup, semantic reconstruction,
index maintenance and failures. Existing one-final-batch and small-root strategies
receive full credit; a ranker or theorem count cannot establish this inequality.

Stop or narrow the lane if (a) exact realization needs unavailable semantics,
(b) summaries cannot be bound without whole-history work on each call,
(c) recursive state needs scratch axiom trust, (d) a return path silently changes
the claim, or (e) the actual useful closure dominates the work we hoped to avoid.

## Independent finite-contract review

**Conditional SOURCE GO, with the following two concrete choices fixed before
implementation.** No fundamental counterexample remains to the theorem-only
rule under its stated exact-closure and protected-event premises. This is not
approval of an implementation, a runtime campaign or a final acceptance label.

1. Select a distinct local `grounded-cut` warrant contract/backend now. Describe
   its assurance as a positive interpretation into the selected Lean foundation;
   do not leave the existing insertion phrase silently reinterpreted. Keep V2
   output bytes only as ordinary inert claims, which a receiver must independently
   admit. A new local support/implementation identity is mandatory. Compatibility
   with old catalog admission or project snapshots is not part of the first slice.
2. Accept exactly ONE new theorem per event initially. Step 4's ordered batch and
   step 7's earlier-committed-only reference rule otherwise conflict when a later
   new theorem uses an earlier theorem in that same batch. One theorem resolves
   this without another event-order protocol; recursive reuse is two committed
   calls. Check output is genuinely `.thmDecl`, its type is Prop, its actual
   inventory equals the claim, and its name is absent from the complete old map.

The realization obligation is tractable, not a requirement to prove equal native
success sets. For this slice, J keeps exact constant names/universe arguments and
maps each scratch proof assumption to its named K theorem. All computational
records present in H have identical complete rules in K. Thus beta/zeta and the
preserved delta/iota/projection/primitive steps, universe substitution and proof
irrelevance used in H retain their interpretations in K. K may have additional
theorem-body reductions, which H never needs to simulate. Positive kernel typing
in H plus this rule correspondence gives the output's K judgment. Implementation
review must tie this finite rule argument to the fixed profile and exact closures;
it must not treat arbitrary `ConstantInfo` injection as kernel checking. Unsupported
generated or primitive cases can refuse rather than weaken the rule.

For the first persistence slice, use one native-bootstrap source lineage and one
conservative epoch; defer legacy-import/cross-epoch migration. Migration must hold
the eligible source's existing owner lock, validate its exact chosen root once,
and derive summaries from accepted bound records, not caller-selected types.
An exact proof-unit hash does not bind a separately substituted summary unless
the protected derivation event establishes that association. Future calls may
trust that retained local association under the existing protected-storage premise.

The mandatory recursive check is concrete: event E1 accepts q; close/reopen the
new owner; E2 uses q's committed interface without restoring E1's scratch state
or proof ancestry. E2 must refuse an altered q summary, a q on another branch,
an uncommitted E1, a name already present outside H, and an ineligible epoch.
Commit recovery must identify the exact event/request; it cannot silently issue
a fresh event after an ambiguous reply. These are source invariants first, not
a request for a broad or repeated mathematics experiment.

Keep original proof claims separately obtainable for ordinary public return.
Retaining only a valid local signature is insufficient for a new remote receiver
to acquire its proof. Conversely losing a custody copy need not erase a sound
protected local event: the contract must distinguish unavailable export from
withdrawn checking support. Do not encode both as mathematical rejection.

Proceed to the smallest source implementation only if the concurrent retained
theorem trace supplies a supported finite closure. First-class boundaries should
be: native-to-summary migration, root membership/freshness, scratch/check worker,
and atomic new-origin commit/reopen. Reuse current supervision and codecs; do not
start with a daemon, network protocol, certificate, new prover or general-purpose
module importer. Review the first recursive state path before expanding the
accepted declaration kinds. This resolves the current decision without asserting
that the remaining controller/refinement implementation has already been proved.
Compare its cost against actual cheap native snapshot restoration and batching,
not an invented full-proof-rechecking baseline. Repeated concrete-definition/group
checking, migration and indexed persistence may outweigh saved imports. A smaller
closure in bytes is a useful structural discriminator, not performance evidence.
