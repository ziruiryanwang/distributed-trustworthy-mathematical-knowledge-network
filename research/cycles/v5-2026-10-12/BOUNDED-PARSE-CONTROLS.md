## Oracle and scope

The oracle is the retained `canonical::parse_validated`/`canonical_size` plus
the retained aggregate census source, compiled by explicit path in a separate
test module. It is not another hand-written parser or mathematical checker.
Successful new tokens must expose exactly the same Value and canonical bytes;
their immutable counters must match small hand-counted examples and the old
aggregate state. Rejected inputs require both routes to refuse, not identical
error order/text or partially mutated failed census. Old bounded canonical K can
be undefined on a syntax-parsed over-node Value; such cases test rejection domain,
not a claimed K-length inequality. The general length proof is in root's decision.

Exact successful Js follow from handing the identical Value to unchanged
`check_bound`; a later separately selected retained-mathematics/native comparison
must confirm the compiled boundary. These syntax/control tests do not claim a
real certificate, substantive native checking, guest execution or speedup.
Only deliberately early schema refusals should invoke relation entry points here,
before foundation/kernel work; no mathematical fixture or checker is reinvented.

## Ten bounded changed-boundary groups

| Group | Finite discriminator |
|---|---|
| 1. Legal strings and key spellings | Literal UTF-8, escaped slash/quote/backslash, short controls and six-byte control escapes, raw astral scalar versus surrogate pair; exact Value/canonical bytes and canonical length<=raw length on each accepted example |
| 2. Keys and Unicode identity | Escaped keys, key reordering, canonically distinct composed/decomposed strings; reject duplicate decoded keys including literal-versus-escaped aliases; no normalization |
| 3. Unsigned number boundary | 0,127,128,u32::MAX,u64::MAX; reject negative1/negativezero,fractions,exponents,overflow and malformed leading zero; exact Value on accepted cases |
| 4. Strict text/EOF | Empty,truncated,concatenated roots,nonwhitespace tail,invalid UTF-8,isolated/misordered surrogates; allow only permitted trailing whitespace |
| 5. Cached census | Small known tree counts/depth; keys are not Value nodes; repeated immutable borrowing leaves Value/counters unchanged; no token construction outside strict parser |
| 6. Actual parser recursion | Exactly127/128 nested arrays and objects, plus a mixed-container path; same acceptance boundary on old/new bytes, not a substitute Value-depth limit |
| 7. Parameterized structural boundary | Root-approved private `cfg(test)` scanner seam, fixed small trees at node/depth maximum and one below; returns only counters/error, NEVER a token |
| 8. Aggregate successful shapes | Exact named and positional top-level/parent record forms with noncanonical JSON spelling; equal returned Value and successful cumulative census |
| 9. Aggregate refusal and accumulation | Missing/extra/wrong-type fields; seed rows,bodies,openings,edges,nodes near actual caps, then success and next refusal; seedusize::MAX to exercise checked-add overflow; successful state only must match exactly |
| 10. Typed relation gate | Independently parse a fresh token for each invocation; compare retained public Value entry with bounded entry on shape-valid but deliberately wrong-schema input; both refuse before any native kernel work |

The groups contain small fixed tables and at most128 nesting constructors, not
long random loops, exhaustive fuzzing, million-node trees or giant byte strings.
Group7 exercises the same scanner recurrence with small limits; **it is not an
actual million-node boundary experiment**. Production's hardcoded one-million
node/256depth calls and private token construction are source-review obligations.
Likewise, Rust field privacy/nonmutability are compiler/API properties, not
something proved by attempting runtime handle forgery. No unchecked constructor,
`Default`, deserialization, mutable Value borrow or caller-provided token counts
may be added for test convenience.
