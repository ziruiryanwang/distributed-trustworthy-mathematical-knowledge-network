## How a real owner can use the package

All ordinary calls use the installed
`receiver/runtime/python/python.exe -I -S -B`, an independently adopted
`RELEASE-MANIFEST.json` digest, absolute ordinary paths, fresh evidence and finite
CPU/wall/memory/process/stdout/stderr limits. State is separate from installation;
one controller owns an active state. Do not invent a new hash from an untrusted
peer's package and call that adoption.

| Purpose | Actual shipped entrypoint | Actual authority/result |
|---|---|---|
| Provision base theorem owner; finite base-node commands or holding lease | `operator/commons.py provision` / `node` | Configured custody and supervised operation; every mathematical network result remains unverified |
| Configure selective theorem candidate search | `candidate/provision_candidate.py`; then returned `start_argv` / `restart_argv` | Exact configured candidate node, not an automatic daemon/supervisor |
| Check/use acquired theorem fragment | `operator/commons.py workflow -- check-fast ...` or `apply-fast ...` | Genuine frontier verification plus local native checking; nontransferable local assurance |
| Retain guest route explicitly | Same workflow entrypoint with `check-fragment` or `apply` | Guest execution and real frontier checks, not a newly produced receipt |
| Provision direct-definition owner | `operator/definitions.py provision` | Fresh exact role/configuration records; node storage initialized at first successful create |
| Pack/prepare/check a direct closed definition | `operator/definitions.py pack` / `prepare` / `check` | Pack/prepare are inert; check inspects the actual body and returns nontransferable local assurance |
| Adaptive definition search/acquisition | `operator/agent_session.py` with definition-candidate config | Bounded live binary-pipe JSONL; caller can inspect each reply before choosing its next request |
| Compose supported definition bodies | `utilities/compile_definition_cli.py --selection ... --selection-sha256 ...` | Exact acquired-capsule inputs become inert compiled output; final checking still required |
| Request a certified cut | `operator/commons.py seal-request` | Handoff record only; not certificate production |

The public workflow does not accept a peer-selected checker/profile override.
`check-fast` needs `--fragment`; `apply-fast` needs `--application-plan` and
`--expected-capsule`, with selected parent/local-definition/local-fragment inputs.
Both require a fresh mathematical run, explicit internal CPU allowance and UTC
deadline in addition to outer process limits. Operation-reservation charges are
not measured CPU; the documented example allowance1200 is distinct from outer
CPU120. A supplied formal target is local construction data, not a mandatory
global research agenda or human-intention acceptance criterion.

For definitions, pack uses `--capsule`, whereas prepare/check use `--artifact`.
The adaptive session is not a console or file-redirection interface: its owner
must supply binary stdin/stdout pipes, wait for ready, and keep at most one
request outstanding. It forwards actual replies and records a separate terminal
closure event. Sender OK, matching IDs and local custody never replace the body
check. Acquisition returns the actual retained `definition_path`; the compiler
must consume that path's bound bytes, not an author's hidden substitute.

## Important asymmetries: do not conceal them in the handoff

1. **Adaptive containment is definition-specific.** The new session verifies the
   exact definition roles/configurations and launches the definition candidate
   node. It does not accept a theorem candidate configuration. The theorem
   candidate guide still requires the caller to supervise the returned raw Node
   program-and-arguments array. The finite base facade cannot dynamically insert
   an earlier command's provider response into a later static request. Therefore
   the new client is a material improvement, not a universal agent SDK.
2. **Construction is still an inert utility.** The definition compiler is shipped
   with exact input-selection grammar and internal bounds, but it is not a new
   bounded `commons.py` subcommand. Its own API requires externally selected
   whole-command resource containment. Actual circulation's root enclosure can
   qualify the selected use, but is not a shipped general agent supervisor.
3. **Cut creation is a separate role.** The compact package cannot run
   prepare-seal/advance. The existing full installation has those real commands,
   described in FULL-SEALER-PATH.md, and needs an independently adopted owner,
   successful capacity and funding. A handoff file or native check does not
   make an unbounded contribution chain self-sealing.
4. **Initial mathematical inputs are formal and restricted.** The agent supplies
   inert typed plans/capsules or compatible acquired objects. There is no ordinary
   natural-language interface, hidden proof search or arbitrary Lean/mathlib
   import. That respects the intention-independent design, but supported semantic
   coverage is still a central engineering limitation.

These are concrete interface/adoption costs to include in any claimed full-route
advantage. They do not require a mandatory network research planner, identity
reputation or a new ledger.
