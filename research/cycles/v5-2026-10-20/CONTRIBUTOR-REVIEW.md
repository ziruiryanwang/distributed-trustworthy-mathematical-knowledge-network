## Bounds and cleanup

One operation grant owns input admission, import, authoring, output admission
and publication. Lower-level packet staging is explicitly outside the client's
action counter but remains bounded by workspace quotas, original grant
deadline callbacks and the enclosing Job; it is not claimed as a separately
metered client action. Authoring uses the runtime's pre-existing non-acquisition
CPU reservation, while both admissions consume the acquisition verification
reservation. An eventual exact selection must fund both, rather than reuse a
reader-only allocation.

The helper bounds source data, root/export counts, CPU/wall options and worker
memory against the enclosing selection. Its workspace is ordinary and disjoint
from installation, source roots and run output. The grant deadline is at most
the original outer deadline minus five seconds. Contexts/warrants are not
serialized as reusable authority.

Cleanup closes all four selected owners, then the workspace, preserving
cancellation first raised during cleanup. Failed cleanup/deadline changes the
report to FAILED; a clean miss or demand may be COMPLETED with
NOT_CONTRIBUTED. Main's zero exit therefore means completed bounded operation,
not necessarily a mathematical contribution. Report-write failures preserve
the primary exception and cancellation objects.

No additional native/full-suite run is justified by this source review alone.
A later selected check should target the new ordinary-owner composition and
installed-path authoring seam, retaining existing verified primitives and
avoiding new cryptographic proof production.
