## Decision

GO for one existing-API interoperability continuation; NO-GO for a new numeric
bridge, import framework, certificate campaign or claimed growth benchmark.
The seam correctly identifies existing machinery and its authority boundaries.
It is a narrow concrete product check, not resolution of both central v5 goals.

## Existing APIs are sufficient in principle

`ModuleExportAdapter` supplies per-declaration structural features and locators.
`find -> resolve -> acquire` and `SemanticReadPlan.stage/preview/finish` already
separate candidates, required semantics and actual live mathematical admission.
`MixedImportSession._build_context` includes complete chosen groups and bodies;
`AuthorLean.installGroup` checks their qualified reconstruction in its environment.
`MixedSourceOperation.finish` decodes imported names as exact external references.
Therefore child reuse should not require any new identity or mapping API.

Use `DMKN.Mod.<M>.Nat`, its explicit recursor/constructors and checked add body.
Builtin `Nat` and M.Nat are distinct. Imported M.OfNat is not builtin OfNat;
normal numeral notation or imported class/tactic registration is not warranted.
The proposed explicit recursor and fixed equality terms avoid that extra seam.
Require the child spec to contain external M references and no recaptured Nat.
The exact add body, not its printed name, determines the induction equations.

## Do not conflate two verification claims

The arithmetic smoke M=349e201e... is a native witness, not a public warrant
or I certificate. Construct its ordinary zero-parent mixed packet, then use
the real configured receiver to issue authority before authoring from it.
Do not reuse the deliberately withdrawn integration-test trust domain.
Authoring can omit ancestral theorem proofs, but existing onward packets retain
uncertified ancestry. A fresh receiver must check that native closure; selecting
few semantic groups does not make the retained packet's proof cost disappear.
Only an actual applicable I/A cut permits the separate certificate-bound claim.
Existing BASE/Tree receipts do not certify M by analogy.

## Discovery must be stated precisely

Handing over M's exact ID tests location, not unknown-ID discovery.
An independent initial query can use declaration-kind=theorem, result-head=
foundation Eq, and type-edge(forall,domain,const). All are implemented and need
no M ID. Resolve a candidate first; its exact M.Nat/M.add export IDs can then
form selective follow-up queries for independently unknown theorem IDs.
The first query is broad. Current edge sets lose position, multiplicity and
repeated-unknown-symbol constraints. Pair indexes do not restore those facts.
Neither a tiny passing corpus nor exact-ID follow-up proves global selectivity.
If discovery is selected next, investigate an address-independent structural
pattern key before another benchmark; preserve exact identity at acceptance.

## One next action and payoff boundary

Use the existing public admission/import/author path once for the explicit
M.Nat addition-associativity child, then verify its exact external references
and fresh onward admission. Resolve only a concrete refusal if one appears.
This tests a new semantic boundary: useful induction over acquired arithmetic.
It does not justify network net benefit: ordinary associativity already exists
in optimized libraries, and transporting it into M's vocabulary is a comparator
option. Any later growth claim must charge that option, publication, acquisition,
failed search and retained proof ancestry; do not call this example a speedup.
No API source change is presently justified. Root owns selection and adoption.
