## Purpose and runner interface

Test one real retained-artifact adoption and no-host complete-path quote, then
challenge the new source boundaries using explicit, narrowly scoped mutation
doubles. This resolves whether the new bridge admits the genuine successful
general arm without laundering its failed optimization screen or changing the
typed image, original provenance, source closure or session identity.

Runner: `typed_production/test_adoption.py --profile PATH
--profile-sha256 SHA --request PATH --request-sha256 SHA --output FRESH_DIRECTORY`.
The profile and retained-general36 request must be explicit
owner-selected typed composite profile; the tests do not silently substitute an
old profile, choose a new image, renew an allowance or discover runtime inputs.
Its support runtime pins must bind the complete29-module typed source closure.
The control source and any CLI source exercised are separately selected.

Required loaded product sources: typed core29, test_adoption.py and, if operator
entry controls are selected, typed_production/operator.py plus unchanged
aggregate_small/operator.py. Base installation support modules remain selected
by the explicit profile. No compiler/toolchain tree is recursively rescanned
for every negative case. Genuine initial owner adoption performs all its real
checks; later captured-record doubles are labeled non-binding controls.

## Evidence limits

One genuine owner construction establishes actual local record/source binding.
Captured-record logical mutations establish only their exercised validation
branches. No test double supplies mathematical authority, a real receipt, a
successful proof stage or durable allowance history. No profile mutation is
accepted merely because JSON looks plausible. This suite does not establish
same-image A-parent certification/renewal, economics, memory feasibility,
independent hosting or full-v5 readiness.
