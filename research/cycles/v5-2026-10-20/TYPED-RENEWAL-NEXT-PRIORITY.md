## What the retained theory actually requires

Let L be a named optimized isolated/local policy, O ordinary decentralized
sharing, and C optionally succinct-certified sharing. All receive the same
initial mathematics, representations, supported local optimizations and cache
policy. New remote discoveries are not donated to L; already known methods are
not withheld from it. O is a valid implementation component of v5, not a rival
that every v5 action must defeat.

The October7 GROWTH-WORKLOAD and October20 GROWTH-CLAIM-TARGET already distinguish
these comparisons correctly. BENEFIT-CASE rejects a speculative SAT experiment
without denying ordinary sharing. Its missing positive-case statements are
historical: the later matched sharing outcome supplies one concrete observation.

The October16 GROWTH-CRITICAL-PATH section headed "A concrete benefit region
that compares both serious alternatives" instead analyzes the stronger claim
that C beats BOTH L and O on the selected workload. That intersection theorem
is legitimate for that stronger claim. Treating its two positive margins as a
universal release requirement for every seal or every shared result would be
self-imposed and stronger than the user goal. Historical CURRENT-DESIGN wording
"against both" must be read with this distinction, not as a renewed universal
gate. Frozen historical evidence should not be rewritten to fix navigation.

Conversely, no simplification permits weakening any of these requirements:

- Actual mathematical acceptance remains bound to the adopted checker,
  foundations, exact objects and real certificates. Popularity is not authority.
- The supported certified route must remove mandatory opaque-theorem proof-
  ancestry replay and must genuinely renew from an earlier certified frontier.
- Search must avoid mandatory corpus enumeration, report finite coverage and
  charge failed work. Bounded attempts alone do not prove recall.
- Operational growth claims need a named resource/capability comparison and
  actual costs or justified bounds. No universal usefulness or novelty oracle,
  provably optimal research algorithm, future cold demand or exponential-growth
  promise is required or established.

## One concrete API recipe

This is a recipe for an optional local agent, not executable code or a selected
experiment. Its mathematical target and formal query are chosen locally.

1. Before work, name an existing local baseline B, its immutable inputs,
   initial cache state and supported finite execution envelope. Give B the same
   local tools/optimizations as the assisted route. Separately select a small
   network envelope Q and an explicit total horizon/resource plan covering
   Q, B, both setup/closure costs and any required provider work. Do not derive
   Q by fabricating future popularity or an assumed hard local proof.
2. Use an ordinary pinned public network request and its own workspace/grant.
   Its owner uses existing bounded formal-query, acquisition, actual admission
   and applicability checks. A hit must reach the same required mathematical
   endpoint as B; an accepted but irrelevant theorem is not a successful branch.
   On success use that live context within its owner; exporting exact bytes for
   a later owner requires normal new verification, not serialized-handle reuse.
3. A settled absent/inapplicable/refused result is an explicit branch outcome.
   Stop that branch, settle outstanding requests, close genuine owners/service
   and record all charges. Unclean closure, lost authority, unexpected storage
   failure or unresolved resource accounting is not an ordinary miss and does
   not justify reviving that owner. No blanket exception-to-fallback conversion.
4. Only after a permitted clean outcome, the agent may invoke B in its separately
   specified ordinary public request/workspace, with the unchanged input/initial
   knowledge policy. The finite two-branch plan was fixed beforehand. This is
   not a renewed grant for the failed search. Fresh baseline owners establish
   their own authority; no mutation/reset of the former run or private state.
5. Preserve the original total deadline in the caller's plan. Before starting B,
   require enough remaining envelope for its preselected costs and cleanup.
   If not, return an explicit overall resource refusal. Issuing B's fresh local
   deadline does not create more total time or erase Q. Reserving B's grant at
   network startup is not an alternative: its wall deadline would age while
   waiting. Memory feasibility, shared-machine interference and persistent disk
   capacity remain separately accounted constraints.

The two-request form is preferable for explaining independent budgets; it uses
the existing launcher twice rather than modifying the commons. A same-owner
optimized recipe may instead use continuing contexts and deliberately leave
headroom in every shared grant dimension, but it cannot claim the same isolation
merely from the author's worker-CPU subtraction. No such optimization is needed
to establish the policy's principle, and no run is selected here.

## Conditional resource statement, not another economics calculator

For one additive resource coordinate, fix a successful supported local B route
of cost b. Suppose the selected network branch, including its setup/closure and
attributed service, costs at most q, and the two-branch transition/additional
baseline overhead is at most h. Suppose a clean miss leaves the independent
baseline inputs and environment satisfying B's same success/cost assumptions.
Then on a permitted fallback the policy reaches B's endpoint at cost at most

    b + q + h.

Proof: the branches are sequential, their charged intervals/work are disjoint,
and B is unchanged; add their upper bounds. There is no parallelism or processor-
share assumption. For several additive coordinates the same statement holds
componentwise. Peak memory is instead a feasibility maximum plus retained state,
not an additive sum. Without actual q/h bounds, this is conditional, not a
physical CPU guarantee inferred from nominal caps. Supervisory overshoot,
termination/report tails and remote provider work must not silently become zero.

If the network is successful, its cost is compared with b at the equal endpoint;
the retained sharing observation is one such positive case. If it misses, the
additional price is bounded by q+h under the stated assumptions. This explains
why optional search can be rational without claiming every query is useful or
that the entire protocol always improves the baseline. It does not prove positive
expected benefit without a defensible success distribution, and does not claim
completion when an outer failure prevents the fallback's required premises.

implementing now. Root can consume this recipe into ordinary agent API guidance

or rerun M/mirror to justify it. If an actual caller later cannot express the
