## Test boundary and economy

Use actual codec group openings, actual ModuleStore/PacketStore instances, the
specialist source index and a distinct ordinary base Store. Retain one opened
workspace and its real exclusive lock. Projection metadata occupies only the
contract's fixed workspace subtree; no second mathematical custody tree exists.
Use small structural declarations with **no theorem acceptance**. Actual query
evidence passes ordinary summary/page verification and provider direct dispatch.

Service controls should invoke the new service selection/cleanup paths while
substituting only HTTP listener start/wait and location process execution. Keep
the actual provider construction, selected index, original custody, source
workspace and target-store closure real. Forbid process startup and sockets.
Clearly label those controls as inert transport/location, not live endpoint,
public advertisement or remote retrieval evidence. Do not replay the established
ordinary-service suite or scale up providers.

## Important evidence distinctions

- The initial base query is defined before candidate IDs and specialist profile
  knowledge; materialization remains an owner's explicit export selection.
  This establishes consumer compatibility, not automatic whole-corpus indexing.
- An empty base-index answer differs from `NAMESPACE_NOT_SERVED`; record both
  outcomes rather than treating cross-profile refusal as an empty matching corpus.
- Partial failure needs actual reopened target inspection, not only an aggregate
  counter assembled from successful return values. A post-commit exception is an
  uncertainty case, not evidence that the transaction rolled back.
- The new actual lifecycle boundary is **workspace ownership plus separately
  retained/borrowed metadata store, selected-provider binding and exception-safe
  closure**. Real object identity and real database/lock cleanup can test it
  without new sockets. Inert transports cannot establish actual external serving.
- A later narrow live check is justified only if the fixed implementation adds
  transport/lifecycle behavior not covered by the existing real service evidence
  and these source/control checks. It is not selected by this plan, and a second
  mathematical/proof demonstration cannot fill that operational evidence gap.
- Same mathematical custody may contain no proof packet for an indexed opening;
  packet unavailability must remain an ordinary explicit refusal. Projection
  neither certifies mathematics nor improves packet/body availability.

## Exit condition

Once the contract is fixed, implement only its changed-boundary controls and
submit source hashes for root's review and one separately bounded execution.
Do not invent unreviewed output/status fields, silently broaden partial-recovery
semantics, or promise exact snapshots stronger than the actual service contract.
Retain honest limits: no global completeness, scale/selectivity, growth benefit,
remote availability, mathematical acceptance or final-v5 claim follows.
