# Bounded conjunction profile: independent design challenge

core_release, source/theory only. Canonical guard passed; current installed SDK
map `a0d5fad8` resolves the actual evidence workspace to interface_views.
No code, test, import, proof, install, network, RAM or Git work. Coordinated with
core_search; read GROWTH-DISCOVERY-SEAM and GROWTH-OPERATING-REGION.

**Recommend the bounded pair-profile implementation in principle.** It changes
a real search-work term, unlike another certificate/demo without justified
demand. This is design clearance, not an implementation or scale-test pass.

## Correctness contract

Let Q be the distinct original atomic query features, 1<=|Q|<=8. An immutable
owner-selected profile P contains at most eight distinct unordered pairs of
distinct, validated existing atomic specifications. No nested compounds. Encode
canonical sorted specifications before computing the profile ID and namespace;
do not create a circular namespace/profile dependency. A separate compound hash
domain binds the new namespace and ordered pair. Old namespaces remain exact.

For an export x with atom set A(x), emit c(a,b) iff {a,b} is a subset of A(x).
For query compilation, consider only configured pairs wholly contained in Q.
Process canonical pair order; accept a pair only when it introduces an atom not
yet covered. Return those compounds plus all uncovered original atoms. If m
pairs cover U, then m<=|U| and output size m+|Q\U|<=|Q|<=8. Their expanded union
is exactly Q, so on correctly extracted records the new and original predicates
are equivalent. AB and BC can both be used; replacing ABC with AB alone cannot.
This deterministic cover is not claimed to choose the optimal/selectivest plan.

Candidate resolve must re-extract the entire profile-specific record from the
authenticated export opening. A provider's compound label is not proof of the
underlying features. Current posting membership authenticates committed records,
not honest extraction or complete corpus inclusion; retain this distinction.
Positive candidate cursors remain advisory, never verified omitted coverage.

## Necessary coherent source boundaries

- Add a distinct feature-schema tag and profile-bound namespace. Store and
  authenticated_index currently whitelist only the two old feature schemas;
  update these exact gates deliberately. Record V2 can retain its current shape.
- Keep MAX_FEATURES=128 and MAX_RECORD=16KiB if desired, but reject an export
  whose complete atomic-plus-compound record exceeds them. Never drop atomic or
  compound features silently. This narrows the fresh profile's admitted domain,
  not legacy compatibility. Bound profile bytes, count and per-pair validation.
- Preserve legacy ModuleExportAdapter behavior exactly when no profile is
  selected. Persist profile in a fresh evidence-workspace config schema;
  staged/validated inherit that actual workspace. Profile changes require a fresh
  namespace/index and charged reindexing; do not mutate old snapshots in place.
- Add adapter.compile_query. Both workspace_atomic.find and direct_contacts.bind
  currently call a free compiler with only namespace/specs; forward via the
  adopted adapter. No hidden mutable namespace-to-profile registry. Existing
  publication uses workspace.adapter and Store, so extraction must be integrated
  there too. Ordinary provider/consumer must adopt the same explicit profile;
  mismatched namespace refuses rather than silently returning a misleading miss.
- Keep mathematical objects, ExportIDs, custody, exact owners and all acceptance
  gates unchanged. No hardcoded Tree keys; Tree.leaf/node may be a caller-owned
  example profile only. Preserve current supplier/interface workspace behavior
  rather than overlaying an obsolete workspace predecessor.

## Real benefit, costs and limits

For the same admitted corpus at a fixed honest snapshot/partition, old driver length is min atomic posting
size. Each selected pair posting is exactly the atomic intersection; uncovered
atoms retain their postings. Every original atom is covered, so the minimum new
driver size is no larger. Two atomic lists of n+1 distinct exports with one common
export require n+1 old positions versus one pair position. Rejecting additional
exports at profile caps is not a search saving and must remain visible. Fixed 256 partitions
do not eliminate this old obstruction. No logarithmic universal semantic-search
claim follows; a hot pair or an unmatched profile can still require large work.

Ingest adds at most eight postings per export, bounded pair membership work and
existing authenticated-tree updates/storage/replication. A wrapper that first
hashes old-namespace atoms then rehashes them adds O(|A(x)|+|P|) work, not merely
O(|P|); extracting once under the chosen namespace avoids that duplicated hash
pass. Charge initial reindexing and ongoing service/retention. Adopt where avoided
search work over a supported horizon exceeds these added costs. Give both sides
of any certified-versus-ordinary growth comparator the same optimized index.

GROWTH-OPERATING-REGION's positive-cost interval is algebraically sound under
its lower demand bound on fixed T, eligible-reuse/cost premises and deterministic
per-queue arrival bounds with dedicated work-conserving service from empty start.
It is a sufficient conditional region, not measured demand, necessary actual
profitability, an average-load theorem or an end-to-end SLA. Conjunction postings
can reduce search q and queue work u; they do not establish eligibility alpha,
certification margin d, indefinite retention or inevitable knowledge growth.

Proceed with one generic bounded source change. Later changed-boundary controls
should distinguish distinct-type hot atoms/tiny pair, overlapping cover, missing
predicates, wrong profile, cap refusal, old cuts and real ordinary compiler/
publication wiring. No new proof production is needed to settle these questions.
