## Nonnegotiable implementation constraints

Use new outer and inner profile schemas and a domain-separated identity. Do not
pretend artifact references are historical build success records. Ordinary
pin-map roles must be explicitly specified wherever inherited `_no_override`
or scheduler/snapshot logic consumes them. Source and data contracts must agree
before substantial code. Do not monkey-patch any existing module or manufacture
old PASS records. Preserve exact inherited snapshot mathematics, wire/journal,
certificate verification, stage graph, limits, charge history and fail-stop rules.

The new `ReleaseLifecycleProducer` may reuse the existing generic lifecycle and
scheduler methods, but must initialize every required invariant explicitly. It
must validate its own complete source closure and imported origins, immutable
profile/descriptor bindings, adopted installation containment, ordinary paths,
finite count/byte bounds and cleanup after partial construction. No constructor,
preflight, snapshot or request construction may implicitly dispatch proof stages.
Only the explicitly selected run action may call the existing finite scheduler.

Avoid descriptor/manifest/profile hash cycles. Payload manifests must not embed
their own hash or the hash of a descriptor that pins them. Trusted owner selection
is external to those objects. Release identity is portable; local operational
profile/session identities may remain path-bound, with no transparent relocation
or continuation of an existing allowance. A relocated instance uses a new profile.

The operational closure must fit the existing256 outer-runtime row ceiling with
room for explicit per-operation inputs. State a smaller defensible installation
ceiling and aggregate-byte bound. Do not omit a required input to fit the count.
The current56-role estimate is a design clue, not a verified runtime inventory.
Do not repeat build/toolchain scans in ordinary calls or infer hermetic OS closure
from selected file hashes. Preserve trusted-local-filesystem assumptions explicitly.
