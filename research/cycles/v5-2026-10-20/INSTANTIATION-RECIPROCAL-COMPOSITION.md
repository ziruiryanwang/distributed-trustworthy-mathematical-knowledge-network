## One concrete, nonexecuted local investigation

Assume the local agent knows exact shared vocabulary A, B, C, predicates P/Q/R,
and functions f:A->B, g:B->C. It does not know result names or ModuleIDs of the
two useful theorems. It investigates, in local context x:A and h:P(x):

```text
R(g(f(x)))
```

An independently contributed method t2 might have type
`forall y:B, Q(y) -> R(g(y))`. After discovering and inspecting t2, the local agent
chooses y=f(x), leaving the formal obligation Q(f(x)). A second query might find
t1 of type `forall z:A, P(z) -> Q(f(z))`. Their potential composition is
`forall x:A, P(x) -> R(g(f(x)))`, with local Lean proof term
`fun x hx => t2 (f x) (t1 x hx)` using the exact imported relocated names.

This is an illustration of a reusable method chain, not an assertion that the
software inferred the instantiations, that these theorem fixtures exist, or that
this elementary composition has measured useful-growth value. The agent chooses
the research problem, applicability checks, substitutions and proof strategy.
Human intention and a global task list remain absent from network acceptance.

For example, a fixed profile observing `fn` and `arg/arg` can retain the rigid
predicate and generalize the argument position. Query the first goal with its
complete `forall x:A, forall h:P(x), R(g(f(x)))` codec wrapper and
`context_binders=2`. Do the same for the residual Q(f(x)) with the same explicit
context boundary. Shared symbols must use authenticated exact external/foundation
identities, not similarly named local constants from unrelated modules.

## Public path and authority transitions

| Stage | Existing public path | What it establishes |
|---|---|---|
| Formal goal | `conclusion_fingerprint.goal_queries(..., context_binders=n)` | Up to eight ordered singleton alternatives; bounded syntactic compatibility only |
| Finite search | `direct_contacts.reserve_queries/next_query`, or `located_queries.reserve_located_queries/next_located_query` | One original funded envelope; replaceable selected contacts or actual located descriptors |
| Candidate | `search_offer`, `search_page`, `resolve`, `describe_candidate` | Authenticated index/opening data and exact formal addresses, not mathematics |
| Evidence | `packet_offers`, `acquire`, or `stage_packet` then `admit_staged` | Actual original issuer verifies selected evidence and issues a same-live warrant |
| Semantics/import | `describe`, `semantic_material`, retained openings/bodies, `import_context` and NEED-only `extend_context` | One selected live context under warranted exact journals; missing semantics remain explicit demands |
| New contribution | `author`, or existing `contribute_from_context` owner helper | Frontend exports a new untrusted packet; separate `admit_local` checks it before claimed contribution |
| Publication | `publish` after new admission | Quota-bounded local custody and active-adapter index insertion; not remote placement or transferable authority |
| Onward reuse | `serve_workspace.serve` or `serve_advertised.serve`, then another client's ordinary pipeline | Fresh discovery/acquisition and fresh mathematical admission at the recipient |

Each generated singleton list is one query; concatenating alternatives would
incorrectly require their conjunction. Generate locally, select/order desired
alternatives and pre-fund actual operations. Neither generation nor a structural
hit grants another request, new owner, longer deadline or successful coverage.
The direct and located routes are alternative operation modes, not a mid-grant
permission to replace one envelope with the other. No contact/routing success is
assumed when a route returns incomplete, times out or finds nothing.

## The important lifetime ordering

For the example, resolve and actually acquire/admit t2 while generation 1 is
live. Save its needed authenticated data and genuine warrant w2. Rotate to a
query for the residual obligation and obtain w1 the same way. A warrant is not
retired merely because a query rotates; its original issuer, grant and pinned
sources still must remain live. Old candidates, raw staging capabilities,
contacts and a generation-specific SemanticReadPlan do retire.

Make **one combined import** with w1 and w2 after collecting the necessary
selected journals, openings and bodies. Do not call `SemanticReadPlan.finish`
after t2 alone if the plan is to add t1 later: finish performs its admission/import
transition, and READY is sealed. The ordinary acquire/admit path is already the
collection API. `MULTIQUERY-IMPORT-COMPOSITION.md` establishes this ordering and
the exact-J representation-conflict rules; no second merge API is needed.

The live context uses exact `(ModuleID, declaration name)` addresses and selected
184-byte journals. Shared parent representations coalesce only when their exact
binding rules permit it; conflicting valid representations require explicit
choices. Equal readable names in different modules do not become equal symbols.
Imported theorem proofs need not enter the authoring frontend. Interface-only
mode can defer unused ordinary definition bodies, but it cannot omit needed
type/recursor semantics or promise definitional reduction without its bodies.

## New output is independently checked, not laundered by publication

`client.author` returns untrusted preparation. The existing trusted-owner helper
`software/v5/examples/contribution.py::contribute_from_context` then:

1. Binds the actual authored bytes, local module, source digest and roots.
2. Stores the packet through public lower-level `workspace.packets.put`, bounded
   by custody quota, the original grant callback and enclosing Job. This store
   call is not a separately charged client action and is not admission.
3. Calls `client.admit_local`, and checks the live output fact against the exact
   packet/module/summary.
4. Calls `client.publish` with selected export names and quota-bounded local
   retention. The resulting index uses `workspace.adapter`, so the new profile
   extracts the new fingerprint without a special contribution branch.

The helper is optional agent-side composition, not an issuer. Its report is not
transferable authority. Publishing alone is intentionally structural: an
untrusted provider can advertise false candidates, but a recipient must still
verify the acquired evidence under its own actual owner. A false source result
does not become mathematics because it was indexed or served.

The read-only service entry dynamically opens the selected Workspace type and
uses its adapter/index; it has no separate hard-coded fingerprint schema gate.
Serving requires the matching source/profile deployment and explicit endpoint,
egress, lifetime and budget. A publication does not automatically start a daemon,
choose external hosts, pay replication costs or ensure indefinite availability.
After local authorship closes, a fresh finite service owner can serve retained
bytes; recipients cannot import the former producer's expired live warrant.
