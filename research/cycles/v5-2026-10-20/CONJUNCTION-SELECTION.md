with the independent design challenge. Existing rare-anchor planning already

## Contract

An optional locally adopted profile contains 1..8 explicit pairs of existing
atomic formal-feature specifications. Each pair has distinct canonical atoms;
pairs are unique and canonical. No nested conjunctions, remote executable
extractor, automatic template selection, or enumeration of subsets. The
profile and feature-schema version are committed into the discovery namespace.
Old default namespaces and records remain byte-identical.

For each structurally authenticated export, append a pair feature exactly when
both constituent atomic features occur. Retain all atomic features. Existing
128-feature, 16 KiB record, storage and work limits remain; overflow refuses,
never truncates. Mathematical ModuleID, ExportID, imports and acceptance do not
change. A new profile creates a fresh separate index, not in-place reindexing.

The adapter's query compiler accepts only the existing 1..8 atomic specs.
If configured pairs match, select the first canonical eligible pair and replace
its two atoms by its compound key; retain every other atom. Otherwise use all
atomic keys in that same profile namespace. This preserves the predicate for
correctly extracted records, does not increase term count, and handles overlap
without ambiguity. It is not a globally cost-optimal pair choice. Providers'
commitments prove metadata membership, not extraction correctness, global
coverage or applicability; ordinary candidate resolution recomputes extraction.

For selected snapshots/partitions, the new driver is bounded by the minimum of
the pair intersection length and the remaining atomic posting lengths, hence
no greater than the previous minimum atomic length on the same corpus. It can
be constant while those atomic lists grow. This is a conditional structural
bound, not an overall speedup. Additional build, update, storage, replication
and retention costs must be recovered over actual repeated queries. Both the
commons and an equally optimized ordinary shared-library comparator receive
the same index improvement; do not attribute a certification advantage to it.
