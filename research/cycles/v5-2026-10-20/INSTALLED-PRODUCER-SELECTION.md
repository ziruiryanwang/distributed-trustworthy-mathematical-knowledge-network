`DMKN_RELEASE_PRODUCER_LAUNCH_V1` fields are exactly:

```text
schema,name,action,release,profile,input,entry,run_directory,
runtime_pins,limits,output_limits,prior_launches,input_launch
```

Actions are snapshot/request/preflight/run. The release is `{root,manifest,descriptor}`;

`RUN/selection.json` pin and exact `RUN/entry.py`; core sources remain installed.

`RUN/OWNER-RESULT.json`; action output is a disjoint fresh sibling location.

`input_launch` is a mandatory completed action=request outer pin for run/preflight,

## Shared helper API

The contract helper uses stdlib imports only and can be loaded from exact held
manifest-pinned bytes by the parent before any product-package import.

- `materialize_profile(root, manifest_pin, descriptor_pin, template)` returns
  profile data, never writes it or constructs an owner.
- `read_selection(path, expected)` returns `(selection, pin)`.
- `validate_selection(selection, selection_pin, fresh_run=...)` returns selected
  root/run/profile/input/action_output/runtime_pins/pins/entry/release/
  request_output/owner_report plus any explicitly agreed provenance data.
- `command(selection, selection_pin)` derives the sole allowed worker argv.
- `rebind_selection(selected)` rechecks the selected inputs/runtime bindings.
- Producer-specific selection and outer adoption hooks validate real public
  evidence without translating it into fabricated LOCAL_CHECK records.

Root's launcher accepts PLAN_PATH PLAN_SHA, using STARTED_NS/STARTED_CPU from
the original public distribution invocation when called there. Standalone
invocation has its own original clocks and validates the same selected roles.
