Standalone mixed `_check(deadline)` gets its own complete phase; every added
active callback must enforce that supplied deadline, not merely the owner's
broader deadline. Preserve all original checks, their order and failure revocation.
No await, worker execution, network operation or user callback lies inside.

Avoid adding nested independent sweeps to import `_live`, which already wraps
this graph. A minimal internal capability may let a phase explicitly register
its exact original mixed owner as a permitted borrower (default none). The
mixed check borrows only while that exact enclosing state is active and its
original registered owner identity matches. Otherwise create an independent
phase; never silently borrow an arbitrary caller's context.

The permitted owner list is an immutable identity snapshot, not a mathematical
authority token or peer input. A borrower must retain its own original active,
deadline, profile and binding checks. Pins and persisted trust share the outer
first/final checks; outer finalization must complete before import returns any
usable result. Pin-checker/expected-value conflicts remain refusals. Closed or
copied-out contexts must not reuse a completed phase. Failure cleanup restores
the outer independent state and discards records; finalization failures revoke
the mixed owner/import before any successful public result escapes.

The default existing phase API must retain independent nested semantics. No
operation-lifetime snapshot, borrowed authority across external execution, or
receipt/native result cache is authorized. Trust assumptions stay explicit:
stable owner-controlled serialized local code/filesystem, not hostile same-
process mutation or concurrent filesystem rollback protection.
