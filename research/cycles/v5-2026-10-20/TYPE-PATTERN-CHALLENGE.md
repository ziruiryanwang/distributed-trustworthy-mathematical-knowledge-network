# Independent challenge: whole-type variant discovery

2026-10-20, core_release. Source/theory only; no implementation or runtime.
Read THEORY `3d1054d4`, SOURCE `9655610e`, the selected conjunction adapter,
formal-feature format and existing authenticated query planner.
**GO for one optional bounded variant-key feature; NO-GO for calling it general
mathematical search, theorem transfer, useful growth or global selectivity.**

## Why this is more than cosmetic deduplication

Existing type keys contain exact module addresses. Existing address-independent
edge/head features forget whole-tree position and multiplicity; combining those
same features cannot recover lost information. A separately constructed local
signature can reproduce the proposed key without knowing the candidate's ID.
That permits candidate location, not merely grouping already acquired objects.

Useful discriminator: query `forall x:T, f(f x)=x` using independently chosen
local T/f placeholders. Index content-addressed structural openings for that law
and `forall x:T, f(f x)=f x` under unrelated module addresses. Their generic old
edge/head predicates coincide; the new whole-type keys differ. Involution versus
idempotence is a meaningful reusable-method distinction. Returned mathematics
still concerns the candidate's own T/f, not the query's local symbols.
An additional strict-position control swaps bound variables in an associativity
law while retaining the same AST tag tree, symbols and old edge/head sets.
Use actual content IDs and explicitly unproved fixtures for feature controls;
fixture openings authenticate structure only, not these mathematical statements.

## Exact assurance boundary

The first-occurrence normalization theorem is sound for valid bounded ASTs:
equal normalized trees characterize bijective renaming of occurring nonfoundation
symbols, fixing every retained field. This is standard syntactic variant indexing.
Hash equality adds collision resistance; it is not an injective mathematical code.
Preserve foundation names, declaration universe arity (including unused parameters),
all level syntax, binders, de Bruijn positions, projection indices and occurrences.
Resolve local/external references to their FULL `(owner, name)` identities before
assigning slots. A single map must cover const and proj; otherwise sharing is lost.
Do not preserve arbitrary module partitions: this is symbol renaming, not a mapping
between module implementations. Do not erase foundation/nonfoundation distinctions.

No key checks the unknown symbols' declarations, equations or computational roles.
A match is neither logical equivalence nor evidence of theorem applicability.
Retain existing exact-object resolution, mathematical admission and explicit
authoring imports. There is no permission to rewrite a received proof by the
slot correspondence or identify independently defined natural-number types.

## Why not a discrimination/substitution-tree service now?

Those standard indexes support richer matching, including variable substitutions
and generalized/instantiated terms; they are preferable when that recall is the
actual selected requirement. A whole-tree key cannot find a generic theorem whose
specialization matches the query, a subterm match, reordered binders, a definitionally
equal formulation, or a different universe presentation. It is deliberately strict.
For EXACT nominal variants, one key reuses the already implemented authenticated
postings, planner, budgets and candidate resolution. A new matching/tree service
has no demonstrated marginal payoff for this particular missing relation. Do not
entrench this cheap key as the only eventual search path or claim a novel theory.

## Cost and scale objections that must remain visible

Normalization is bounded local work in encoded bytes and expanded occurrences,
including levels and names; it reads no proof or ancestral definition body.
Do not serialize arbitrary caller ASTs before bounding repeated DAG expansion.
The proposed iterative preflight before codec validation addresses that seam;
cycles and huge shared trees must terminate by refusal, not by visited-node dedup.
No guarantee follows for unbounded conversion costs, since no conversion is done.

The query bucket can contain the entire corpus; familiar law schemas may be hot.
Existing partitioned/budgeted query outcomes remain necessary. A gain from H broad
candidates to m exact variants is conditional on m<H, not a logarithmic-search or
global-completeness theorem. Increasing corpus size can still increase m without bound.

One extra feature/posting applies relative to a rebuilt pattern-profile index.
Because namespaces change, migration requires re-extraction/reindexing; serving
legacy and new profiles together can duplicate ALL inherited postings. Charge this
maintenance cost. No mathematical recertification is needed merely to add metadata.
Keep the 128-feature cap; overflow refuses explicitly rather than dropping features.

## Smallest selected boundary and acceptance conditions

One public `pattern_spec(codec, owner, universes, type_expr)` helper plus the five
SOURCE-listed adapter/schema/workspace successors is sufficient in principle.
Query construction must not read the target descriptor, module ID or exported name.
Default and existing pair-profile namespaces/record bytes remain unchanged. Use a
fresh immutable pattern profile; old query modes/pair atoms reject the new tag.
Validate profile before workspace mutation; no silent migration or global switch.
Only one changed-boundary contract run is justified after independent source review:
renaming/alias/sharing/const-proj invariants, preserved syntax distinctions,
malformed/cycle/shared-DAG caps, legacy byte identity, profile denials and actual
store/query/resolve for the bounded independent-template discriminator. No native
checker, receipt, full unchanged SDK campaign or benchmark is required for this gate.
