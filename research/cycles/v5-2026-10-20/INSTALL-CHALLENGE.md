## Decision

**Direct-contact discovery/acquisition now has higher marginal payoff than
packaging.** An immutable relocatable installation is necessary for final v5,
but packaging the present facade would preserve a central user-workflow gap:
`serve_workspace` returns an HTTP endpoint, whereas the ordinary client's
`find`/`resolve` path requires an exact located handoff assembled through
`ServiceLocationProcess`. An operator cannot directly use the returned service
endpoint through that facade without another low-level/DHT recipe.

Implement the smallest owner-configured endpoint binding to the existing
search/acquisition components and original acquisition budget. Preserve exact
mathematical owners and do not treat an endpoint/index result as authority.
No new discovery algorithm, trusted cache, network identity or proof is needed.
Root has selected a separate direct-contact source investigation.

## Why not package first

`client/launch.py` already supplies exact source snapshots, imported-origin
enforcement, fixed supervisor-manifest binding and bounded original-deadline
execution. `RuntimeProfile` now rebases selected source/runtime roles, but
external Lean/host/image roles still require explicit adopted pins. A minimal
release needs an immutable nested supervisor, relative SDK/asset map and public
plan construction; it does not need a second supervisor or full reinstall
framework. core_release's approximately 235.7 MB base estimate is a copy cost,
not a mathematical or growth gain.

The actual ordinary reader integration costs 5.140625 known CPU seconds; all
serving attempts together cost 4.9375 known CPU seconds, including failures.
These support another focused cheap integration, not a predicted speedup.
The prior actual retained-method reuse cost 38.859375 known CPU seconds and
already establishes substantive extension/cold readmission; do not repeat it
merely to obtain one all-green package report.
