## Compare complete local histories, not counts of theorem instances

Fix a finite horizon, explicit initial libraries/caches, formal endpoints and
deadlines for each participating local library. Include the producer's result,
substantive downstream results, and at least one later use of a contributed
successor. These are an evaluation scenario, not a mandatory network task list.
The endpoints are exact formal statements and valid proofs under the same
foundation/policy, independent of human intention; producer-specific names or
one chosen proof encoding must not unnecessarily constrain the baseline.

Two routes start from the same mathematical data and computational tools:

- **O, isolated optimized libraries:** each library can simplify, choose direct
  proofs, generalize, share proof DAGs, and retain all its own discoveries and
  compiled/canonical caches. It may solve a generic core once for all its later
  local uses, or avoid that core entirely if another derivation is cheaper.
- **S, sharing libraries:** the same options plus discovery and use of genuinely
  new remote contributions through the current public interfaces. New remote
  proofs are not given to O for free. Conversely, an already known initial lemma
  is not artificially withheld from O or credited as a new discovery by S.

The comparison unit is a **complete cache-aware history at one library**, not one
substitution. N repeated uses in one warm library do not become N avoided searches.
If isolated libraries independently elect to discover the same absent core, its
first-discovery cost occurs once per such library. That multiplicity is a fact
to establish for the selected strategy, not an instruction to make O rediscover.

For a specified priced cost, write O_i for the cheapest complete successful route
among an explicitly enumerated, supported local portfolio. Include direct proofs
and existing optimized solvers when they can reach the required accepted endpoint.
The locally supplied CaDiCaL is a relevant alternative, not a license to interpret
every RAT step as a constructive implication. Do not port a solver/checker merely
to manufacture this comparison. If a claim concerns only one fixed executable
portfolio policy, name it instead of calling it the optimum over the portfolio.

**One long solver trace is not a lower bound on that minimum.** To prove
O_i >= L_i for the finite portfolio, every allowed cheaper route must be excluded
or bounded, including cross-target generalization and caching. No lower bound
against every imaginable mathematician or algorithm is required. An undisclosed
weak DPLL implementation is not an acceptable substitute for this obligation.

## Full-cost identity, with no free producer or free server

Choose a resource vector, such as CPU work, transferred bytes, written bytes and
retained byte-time. Either compare it componentwise, or fix nonnegative prices
before evaluating the case. Peak memory and deadline feasibility are constraints,
not additive work units. Theorem counts, source calls and elapsed CPU/byte mixtures
are not an implicit common currency.

Let S_i include the whole sharing-route local history and its attributed
per-request provider work. Let H contain only remaining shared costs, such as
unattributed standing custody, indexing, repair, service startup and retirement
over the supported horizon. Count each actual resource event exactly once.
Then the exact priced advantage is

    Delta = sum_i O_i - (sum_i S_i + H).

The producer is one of the i. Its original search, reconstruction, checking and
publication are not a historical free gift. If the producer obtains exactly the
same result by exactly the same method in both routes, that common part cancels;
extra abstraction/export/certification/publication does not. Reuse native proofs
first. Optional succinct certification has a separate premium comparison against
the same native-sharing route, not against an artificially flattened baseline.

Similarly, recipient checking cancels **only when the actual proof/check route
and charged inputs agree**. An optimized direct proof can have a smaller check
than importing the producer's proof DAG. Imported interfaces, parent checks,
semantic decoding, local context preparation and subsequent contribution checks
must not vanish behind a one-line theorem application.

For a concrete prospective bound, let d_i be a justified lower bound on O_i-S_i
for each successful receiving library. Let F bound the producer's incremental
overhead and let Q bound additional cost of unsuccessful receiving histories
relative to the same local fallback. H is as above. A sufficient positive region is

    sum_successful_receivers d_i > F + Q + H.

This is usable only after those quantities are supplied for an exact case.
They are not inferred from request caps. If fallback runs are not equivalent
because of shared memory, I/O or scheduling interference, bound the altered
fallback explicitly rather than assuming its cost unchanged.

In the homogeneous case d_i >= d > 0, a supported service horizon permits a
positive integer-volume witness only if

    floor((F + Q + H)/d) + 1 <= k_max,

where k_max is a justified feasible number of independent cold receiving histories
within that horizon, not unlimited future use. Apply the existing per-queue
traffic/service conditions in `GROWTH-OPERATING-REGION.md` to establish feasibility.
No new queue model or calculator is needed. A finite retention promise, actual
query success and capacity cannot be replaced by multiplying a hypothetical N.

## Can source reasoning eliminate an experiment?

**Yes for a fully specified algorithmic conditional result; not from theorem or
high-level API-call counts alone.** The exact reusable observation is:

If k isolated copies start from identical cold states and execute the same
deterministic proof-search policy on the same core input, and a source proof
establishes a trace of s elementary steps, the k copies incur k*s such steps.
One producer plus recipients using its proof incurs that discovery trace once.
No k-machine replay is needed to justify the discovery multiplicity. Different
substitutions do not establish this premise automatically: their optimal local
proofs and cache histories may differ.

To lift that fact into a full benefit result **without any new execution**, one
must additionally supply supported exact proof/type/serialization size bounds,
successful reconstruction/admission reasoning for that representation, a query
whose bounded search actually finds the case, upper bounds on every differing
sharing/maintenance step, and a same-model lower bound for the selected local
portfolio. State the machine/resource model. An abstract operation bound does
not become a physical CPU-time guarantee without a justified implementation
cost correspondence. Existing evidence may discharge unchanged components;
there is no requirement to rerun them or simulate the entire global network.

The current source counters do not supply this missing bound:

- Both routes can call `author` once per accepted downstream declaration; productive
  local search happens before that call. Saving source calls is not established.
- One `admit` can traverse a large proof while another admits a small direct proof.
  Equal calls or fewer named lemmas do not imply less checked work.
- Resolution proof length lower bounds also lower-bound proof transmission/replay;
  they do not by themselves separate search cost from verification cost.
- A worst-case search lower bound for some family member is not a bound for a
  chosen easy member, another solver, or a cache-generalized downstream task.

If only a constant or exact exported interoperability point remains uncertain
after the source screen, select at most one small matched case covering that
uncertainty. A retained deterministic search trace can stand in for repeated
copies; prior service/store evidence can stand in for unchanged mechanisms.
Do not run a case merely to discover whether any plausible inequality exists.

## Minimal evidence and falsification/stop rules

A future source GO needs one fixed supported mathematical core and genuinely
different downstream endpoints; their bounded proof/type representation;
independently derived formal query and specified searchable cut; equal initial
libraries and explicit cache-aware portfolio; and concrete count/bound evidence
that produces a nonempty capacity-feasible benefit interval. Later exact
admission/use evidence is needed only for implementation premises not already
covered by adopted guarantees. All failed preparation/search/production costs
remain part of the history.

Stop or retract the corresponding claim if any of the following occurs:

- A supported direct proof, solver, initial lemma or generalized local cache
  removes the claimed cold-search margin. Never disable that alternative.
- The trace needs unsupported RAT-to-implication reasoning, classical assumptions
  not in policy, expanded types beyond codec bounds, or a new checker/solver port
  whose cost was omitted. Named steps do not automatically compress type trees.
- The query uses the answer's identifier/unknown vocabulary, cannot find it within
  its allowed selected cut, or relies on unbounded postings/corpus scanning.
- Only structural records, renamings, repeated warm substitutions or unconsumed
  successor packets are obtained; the stipulated warranted downstream endpoint
  or genuine subsequent use is absent.
- Failed queries, native checks, transferred semantics, standing service or
  repair erase the margin; a cap exhaustion is not successful benefit evidence.
- Required demand exceeds queue capacity, policy withdrawal/expiry shortens the
  horizon before payback, or the only copies disappear. Do not extend T or grants
  after observing failure to preserve a profitable calculation.

At present the first necessary witness—a concrete supported case with positive
margin against its local alternatives—is absent. The useful decision is to retain
the rejection and avoid a solver/certificate experiment, not to rename a symbolic
inequality as demonstrated growth. Core_release is recording the matching
construction decision separately. Full v5 and its useful-growth obligation remain
open; no further RAM investigation or generic accounting mechanism follows here.
