## Bounded changed-boundary cases

Search proposes one new `located_queries/client/located_queries.py` helper:
`reserve_located_queries(client, channel, envelope, policy)` and async
`next_located_query(client, specs, location_limits, search_limits, *, routes,
descriptor_bytes=4096, descriptor_age_ms=60000)`. The envelope has exactly
`search` (SearchSession fields plus generations) and `location` (WorkflowBudget
fields). One outer prepayment charges location route operations + descriptor
requests + search requests, and location reply bytes already include search bytes.
Retain the original validated facade through the check/report/terminal protocol.
This is a proposal, not code/adoption. Reuse the already adopted direct-generation
arithmetic and stale-handle controls; do not rerun all seven direct dimensions.

1. **Two distinct located queries, one original operation.** One channel starts
   once; real workflow/ticket parsing yields query-appropriate contacts twice.
   Run one real structural offer/page/resolve per generation through in-memory
   provider dispatch. Assert distinct compiled keys, immutable first custody,
   original grant/budget/owners/deadline, one aggregate prepayment, full allocated
   vectors and proper old-scope retirement. Reusing the same peer with a different
   selected query is useful: prior descriptor nonce/key must not be reused.
2. **No contact does not mean absence or renew resources.** In separate short
   subcases, use (a) valid empty route peers and (b) one located peer returning the
   exact typed `DESCRIPTOR_UNAVAILABLE`. No search is issued; pending ticket clears;
   reserved route/descriptor costs remain charged; global completeness stays false.
   A second query retires even the old no-search workflow and may proceed only
   within the original envelope, not a new grant.
3. **Cross-generation stale reply refuses.** Return a first-generation route key
   or descriptor nonce in a later query's response. The real parser rejects it,
   settles the current ticket without refund and fails/closes according to the
   selected contract. Use only these changed binding discriminators, not a full
   protocol-fuzz matrix already covered by predecessor controls.
4. **Cancellation settles and cannot revive.** Use an Event to block the inert
   command after real route issuance, then cancel and await the actual public
   action. Repeat only at descriptor issuance (different settlement rule). Assert
   pending zero, complete route allowance/descriptor maximum charged, busy cleared,
   original channel/owner cleanup and permanent failure. No sleeps or polling.
5. **New aggregate location limits are finite.** One tiny valid query consumes
   the prospectively selected location vector; an otherwise valid next query
   exceeds one selected new location dimension and is refused before command I/O.
   Assert fixed service lifetime/command allowance and no restored capability.
   Exact fields and whether this merges into case 1 depend on the accepted design.

Both channel-command logs and actual workflow reports should be retained so the
outcome distinguishes "mock supplied a reply" from "real ticket parser accepted it."
The final report must label owners/channel transport inert and mathematical
acceptance false. Do not count an empty route as proof of missing mathematics.

## Cost and stopping rule

A single explicit suite of at most these five groups is the prospective target;
root fixes its exact sources and limits after source review. No actual location
process, TLS, Lean, receipt, proof producer, package rebuild or full runtime hash
campaign is needed to decide this lifecycle implementation. If source inspection
finds the API cannot preserve a shared deadline/budget or settle cancellation,
resolve that in design first. These controls cannot substitute for prior real
transport evidence or a final independently operated deployment qualification.
