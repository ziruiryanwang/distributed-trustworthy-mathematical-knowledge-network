# Full formal discovery: bounded preparation and integration contract

Date: 2026-09-20. Proposed local experimental contract; source/extractor preparation in progress, **no run and no Gate B qualification**. This follows the completed [R1 checkpoint](2026-09-20-proof-context-reconciliation-qualified.md). The user's authorization permits useful bounded local prototypes; this work adds no network service or deployment.

## Central decision and unchanged target

Implement the smallest local path that can test the original [full existential Gate B](2026-09-20-subtype-composition-contract.md#gate-b-preregistration-target-corpus-and-access-arms): a fresh independent controller, without useful contribution IDs, discovers formal definitions/theorems and may use them to construct, check, export and replay a successor. Local-only and oracle-assisted known-ID arms remain diagnostic comparisons. Do not replace the existential witness problem by theorem-name lookup or projection injectivity alone.

Mathematical completion does not require imported evidence. Direct construction and ordinary standard support remain available. Subtype is a conformance workload, not an asserted efficiency discriminator. Report completion, genuinely acquired-reference use, discovery-origin use, new-to-consumer evidence and cost separately. No compulsory network task list, human-intention acceptance test or mandatory prover is introduced.

The [native-controller proposal](2026-09-20-discovery-controller-native-proposal.md) and [metadata proposal](2026-09-20-discovery-metadata-proposal.md) provide source-grounded component plans. Root selects their common architecture with the precise integration dispositions below. Later substantive implementation changes require a new reviewed cut; proposals and earlier experiment records stay preserved.

## Preparation first, measured arms later

There are two distinct cuts:

1. **Finite preparation:** compile/capture the seven fixed control contributions; independently replay them; establish actual common identities and corpus type shapes; implement/test a supported exact-on-success feature extractor. This can resolve concrete support ambiguities without a consumer receiving the answer.
2. **Controller conformance and arm freeze:** bind real query capture, safe search suspension, admission and fresh environment restarts, complete export, exposed inputs and aggregate accounting. Only after these pass may the three frozen arms run. A controller pilot is not a measured utility result or a reason for endless tuning.

This contract authorizes root's reviewed finite preparation stages, not unbounded experiments. Use at most two numbered preparation attempts, stages A0–A2 at most once per attempt, with at most one reviewed implementation retry. Root alone launches. Each stage has 300 seconds wall and aggregate child CPU, 4 GiB private commit, one active child, and the inherited 256-MiB whole-attempt staging cap. Canonical closures remain at most 64 MiB and native extension limits remain 256 rows/1024 exports. No resource budget silently refills after failure. Source capture may run before extractor unit tests because it does not invoke the new extractor. Frozen code/plan/copied-input hashes and independent launch review are required.

The subsequent controller pilot/three-arm execution needs a separate exact finite launch cut. Its original 300-second/4-GiB per-arm envelope and eight acquisition attempts are retained, together with the explicit discovery-clock revision below. No measured arm has begun under this document.

## Exact-on-success metadata fragment

Use the existing FoundationID, exact seed Eq/Iff role references, ExtractorDescriptor `0x8123/1`, StructuralDescriptor `0x8124/1`, and mode-6 predicate semantics. Compute actual IDs from canonical bytes; no release digest is invented. The first local query path is token-only, `patternOption=[0]`; optional provider pattern filtering is not implemented silently or advertised as present. Descriptor extraction must still supply exact patterns/summaries.

The initial implementation supports a justified finite redex-free native-type fragment. On unsupported syntax, required beta/zeta contraction, any unimplemented bound/cut behavior or inability to establish its safety margin, it returns `NOT_EXTRACTED` and publishes nothing. It never calls an implementation limitation `NORMALIZATION_INCOMPLETE` or fabricates a deterministic truncated prefix. Corpus targets are not rewritten/dropped just to make extraction pass.

For supported inputs, normalize by the prescribed complete redex search: zero contractions does not mean zero work. Emit and inspect completed normalized companions even when identical to raw views. Respect binder scope, exact Eq/Iff recognition, native projection/constant differences, fixed focus order, occurrence-tree pattern limits, feature generation order and the distinct 16/8/4/4 lanes. No delta/iota/projection reduction, arithmetic evaluation or source binder/class hints enter this extractor.

### Concrete accounting ambiguity and bounded disposition

Implementation review exposed a wording tension in the selected STRUCT2 phase-2 description. One reading charges extra operation-head reads only at applications and argument-head reads only for informative parents; another literal phase reading charges a head scan at every occurrence and argument scans even for noninformative application heads. Their READ counts can differ. This contract does not silently declare either general reading authoritative under the existing ExtractorID.

For the restricted no-cut fragment, compute a sound occurrence-level upper bound `U` covering both explicit readings. Require `U ≤ 8192` and successful margins for depth, normalization, pattern occurrence size/depth, feature enumeration/bytes, payloads and descriptor size. Establish that both readings inspect the complete same relevant syntax and yield identical descriptor bytes in this fragment. Record `U` **as an upper bound, not an exact normative READ count**. Reject extraction when this invariance/safety-margin condition is not established. Distinct DAG-node counts are insufficient because shared subterms can be visited repeatedly.

Tag-3 operation features with role 5 (binder-domain focus) have no selected public token lane. They may be retained as local generated material and incur applicable enumeration/byte charges, but cannot occupy the conclusion/relation lane or affect its broad-fallback criterion. Last-domain raw/normalized pattern summaries and assigned public tags 4/5 remain. This follows the explicit lane definitions; no new token meaning is selected.

This approach qualifies descriptor bytes only on the certified fragment. The general read-count/truncation interpretation remains an issue for a full extractor release. Do not claim general capability-7/FULL_FEATURE implementation, and do not label an incomplete fixed ten-target scope complete. The first preparation result may legitimately be that some actual required type remains unsupported.

## Controller integration dispositions

### Candidate authority and checked environments

Select inert descriptor candidates by the declared finite lane/provider/descriptor-CID order. Debit an acquisition attempt, obtain the exact complete package and independently reconstruct/check its dependencies **before** native type inspection/application. The 32 type-inspection ceiling is not a promise that 32 free checked candidate types are available. An optional earlier syntax-only inspection remains untrusted and cannot install Lean declarations or call native unification on nonexistent constants. Use no trusted-header substitute.

A compatible admission creates a new immutable local environment; discard the previous tentative metavariable state and restart the original target. Incompatible contexts are refused in this first Gate B cut; no unbounded repair or silent alias overwrite is added. Same-ID already-held evidence is reacquisition, not a fresh discovery or new mathematical object.

Use existing generic `SolveByElim`, actual definition/theorem application, introductions/constructors and the proposed bounded generic projection-congruence operation. Direct local construction and common/standard support remain enabled. The outer exposure accumulator, budget counters and stop/barrier flags must survive all Lean backtracking; an exception swallowed by search is not an acquisition handshake. Reserve a restart before suspending. Commit only a completely instantiated closed proof, then capture/export and freshly replay it.

### Actual open goal, not an invented closed query

The bridge receives the actual selected metavariable's local context and type, after instantiating assigned metavariables. Preserve a scoped telescope separately from the selected query focus. Abstract free variables capture-avoidantly; do not turn context assumptions into arbitrary leading goal Pis and then accidentally query a different terminal. Provider full-Pi source types and client scoped query views are distinct interfaces.

Every constant reference must correspond to already checked semantic state. Any remaining expression/universe metavariable, escaped binder, missing correspondence or unsupported encoding yields `QUERY_NOT_REPRESENTABLE`, not a fabricated ID, erased required argument or theorem-falsity verdict. A desired function goal can supply its actual domain/output focus to FUNCTION_OUTPUT; a proposition can supply its actual focus to APPLY_RESULT. Selecting those obligations is local search policy, not a public task assignment.

Before a consumer trial, capture at least the actual existential data-witness obligation and, if reached by the controller, a later map-dependent obligation. Check their telescope/focus correspondence, not merely a hand-authored expected token. A capability the controller never reaches is reported unexercised. Extraction inability skips the query, not the local proving opportunity.

## Explicit local-prototype discovery-clock revision

The two proposals preserve a continuous ten-second discovery deadline across imports. Root instead selects the following **explicit preregistered prototype-only revision** to expose interleaved discovery/import capability:

- At most ten seconds **summed elapsed time of serial active discovery episodes**, with the same aggregate two local CPU-seconds, eight lanes, 24-page ceiling, 8-MiB traffic and 64-MiB discovery memory.
- An episode begins before query capture/projection/lane planning or any provider request and ends only after that operation's response parsing, validation, candidate ordering and accounting complete. Do not pause in-flight work or exclude expensive extractor/matching/service work.
- Checking/admitting evidence and ordinary proof search between completed episodes are charged to their own operation and to the unchanged **absolute 300-second wall/CPU arm**; they neither reset discovery counters nor get a new resource account.
- Report both the active discovery sum and first-discovery-start to last-discovery-end elapsed span, including all import/proof gaps. A query/check failure remains charged. Admission, retry, lane, page, byte and restart limits never reset.

The original continuous-ten-second interactive envelope is preserved as historical and **is not claimed tested or satisfied by this revised arm**. The change is an experimental local scheduling budget, not a change to descriptor/predicate semantics, a network profile or a ten-second user-experience claim. A cold native import can otherwise consume the entire continuous discovery interval before an acquired-definition-dependent query is possible. Root and the independent reviewer selected this change before any arm execution; it cannot be retrofitted after observing a favorable result.

## Decisions still required before controller trials

Freeze concrete controller source and accounting hooks, local standard-catalogue exposure/on-demand admission, exact candidate selection and known-ID scheduling, query bridge schema, provider cursor/expiry implementation, complete input isolation, and the finite pilot/arm run plan. Preserve actual corpus identities, extracted descriptor bytes and feature traces. Keep provider/evaluator labels and prior-arm artifacts out of consumer inputs. A deterministic controller must have a closed, auditable input set; a prompt saying to ignore known answers is insufficient.

The immediate next execution is finite corpus capture/replay and extractor conformance, not a broad search benchmark. A missing practical interface is fixed only at its demonstrated boundary. No new blockchain, attribution, training loop, general solver or optional index-maintenance mechanism earns priority through this preparation.
