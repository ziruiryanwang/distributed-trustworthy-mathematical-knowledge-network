# Qualified source-derived composition and next central question

Date: 2026-09-20. Bounded executed checkpoint; full project objective unchanged and unfinished.

## Result

The [held shared-Subtype Gate A contract](2026-09-20-subtype-composition-contract.md) has passed its actual source-capture, separate-producer, known-ID consumer, inverse-export, fresh-replay and five-control requirements. Read [results and costs](../../experiments/lean-source-composition/RESULTS.md) and the [audit scopes/bindings](../../experiments/lean-source-composition/AUDIT.md).

The new evidence is not another hand-built proposition: ordinary source with a polymorphic proof-bearing nominal group crossed the canonical boundary. A generated proof helper required a genuine nonempty representative map. A fresh ordinary-source consumer used both contributions, producing an exact 51-object successor. Actual inverse export and fresh replay preserved those bytes. Native and canonical-data reviews reconciled the result separately. Ten stage invocations across four retained attempts include failures; no favorable attempts were substituted silently.

The earlier contract's NOT RUN and authorization text is historical. The subsequent explicit permission opened this local implementation. Neither that permission nor this success is represented as deployed-network qualification. The goal tool still exposes its earlier blocked status with no agent-controlled resume operation; this is a tool-state limitation, not completion or a current lack of local authorization.

## What changes in our understanding

Source-level mathematical exchange over a real shared proof-bearing interface is now demonstrated in one finite supported fragment. The previous uncertainty was operational, and the experiment discharged it at that scope. The selected protocol does not need a new version or a global consensus authority because this example worked.

The observed generated `map._proof_1` shows why semantic content and exact evidence contexts must remain separate. A theorem list indexed only by source spelling is insufficient. Likewise, proof frequency cannot authorize a mathematical assertion; local checking remains mandatory while usefulness estimates remain heuristic.

The concept is still not a demonstrated operable decentralized product. The most consequential remaining questions are heterogeneous composition, discovery/application by local agents without answer-bearing IDs, and useful accumulation under real costs and continuing supply. Correct refusals alone cannot establish those positive capabilities.

## Next bounded discriminator: independently different proof contexts

**Capability:** local agents must reuse contributions despite independently choosing different proofs of the same semantic dependency.

**Observed obstacle:** the actual B map contains a semantic helper-judgment reference and a separately selected helper proof instance. The implemented joint preparation intentionally rejects incompatible representative maps. Current Gate A used compatible choices; it did not show operational reconciliation.

**Existing route, not a new mechanism:** [PI1's finite branch join](../../notes/analyses/CP-001G-proof-instance-composition.md#joining-independent-finite-branches) selects grounded evidence, derives exact restricted maps, and creates new replay contexts that are rebuilt and rechecked. Original artifacts/certificates are not relabeled or overwritten. [REDUCE1](../../notes/analyses/CP-001H-proof-computation-and-reconstruction.md) warns that structural groundability and same-proposition proofs do not guarantee successful native conversion or acceptable cost in arbitrary library cases.

**Smallest sufficient next investigation:** one separately source-authored B variant with a different actual helper proof but the same captured helper judgment and map definition. First verify those equalities from real captures and independently replay both branches. Then show unchanged conflicting replay contexts cannot simply be pooled; construct a coherent newly bound replay using the existing procedure, preserve both direct proof instances where selected, rebuild from empty, and observe actual use/export/replay. No canonical payload surgery may manufacture the initial semantic equality.

**Stop condition:** one fixed source candidate and at most one reviewed repair/retry for implementation or case instantiation, within explicitly declared local ceilings. If source capture changes the semantic definition or coalesces both proofs, report noninstantiation. If native conversion fails after a grounded choice, report that boundary and use REDUCE1's existing decision rules. Do not expand this into a general theorem prover, universal reconciliation engine or unrelated index mechanism. After this discriminator, return to discovery/usefulness; the project must not spend indefinitely proving more variants of safe refusal.

This is the next research decision, not a claim the new variation has run. A separate bounded contract and reviewed implementation are required before its execution. No network changes, mandatory task list, human-intention acceptance rule, authorship policy or global ledger is introduced.

## Utility remains a separate obligation

Subtype is an easy conformance case: `Subtype.ext` and direct map construction remain available to local agents. Do not hide them or require downloads to manufacture a benefit. Gate B still needs a concrete bounded local policy and fair exposure; if this example cannot discriminate useful reuse, select a justified workload rather than claiming growth from object counts. Record acquisition, checking, adaptation, local proof work, publication and retained-state costs separately.
