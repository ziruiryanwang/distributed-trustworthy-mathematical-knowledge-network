its outer-envelope requirement. Do not select another index/filter, generator,
representation or proof mechanism.** The source-level discriminator is now
resolved: no existing Lean/Lake project is needed, but the supplied public CLIs

owner-approved Lean invocation suffices when the operator already supplies an

If root chooses to close that latter product requirement, the maximum justified
software change is one fixed Init-only type-extraction companion using the
existing supervisor and compiled helper. No general `--source` interpretation
mode, checker change, new search semantics or frozen-package mutation follows.

This recommendation is deliberately a boundary decision, not a claim that
query-source ergonomics is the dominant cost of all future mathematics. The
central unresolved capability is *finding a relevant reusable connection at an
acceptable total cost*. Existing local evidence establishes exact retrieval
and selected reuse, but not general relevance, recall or whole-workflow benefit.
The input handoff below is the concrete first-user obstruction demonstrated by
this source audit; it is a cheaper, testable prerequisite to investigating that
central capability than another speculative search backend.

After obtaining candidates, the existing preview/inspection, independent

## Theory in principle and simpler alternatives

The proposed connection performs only

`approved local type syntax -> existing elaborator/serializer -> existing context binding -> existing search specs`.

It does not require proving the requested statement. Context binding chooses
the portable interpretation, and the search result remains an untrusted
candidate. Any mismatch between an unrelated local project's meanings and the
selected context can spoil search; equal printed names do not establish project
correspondence. Later independent admission still establishes mathematical
warrants. No inference from source compilation to theorem truth is introduced.

The current exact-type key ignores binder/universe labels and DAG sharing, but
preserves ordered universes, symbol identities and expression structure. It does
not normalize definitionally equal formulations, reorder hypotheses or instantiate
arbitrary theorems. Making this input reachable therefore does not prove useful
recall or cheap exploration. Known-symbol, kind/head and configured sparse-pair
queries remain preferable when the investigator does not know a complete type.

The simpler existing route is a single owner-approved `.lean` file importing
`Init` and packaged `OwnerQueryCommand`, run under an explicitly selected
equivalent outer envelope, followed by the already public
`run.py query --native-type ... --context-root ...` route. This actual shape was
already executed successfully in the retained public query check. A Lake project,
new module generator or arbitrary peer source is not intrinsically required.
Ordinary approved-library/Loogle-style search also remains a strong alternative
when available; compatibility or a willing provider is not supplied by this
checkpoint. Do not fetch/install a comparator merely to create activity.

## The envelope discriminator is complete

The current public source path cannot be made into a whole-operation bounded
command merely by spelling existing flags differently:

- `run.py` has no native/query-source entry and rejects extra query source flags.
- Packaged `author_worker.py` executes the approved source but expects its caller
  to supply the enclosing Windows Job. It has no wall/CPU/memory/process/log
  allowance interface and supplies no terminal supervision report.
- Packaged `supervisor/commons.py` exposes provision/node/workflow/seal-request
  against its historical release layout. Its CLI is not a general standalone
  ordinary Lean runner. Its reusable `supervise` function is a Python API that
  needs an approved adapter to bind inputs, environment, limits and result.
- `supervisor/run_stage.py:314–325` requires its loaded sources at
  `domains.install/py/domains.py` and `domains.install/py/run_stage.py`. The current
  package's selected copies are under `installation/supervisor`, so calling that
  historical CLI directly is not a no-change public recipe. Do not copy/relocate
  support into a pretend old installation merely to satisfy those checks.

Thus a recipe may honestly require an operator-supplied equivalent envelope;
it must not silently call `author_worker.py` or Lean directly and label the
result protected by `run.py`. The missing software edge, if self-contained
enforcement is required, is exactly the **fixed native query-extraction launch**.
It is not expression elaboration, portable binding or theorem acceptance.

## Concise recipe text and minimal conditional implementation

Suggested public text:

> No existing Lake project is required for an Init-only formal question. In a
> fresh owner-controlled source directory, write an explicitly approved
> standalone Lean file with `module`, `public import Init`,
> `public meta import OwnerQueryCommand`, the required universe/variable
> declarations, and `#ordinary_type_query [...] "ABSOLUTE_FRESH_AST.json" : ...`.
> Use your own desired type, with no result name, proof, copied preview, additional
> imports or redefined vocabulary. Invoke the selected Lean executable with
> `-DElab.async=false`, that source directory as `-R`, and a fresh `-o` path.
> Use only the selected runtime library and the package's verified
> `authoring/helpers` on `LEAN_PATH`, with inherited Lean/Python overrides removed
> and the selected runtime executables on PATH. Execute under an independently
> supplied finite whole-process-tree envelope with explicit wall, aggregate CPU,
> private-memory, process and log caps. This extraction is not a `run.py` action;
> the package currently supplies no direct bounded source-query launch. Require
> exit zero, clean closure and the exact fresh AST before running existing
> `run.py query --native-type ... --context-root ...` with that owner's original
> paths, store ID and limits. Its `SPECS.json` then supplies the existing search
> input. Local source approval is necessary; resource limits are not a sandbox.
> These are query hints under the selected context, not theorem acceptance or a
> proof that an unrelated project's same-named constants mean the same thing.

The recipe is functionally complete for a caller with its own approved envelope;
that external prerequisite must remain visible. It is not an instruction to
create a custom harness implicitly, and no invocation has been performed here.

For self-contained enforcement, a fixed source-side extractor is the smallest
defensible implementation: bind selected package/runtime/helper bytes, accept
the explicitly approved Init-only query input, run exactly one extraction under
the existing `commons.supervise`/`Job` machinery, require clean closure and a
bounded valid AST, and retain failures/partial outputs. Keep its source outside
the hash-bound default package. Reuse the existing source-companion architecture
only after root selects this exact boundary; do not silently revise the pending
workflow archive. No arbitrary shell/executable dispatch, admissions, provider
startup, retries or approval inference. Keep the context query command unchanged.

Do not misuse `owner contribute` as a source-query runner: it requires nonempty
output names and can insert admitted artifacts. A query must not need a dummy
theorem, new axiom, sacrificial definition or acceptance fixture.

Only a genuinely new runner would justify a changed-boundary check: one
proof-free extraction with an independently chosen type under the real wrapper,
plus its focused source/input/closure refusals. No theorem proof, search corpus,
native helper rebuild, owner initialization, new concept episode, network service
or reciprocal exchange belongs in that check. Its claim is input delivery and
accounting, not discovery or growth. Root must select any such implementation
and finite run separately; this checkpoint selects neither.

Reuse the existing 42 query/preview controls, successful generic command
compilation plus preserved failed harness/postcheck, eleven context-binding

`ORDINARY-QUERY-PUBLIC-OUTCOME.md`'s standalone-query-to-index-to-use evidence.
