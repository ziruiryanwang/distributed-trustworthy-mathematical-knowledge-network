# Selected next implementation: portable inert export from local custody

2026-10-26. Full v5 remains active, local and unpublished. Root selects a
source implementation, then independent review and one narrowly scoped test
allocation if justified. No new native build, proof, network service, mathematical

## Concrete investigator obstruction

After receiving and extending mathematics without a producer project, an operator
cannot currently export selected original exact targets and their complete inert
dependency closure through a public command. `produce-baseline` needs an approved
compiled project; `export-module` does native realization work and emits compiled
modules; ordinary `serve` exposes the whole custody. New contribution output
contains its new units, not necessarily all acquired prerequisites. Direct private
database extraction is not a satisfactory public workflow.

This is more consequential than another search filter: it enables offline
replication, independent re-admission into a deliberately small context, and a
separate disclosure-approved serving owner without source execution or rebuilding
mathematics. It does not make re-admission, storage, context validation or required
proof dependencies free. The destination still checks its imported mathematics.

## Minimal mechanism and assurance boundary

**Revised before implementation:** choose a separately approved bounded inert
export companion, not a new `owner` operation. Prior local acceptance is not
needed to copy evidence that the receiver must check independently. Avoid opening
the mathematical catalog or restoring its whole selected history. Existing
`OrdinaryStore(create=False)` is read/write and is not an adequate read-only open.
Use an ordinary-path-checked SQLite `mode=ro`, `query_only=ON`,
`trusted_schema=OFF` connection and one bounded read transaction; no `immutable=1`
on live data, journal recovery, WAL access, schema migration or write pragma.
Refuse live journal/sidecar states in this first read-only profile. The protected
filesystem and supported SQLite format remain premises. Snapshot reads can
temporarily block supported DELETE-mode writers; finite termination matters.

Collect complete atomic evidence units by their exact locators, follow **all
declared imports**, and stop only at the exact fixed basis. Check target, export,
unit, semantic and full-closure identity bindings; reject missing bytes,
conflicting names, cycles and bounds. This is not the smaller theorem
signature frontier used for authoring. Preserve original evidence bytes.

Use existing `baseline_bundle.split_units` / `make_manifest` and the existing
baseline manifest schema. Do not fabricate a native writer document, extraction
statistics, proof certificate or acceptance event. An additional result sidecar
may record exact targets, custody selection, manifest hash and bounded cost; mark
it explicitly as inert export with source acceptance **unasserted**, not
mathematical acceptance or receiver authority. Structurally valid false claims
may be exported; closure consistency never proves their mathematics.
Use a fresh output directory, exclusive creation, exact readback and terminal
success only after completion; failures preserve partial output. No network,
source compilation, local admission, automatic publication or grant renewal.

Keep one finite collector envelope no larger than existing ordinary preflight
(1024 units / 64 MiB and its node/name/edge ceilings), with existing per-unit and
target bounds. Explicitly count all selected work, including group siblings and
proof-only imports. Do not enlarge native/module/custody limits. Output path must
be separate from source state/package/runtime and all selected inputs.
