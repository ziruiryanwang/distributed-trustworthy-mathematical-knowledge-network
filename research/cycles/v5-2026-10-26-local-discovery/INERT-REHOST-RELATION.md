# Inert rehosting: separate availability work from mathematical authority

2026-10-26. Source/theory only; no product/state/native/network/test/Git mutation.
Companion implementation coverage is in INERT-REHOST-PATH.md. The default is still
ordinary_release_bundle/ADOPTION.md; all activity remains local and unpublished.

## Decision

Support the role, but do not invent a new trust protocol. A storage-only volunteer
can preserve a disclosure-approved finite bundle, derive formal search hints and
serve exact evidence without being a mathematical consumer. Only an actual user
needs to establish local warrants. Lower-level APIs already permit this role;
the candidate advance is a bounded supported operator workflow, not unique power.
Keep a static exact bundle when backup/known-bundle transfer is the whole need.

The currently missing public edge is bundle -> inert custody/index -> finite
existing-provider service, without initializing/admitting a mathematical owner.
Use unchanged OrdinaryStore and discovery Store APIs if this edge is selected.
A direct immutable bundle reader is not presently a drop-in alternative:
ordinary_acquisition.serve requires `type(store) is OrdinaryStore`. Do not change
that transport boundary merely to avoid a small preparation adapter.

## Four different predicates

For exact bundle B, selected index snapshot J and consumer context C, distinguish:

- `Bound(B)`: supported encoding, bounded census and exact content identities.
- `Closed_F(B,T)`: every dependency needed by selected targets T is present with
  its exact identity, or is in the locally pinned foundation F; group siblings
  remain indivisible. This is a syntactic closure property, not consistency.
- `Indexed(J,B,T)`: advertised records derive from B's exact selected type
  previews through the selected feature adapter; coverage is only those records.
- `Accepted_P(C,t)`: the consumer's existing checker/policy grants t in C.

None of the first three implies the fourth. A manifest alone implies neither
closure nor even possession: validate_batch checks bytes/structure, not imports.
The selected exporter establishes closure relative to its pinned basis; a new
recipient must validate what it actually received rather than trust its report.

Safety argument: assume the existing consumer checker/policy and protected local
state are sound, exact-byte bindings hold, and no mirror status can mint a grant.
For the same selected evidence, context and policy, replacing the supplier with
an inert mirror does not change the mathematical acceptance predicate. The
consumer still resolves exact dependencies and performs its existing checking.
An invalid candidate can cost time, hide better candidates or fail to arrive;
it cannot become a theorem merely by being mirrored, indexed or frequently used.
This is an authority-separation argument, not a new proof of checker correctness,
availability or identical discovery behavior. Preserve all receiver-side checks.

## Minimum operational conditions

1. Authorize disclosure of the complete selected closure, including proof-only
   imports and group siblings. Target selection is not a per-object access list.
   Copy no owner catalog, native module, private source or producer success flag.
2. Pin manifest/semantic identity and bounded exact files, reject malformed,
   conflicting or oversized input; derive locators/previews locally. Publish
   search records only after exact preview/evidence binding. No remote writes.
3. Prefer complete closure relative to the pinned basis in this first workflow.
   Arbitrary partial custody is safe as bytes, but cannot promise autonomous
   recovery after the producer vanishes. If partial service is later needed,
   expose missing exact imports and allow consumer refusal; never invent them.
4. Build into fresh exclusively owned stores before opening the endpoint. Retain
   interrupted preparation as incomplete, not READY. Never copy a live SQLite
   catalog or bypass an owner's lock. A read-only service still relies on locally
   protected immutable-by-policy state; hash reads detect corruption, not access
   races or a hostile local operator. New content means a new approved snapshot.
5. Bound input units/bytes/nodes/edges, previews/postings/snapshots and retained
   disk, plus preparation CPU/memory/wall. Retain existing service attempts,
   connections, response-byte and original lease/cleanup budgets. Failed requests
   consume resources; quotas bound loss but do not supply fairness or liveness.
6. Report `mathematical_acceptance:false` throughout. Do not manufacture authoring
   offers or checked roots. A complete byte closure still may be false, invalid
   under the receiver's policy, too expensive to check, or unavailable later.

False but well-formed mathematics is an intended discriminator, not malformed
input. A statement such as False with a mismatching proof term may survive inert
structure/identity checks. Indexing it is permitted by this role; accepting it is
not. The existing selected-export controls already include deliberately false
inert data. Do not rerun a theorem campaign to rediscover this separation.

## Concrete cost region and honest comparators

Fix one already produced complete bundle B, one selected target set, r new
storage-only replicas and identical receiver demands. Compare these actual paths:

| Path | Each replica's extra work beyond transfer/retention/service |
|---|---|
| Current public owner route | Owner bootstrap; strict bundle planning/intake and native grants; preview/locator generation and index insertion |
| Inert preparation route | Exact structural parsing, closure validation, locator/preview generation and index insertion; zero native grants |
| Existing lower APIs | The same inert operations, assembled/serialized by the caller |
| Static file mirror | Exact-byte transfer/retention; no formal candidate endpoint or selected per-unit protocol |

Thus r copies do not justify r mathematical checks when none will use mathematics.
The current intake preplans structural dependencies, then invokes independently
checked batches; most preparation is common, not avoided work. New helpers must
not decode/index the entire global library: charge B and selected target previews.
Reading/hash-checking proof bytes remains linear in selected bytes. Structural
closure may examine all B's imports; this does not remove consumer cold checking.

A nonempty operational region is a custodian allowed to run the approved inert
Python data service but not native Lean checking. Given sufficient bounded data
resources, inert preparation can serve B; the owner-init/intake route cannot run
under that policy. This is useful role accessibility, already achievable through
the lower APIs, not evidence of faster mathematics. Full package source/native
pins may still be needed for the existing loader; do not promise a Python-only
distribution or disk saving until source coverage establishes that separately.

For a CPU-priced comparison let N_B be the removed bootstrap/checking work per
fresh replica, D_B the inert route's additional structural/orchestration work
over the common old data work, and H the helper's amortized engineering/operation
cost in the same units. Exactly the conditional region r(N_B-D_B)>H benefits;
it is concrete only after D_B is bounded or measured, not a speedup claim now.
Native-event counts provably drop to zero at custodians; elapsed/CPU need not.
Existing already-checked custodians can have N_B=0, and the API comparator already
has zero native checks. No benefit is claimed over that comparator except reduced
operator implementation/error burden. Do not credit avoided receiver checks.

Static mirrors are the preferred cheaper comparator for known bundles or backup.
Integrated rehosting earns additional work only when unchanged clients need
unknown-ID formal discovery and selective preview/evidence retrieval. If ordinary
Git/static distribution plus existing indexes already meets those needs, reuse
it; no new decentralized mechanism or fresh certification is justified.

## Falsifiable downside and stopping rule

One false attractive theorem replicated r times can cause many consumers to pay
failed checking costs. Blindly mirrored broad indexes can therefore cost more
than a checked publisher even when custodians save CPU. Deduplicate exact IDs,
bound selected queries/acquisition/checking, and let local operators curate what
they advertise. These mitigate waste, not guarantee useful growth or Sybil safety.
Honest missing imports, stale snapshots or damaged bytes must yield explicit
incomplete/unavailable/refused outcomes, not acceptance or silent substitution.

Select at most one small public preparation/service contract if PATH confirms
the gap and the target role needs discovery. Otherwise publish the existing recipe
or use static retention. Decisive later evidence is native-free preparation,
closed exact discovery/acquisition and explicit refusal/partial-state cases;
reuse existing receiver-checking evidence. No new cryptography or growth episode.
