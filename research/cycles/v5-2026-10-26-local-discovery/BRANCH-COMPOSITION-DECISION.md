## Decision

**Compatible independently developed mathematics can be combined using existing
public paths, conditionally on available evidence, supported semantics and finite
limits. Already checking each branch does not make their union an accepted context.**
Use coherent Lean/Lake dependencies and selected inert export/intake as today's
working route. A protected local checked-branch join deserves comparison: actual
saved siblings expose repeated work. No implementation or experiment is selected.

The concrete efficiency obstruction is parent-scoped acceptance reuse: a unit
checked on local branch B but absent from selected branch A is checked again when
admitted into A. Same-catalog storage does not remove this cost. This is a genuine
implementation limitation, not yet a demonstrated large cost. Same-name/different-ID
conflicts are separate; a zero-replay join alone would not solve them.

## Three objects that must not be confused

| Object | What it supplies | What it does not supply |
|---|---|---|
| Approved ordinary source project and compiled imports | Lean development environment, notation/tactics/instances where actually supplied | Automatic owner acceptance or exact correspondence to some other project's names |
| Checked owner context `R` | Exact name-to-ExportID bindings under local checking policy and protected snapshots | All other stored branches, source notation or a transferable proof certificate |
| Registered local module anchor | Checked materialization of exact whole units for ordinary imports | Authority to add those bindings to a context that lacks them |

Ordinary Lean already combines coherent dependency versions. The project adapter
accepts prebuilt imports; it does not run Lake/fetch dependencies. Same names need
not mean the same thing. Return checking warrants receiver meanings, not arbitrary
equivalence with the source project. Approved source/plugins execute as local code;
peer `.olean` files are not mathematical authority.

## Existing operable route

1. Choose A or a smaller eligible earlier context; never infer the latest/merged root.
2. Select exact useful B targets. Reuse a retained bundle, or `ordinary_selected_export`
   its full declared-import closure through custody to basis, including proof imports
   and atomic group siblings. Export does not assert source acceptance.
3. Run public `owner intake-baseline --parent-root A` on that exact manifest/bundle;
   use `peer receive`/`bounded-closure` only when providers are needed. Exact units
   in A are reused; missing compatible units are checked into new context R_AB.
4. Author/check new definitions and consequences under R_AB. Both contribution routes
   independently bind/check new evidence; project imports do not supply missing
   owner targets or bypass existing 32-group/4-MiB request/binding limits.
5. Optionally `export-module` selected vocabulary from R_AB, extending one compatible
   anchor. Return checked new work via contribution/publication or inert export.

Let K_B(T) be selected targets T's whole-unit closure, including proof ancestry,
stopping at fixed basis; let U_A be units exactly warranted in A. With no conflicts,
intake checks **D = K_B(T) minus U_A**, not all B history and not merely T.
An ancestor in B but absent from A is rechecked if selected closure reaches it.
Offline export reads K_B(T) even when intake later reuses part; receive cuts fetches
at exact A bindings but fetches T. `selected-unit-only` refuses missing premises.

## Exact obstruction and safe refusal

`ordinary_admission._plan` compares outputs/imports only against its supplied
context plus the selected batch. A whole unit is reused only when all its exact
outputs and imports are present in that context. `admit` re-preflights and invokes
the native worker for remaining units. `portable_catalog.context(R)` walks R's
single parent chain, not all branches; each extension reserves one parent.
Thus, for a nonbasis unit u accepted only on B and compatible with A, intake into
A places u in the new-check set. B's former acceptance is not consulted.

Different IDs under one name refuse `ADMISSION_PARENT_NAME_CONFLICT` or
`ADMISSION_PARENT_IMPORT_CONFLICT`; partially present atomic groups also refuse.
Printed equality/type ASTs/proof irrelevance do not override exact evidence rules.
The prior rebuilt concept case changed 22/106 units and all twelve endpoints,
including definitions. Pin one revision or check an explicit bridge/renamed revision.
Branches preserve coexistence, not joint use of conflicting declarations.

## Warm anchors are useful, but not cross-branch acceptance

`anchor_store.load` checks the whole anchor chain, policy/support and artifacts.
Originating context equality is unnecessary; **every represented binding must now
be warranted**. A's anchor can survive admission into R_AB but cannot authorize B in A.
A foreign registration is not a warrant; any conflicting represented name refuses.

`module_closure` cuts exact anchored units without proof fetches; zero delta has
zero native calls. Unanchored selected closure still has 32-unit/4-MiB limits.
Anchors form a chain, not two-anchor union. Distinct cold chunks can duplicate exact
declarations; ordinary module-name deduplication alone does not reconcile those.
Extending one compatible anchor after R_AB exists is the present route.

## Conditional safety and whole-cost argument

Assume the pinned checker/foundation are sound, protected local artifacts remain
authentic, exact hash bindings hold and actual native completion is clean. Let
Gamma_A be the warranted parent and D the topologically ordered new units. Each
unit must name exact bindings in Gamma_A or earlier D, introduce no shadowing, and
pass kernel checking. Induction over D then warrants Gamma_A extended by D.
Neither B's reputation nor its old report is a premise. This explains why the
existing route is safe without a new abstract branch-union rule.

Its cost includes export/acquisition of selected evidence, metadata planning,
validation/loading of A's protected snapshot chain, checking D, persistence and
any separately requested authoring/materialization. No term requires scanning the
entire network or every unrelated catalog branch. **There is still a dependence
on the entire selected local parent chain and on cold selected proof closure.**
Snapshot import avoids kernel replay of A's old proof steps, not artifact loading
or validation cost. B's acceptance elsewhere does not subtract checking of D.
Warm-anchor savings apply to materialization, not to a missing owner-context join.

Credit optimized ordinary Lean libraries' cached imports/dependency resolution.
This audit proves no growth speedup or universally favorable numerical benefit.

## Highest-payoff response and stopping rule

Compare current re-admission cost R with a protected local join's integrity,
compatibility, loading, snapshot/transaction cost J and engineering/security cost H.
Over m expected useful recombinations, reopen when sum(R_i - J_i) plausibly exceeds H;
charge common discovery/authoring/service costs equally. The tiny saved case is a
minimal correctness discriminator, not a reason to predict a large timing win.
Repeated expensive compatible closures justify source/theory work on local joins
now; general semantic equivalence or expensive certificates are unnecessary.

A safe join must bind both genuine local warrants, exact name/universe/group/import
semantics, common foundation and support; coalesce overlaps without rebinding;
authenticate its complete artifact import graph; and atomically commit a distinct
recoverable context with withdrawal/crash rules. Existing LocalSnapshot enforces a
one-parent chain, so changing only catalog metadata cannot implement this. Shared
basis modules can be deduplicated; overlapping declarations in distinct chunks
(actual B/C) require more. No peer binary or success report becomes authority.
Root can first select a bounded design against actual disjoint A/B, preserving the
existing native re-admission fallback. Runtime should test only a changed boundary,
not repeat source-obvious cost or the concept episode. No implementation selected here.
