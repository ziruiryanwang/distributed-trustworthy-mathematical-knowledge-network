## Decision

**The small companion is worth selecting, with the contract corrections below.**
It closes a concrete deployment-role gap: a custodian can supply unchanged formal
discovery and selected evidence routes without initializing a mathematical owner
or running Lean. This is core reciprocal availability, not a new truth protocol.
Existing lower APIs already provide the capability; the advance is a supported,
bounded public composition that avoids bespoke operator glue and accidental
acceptance coupling. Do not claim unique functionality or discovery acceleration.

Static exact bundles remain preferable for backup or known-bundle transfer.
They do not alone supply the unchanged candidate/locator/evidence endpoints.
A recipe is an adequate interim answer for a trusted developer, but would leave
source selection, closure validation and safe preparation/lifecycle composition
to every operator. One small reusable adapter is justified by those obligations.
Do not expand it into automatic replication, maintenance, a daemon or a new
store/transport abstraction. The fixed existing APIs are the cheaper route.

## Actionable contract corrections

1. **Say syntactic closure, not verified group completeness.**
   `P/installation/py/ordinary_evidence.py:302-395` checks shape and references;
   for inductives it only requires descriptor types/constructors to occur in the
   supplied inventory. It does not establish complete actual kernel-generated
   siblings/recursors or descriptor/inventory equality. A syntactically plausible
   false/incomplete group may therefore pass this parser. Preserve each supplied
   raw unit whole and derive IDs/locators from its actual supplied rows, without
   trimming or inventing members. Claim only exact-byte, syntactic import closure
   over those rows. Actual group completeness is a receiver-checking obligation;
   do not add native checking merely to justify the mirror's label.

2. **Specify the exact closed data set and disambiguate refusal.**
   `P/reference/baseline_bundle.py:221-286` does not establish import closure or
   cross-unit name coherence. For the simple first profile, select one manifest,
   verify every listed unit and accumulate all batches under aggregate bounds.
   Build one unique name-to-ExportID/unit map plus the pinned basis map; reject
   basis shadowing, conflicting output names, mismatched import IDs, missing
   imports and cycles. Advertised targets must resolve to exact supplied rows.
   The manifest is the full disclosure/custody set; target selection only limits
   indexing. This conservative one-context restriction may reject otherwise
   individually valid incompatible branches. Report profile/structural refusal,
   never mathematical falsity. Do not claim minimum closure or all mathematics.

3. **Make readiness a complete preparation result, not an individual put.**
   `OrdinaryStore.put_evidence` creates locators for all supplied outputs; its
   put and index `Store.admit` commit independently
   (`P/support/transport/ordinary_acquisition.py:148-217`;
   `P/support/discovery/discovery_store.py:221-274`). A late failure can leave
   partial durable stores. Keep those fresh outputs as incomplete, with no
   service startup and no resume/overwrite implied. Derive selected previews
   from exact stored evidence, resolve them, index them, and bind the final
   readiness result to manifest, target set, namespace and final snapshot.
   If serving is a separate invocation, require this locally protected prepared
   selection, not an arbitrary directory or caller-provided READY string.
   Existing exclusive-store/immutability premises suffice; do not invent a
   transferable custody attestation or pretend transactions span both stores.

4. **The cheap role must actually avoid native installation.**
   Reuse selected-export's `export.py:163-184` codec-loading pattern and
   `P/run.py:224-257` bootstrap pinning, not `profile.load`. Pin the full Python
   execution/import closure, including lazy request-route dependencies, before
   accepting bundle data. No import/search path may come from the bundle or
   authoring offers; missing local code must refuse rather than auto-fetch/run.
   Approved runtime/code remain a trust premise. Bundle hash approval authorizes
   exact data/disclosure, not any executable project. Check that the documented
   source setup can obtain these payloads without a Lean build; otherwise the
   claimed storage-only accessibility gain has not reached the public route.

The prior PATH already requires aggregate resource bounds, finite supervised
lease/cleanup, protected local stores and unchanged TLS policy. Retain those;
this review adds no parallel supervisor or permission system.

## Payoff and stopping rule

The defensible gain is zero mathematical grants at new storage-only replicas,
plus less operator glue. There is no avoided checking relative to the existing
lower-API comparator, no avoided consumer checking, and no demonstrated wall/CPU
speedup. The extra parse/copy/index work must remain charged; source-level removal
of native calls and explicit fixed ceilings justify selecting a small adapter
without a new mathematical benchmark. One false popular candidate remains a
possible downstream cost amplifier; do not label inert advertisements CHECKED.

Stop after the minimal source contract and its implementation boundary are
resolved. Any later targeted integration should establish this missing public
edge using retained data, not repeat theorem production, old acceptance audits
or a global-growth experiment. If setup requires a new build framework, changing
Provider/store type guards or a broad protocol redesign, revert to the existing
API recipe/static bundle until that additional cost has its own justification.
