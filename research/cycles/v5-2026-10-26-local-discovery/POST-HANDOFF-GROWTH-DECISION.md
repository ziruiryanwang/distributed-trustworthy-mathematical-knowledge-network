## Exact recipe boundary

The companion emits `[[structuredName, portableSymbolID], ...]`, not a dictionary
or complete context inventory (`formal_query.py:77-101`). Pin the actual file
through terminal `files["BINDINGS.json"]`, retain the approved profile/namespace,
deliberately choose one/two rows by their exact names and copy each row's second
value to `{"tag":"type-symbol","symbol":{"kind":"portable-symbol",
"symbol_id":value}}`. Optionally add theorem kind. **Replace, never append to,
the original exact-key specs.** Preserve original output bytes.

All selected symbols are ANDed. Automatically selecting every goal reference
creates false negatives under specialization; a theorem's parameters can later
be instantiated by terms containing symbols absent from its declared type.
Unknown/body-only/cross-representation relevance remains outside the guarantee.
No symbol choice proves premises or applicability. Existing preview/inspect,
independent acquisition and ordinary Lean application remain mandatory stages
when that method is actually reused.

Do not substitute UnitID, AnchorID, type key, compiled feature atom or an arbitrary
candidate ExportID. The query report's existing `features` is for the old exact
query, not the new symbols. Directories require route subsets of the replacement
specs; sparse pairs require separately compiled feature IDs and do not change
query semantics. No new provider, namespace, reindex or automatic retry is needed.
