# Real-library workflow after the first Std export

2026-10-26. `practical_library_route`; source/theory decision for root. Canonical
guard passed. Source/read-only work only. Root supplied the `std-export01` actual
figures; the separately assigned outcome audit controls adoption.

## Decision

**Keep ordinary approved libraries as the working format; treat independent
inert grounding as an amortized library-acquisition operation, not a compulsory
export of a library every time someone uses one of its lemmas.** Preserve strict
independent checking. This result warrants a concrete producer binding-efficiency
revision and an explicit bootstrap-versus-warm-use contract, not a new certifier,
larger allowance, trusted-library waiver or neighboring-lemma campaign.

The next implementation candidate is avoidable producer controller work, justified
by an existing useful warm route below. No new checker or materializer is needed
in principle for approved-Std authoring above an independently grounded context.

## What the first result actually changes

Native export completed: 2,651 selected units, 16,226 dependency edges,
1,102,333 scan nodes and 38,094,420 unit JSON bytes. It loaded 39,939 source
records/1,233 grouping records; writer output was 38,154,768 bytes. Native cost

68.71875 controller CPU seconds, 117.411 overall wall / 89.078125 known inclusive
CPU seconds, 919,453,696 bytes peak commitment; clean closure was reported.

Therefore this is **failed complete production with successful native extraction**,
not a usable baseline, mathematical acceptance or semantic incompatibility. Kernel
admission has not run; the failure does not license salvaging partial files as a pass.

The controller, not native extraction, consumed most measured CPU. Source shows
avoidable repeated work is a credible candidate, though no per-function timings
identify its exact share: `baseline_bundle.bind_writer` inspects each unit,
serializes it, constructs evidence, calls `PE.read_evidence` (which inspects it
again), then serializes the unit again for measurement. Its writer parser also
performs a Python byte-by-byte lexical scan over the complete writer payload.
Preserve lexical, identity, ordering, group and resource checks; consolidate
validated local representations, not external acceptance. No speedup is yet measured.

## Three distinct user situations

| Situation | Appropriate route | Trust and cost that remain |
|---|---|---|
| Std already approved for ordinary local work | Import/use Std normally; keep its notation, classes and tactics | Approval is an execution/environment premise, not a commons warrant |
| Recipient needs independent grounding of unfamiliar mathematics | Explicit one-time selected closure acquisition, existing bounded batch intake, exact protected context | Fetch/check all missing ordinary evidence for that choice, or refuse; no acceptance from producer reports |
| Repeated extensions above an already warranted base | Existing exact-parent delta checking and approved-project authoring | Restoration, required semantics, new checking and explicit local interpretation remain |

Ordinary authoring does **not** close fresh grounding for free. Unwarranted Std
premises still require evidence; `extract-project`/`complete`'s combined 32-unit/
4-MiB limit is not a large-library bootstrap interface. Approval is not a warrant.

**Concrete existing warm path:** after genuine bootstrap, approved-project
`contribute` can select `acquired_targets=[]`, preparing only the warranted basis
Eq, and author normally with imported Std. `SuccessorExport.selectedDeferred`
stops at safe imported constants and emits unprepared names as **unclaimed**.
`portable_candidate.bind_candidate` resolves them from the protected parent;
complete new units then undergo actual `preflight`/`admit`. Thus no large inert
Std definition frontier need be reconstructed in this approved authoring case.
This is newly checked recipient-local interpretation, not an assertion of original
package correspondence or permission to replace an explicitly claimed identity.
Missing names, incompatible proof/conversion and oversized new outputs still refuse.

## Minimal realistic progression, not another broad experiment

1. Preserve this first refusal and writer. Select source-only consolidation of
   producer binding if its review proves equivalent refusals and exact identities.
2. Separate a reusable, explicitly priced bootstrap from small repeated deltas.
   Existing baseline intake already batches; a single peer receive's 1,024-unit
   ceiling is not the total-intake ceiling. Do not make ordinary users assemble
   thousands of per-theorem requests or silently approve another person's code.
3. Prefer the existing approved-project warm path where approval is acceptable;
   use F to assess the distinct no-project route. Do not require cold full-proof
   module export for ordinary authoring. Exact original-base correspondence is
   only needed for the stronger original-identity/same-base materialization case;
   its prior thin-delta analysis does not solve first mathematical grounding.
4. Select changed-boundary execution only for a usable end-to-end route, not
   intake merely because output can pass or another toy method composition.

No retry, cap increase or run is selected. General Std end-to-end support is not
established by composing source arguments; failed complete production stays failed.

## Growth and the honest operating region

For one recipient let A be selected cold grounding/setup cost, W_i the full cost
of warm extension i, and S retention/service/failures. The sharing route costs
`A + sum_i W_i + S`, not `sum_i A`. It is beneficial against an equally capable
ordinary alternative only when its real avoided work exceeds that total premium.
Count initial creator/export cost system-wide; recipients each pay their actual
independent acquisition. Do not charge the comparator repeated reconstruction
of its already approved checked Std. Amortization is conditional, not observed speedup.

Value is usable unfamiliar methods and new definitions/consequences, not reproducing
Std or maximizing artifact counts. A 38-MB bootstrap may be reasonable for many
uses but poor for one easy lemma. Demand, reuse and full cost decide.
