## Decision

**Do not launch a blinded from-zero end-to-end investigator campaign or invent
another code/spec mechanism now. Select one small no-project contribution plan
over the already received mixed vocabulary; if it passes the source conditions
below, its single public owner call is worth executing.** A history-restricted
fresh author is useful for a cheap usability observation, not a reason to delay
this precise composition check. No execution is authorized by this note.

The new observation should be whether a recipient can turn a genuinely useful
received concept/method into a fresh checked consequence through the advertised
simple route, using only operational documentation and public outputs. Its
uncertain seam is scratch reconstruction plus new-proof return/admission, not
source packing, initialization, earlier intake, module production or the ability
to state a formal question. Stop at that boundary; a full network replay adds
mostly already covered work.

This is a prospective software-usability and composition test. A history-limited
agent is not an independent human, and supplying already discovered targets is
not blind unknown-ID discovery. Neither term should become a growth claim.

## Cost and result-dependent choices

One contribution has two relevant sequential native phases: source elaboration/
export and independent admission. Controller preparation, pinning, acquisition
from local custody, serialization, durable writes, closure and review also cost
resources. The actual new proof must fit existing request/candidate bounds; no
fixed allowance proves that it will.

For orientation, retained generic actual03 used 8.388 wall / 6.515625 known CPU
seconds for three groups and two new outputs; all its failed attempts remain
charged. Retained project `mapFour` used 23.298 wall / 10.953125 known CPU seconds.
These are different workloads, **not predictions or a causal comparison** for
the 21-group case. A prior comparable public return used a 180-wall/110-CPU/
2048-MiB outer envelope and 150-wall/90-CPU/1536-MiB inner owner allocation.
Root should select the final finite envelope after reviewing the actual source;
all phases derive from one allocation. No grant is made here.

The existing alternative needs no foreign project: create an owner-approved

bridge using **all** public `import_directories`. The project-return adapter can
then reuse its real interfaces rather than reconstruct absent concepts. It still
prepares exact labels and independently checks the new contribution, so it is
neither free nor a new trust mode. A failure of the simpler route would justify
trying this only by a fresh decision, not an automatic second experiment.

## Why not a complete blinded loop now?

Starting fresh would pay again for a supported native build, five overlays,
owner initialization, existing input acquisition, module realization, question
extraction, service setup and earlier search before reaching the uncertain step.
Those costs would obscure whether the new source-to-new-warrant boundary is
usable. Reusing retained public outputs gives a sharply attributable answer.
A narrower continuation is not a complete end-to-end qualification, and must not
be described as one.

The local/unpublished restriction does not block this useful work. A second host,
human participant or license decision is not the sole next gate; none is reopened
by this recommendation. The inert peer protocol's established source-trust
argument also removes any need to build a generic hostile-project sandbox merely
for this continuation. Approved source still runs with actual account privileges;
protected local state and checker correctness remain real premises.

If this one boundary and its public-input plan pass, another speculative matcher,
certificate, metadata recovery system, repeated cold demonstration or guide-only
audit is not justified by the remaining broad goal alone. The next high-value
feature decision should then be driven by a concrete user investigation or a
specific operational/security failure under the supported profile. Such local
real-use evidence can be gathered without external publication. It must remain
separate from the unresolved large-network and full-cost useful-growth claims.
