## Latest refinement: prefer one query key for this selected workflow

After the initial review below, root proposed transposing the tiny relation:
index **correlation only**, with source key replication instead of query OR.
This is the cheaper supported discriminator for the actual TheoryB example.

Let `R` be the source's positive endpoint-equality partition, using precisely the
exact-parameter-endpoint rules below. At source extraction emit a key for every
partition `E` whose equality relation contains `R`. For at most three positions:

- no source equalities: all five partitions;
- one required pair: that pair partition and the three-way partition;
- three required equal positions: the three-way partition only.

The query computes **one** exact raw endpoint-equality partition `E_g`; missing
endpoints each get their own singleton. It searches only its one partition key.
Raw instantiation implies `R` is contained in `E_g`, so the source emitted that
key. Treat containment as inclusion of positive equality pairs, never inclusion
of inequalities. Missing endpoints do not invalidate the argument: a source
required equal pair has actual parameter endpoints along rigid application
paths, and hence both endpoints exist in a raw instance. Distinct source
parameters may map to equal query terms, which is why every coarsening is indexed.

Fix the two paths in canonical order:

```text
[[arg,fn,arg], [fn,arg,fn,arg]]
```

**Assessment: prefer this variant for the two-path TheoryB responsibility.**
With two paths it adds at most two keys per source, not five, and makes one
query. The useful `same_constraints_same_run` source has no equality requirement
between its two schedule-parameter positions, so it emits both pair partitions.
A reflexive schedule theorem requires the pair equal and emits only that key.
The raw-distinct schedules in the independently fixed goal produce the singleton
partition, finding the useful theorem but excluding the reflexive family.
Nonvisible premises remain irrelevant to extraction and need not be guessed.

This variant deliberately drops the old token vector. It is **not** a general
shape index: unrelated declarations with no required equalities emit every key,
including missing-path and early-parameter cases. Therefore use the existing
known `run` symbol/theorem-kind conjunction for this concrete workflow, with an
explicit narrower coverage statement. It is legitimate here because the actual
desired source contains that rigid `run` symbol; arbitrary raw-instance recall
does not permit automatically conjoining every symbol in a goal. The general
unconjoined correlation filter remains recall-safe but can be very broad.

Compared with the 40-key combined-vector design below, this trades a bounded
extra source posting for eliminating OR-query fanout and any client
multi-alternative accounting change. Provider indexing, complete namespace/map
integration and holding costs still count; the separate integration reviewer
owns that source boundary. One query does not prove constant service cost or
global completeness. The full cost and native/Loogle comparisons below remain
unchanged, and no new growth or runtime claim follows.

The rest of this note preserves the initial combined-vector challenge and the
actual theorem/source argument. Its recommendation to consider a 40-query
combined key is superseded for this particular two-path workflow by the simpler
source-replicated correlation-only option, subject to root's explicit contract.

Naming caution: an `equal` query key means two existing endpoints have equal
raw structure; its complement also includes missing endpoints. Call that key
`discrete`/`not-equal-endpoints`, or explicitly document the missing case. It is
not proof of mathematical inequality. A source that emits the discrete key is
asserting no required positive equality, not asserting its parameters unequal.

The original combined-vector bound below was deliberately loose. Once groups
are confined to STAR positions, its sharp maxima are 15 keys for three positions
and five for two (`sum_s binomial(d,s) Bell(s)`). Those bounds supersede the
loose 40 for planning, although that upper bound was valid. Neither is needed
for the preferred two-posting/one-query correlation-only variant.

## Initial combined-vector verdict

**No fatal recall flaw was found in the proposed restricted refinement**, provided
the endpoint/equality/partition rules below are explicit. It repairs the concrete
variable-sharing obstruction in `INSTANCE-GAP.md` with at most 40 keys for three
paths, without implementing a unifier. It does not repair arbitrary substitution,
normalization or relevance, and its worst-case candidate population remains large.

There is also a stronger existing-source workflow than unconditional
commutativity: discover `same_constraints_same_run` from a concrete equality of
two repair schedules without already knowing its order/closure vocabulary or
complete premise telescope. That theorem and its inert representation actually
exist locally. Merely abstracting the goal's two schedules into parameters does
not reproduce its full declared type.

This supports a **conditional portable-index feature choice**, not a conclusion
that adding it beats ordinary Lean/Loogle or increases research productivity.
The nonempty benefit region is a selective, repeated, already-inert corpus query
whose complete theorem telescope is unknown. It is not a blanket preference for
the new filter. If an approved imported library or useful existing Loogle provider
already supplies the candidate cheaply, use that route.

## Exact contract needed for the recall argument

Fix `d <= 3` distinct paths over `fn` and `arg` only, each with a fixed length
limit. These edges descend through application nodes; they never enter a binder,
let body, domain, projection structure or arbitrary expression child.

For a validated source type `forall Delta, t`, strip its complete leading
forall telescope with `k` parameters. Reuse the old STAR/token observation at
each path. Additionally record `endpoint(i) = j` only when:

1. every edge of path `i` was traversed;
2. its final node is the stripped parameter `bvar j`, with `0 <= j < k`;
3. the parameter was not encountered with edges still remaining.

Source correlation is an equivalence relation on positions: positions with the
same recorded `j` form a block; all other positions are singleton blocks.
Singleton means **no equality constraint**, not a promise of inequality to any
other position. There is no need to encode which singleton came from a parameter,
an early STAR, a rigid endpoint or absence. Include the canonical partition in
the one source key along with its old vector and exact profile.

The query strips exactly its explicitly supplied local-context wrapper, not all
of its goal's leading binders. For each original keep/STAR choice, enumerate all
partitions satisfying:

- every nonsingleton block consists only of positions selected as STAR;
- each position in that block has a real endpoint in the query;
- those endpoint subterms are equal under one specified raw structural equality.

**Every refinement of the observed equality classes must be allowed.** Emitting
only the maximal equality partition is wrong: distinct source parameters may
be instantiated to the same term, while the source key still has singleton
positions. The all-singleton partition must always be emitted.

For `d=3` there are five set partitions in total, so the deliberately loose bound
is `5 * 2^3 = 40` keys. Restricting blocks to STAR positions, forced context STARs,
endpoint incompatibility and deduplication can reduce that count. Forty generated
keys are not forty authorized searches: aggregate query/partition/page budgets
and explicit unsearched alternatives remain mandatory.

### Raw endpoint equality cannot mean pointer equality

Two equal subterms may be represented by different DAG nodes, or two separate
copies of an equal subtree. Comparing node indices would create false negatives.
Use a bounded bottom-up structural comparison/digest over the validated DAG,
including exact portable constant identities, levels, bvar indices and the
chosen metadata convention; never expand the DAG into a tree. There is no need
for Lean conversion, dependency retrieval or proof replay to compare raw syntax.

For the simplest proof below, exact structural equality after one simultaneous
substitution is the supported relation. Any ignored binder labels or metadata
must be consistently ignored at both source/query boundaries and in the stated
relation. Do not silently combine an alpha-equivalence coverage claim with a
stricter endpoint comparator. Hash collisions may admit false correlations;
they must never be reported as mathematical equality or acceptance.

### Conditional no-false-negative argument

Assume well-scoped simultaneous substitution `sigma` from `Delta` into query
context `Gamma`, consistent universe instantiation, and raw equality
`g = sigma(t)`. The old vector-compatibility lemma supplies one keep/STAR vector
equal to the source vector. For any source correlation block, all its paths end
at the same parameter and traverse no binder. Their query endpoints therefore
exist and all equal the same raw term `sigma(parameter)`, with no differing
de-Bruijn shifts. The query enumeration includes the source partition, hence its
complete source key. Premises and dependent parameter types are not discharged
by this argument; they remain ordinary Lean obligations after acquisition.

Excluding an early encountered parameter from correlation is essential. If a
path continues below a parameter, its substituted suffix need not equal the
substitution itself or the endpoint at another suffix. Likewise, extending these
rules under binders would require scope-aware shifted equality; this proof does
not authorize that extension.

## It distinguishes the earlier example with the right paths

Write Lean's equality as curried `Eq A lhs rhs`. For

```text
T: op x y = op y x
D: op x y = op x y
```

choose:

```text
p1 = [fn,arg,fn,arg]    -- lhs's first explicit op argument
p2 = [arg,fn,arg]       -- rhs's first explicit op argument
```

Both old token vectors are `(STAR,STAR)`. `T` has singleton blocks and `D` has
one equal-position block. For local target
`op (f a) (g b) = op (g b) (f a)` with raw-distinct `f a` and `g b`, the two
query endpoints differ. Its keys include `T`'s partition but exclude `D`'s.

Sampling only the whole lhs/rhs would not work: those endpoints are applications,
not exact source parameters, so the refinement deliberately attaches no relation
to them. The path profile must be independently specified and justified, not
chosen after observing whichever example happens to pass.

### Investigator interaction that the exact-contract shortcut does not provide

An investigator already using TheoryA's `Repair`, `run` and `Settled` asks whether
two locally constructed schedules have equal outputs. For example the query
conclusion is `run [r,s] x = run [s,r] x`, with raw-distinct schedule terms.
The investigator may have raw proofs that a common relation is reflexive,
transitive and antisymmetric, that each repair is extensive and monotone for it,
and that each repair preserves the other's fixed states. Those facts can later
construct `OrderData`, `AllClosure`, `Safe` and the equivalence of the two
`Settled` predicates. They need not already be packaged using those B identifiers.

The index can suggest the theorem from the conclusion alone. Its preview exposes
the additional vocabulary and obligations; then the normal acquire/check/import
route and Lean application can determine whether the local data meets them.
The conditional example is chosen to make the target actually supportable; for
arbitrary repairs the schedule equality may be false. Query success is never
evidence that the side conditions are available.

Abstracting only the two schedules and state gives
`forall rs ss x, run rs x = run ss x`, which is false in general and does not
equal this theorem's declared type. Adding local hypotheses verbatim still does
not reproduce the named `OrderData`/`AllClosure` telescope or its dependent order.
The complete exact-query helper requires the missing expression and exact IDs;
it cannot express an existential hole for unknown premises.

This is a meaningful information advantage over requiring the consumer to supply
the complete generalized type. It is not a proof that every intelligent consumer
fails to invent the closure concept or derive the result directly. Discovering
that bridge from existing work is precisely a legitimate supported interaction.

### What selectivity it can and cannot add

Valid reflexivity declarations may have the same premise vocabulary/telescope
and conclude `run rs x = run rs x`. Add harmless unused parameters to make
distinct bounded types if a family is needed. All current non-exact ordinary
features can coincide with the useful theorem's; optional pairs do not separate
them. The proposed two-path correlation excludes this family when the queried
schedules are raw-distinct, while keeping the useful theorem regardless of its
unseen premise telescope. A fixed provider snapshot with `n` such distractors
before the target has an `n+1` candidate barrier in the existing broad route.

This family is a theoretical discriminator, not a claim that the retained corpus
contains those distractors or that reflexivity dominates real mathematics. Other
conditional equalities with independent schedule parameters remain in the same
singleton bucket, potentially arbitrarily many. Merely using a different goal
order or a random ranker does not supply a worst-case relevance bound either.

## Fair alternatives and a defensible benefit region

This is useful only under explicit, ordinary operating conditions:

1. Compatible portable type previews already exist at an index provider. The
   consumer knows the shared conclusion vocabulary, but not the complete theorem
   telescope. It can acquire the relevant evidence if a useful candidate is found.
2. The provider chooses a data-only portable index; it does not already have an
   approved native environment/search service covering this corpus. No claim is
   made that Loogle cannot be supplied. Doing so is a distinct ingestion/indexing
   choice with actual preparation, safety and maintenance costs, not a free
   hypothetical existing service.
3. The consumer's approved imported environment does not contain this theorem.
   Its real local tactics and direct derivation remain available and credited.
4. The refined cohort is substantially smaller for repeated actual demand, and
   endpoint hashing plus query fanout, reindexing and maintenance fit the saved
   candidate handling cost. Selected theorem acquisition/obligation discharge also
   fits; a smaller candidate count alone is not enough.

Let `C_b` be the existing broad portable query plus candidate inspection cost,
`C_r` the refined query cost including every attempted alternative, `I/Q` the
amortized added indexing/holding cost per query, and `C_u` the unchanged selected
evidence/check/application cost. This lane improves that portable workflow when

```text
C_r + I/Q < C_b.
```

A user-level preference additionally requires

```text
C_r + I/Q + C_u < min(C_native, C_Loogle_or_package, C_b + C_u)
```

over actually available and policy-permitted alternatives, including their real
initial setup amortization. An absent useful provider is an availability premise,
not evidence that Loogle is intrinsically worse; if it becomes available cheaply,
the preferred route can change. Native search over already imported B is a strong
baseline, not forbidden. A direct short local proof may also win this example.

The first inequality has a nonempty conditional region when avoided distractor
handling grows while one indexed source key and bounded query-key family remain
fixed, provided query demand pays indexing/holding within its retention horizon.
This is an architecture-level candidate-retrieval argument, not a measured
physical-cost gain or lower bound on all mathematics. The second inequality is
not established by the source inspection and must not be asserted as a growth
result. No large benchmark is warranted merely to demonstrate the first family.
