# Next decision: does ordinary investigation obtain value from our discovery path?

2026-10-28. Source/theory audit only. No product import, owner/database access,
network, Lean operation, experiment, implementation selection or Git action.
Root owns any subsequent finite study. The full v5 goal remains open.

**Recommend one developmental investigation using the current software, before
adding a search mechanism.** Offer the current exact mathematical index as an
optional tool alongside a fully capable ordinary-source workflow. The decision
is whether our index supplies an affordable, useful
connection during an actual investigation, and precisely which boundary fails
when it does not. This is an engineering discriminator, not a statistical claim
of accelerated discovery or an abbreviated final-release criterion.

The rich reciprocal workflow now works, and the new operator kit addresses its
mechanical handoffs. Neither result establishes that an investigator who does
not know the answer will choose a productive query or benefit from the returned
mathematics. This is the next central uncertainty with the highest expected
payoff. A generic ranker, another reciprocal theorem, more local peers or a larger
synthetic posting-list test would not resolve it.

## The central obstruction, stated precisely

For a known statement, exact-type lookup can be excellent. For an investigation,
the useful statement or abstraction is often what must be discovered. Known-symbol
neighborhoods are a reasonable bridge, but two limitations remain:

1. A useful connection may not contain the investigator's known symbols in its
   visible type. A definition's public type can hide the symbols in its body;
   further abstractions can replace an old vocabulary. More hash partitions,
   replicas or pair indexes do not reveal that missing connection.
2. A common symbol or coarse head can match many irrelevant statements. A
   mathematically interesting bridge can be buried among otherwise valid results.
   Bounded work ensures an honest stop, not that useful information arrives first.

There is a concrete current illustration of the first issue, without inventing a
failed query: `ordinary_finite_map_effects/Body.lean` defines `Plan` with public
type `Type u -> Type v -> Type ...` and `mustWrite : Plan K V -> Bool`. Neither
type names `Std.HashMap`. Its `Exec` interface and several theorems explicitly do.
A HashMap-symbol query can expose those bridges; it cannot directly expose every
new abstract interface. The refinement library similarly contains interfaces
whose known vocabulary is hidden behind `Plan` and newly defined relations.
This is not a demonstrated lost result: a reader may cheaply follow a returned
bridge, inspect definitions and issue another query using the discovered symbols.
The question is whether that path is affordable and practically usable.

The actual [discovery plan](../../../software/v5/ordinary_finite_map_refinement/DISCOVERY-PLAN.md)
used HashMap plus generic object/theorem kinds; its selected index then contained
nine outputs and six matching theorems. This correctly demonstrated unknown-ID
access. It did not test how an unbriefed investigator selects queries in a mixed
library. The subsequent checked 37-unit receive/offline extension/return is strong
evidence of supported interpretation, not a substitute for that missing exposure
step.

The [concept-capability argument](../v5-2026-10-24-growth-selection/CONCEPT-CAPABILITY-THEOREM.md)
already proves the relevant limited pruning result and names affordable exposure
as the missing premise. The [discovery bottleneck audit](../v5-2026-10-24-growth-selection/GROWTH-DISCOVERY-BOTTLENECK.md)
already compares ordinary specialist search fairly. Repeating either argument
cannot establish that this premise holds for our actual users.

## Smallest decision-changing study

Use **one fresh local investigator session**, started without inherited producer
conversation or a supplied desired result ID/name. No paired benchmark, new model
API, agent platform, training, network topology or external participant is needed.
The available subagents share a filesystem and have unrestricted tools: giving
one a bounded brief does not enforce isolation, prevent reading other files, or
provide trustworthy per-arm model-compute metering. This is explicitly a
developmental diagnostic, not blinded or causal efficacy evidence. Root should
make one finite selection after source/fixture review; this note launches nothing.

Freeze the study's corpus by whole retained source modules before examining its
outputs: the already checked repair/closure and finite-map theories, their actual
selected publication endpoints and the common supported Lean/Std base. Record
exact module/source versions and which endpoints are actually indexed. Do not
add only records chosen because they support the investigator's eventual claim,
manufacture duplicate distractors, or export all of Std to make the corpus look
large. This deliberately small corpus tests a workflow premise, not large-scale
recall. Missing publication coverage is an observed outcome.

The investigator receives a broad brief, for example:

> Investigate when independently specified finite-state updates can be combined
> or substituted while preserving a useful observable property. Choose your own
> claim. You may introduce definitions, seek general laws, or refute a tempting
> law. Produce checked, extendable mathematics if the allowance permits.

This is a local study brief, not a system-wide task list. It supplies neither the
known contextual-distributivity theorem nor a hidden target disguised as a broad
request. Do not count a supplied or previously copied endpoint as fresh discovery.
Choose and freeze the exact brief before launch. Request a record of what was
actually consulted; a claim of unassisted use must not survive undisclosed
producer-context or evaluator-target exposure. There is no technical secrecy
guarantee in this shared workspace.

- Supply the approved ordinary source corpus, explanatory material, installed
  base, persistent scratch library, ordinary Lean tools and available local/formal
  search. Permit source inspection, invented lemmas, revised definitions, caches,
  countermodels and the best ordinary route. Ordinary source/library search is
  the practical alternative, not a deliberately weakened control arm.
- Also supply current index/kit/API instructions and selected contacts. The agent
  may use that route or ignore it. Do not force inert exchange when approved
  ordinary source use is cheaper. Its selection is a diagnostic observation,
  not a randomized treatment assignment.
- Fix model/settings and explicit finite operational allowances. Keep new scratch
  outputs; no parent mathematical repair or useful-result naming. If infrastructure
  assistance is unavoidable, record it and stop any claim of unassisted operation
  for that segment. Do not invent model-token or compute measurements the session
  does not expose.
- Use a warm supported base when available. Do not repeat the completed
  cold grounding or reciprocal fixture. Root must select any required new owner
  operation explicitly and charge it. No copying private owner state to fabricate
  a fresh recipient, silent reset, service renewal or fallback allowance.

Cap this discriminator at one investigator session, at most one separately
reviewed successful extension, and no repeated attempts after the
original allowance. Root should fix numerical model/native/wall/read budgets
using existing costs before launch; model effort must not be presented as fully
measured if the session exposes no reliable usage record. Lean runs serve the
chosen investigation, not repeated product qualification. Stop early on a named
operability obstruction that already determines the engineering decision.

The primary output is a **query-to-use trace**, not theorem count:

1. The vocabulary and problem state known before each query; why that query was
   selected without knowing the answer.
2. Actual returned candidates, inspected bytes, misses and unavailable routes;
   which information first changed the investigation or eliminated a false path.
3. The selected mathematical statement/definition, a checkable dependency on
   reused mathematics if present, and the newly warranted capability it supports.
4. Source-search, reading, adaptation, checking and service costs, including
   abandoned approaches. Record already incurred publication/construction costs
   separately; this small marginal study cannot erase them or establish full-cost
   economic acceleration.

Keep cheap direct proofs, ordinary-source successes and independent rediscoveries
in the record. They can defeat the proposed value of an interchange route for
this case. An unused index is informative, not a reason to instruct the agent to
use it. Do not replay the same research with knowledge of its outcome and call
that a matched baseline. Kernel dependencies show literal reuse; they do not
demonstrate that reuse improved research.

## The decision this study must change

| Observed obstacle or outcome | Next decision |
|---|---|
| A useful unfamiliar bridge is found, understood and reused at modest additional cost | Retain the existing mechanisms. Select stronger transfer evidence under the existing study design, rather than add a new matcher. |
| A relevant available artifact is found by ordinary source search, but no query expressible from the prior known vocabulary exposes it affordably | Preserve that exact query/artifact miss. Compare one minimal advisory feature or interface-display change against the existing ordinary tool; design that specific change next. No general semantic search project follows. |
| The product returns relevant candidates, but type/body interpretation or query construction dominates | Repair the demonstrated frontend/representation handoff; do not optimize network routing or certificate production. |
| The needed artifact is absent, unindexed, unavailable, or has unsupported source/library semantics | Address that concrete supply/adoption issue. A richer ranker cannot create missing data or compatibility. |
| Ordinary source tools suffice and the optional index adds no value, or the investigation makes no substantive progress | Keep interchange as optional reliable sharing. Select a better justified workflow/domain before funding a search extension; do not relabel the episode as growth evidence. |

This is intentionally one engineering study, not the full three-test paper
campaign in [DISCOVERY-STUDY-DESIGN](../page-2027-paper/DISCOVERY-STUDY-DESIGN.md).
One diagnostic session cannot establish causal speedup. There is no isolation or
model-compute-accounting claim. The purpose is to obtain a concrete query/failure
trace that can invalidate an architectural investment before we implement it;
stop once that diagnosis is sufficiently specific, even without another theorem.

## Consequence for huge-scale claims

Useful known-vocabulary bridges, bounded relevant-corpus selection and selective
postings are the premises that could let an agent work through a small part of a
huge commons. The current software bounds the work it authorizes; it does not
guarantee those premises. Prior [placement analysis](../v5-2026-10-20/SHARDED-DISCOVERY-DECISION.md)
already distinguishes exact hash routing from useful selective coverage. A local
investigation cannot establish global placement, independent retention or broad
recall. It can tell us whether the query class worth scaling exists in practice,
and which metadata actually helps it.

Therefore no discovery-core change is selected by this audit. Finish the bounded
operator controls, then obtain this practical discrimination. Build a narrower
retrieval or supply improvement only from its identified failure, keeping ordinary
Lean/source sharing as the equally capable baseline and mathematical acceptance
independent of relevance judgments.
