## Manifest transport must preserve the whole dependency relation

The proposed one-file manifest removes Windows argv growth without changing
the proof DAG. Exact `16+m` arguments including executable is the correct
count for the proposed trailing path/length/digest replacement. Actual quoted
UTF-16 length including NUL still needs a check; bounded argument count alone
does not bound operand lengths.

The controller's manifest must be created new, synced, pinned and charged before
host dispatch. Independently expected digest/length travel in argv. Host hashes
the actual bounded bytes before parsing and checks exact schema, session,
capsule and stage binding. The dependency rows must equal the independently
derived **ordered** graph dependencies, not merely be an admissible subset or
set. A segment takes none, lift its segment, join its left prefix and right
lift, resolve its predecessor, finish every segment in order and the final
resolved (or m=0 joined/lifted) prefix. Row key/path/bytes/hash are all bound;
duplicate/missing/extra/reordered rows and recursive manifests refuse.

Each actual dependency read must satisfy the ordinary-path policy, row digest
and length, total read bound and checkpoint capsule/key binding before normal
SDK verification. No row pin, manifest digest or checkpoint header supplies
cryptographic authority. Unused cache material still refuses. Post-call
rebinding preserves detection of retained-input mutation; it does not create
filesystem immutability or a hostile-source sandbox.

Canonical controller output with raw digest binding plus strict typed native
JSON is sufficient; duplicating Python's Unicode canonical serializer in Rust
is unnecessary. **One requested correction:** JSON arrays normally have no
exact `SeqAccess::size_hint`. Their count bound must be enforced incrementally
before accepting/pushing the first excessive element, with bounded capacity.
The existing bincode visitor requiring an exact declared count cannot simply
be copied as the manifest decoder. Duplicate/unknown fields, wrong numeric
types, trailing data and invalid digest spelling still refuse.
