## Initial contract challenge: demand-only correction is supported

The correction removes equality to a historical **proof representation**, not
the target or downstream verification obligation. For a fixed canonical local
interface S, relation image I and exact BASE/FIRST parent journals of ranks0/1:

```text
rank(SECOND) = max(0,1)+1 = 2
J_SECOND = encode(I, S.foundation, S.policy,
                  module_id(S), group_root(S), group_count(S), 2)
```

Inspected actual `SourceRows.reference`, `SourceRows.module`, theorem decoding,
`codec.summarize/module_id`, `MixedSourceOperation.finish` and `expected_journal`.
External declaration references encode ModuleID plus relative name, not their
temporary imported row number. Nonlocal declaration groups are excluded from
the resulting local spec. Theorem proof expressions are kept separately, with
no theorem-value hash in the interface. Therefore omitting an unused imported
group need not alter S or J even though rows, names, proof terms, openings and
packet bytes can differ. The fixed author source uses explicit qualified names;
it does not select the target through an imported notation/typeclass search.

This is not a universal claim that Lean elaboration is context-independent.
The adapter must compare **actual** canonical local_spec and exact J after the
author closes. A changed exported local interface still refuses. No rewriting
of the old corrected witness is appropriate. C must actually admit the newly
emitted witness; an inspector, hash match or source comment cannot do this.

The current importer is demand-driven at the **selected declaration closure**
boundary, not a minimal runtime-evaluation oracle. `_build_context` examines
every selected group's type and requests every selected definition value and
recursor rule, recursively following their references. It omits opaque theorem
proofs. Thus avoiding unused `binary_congr` is supported, but statements that
only bodies actually reduced by Lean are fetched would overclaim this code.
