## Finding

The retained same-shape test demonstrates **loss of an exact name-erased type
from a bounded candidate stream**, not merely failure to recover a preferred
declaration name. It does **not** demonstrate that an agent lost the ability
to complete mathematical work, or that a different search policy would produce
net useful growth. Its scorer, interfaces, applicability and downstream reuse
are different predicates.

This corrects the overly loose phrase "named-target miss" without revising any
retained test or audit. The existing independent shape outcome remains valid
for its expressly inert syntactic scope.

## Four predicates that must remain separate

| Predicate | Meaning | Evidence here |
|---|---|---|
| Identity retrieval | Exact bundle/interface/name or exact name-erased full type appears in the bounded reply. | Exact A-type absent; all returned types are R. |
| Type usability | A received, actually certified interface can be imported under the current support rules. | Genuine A passed in the separate public prepare; synthetic R offers were never qualified. |
| Application/matching | In a specified formal context, a candidate can be instantiated toward a goal, with explicit residual obligations and conversion work. | Source analysis below, not an executed general matcher or complete proof search. |
| Successful reuse | An actually checked downstream proof depends on the selected acquired interface, within the stated operation resources. | A twice in the adopted composition example; no downstream task was attempted by the crowded search test. Dependency is not indispensability or speedup. |

For a local formal context Gamma containing the displayed A premises and rigid,
distinct locals x,y, the goal is `x = y`. Instantiating A supplies this goal
with the stated premises. Instantiating R alone has conclusion `t = t` and
cannot close it by definitional conversion unless x and y are definitionally
equal. Hypotheses asserting equality do not make arbitrary locals definitionally
equal. This is a narrow, checkable distinction in **direct application**, not
a theorem that R plus the unchanged foundation cannot prove the goal. The
retained `OwnerA.lean` already gives a short direct proof using equality
reasoning; withholding that route would manufacture an advantage.

Nor is mutual logical derivability an appropriate usefulness quotient: both
universally closed valid theorems are already consequences of the foundation,
so unrestricted proofs can ignore either supplied lemma. Capability here must
mean an accessible proof interface plus an actual resource-bounded use, not
an enlargement of the foundation's deductive closure. A local formal goal is
an evaluation instrument/agent choice, never human intention in acceptance.

## Smallest next discriminator: close the candidate-to-application bridge

Do **not** commission another long local-only growth baseline or new certificate
campaign. Preserve the completed exact-key, shape, route and A-reuse evidence.
The next selected search experiment, if root later chooses one, should freeze
one local formal application context of the form above and report four separate
bits: A identity hit; certified interface available; application with discharged
residuals; checked downstream dependency. Do not give the query builder A's
name, full type hash, scorer mapping or a known-ID answer. An exact-ID control
is labeled oracle-available and is not counted as discovery.

The minimal new discriminator is a **candidate-stream intervention**, using
the existing `offer`/`find`/selected-acquire/`prepare` boundaries, not a new
semantic-search API:

1. Retain the already observed 32-R-prefix/late-A and different-shape outcomes
   as controls. Their old query budgets and namespace remain historical; do
   not silently rerun or reinterpret them under a new index version.
2. For any future candidate policy, freeze its output ceiling at16 candidates,
   65536 aggregate reply bytes and two bounded page calls. Score exact type
   diversity separately from direct applicability; preserve `incomplete`.
   A matching interface can have another name: success is not conditional on
   reproducing `BatchProbe.left_inverse_injective`'s spelling.
3. Reuse the retained genuine A/prepare witness for the known-interface
   positive. If a future policy claims an **actual end-to-end** improvement,
   its newly selected acquisition must bind to the genuine four-file bundle
   and its actual public prepare must check the formal endpoint; metadata hits
   or inert fixture receipts cannot substitute. Do not relaunch the current
   composition/proof campaign merely to fill this column. A fresh endpoint is
   needed only for a new downstream-benefit claim, not for candidate diversity.

Thus the immediate missing information is bounded application/obligation
behavior for retrieved candidates, and a measured link from a non-oracle
candidate selection to use. Broad semantic equivalence, universal novelty and
long proof baselines are **not prerequisites** for improving this search seam.
Conversely, until that link is actually tested, the strongest result remains
candidate diversity/local applicability, not faster knowledge growth.

## One conditional implementation seam: materialized type-diverse candidates

Recommend examining **only an optional type-diverse representative range**,
not another exact/shape key or XOR router. This is the already recorded,
unimplemented alternative in `certified-query-selectivity-01/REMEDY-DECISION.md`,
now grounded by the actual same-shape duplicate result. Its narrow objective is
to prevent renamed copies of one existing type from consuming every candidate
slot. It is not a general matcher, semantic deduplicator or proof authority.

Current source `cert_index.py:270-291` already derives the full name-erased
fingerprint during offer; lines345-347/442-445 store entry/posting rows;
`FIND_SQL` at296 orders all matching entries by sequence. Query replies do not
currently expose a type key, so client-side diversity is not free: fetching
capsules or rescanning duplicates would spend the very budget at issue.

The grouping key must commit **foundation, discovery namespace, exact ordered
universe parameters and the complete structural formal type**, as current
`discovery_features` already does. It excludes the exported declaration name
only. Do not group by terminal shape, a pretty-printed type or unordered
universes. Equal fingerprints mean exact structural grouping subject to hash
binding, not semantic equivalence or interchangeable local names.

For a fixed store/namespace/key/cut, the proposed invariant is: an optional
diverse stream contains one immutable first-sequence representative per
such fingerprint, never more than one per class; original offers
and exact lookup remain intact. Materialize `(namespace,key,type-key)` on
offer with an indexed representative-sequence range. Do not implement this as
query-time `DISTINCT`, `GROUP BY` or an uncharged duplicate walk. Scope it to
broad constant/shape discovery, not every exact-ID posting. Cursor/mode/schema
version and acquisition rederivation must bind any newly exposed type metadata.
Fresh state or explicitly charged selected re-offers are required, not a
whole-corpus startup/backfill or reinterpretation of old cursors.

This is not wire-transparent if exposed publicly. The smallest explicit mode
design adds `mode=type_diverse` to find/peer-find query validation and CLI,
echoes/binds that mode in responses and remote selections, and exposes each
representative's unverified full type key for acquisition rederivation. Current
`cert_peer.py:79-89,111-113,231-251,270-271` rejects those extra fields. Therefore
use versioned query/reply/remote-record schemas and a distinguished peer find
route; old peers must refuse, not return an empty complete answer. Offer and
four-file bundle/receipt schemas need not change. New store schema/discovery
namespace and cursor version commit the grouping/mode; cursors also retain
store, exact base key, high-water cut, next representative sequence and all
budgets. This is one search-mode seam, not an authorization to implement it.

A first cheap focused successor can exercise the local Store API and exact
wire-schema contracts with inert receipts, without real sockets, a new checker
image or **any new certificate generation**. Reuse genuine A evidence for its
already-established mathematical capability. A later genuine transport/reuse
claim still requires its own scoped changed-path qualification; it cannot
inherit runtime success from these source conditions.

For this constructed prefix the stream has R then A: two classes rather than
33 offers. That arithmetic supports a bounded diversity opportunity, **not**
an executed improvement. It generalizes to name-copy multiplicity, not arbitrary
semantic duplicates. A future focused screen needs at most the existing33-row
case plus one distinct-type crowding counterexample, not another100000-row
locality benchmark or new proof image.

Costs shift to publication: one uniqueness lookup/possible representative
insert per selected broad key; retained original rows plus representative
indexes and a finite database-page charge. Query work should be indexed in
representatives examined, with ordinary response/time bounds; measure VM work
and offer/storage cost, not just returned counts. No claim that B-tree physical
I/O or maintenance is independent of stored index size follows.

**Falsifiers and limits:** more than16 distinct same-shape types still defeat
the same budget; binder/universe renamings may evade this fingerprint grouping;
the first representative may be unavailable or have an invalid certificate,
even when a later offer of that exact type has a valid certificate. This is a
concrete **representative-poisoning** case: grouped search can conceal valid
usable supply. For the smallest proposed slice, explicitly limited recall is
the selected design condition; no availability/valid-type coverage promise and
no implicit fallback. If broader recall is later claimed, require an explicit
bounded alternate-provider fallback whose attempts/bytes/verification costs
share the original allowance. Never promote the type to verified, transfer
acceptance from one member to another, or delete the other offers.
An optional stream must not silently replace exact access or advertise complete
recall. If it scans all duplicates, reads proof bodies during find, hides costs,
changes acceptance, or fails to improve the fixed duplicate case within its
new declared bounds, reject this seam. A raw stream may legitimately outperform
it when the first representative is bad; there is no dominance claim.

A pass would justify only a versioned diversity option that reduces duplicate
candidate consumption. A subsequent genuine acquisition/application pass would
justify a bounded search-to-use improvement. Neither licenses global semantic
recall, affordable certification or net useful growth. This candidate remains
unselected; no v3 capability adoption follows from this decision.
